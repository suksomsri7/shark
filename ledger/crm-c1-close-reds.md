The debt already recorded in CRM-RUN (17 Sep) that `safeReason` swallows the real exception still stands.

Trap I hit during this work: running `with-gate-lock.sh bash scripts/acc-v2-serve.sh start` makes `next start` inherit **both gate-lock fds** until the server stops, which blocks every other suite and session. Start the server outside the lock wrapper, as `run-c1-reds.sh` does, and don't wrap it in `iso.sh` either: the unit would kill the server when it exits.
