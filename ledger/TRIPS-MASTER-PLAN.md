## 2. มติเทคนิค (ผู้วางแผนเคาะ — แก้ได้ในใบ P0.3 ก่อนโค้ดแรก)
1. **3 โมดูล + 1 ชั้น**: «modules/trips» (ทัวร์+Liveaboard) · `modules/ticket` เดิม (ต่อยอด) · «modules/agency» · «modules/supplier» — ชั้นเอเจนซี่และผู้ให้บริการอ้างสินค้าด้วย `productKind` (ข้อความตรวจกับทะเบียน: `TRIP` · `TICKET` · `HOTEL`) + `productId` แบบเดียวกับ `scope` ของค่าตั้ง
2. **หน้าสัมผัส "ของที่ขายได้"** «core/sellable.ts»: `quote()` · `hold()` · `confirm()` · `cancel()` · `availability()` — trips และ ticket implement · หน้าจอง/พอร์ทัลเอเจนซี่/ช่องทางออนไลน์/API เรียกผ่านนี้เท่านั้น
3. **ตัดที่ = คำสั่ง SQL เดียว** (`UPDATE … SET sold = sold + n WHERE sold + held + n <= capacity RETURNING`) ต่อหน่วยที่ขาย (รอบ / เตียง / โควตาตั๋ว) — บทเรียน `reference_atomic_counter_single_statement` · เคบิน Liveaboard ใช้แถวต่อเตียง + ล็อกแถว (แบบ `RoomOccupancy` ไม่ใช่ตัวนับ)
4. **ทุกค่า = ค่าตั้งแบบชั้น** โดเมนใหม่ «trips» «agency» «ticket» ใน `core/settings/defs/` · แม่แบบ `DIVE_SHOP` `DAY_TOUR` `LIVEABOARD` `ATTRACTION` · ไม่มีค่าตายตัวในโค้ด (มติรอบ 4) · scope ใหม่: `PRODUCT` `DEPARTURE` `AGENT` `AGENT_TIER` `VESSEL`
5. **ราคา**: resolver เดียว ลำดับ ขายปลีก → ฤดูกาล/รอบ → ระดับเอเจนซี่ → สัญญาเอเจนซี่ → ช่วงพิเศษ → แก้มือ · ผลลัพธ์จดลง `policySnapshot` ของการจอง (ราคา · คอมมิชชัน · ตารางยกเลิก · งวดจ่าย · ธง "คิดคอมฯ/ลดได้" ต่อบรรทัด) · ทุกการคำนวณย้อนหลังอ่านจาก snapshot
6. **เงินทุกบาทผ่าน POS/บัญชี V2** (หลักเดียวกับโรงแรม): มัดจำ = รายได้รับล่วงหน้า รับรู้เมื่อปิดทริป · ค่าอุทยาน = เงินเก็บแทน บรรทัดแยก · ลูกหนี้เอเจนซี่ · เจ้าหนี้ผู้ให้บริการ · คอมมิชชันค้างจ่าย
7. **ตัวตนเอเจนซี่ระดับแพลตฟอร์ม** «AgentIdentity» (ไม่มี tenantId) ↔ «AgentAccount» (ต่อร้าน) — รุ่นแรกเอเจนซี่เห็นทีละร้าน · เฟส 2 เปิดเครือข่ายข้ามร้านโดยไม่ migrate (Q7)
8. **ไม่บล็อกเรื่องใบอนุญาต/กฎหมาย** (มติรอบ 3): ตัวตรวจกฎหมายของค่าตั้งใช้ระดับ `OK`/`WARN` เท่านั้น ไม่มี `BLOCK` ในโดเมนนี้
9. **ผังเรือมีเวอร์ชัน** · ทริปจด `deckPlanVersionId` · เผยแพร่เวอร์ชันใหม่ต้องผ่านตัวตรวจผลกระทบ (TA §11)
10. **หน้าจองสาธารณะ = route เดียว** `/b/[shop]/…` รับ `?a=` `?s=` `?d=` · LIFF และ embed เป็นเปลือกของ route เดียวกัน (ไม่มีโค้ดจองซ้ำ 3 ชุด) · ลูกค้าไม่ล็อกอิน ใช้ `publicToken` + ยืนยันตัวตนเมื่อแก้ไข
11. **ออฟไลน์เฉพาะ 3 จอ**: วอเชอร์/ตั๋วลูกค้า · เช็กอินของไกด์ · สแกนประตู — คิวในเครื่องแล้วซิงก์ · กันสแกนซ้ำด้วยการรวมผลฝั่งเซิร์ฟเวอร์ (ครั้งแรกชนะ ครั้งหลังขึ้นเตือน)
12. **PDPA**: ไฟล์พาสปอร์ต/แบบฟอร์มแพทย์ = ที่เก็บ private · ปิดบังบนจอ · บันทึกการเปิดดู · งานลบอัตโนมัติตามค่าตั้ง (ค่าเริ่มต้นตาม LG)
13. **หลายสกุลเงินเฉพาะ Liveaboard**: ราคาตั้งต่อสกุล (ไม่แปลงสด) · จดอัตรา ณ วันจอง · บัญชีลงเป็นบาท
14. ตั๋ว: ตาราง `Ticket*` เดิมคงชื่อ · เพิ่ม «TicketSession» «TicketChannelQuota» «TicketBatch» · การจองที่มีอยู่ backfill เป็นรอบเดียวต่ออีเวนต์

## 6. ความเสี่ยง
1. **E1 ไม่เกิด** → เริ่มไม่ได้ · ทางสำรอง: แตก `session/trips` จาก `session/svc` (เสี่ยง conflict ตอนขึ้น main ทีหลัง — ต้องให้เจ้าของเลือก)
2. **เครื่องร่วมกับ HR**: build ชนกัน → ใช้กติกา RAM/ล็อก gate ต่อ RUN ของตัวเอง · งานยาวต้องมีตัวเฝ้าจนจบ
3. **กฎหมาย/ภาษี**: LG เป็นการค้นคว้า ไม่ใช่คำปรึกษาทางกฎหมาย — ค่าที่ไม่ยืนยันติดป้ายในจอค่าตั้งว่า "ตรวจกับนักบัญชีของร้าน"
4. **ขนาด 72 ใบ** ใหญ่กว่า RUN ใด ๆ ที่ผ่านมา (POS 55 · CRM 53) → หมุด M1–M5 ส่งมอบเป็นช่วง แต่ละหมุดใช้งานได้จริงโดยไม่ต้องรอหมุดถัดไป
5. **ร้านนำร่องขายของคนอื่น**: ถ้า S ล่าช้า SiamDive ใช้ได้แค่เดย์ทริปของตัวเอง
6. **ออฟไลน์** (ไกด์/ประตู): ซิงก์ชนกัน — จำกัดให้เขียนได้เฉพาะ "เช็กอิน" ตอนออฟไลน์
