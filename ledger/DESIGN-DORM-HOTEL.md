### เปลี่ยนอะไร (3 ก้าว)
1. **แกนห้องร่วม** — อาคาร · ชั้น · ห้อง · ประเภทห้อง · สถานะห้อง · "ห้องนี้ถูกใช้ช่วงไหน" (กันขายซ้อนระดับฐานข้อมูล) ใช้ร่วมทั้งหอและโรงแรม · ห้องเดียวกันปล่อยรายเดือนหรือรายคืนได้ (อพาร์ตเมนต์ไทยจำนวนมากทำทั้งสองแบบ)
2. **หอพักครบวงจร** — สัญญา+เงินประกัน · จดมิเตอร์มือถือ · ออกบิลทั้งตึก → ใบแจ้งหนี้ในบัญชี V2 → LINE ของหอ → QR → สลิป → ตรวจ → ใบเสร็จ → ลงบัญชีเอง · ทวง/ค่าปรับ · ย้ายออกคืนประกัน · แจ้งซ่อม→บอร์ดงาน · ประกาศ · รายงาน · **กฎ สคบ. ฝังในระบบ**
3. **โรงแรม V2** ตามสเปกเต็มที่มีอยู่ — tape chart · ราคาตามวัน/ฤดู · folio ต่อ POS (ROOM_CHARGE) · แม่บ้านมือถือ · ร.ร.3/ร.ร.4/ตม.30 · night audit ย่อ · จองออนไลน์ V2 · OTA เป็นเฟสหลัง

2. **ลูกค้าโรงแรมไม่ต้องรอเปล่า**: P1 วันนี้ใช้รับจอง/เช็กอิน-เอาต์/มัดจำออนไลน์ได้แล้ว — ถ้าลูกค้าโรงแรมเล็กยอมเริ่มด้วย P1 ระหว่างรอ V2 จะได้ข้อมูลจริงมาออกแบบ tape chart/ราคา (เจ้าของตัดสิน §13)

### ตัดสินใจหลัก 12 เรื่อง (ปรับ 27 ต.ค.)
1. **ไม่ฮาร์ดโค้ดตามลูกค้ารายแรก — ทุกนโยบายเป็น "ค่าตั้ง" มีค่าเริ่มต้น** เก็บแบบชั้น กิจการ → หน่วยธุรกิจ → อาคาร → ประเภทห้อง → ห้อง → สัญญา (ชั้นที่เจาะจงกว่าชนะ) · ทุกค่ามีชนิด/ช่วงค่าที่ยอมรับ/ตัวตรวจกฎหมาย/ประวัติว่าใครแก้เมื่อไร · บิลและสัญญา **จดค่าที่ใช้ ณ ตอนออก** (แก้ค่าตั้งทีหลังไม่ย้อนไปเปลี่ยนบิลเก่า) · รายการทั้งหมด = ภาคผนวก ก
2. **โหมดตามกฎหมาย 3 แบบ ตั้งต่อหน่วยธุรกิจ**: *เข้มงวด-บล็อก* (ค่าเริ่ม เมื่อระบบตรวจว่าอยู่ในขอบเขตประกาศ สคบ. 2568: ≥ 3 ห้อง อพาร์ตเมนต์/ห้องเช่า) · *เตือน* (บันทึกได้แต่ต้องติ๊กยอมรับ + เจ้าของกิจการอนุมัติ + เก็บประวัติ) · *นอกขอบเขต* (ต้องระบุเหตุผล+หลักฐาน เช่น < 3 ห้อง/หอพักนักศึกษามีใบอนุญาต) · เปลี่ยนโหมดได้เฉพาะเจ้าของกิจการ
3. **ศูนย์เชื่อมต่อระดับกิจการ (Integrations) ใช้ร่วมทุกระบบ** — ตัวต่อทุกชนิด (LINE OA · พร้อมเพย์ · เกตเวย์รับเงิน · ตรวจสลิป · ช่องทางขายห้อง/OTA · SMS · มิเตอร์อัจฉริยะ) อยู่ที่เดียว · คีย์เข้ารหัส ไม่แสดงซ้ำ · ทดสอบ/สุขภาพ/โควตา · เลือกใช้กับหน่วยธุรกิจไหน · **ไม่เชื่อม = ระบบทำแบบมือแทนเสมอ** (ไม่มีฟีเจอร์ไหนพังเพราะไม่ได้สมัคร) · ใช้ร่วมกับเลนจองคิว
4. **ตัวต่อ = adapter ตาม interface กลางต่อชนิด** (เช่น `SlipVerifier.verify()` · `ChannelManager.pushAri()/pullReservations()`) — เพิ่มผู้ให้บริการใหม่ = เขียน adapter 1 ไฟล์ + ข้อสอบสัญญา ไม่แตะหอ/โรงแรม
5. **แกนห้องใช้ตารางห้องของโรงแรมเดิม** (`HotelRoomType`/`HotelRoom`) — เพิ่มคอลัมน์ additive + ตารางอาคาร · เปลี่ยนชื่อในโค้ดเป็น `RoomType`/`Room` ด้วย `@@map` **ไม่แตะตารางจริง** · หอและโรงแรมเรียกผ่าน facade `rooms/index.ts` เท่านั้น (กติกา F2)
6. **"ห้องนี้ถูกใช้ช่วงไหน" เป็นตารางเดียว** (`RoomOccupancy`: สัญญาเช่า/การพัก/ปิดซ่อม/ถือไว้/**กันไว้ให้ช่องทาง**) + ข้อห้ามซ้อนช่วงวันระดับ Postgres — สัญญาหอ การจองหน้าเคาน์เตอร์ และการจองจาก OTA ชนกันไม่ได้แม้เข้าพร้อมกัน
7. **หอพักเดินเงินผ่านบัญชี V2 โดยตรง** (ใบแจ้งหนี้ลูกหนี้รายเดือน → รับชำระ → ใบเสร็จ) · **โรงแรมยังปิดยอดผ่าน POS** ตามสเปกเดิม
8. **เงินประกันผู้เช่า = หนี้สิน** (บัญชีใหม่ "เงินประกันรับจากผู้เช่า") ปิดตอนย้ายออกด้วยรายการเดียว
9. **รอบบิลหอสร้างใบแจ้งหนี้เองต่อห้องต่องวด** (idempotent ต่อสัญญา×เดือน) ไม่ใช้ `AccountRecurringRule` · **ภาษีต่อบรรทัดมาจาก "ชนิดภาษี" ของรายการ** (ค่าห้อง = ยกเว้น · น้ำไฟ/บริการ = VAT 7% เมื่อหน่วยธุรกิจจด VAT) — ไม่ให้ผู้ใช้กรอก VAT เอง
10. **LINE OA ของร้านเป็นหลัก** (มติ) เชื่อมในศูนย์เชื่อมต่อ (ต่อยอด `ChatChannelConnection` เดิม) · ผูกผู้เช่าด้วย "รหัสผูกห้อง" ในแชท OA · เมนูล่างกด → บอทตอบลิงก์ส่วนตัวที่เซ็นแล้ว — ไม่ต้องมี LIFF รายร้าน · ร้านมีหลาย OA ได้ (หอ/โรงแรม) เลือก OA ต่อหน่วยธุรกิจ
11. **ตรวจสลิปแบบชั้น**: ระบบตรวจเองเสมอ (ยอด · สลิปซ้ำ · บัญชีผู้รับ · เวลาโอน) → ถ้าเปิดตัวต่อ ส่งตรวจกับผู้ให้บริการ (ผู้ใช้สมัคร/จ่ายเอง) → ไม่ผ่าน/ตัวต่อล่ม = คิวตรวจมือ (ตั้งได้) · ชิ้นเดียวใช้ทั้งหอ/โรงแรม/POS/จองคิว
12. **AI เสนอ คนยืนยัน**: อ่านเลขมิเตอร์/พาสปอร์ต · เดาคอลัมน์นำเข้า · ร่างข้อความทวง — ไม่ส่งเงิน/ไม่ส่งบิลเอง

## 5. ของกลาง (R0) — แกนห้อง · ค่าตั้ง · ศูนย์เชื่อมต่อ

### 5.1 แกนห้องร่วม
- **อาคาร → ชั้น → ห้อง** (`RoomBuilding` ใหม่ · ชั้นเป็นเลขในห้อง) · **ประเภทห้อง** มีทั้งราคาคืนและราคาเดือน · ห้องตั้ง `rentMode` = รายคืน / รายเดือน / ได้ทั้งสองแบบ (B205 ในจอ 08) [R0]
- **สถานะห้อง 2 ชั้น**: สถานะกายภาพ (สะอาด/รอทำ/ตรวจแล้ว/ปิดซ่อม — ของแม่บ้าน/ช่าง) แยกจาก "การใช้งาน" ที่คำนวณจาก `RoomOccupancy` (ว่าง/มีผู้เช่า/มีแขก/จอง/ถือไว้) + ป้ายการเงินจากหอ (ค้างจ่าย/สลิปรอตรวจ) → ผังห้องจอ 01 และ tape chart จอ 08 อ่านจากที่เดียว [R0]
- **`RoomOccupancy`** (ห้อง · วันเริ่ม · วันจบแบบไม่รวม · ชนิด LEASE/STAY/HOLD/BLOCK · อ้างอิงต้นทาง · active) + `EXCLUDE USING gist (roomId WITH =, daterange WITH &&) WHERE active` → **ฐานข้อมูลปฏิเสธการซ้อน** ไม่ว่าจะมาจากหอ หน้าเคาน์เตอร์ หรือหน้าจองออนไลน์ (ต้องเปิด `btree_gist` บน Neon — ตรวจตอน R0.3) · ระดับ "ประเภทห้องเหลือกี่ห้อง" ของโรงแรมยังใช้ `HotelBookingNight` ตามสเปกเดิม [R0/H]
- **ผังห้องเป็นคอมโพเนนต์ร่วม** (ตามชั้น · รายการ · ตัวกรอง) ใช้ในหอ (จอ 01) และหน้าแม่บ้านโรงแรม [R0]
- **หน่วยธุรกิจ**: เพิ่ม `UnitType.DORM` (additive) — ต่างจาก HOTEL แค่เมนูเริ่มต้น · ทั้งสองเปิดโหมดรายเดือน/รายคืนได้ใน `settings.rooms.modes` [R0]
- **มิเตอร์ผูกกับห้อง ไม่ผูกกับผู้เช่า** (เปลี่ยนผู้เช่ามิเตอร์ยังอยู่) · มิเตอร์หลักของตึกเป็นมิเตอร์ชนิดพิเศษไว้คำนวณต้นทุนจริง · ตึกที่ไม่มีมิเตอร์รายห้อง = ใช้มิเตอร์รวมแล้วเฉลี่ย (ตามคน/ห้อง/พื้นที่ — ค่าตั้ง) [D1]

### 5.2 ระบบค่าตั้งแบบชั้น (Settings) — R0.5 · 🖼10 🖼17 · รายการเต็ม = ภาคผนวก ก
- **ทะเบียนค่าตั้งในโค้ด** (ไม่ใช่ตาราง): ต่อค่ามี `key` · ชนิด (ตัวเลข/เงิน/ตัวเลือก/ข้อความ/แม่แบบ/ตาราง) · **ค่าเริ่มต้น** · ชั้นที่ยอมให้ตั้ง · ช่วงค่าที่ยอมรับ · **ตัวตรวจกฎหมาย** (คืน ผ่าน/เตือน/บล็อก ตามโหมดกฎหมาย) · ใครแก้ได้
- **ค่าที่ผู้ใช้ตั้งเก็บแบบชั้น** `กิจการ → หน่วยธุรกิจ (หอ/โรงแรม) → อาคาร → ประเภทห้อง → ห้อง → สัญญา` — ค่าเจาะจงกว่าชนะ · หน้าตั้งค่าแสดง "ค่านี้มาจากชั้นไหน" + ป้ายค่าเริ่มต้น (ภาพ 17) · ตั้งค่ามีวันที่มีผล (เช่น ค่าส่วนกลางขึ้นเดือนหน้า)
- **บิล/สัญญา/การจองจดค่าที่ใช้ไว้ (snapshot)** — แก้ค่าตั้งไม่ย้อนเปลี่ยนเอกสารเก่า · ทุกการแก้มีประวัติ (ใคร · ค่าเดิม→ใหม่ · เหตุผลถ้าเป็นการข้ามกฎ)

- ใช้ร่วมกับระบบอื่นได้ (จองคิวมีค่าตั้งแบบเดียวกัน: % เปิดจอง · ผ่อนผันมาสาย · มัดจำ) — เสนอให้เป็นของกลางที่ `src/lib/core/settings`

## 6. หอพัก — โมดูลทั้งหมด (🖼 = ภาพใน `design-dorm/`) [D1/D2]

### A1 ผังห้อง + ภาพรวม 🖼01
- 36 ห้องในจอเดียว · สถานะแยกด้วยรูปทรง (ไม่พึ่งสี) · KPI (เข้าพัก % · ว่าง/จอง/ซ่อม · รับแล้ว/รอเก็บ · ค้างเดือนก่อน) · "ต้องทำวันนี้" (ค้างจ่าย → ทวง · สลิปรอตรวจ · แจ้งซ่อม · ผู้เช่าเข้าใหม่ · สัญญาใกล้หมด) · ความคืบหน้ารอบบิล [D1]

### A2 ผู้เช่า · สัญญา · เงินประกัน 🖼02
- ผู้เช่า = Party (หาซ้ำด้วยเบอร์/เลขบัตร) · ผู้พักร่วม · รถ · ผูก LINE · เอกสาร (บัตร · สัญญาลงชื่อ · รูปห้องวันเข้า · มิเตอร์เริ่ม) [D1]
- สัญญา: ระยะ (สั้น ≤ 3 ปี) · ค่าห้อง/ส่วนกลาง **ล็อกตลอดสัญญา** · วันครบกำหนด · กฎค่าปรับ · แม่แบบตามประกาศ สคบ. 2568 (ข้อห้ามไม่มีในแม่แบบ) · ลงชื่อบนจอ/พิมพ์ · ต่อสัญญา (ขึ้นราคาได้ตอนนี้เท่านั้น) · ย้ายห้อง (ปิดสัญญาเก่า-เปิดใหม่ โอนประกัน) [D1]
- เงินประกัน + ค่าเช่าล่วงหน้า ≤ 3 เดือน (ตัวกั้น) · ใบรับเงินประกัน · ลงบัญชีเป็นหนี้สิน · ยอดประกันที่ถือทั้งตึก [D1]
- จอง/รอเข้า: รับเงินจองก่อนทำสัญญา (หักเข้าประกันวันเข้า) [D1]

### A3 มิเตอร์ 🖼03
- มือถือ: ไล่ทีละห้องตามชั้น · ถ่ายรูป → AI อ่านเลขให้ (เสนอ คนยืนยัน) · พิมพ์เองได้ · ออฟไลน์แล้วส่งทีหลัง · จดห้องว่างด้วย (จับไฟรั่ว) [D1]
- ตรวจผิดปกติ: สูง/ต่ำกว่าค่าเฉลี่ย 3 เดือนเกินเกณฑ์ · เลขถอยหลัง (→ ฟลว์เปลี่ยนมิเตอร์ คิดหน่วยรวม 2 ตัว) · ห้องว่างมีการใช้ → สร้างงานตรวจในบอร์ดงาน · ห้องผิดปกติถูกพักไม่ส่งบิลจนตรวจ [D1]
- มิเตอร์ดิจิทัล/IoT 🔜 (โครงข้อมูลรองรับ `source`)

### A4 ค่าน้ำไฟ · มิเตอร์ · VAT · โหมดกฎหมาย — ตั้งต่อหอ 🖼10
- **วิธีวัด** (ต่อน้ำ/ไฟ แยกกัน · ต่อหอ แก้รายห้องได้): มิเตอร์รายห้อง · มิเตอร์รวมแล้วเฉลี่ย (ตามคน/ห้อง/พื้นที่) · ไม่มีมิเตอร์ [D1]
- **วิธีคิดเงิน**: *ต้นทุนจริง* (ค่าเริ่ม — ยอดบิลการไฟฟ้า/ประปา ÷ หน่วยมิเตอร์หลัก + รูปบิล) · *ตารางอัตราของการไฟฟ้า/ประปา* (ขั้นบันได+Ft · ระบบเก็บตารางมีวันที่มีผล) · *คงที่ต่อหน่วย* · *เหมาจ่ายต่อห้อง/ต่อคน* · **ค่าขั้นต่ำ** (เปิด/ปิด + ยอด) · ปัดเศษ [D1]
- **โหมดกฎหมาย** (ตัดสินใจข้อ 2): ทุกค่าที่เกี่ยวผ่านตัวตรวจ — อัตรา > ต้นทุนจริง · มีขั้นต่ำ · เหมาจ่ายเฉลี่ยแล้วเกินต้นทุน → *เข้มงวด* บันทึกไม่ได้ / *เตือน* ต้องยอมรับ+อนุมัติ+มีป้ายในประวัติ / *นอกขอบเขต* ไม่ตรวจแต่ต้องมีเหตุผล · ตรวจซ้ำทุกเดือนตอนใส่บิลการไฟฟ้า (ต้นทุนเปลี่ยน → อัตราคงที่อาจกลายเป็นเกิน) [D1]
- **VAT**: หน่วยธุรกิจตั้ง "จด VAT หรือไม่" + ราคาที่กรอก "รวม/ไม่รวม VAT" · ทุกรายการค่าใช้จ่ายมี **ชนิดภาษี** (ค่าเริ่ม: ค่าห้องที่อยู่อาศัย = ยกเว้น · น้ำ/ไฟ/ส่วนกลาง/ที่จอด/บริการ = VAT 7%) → บิลแยกบรรทัดและคิด VAT ให้อัตโนมัติ · จด VAT → ออกใบกำกับภาษีให้ส่วนที่มี VAT [D1 · D1.13]
- ส่วนต่างต้นทุน (ส่วนกลาง/ห้องว่าง) เป็นต้นทุนหอในรายงาน (🖼14)

### A5 รอบบิลรายเดือน 🖼04 (ค่าตั้ง: วันออกบิล · วันครบกำหนด · ค่าห้องล่วงหน้า/น้ำไฟย้อนหลัง · คิดเศษวันเข้า-ออก · ช่องทางส่ง · ส่งอัตโนมัติหรือตรวจก่อน — 🖼17)
- ขั้น: จดมิเตอร์ครบ → **ตรวจบิล** (ตารางทุกห้อง · ที่มาทุกบรรทัด · ตัวอย่างบิลที่ผู้เช่าเห็น) → ส่ง → เก็บเงิน · ห้องแจ้งย้ายออกไม่ออกบิล (ไปคิดในใบย้ายออก) [D1]
- กดส่ง = ใบแจ้งหนี้ 1 ใบ/ห้องในบัญชี V2 (ลูกหนี้ = ผู้เช่า · idempotent ต่อสัญญา×งวด) + ลิงก์จ่าย (QR ยอดตรง) + LINE (Flex) / ลิงก์ SMS สำหรับคนยังไม่ผูก LINE / พิมพ์ใส่ห้อง · ตั้งเวลาส่งได้ [D1]
- บรรทัด: ค่าห้อง · ส่วนกลาง · ไฟ (เลขก่อน→หลัง × อัตรา) · น้ำ · ค่าปรับเดือนก่อน · ยอดยกมา/ยกไป · อื่น ๆ (ที่จอดรถ มี VAT ถ้าหอจด) [D1]
- แก้บิลหลังส่ง = ใบลดหนี้/เพิ่มหนี้ (ไม่แก้ทับ) [D1]

### A6 ผู้เช่าผ่าน LINE + หน้าจ่าย 🖼05
- **LINE OA ของร้าน** (มติ — เชื่อมที่ศูนย์เชื่อมต่อ · ร้านมีหลาย OA ได้ เลือกต่อหน่วยธุรกิจ) · ผูกด้วยรหัสผูกห้อง (QR ติดในห้อง/ในสัญญา) · เมนูล่าง: บิลของฉัน · แจ้งซ่อม · ประกาศ · สัญญา/เอกสาร · พัสดุ · ติดต่อหอ [D1/D2]
- บิล Flex → หน้าจ่าย (ลิงก์เซ็น · เปิดใน LINE) : QR ยอดตรง · บันทึก QR · แนบสลิป · สถานะ · ใบเสร็จ PDF · ประวัติบิล [D1]
- เตือนก่อนครบ/วันครบ/เลยกำหนด (ไม่ส่งเกินที่ตั้ง · เคารพโควตาข้อความ OA) [D1]

### A7 ตรวจสลิป · รับเงิน 🖼06
- สลิปเข้า → ตรวจ: ยอดตรงบิล · ไม่เคยใช้ (เลขอ้างอิง/แฮชรูป) · ผู้รับคือบัญชีหอ · วันเวลาโอนสมเหตุสมผล · **ถ้าเปิดตัวต่อตรวจสลิป** ส่งตรวจกับผู้ให้บริการที่ผู้ใช้สมัครเอง (interface §5.3) → ผ่าน = รับชำระ + ใบเสร็จ + LINE อัตโนมัติ [D1]
- ตั้งได้: อนุมัติอัตโนมัติเมื่อผ่านทุกข้อ (เปิด/ปิด) · ยอมรับยอดคลาดเคลื่อน ± ฿__ · ชื่อผู้โอนต้องตรงไหม · ตัวต่อล่ม → คิวมือ/ปฏิเสธ
- ไม่ผ่าน → คิวให้คน: ชื่อผู้โอนไม่ตรง · ยอดขาด/เกิน (รับบางส่วน+ยกยอด / ขอโอนเพิ่ม / ปฏิเสธ) · สลิปซ้ำ (ปฏิเสธ+แจ้งเหตุผล) [D1]
- รับเงินสด/โอนเข้าบัญชีอื่นด้วยมือ · จับคู่ statement ธนาคาร (ของบัญชี V2 มีแล้ว) เป็นอีกทางยืนยัน [D1]

### A8 ทวง · ค่าปรับ [D1]
- ค่าปรับเป็นค่าตั้ง (ไม่มี/ต่อวัน/ครั้งเดียว/% · เพดาน · วันผ่อนผัน · ยกเว้นรายคนพร้อมผู้อนุมัติ — 🖼17) ล็อกลงสัญญาตอนทำ · ขึ้นบิลถัดไปเป็นบรรทัดแยก · ตารางเตือน/ทวงและข้อความเป็นค่าตั้ง · ทวงทาง LINE (AI ร่างข้อความสุภาพ คนกดส่ง) · นัดจ่าย · หนังสือบอกเลิกสัญญาจากแม่แบบ — **ไม่มีตัดน้ำไฟ/ล็อกห้อง/ยึดของ**

### A9 ย้ายออก · คืนประกัน 🖼07
- แจ้งย้ายออก (นับ N วัน — ค่าตั้ง ค่าเริ่ม 30) → ตรวจห้องเทียบรูปวันเข้า (ใช้งานปกติ = หักไม่ได้ · เสียหาย = ต้องมีรูป/ใบเสร็จ) → มิเตอร์วันออก → สรุปเงิน (ประกัน − น้ำไฟถึงวันออก − ค่าเสียหาย − ค้าง) → ส่งใบสรุปให้ผู้เช่าดู → โอนคืน · **นับถอยหลัง N วัน (ค่าเริ่ม 7 · เกิน 7 = ขัดประกาศ → ตามโหมดกฎหมาย) + เตือนทุกวัน** · ห้องเปลี่ยนเป็นทำความสะอาด → ว่าง/จอง [D1]
- หักเกินวงเงินที่ตั้ง (ค่าเริ่ม ฿2,000) → ขออนุมัติเจ้าของ (approval core) · รายการค่าเสียหายมาตรฐาน (กุญแจหาย ฿__ · มุ้งลวด ฿__) เป็นค่าตั้ง [D1]

### A10 แจ้งซ่อม · ประกาศ · พัสดุ · รายงาน [D2]
- แจ้งซ่อม (หมวด · ข้อความ · รูป/คลิป · อนุญาตเข้าห้อง · เวลาสะดวก) → การ์ดในบอร์ดงานของช่าง · สถานะกลับ LINE · ให้คะแนน · ค่าอะไหล่เบิกคลัง/ลงค่าใช้จ่าย 🔜 🖼05
- ประกาศ: ทั้งตึก/ชั้น/ห้อง · อ่านแล้วกี่คน · พัสดุ (ทางเลือก): บันทึกรับ+รูป → แจ้ง LINE → ผู้เช่ากดรับ
- รายงาน: อัตราเข้าพักรายเดือน · รายได้แยกประเภท · ค้างจ่ายตามอายุหนี้ · ต้นทุนส่วนต่างน้ำไฟ · ห้องว่างนาน · ผู้เช่าจ่ายช้าซ้ำ · ส่งออก Excel

### 7.1 โครงช่องทางขายห้อง (OTA) — วางใน H (H.10) · ตัวต่อเจ้าแรก H2 · 🖼11
- **แม็ป**: ประเภทห้อง ↔ room type ของช่องทาง · แผนราคา ↔ rate plan ของช่องทาง (ราคาส่งช่องทาง = แผนราคาที่ผูกสูตร เช่น +15% — 🖼15) · เลือกห้องที่เปิดขายผ่านช่องทาง (เช่น ห้องรายเดือนไม่ส่ง)
- **ขาออก (ARI = ห้องว่าง/ราคา/ข้อจำกัด)**: ทุกครั้งที่ห้องว่างหรือราคาเปลี่ยน (จาก `RoomOccupancy`/`HotelBookingNight`/ราคา) → outbox `channel.ari.changed` → คิวรวมเป็นชุดต่อช่วงวัน → adapter `pushAri` · ส่งซ้ำได้ (ค่าล่าสุดชนะ) · **ค่าตั้งกันขายเกิน**: กันห้องไว้ไม่ส่งช่องทาง N ห้อง/ประเภท (buffer) · ปิดขายช่องทางรายวันได้
- **ขาเข้า (การจอง)**: webhook/ดึงเป็นรอบ → `ChannelReservationInbox` เก็บข้อมูลดิบ · **idempotent ด้วย (ตัวต่อ, externalId, version)** · แปลงเป็น `HotelReservation` (`source=OTA` · `channelRef`) → ลง `RoomOccupancy` ในธุรกรรมเดียว · แก้/ยกเลิกจากช่องทาง = version ใหม่ของ externalId เดิม
- **ชนห้อง**: OTA ขายไปแล้วปฏิเสธไม่ได้ → ถ้าไม่มีห้องจริงว่าง จะไม่ทับใคร แต่เข้า **คิว "ต้องจัดห้อง"** ให้หน้าเคาน์เตอร์ (ย้ายห้อง/อัปเกรด/ติดต่อแขก) + แจ้งเตือนทันที · ป้องกันต้นทางด้วย buffer + ส่ง ARI ทันที
- **ราคาสุทธิ/ค่าคอมฯ ช่องทาง**: เก็บยอดที่ช่องทางแจ้ง (gross/commission/net) ไว้ในการจอง → folio/บัญชีใช้ได้ภายหลัง · ช่องทางเก็บเงินเอง (prepaid) vs จ่ายที่โรงแรม เป็นฟิลด์ของการจอง
- **ไม่ทำใน H**: ตัวต่อเจ้าจริง (H2 · ต้องผ่านการรับรองของผู้ให้บริการ — ระยะเวลาไม่แน่นอน) · iCal (บางช่องทางรองรับ — ยังไม่ได้ตรวจ ใช้เป็นตัวต่อทางเลือกราคาถูกได้)

## 13. คำถามที่ต้องให้เจ้าของตอบ (ปรับ 27 ต.ค. — ตัดข้อที่ตอบแล้ว)
✅ ตอบแล้ว 27 ต.ค.: ค่าน้ำไฟ/มิเตอร์/VAT = ตั้งได้ต่อหอ · LINE OA ของร้าน · ตรวจสลิป = ตัวต่อผู้ใช้สมัครเอง · OTA = ต้องเชื่อมในอนาคต (วางโครง) · ทุกนโยบายตั้งได้ · ข้อมูลเฉพาะลูกค้ารายแรก (อัตรา/มิเตอร์/VAT/OA) **ไม่ใช่คำถามออกแบบแล้ว** — เป็นข้อมูลตอนเปิดใช้ (นำเข้า+ตั้งค่า)
1. **ที่ปรึกษากฎหมาย** ตรวจ: ตัวบทประกาศ สคบ. 2568 (คืนประกัน 7/14 วัน · วิธีคิดค่าไฟตึก · ค่าปรับ) + แม่แบบสัญญา — มีคนไหม (ต้องก่อน D1.12)
2. **โหมด "เตือน" (ยอมให้ตั้งเกินกฎหมายได้ถ้ายืนยัน)** — ให้มีตามแบบ (เจ้าของกิจการเปลี่ยน + อนุมัติ + ประวัติ) หรือ SHARK ไม่เปิดโหมดนี้เลย (ปลอดภัยกว่า แต่ยืดหยุ่นน้อยลง)
3. **ตัวต่อตรวจสลิปเจ้าแรก**: ทำตามเจ้าที่ลูกค้าหอรายแรกสมัคร (แนะนำ) หรือให้ทีมเลือกเจ้ามาตรฐาน 1 เจ้าก่อน
4. **OTA เจ้าแรก + จังหวะ H2**: เริ่ม H2 ทันทีหลัง H หรือรอมีลูกค้าโรงแรมที่ใช้ OTA จริง · เลือก channel manager เจ้าไหน (ขอชื่อจากลูกค้าโรงแรม)
5. **ศูนย์เชื่อมต่อ + ระบบค่าตั้ง** สร้างในเลนหอ (R0.5–R0.6) หรือเลนจองคิว — ผู้คุมเคาะได้ (ชิ้นเดียว ใช้ร่วม)
6. **ลำดับ**: แกนห้อง + หอก่อน (แนะนำ) — ระหว่างรอ ~5 สัปดาห์ ให้ลูกค้าโรงแรมเริ่มใช้ P1 ที่มีอยู่ก่อนได้ไหม
7. **สัญญา**: ลงชื่อบนจอพอไหม หรือต้องพิมพ์เซ็นกระดาษ/ลายมือชื่ออิเล็กทรอนิกส์มีใบรับรอง
8. **พัสดุ** เอาในรอบนี้ไหม (D2.3 · ตัดได้)
9. (เทคนิค — ผู้คุมเคาะได้) เปลี่ยนชื่อโมเดล Hotel* → Room* ด้วย `@@map` · รหัสบัญชีเงินประกันผู้เช่า

## มติเจ้าของ รอบ 2 (27 ต.ค. 2569)
1. มีที่ปรึกษากฎหมาย → ตรวจประกาศ สคบ. 2568 + แม่แบบสัญญาก่อนปิด D1
2. เปิดโหมด "เตือน" ตามแบบ (เจ้าของกิจการยืนยัน + เก็บประวัติ)
3. ตัวต่อตรวจสลิปเจ้าแรก = เจ้าที่ลูกค้าหอรายแรกสมัคร
4. ค่าบริการภายนอก (SMS · ตรวจสลิป · Beam · OTA) **ร้านจ่ายเองโดยตรง** — SHARK ไม่เก็บเงินแทน
5. โรงแรม: ยังไม่มีลูกค้าใช้จริง → รอ V2 เลย ไม่เปิดรุ่นแรกระหว่างรอ (เฟส H ทำหลังหอได้)
6. ระบบพัสดุ — **เอาด้วย** (รับพัสดุถ่ายรูป→LINE แจ้งผู้เช่า→เซ็น/สแกนรับ→เตือนค้าง · ~2–3 วัน · อยู่ใน D2)
7. อนุญาตแก้สัญญา POS 2 จุด (บิลพักผูกงานบริการ · ค่าคอมฯ ตามผู้ให้บริการ) หลัง POS RUN 100%
ผู้คุมเคาะ: ศูนย์เชื่อมต่อ + ระบบค่าตั้ง = ชิ้นกลางชุดเดียว สร้างครั้งเดียวต้นงาน (R0) ทั้ง 2 ระบบใช้ร่วม · รวมชื่อ/สัญญาให้ตรงกันก่อนแตกใบงาน
