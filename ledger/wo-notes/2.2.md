## เบี่ยงเบนจากแบบ/สเปค (ตามกติกา "ต่างได้เฉพาะที่ข้อมูลจริง/SPEC บังคับ — ต้องจดที่นี่")

1. **KPI "พ้นกำหนด" รวม 2 ฝั่ง (รับ+จ่าย) ตาม DESIGN-SPEC §4 ข้อ 2** — ค่าจริงจาก `dashboardSnapshot.kpi.overdue` = **6 ใบ / ฿205,900.00** (ลูกหนี้ 4 ใบ/฿128,400 ตรง f1 + เจ้าหนี้ 2 ใบ/฿77,500 ที่ f1 รอบ 1 ยังไม่ได้วาดเพราะตอนนั้นยังไม่มี payable overdue ใน seed) — **คำสั่ง WO เขียน assert ว่า "kpi-overdue: '4'"** ซึ่งตรงกับฝั่งลูกหนี้อย่างเดียว ไม่ใช่ค่ารวมตามสเปคที่อนุมัติแล้ว จึงใช้ค่ารวมตามสเปค (ถูกต้องตามข้อบังคับ §4) และปรับ `ASSERT_MAP["2.2"]` ในสคริปต์ภาพเป็น `"฿205,900"` แทนที่จะก็อปเลข "4" จากคำสั่งตรง ๆ — **ขอให้ Fable ยืนยันว่าตีความถูก** (ยึดสเปคที่อนุมัติเหนือกว่าเลขตัวอย่างในคำสั่ง WO)
2. **บล็อก "เอกสารที่ออก" (§4 ข้อ 6) และ 3 การ์ดอันดับ (§4 ข้อ 8) และ "บัญชีที่ติดตาม" ฝั่งผังบัญชี (§4 ข้อ 9)** — ไม่มีในภาพ f1 รอบ 1 เลย (f1 จบที่ "บัญชีเงินที่ติดตาม" การ์ดเดียว) — DESIGN-SPEC-V2 §4 ระบุชัดว่าเป็นของ "เพิ่มจาก PEAK" หลังจบรอบ 1 และ WO 2.2 (คำสั่งที่ได้รับ) ก็ระบุ 10 ขั้นตอน BUILD ตรงกับ §4 ครบทุกข้อ ⇒ สร้างตามสเปค+คำสั่ง โดยใช้ภาษาภาพเดียวกับการ์ดข้างเคียงที่มีแบบจริง (การ์ดสีขาวขอบเทา ปุ่มรอง ตัวเลขจัดวางแบบเดียวกัน) เพราะไม่มี pixel reference ให้เทียบ
3. **"เอกสารที่ออก" ตัดตัวเลือก "ช่วง" ทิ้ง เหลือแค่ "ชนิดเอกสาร ▾"** — §4 ข้อ 6 ระบุ "เลือกชนิด▾ + ช่วง▾" 2 ตัวกรอง แต่ `dashboardSnapshot.issued` คำนวณจาก `yearRange` คงที่ (ผูกกับ `year` ของทั้งหน้าอยู่แล้วผ่านตัวเลือกปีของกราฟ) — เพิ่มตัวกรอง "ช่วง" แยกอิสระต้องเรียก `documentsIssued()` เพิ่ม (+1 query เกินงบ 12 ที่ dashboardSnapshot คำนวณไว้ครั้งเดียว) ⇒ ใช้ปีที่เลือกจากกราฟเป็น "ช่วง" แทน (ไม่เพิ่ม query) แทนที่จะทำตัวกรองอิสระ
4. **3 การ์ดอันดับ (§4 ข้อ 8) เป็นรายปี ไม่ใช่รายเดือน** — คำสั่ง WO บอก "month select shared with 6" (หมายถึงแชร์กับโดนัท) แต่ `dashboardSnapshot.topCustomers/topProducts` คำนวณจาก `yearRange` คงที่ในตัว snapshot (query ที่ 10/11 ของงบ 12) เปลี่ยนเป็นรายเดือนต้อง query แยกใหม่ (+2 query) ⇒ **ไม่ทำ** ตามกติกาห้ามเกินงบ · "รายได้อะไรมากที่สุด" (การ์ดที่ 3) ไม่มีฟังก์ชันคำนวณสำเร็จรูปใน WO 2.1 เลย ⇒ เพิ่ม `dashboard.ts::incomeCategoriesFromRows` (additive export ใหม่ ไม่กระทบของเดิม) สรุปจาก `glRows` ที่มีอยู่แล้ว (ฟรี ไม่เพิ่ม query) กรองเฉพาะ periodKey ของปีที่เลือก
5. **MoneyText/จำนวนเงินไม่มีทศนิยมเป็นค่าเริ่มต้น** (`฿486,300` ไม่ใช่ `฿486,300.00`) — f1 ใช้ `.00` ทุกจุดรวม KPI/ตาราง/บัญชีเงินที่ติดตาม แต่หน้าอื่นของโมดูล V2 ที่ผ่าน QC แล้ว (StatCard เดิมของหน้าหลัก V1.5, ตาราง list ต่าง ๆ) ใช้ `MoneyText` แบบไม่บังคับทศนิยมเป็นมาตรฐานทั้งแอปอยู่แล้ว และ **คำสั่ง WO ระบุ assert ตรง ๆ ว่า `kpi-receivable "฿486,300"` (ไม่มี .00)** ⇒ ยึดตามคำสั่ง/มาตรฐานแอป ไม่ใช่ภาพ f1 พิกเซลเป๊ะ (สอดคล้องกับ hard rule "MoneyText ฿x,xxx or ฿x,xxx.xx per UI_STANDARD" — ให้ UI_STANDARD/ธรรมเนียมแอปตัดสิน ไม่ใช่ pixel เดา)

7. **มือถือไม่มี bottom sheet เต็มจอสำหรับเมนูสร้างเอกสาร** — ใช้แผง dropdown ธรรมดา (แบบเดียวกับเดสก์ท็อป แต่เต็มความกว้าง) แทน bottom sheet ของ `AccountTabBar` (ซึ่งเป็นคนละกลไก/คนละสถานะ) — ยังกดใช้งานได้ครบทุกฟังก์ชัน เพียงแต่ animation/ตำแหน่งไม่เหมือน sheet เต็มจอ

1. 🔴 **คอมโพเนนต์ที่เรนเดอร์ 2 ชุดตามจอ (ซ่อนด้วย CSS `hidden`/`lg:hidden`) ต้องมี `data-testid` แยกกัน** ถ้าจะมีสคริปต์ QC คลิกมัน — `scripts/visual-acc-v2.mts` หา element ด้วย `document.querySelector` (ตัวแรกที่เจอในซอร์ส ไม่สนใจ CSS visibility) เหมือนที่ WO 1.6 เจอมาก่อนแล้วแก้ด้วย `ref-row-`/`ref-card-` แยกกัน — `DashCreateMenu` เจอเคสเดียวกัน แก้แล้วด้วย `testId`/`menuTestId` prop (`btn-create-doc`/`btn-create-doc-m`) — **`DashCollapseToggle` ยังไม่แก้ (เรนเดอร์ 2 ชุด testid เดียวกัน `btn-dash-collapse`)** เพราะไม่มีสคริปต์คลิกปุ่มนี้ในรอบนี้ ผลคือแค่ label ข้อความอาจไม่ sync ระหว่าง 2 instance (ไม่กระทบการทำงานจริงเพราะ `applyToSections` เป็น global querySelectorAll ไม่ผูกกับ instance) — จดไว้เป็นหนี้เล็กถ้าจะมี WO ต่อไปคลิกทดสอบปุ่มนี้
