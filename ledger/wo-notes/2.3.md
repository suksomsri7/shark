## จุดที่ต่างจาก mockup/SPEC (จดตามกติกา parity — SPEC บังคับ vs ภาพจริง)
1. **"เอกสารที่ออก" การ์ด**: SPEC §6 เขียน "(เลือกชนิด+ช่วง)" (2 ตัวเลือก) — ของจริงใน f4 มีแค่ 1 ตัวเลือก (ช่วงเวลา
   "เดือนนี้ ▾") ไม่มีตัวเลือกชนิดเอกสารแยก เพราะการ์ดนี้โชว์ **4 ชนิดเอกสารพร้อมกัน** (breakdown ตามชนิด ไม่ใช่ตามสถานะ
   ของชนิดเดียวแบบการ์ดชื่อเดียวกันบนหน้าหลัก) ⇒ ยึดภาพจริง (f4) มีแค่ select ช่วงเวลาเดียว
2. **บล็อกล่าง 2 การ์ด ไม่ใช่ 3**: SPEC §6 ระบุ 3 บูลเล็ต "จ่ายค่าอะไรมากที่สุด · จ่ายให้ใครมากที่สุด · ค่าใช้จ่าย
   ตามหมวดบัญชี" แต่ f4 จริงมีแค่ 2 การ์ด ("คุณจ่ายให้ใครมากที่สุด" + "คุณจ่ายค่าอะไรมากที่สุด" ซึ่งรายการเป็นหมวดบัญชี
   จริง ๆ) — เพราะระบบไม่มีฟังก์ชัน "top รายการค่าใช้จ่ายต่อชิ้น" (มีแต่ topVendors + topExpenseCategories จาก WO 2.1)
   ⇒ 2 บูลเล็ตแรกยุบเป็นการ์ดเดียว (topExpenseCategories) ตรงกับภาพจริงเป๊ะ ฝั่งรายรับคู่ขนาน = 3 การ์ด
   (topProducts/topCustomers/topIncomeCategories — มีฟังก์ชันครบ 3 ตัวจริงจากหน้าหลัก WO 2.2)
3. **"ลูกหนี้/เจ้าหนี้ที่ติดตาม"**: f4 screenshot ที่ได้มา (2880×1702 เต็มหน้า) ไม่มีการ์ดนี้ปรากฏ (จบที่การ์ดอันดับ 2 ใบ)
   แต่ DESIGN-SPEC-V2 §6 เขียนไว้ชัด "ลูกหนี้/เจ้าหนี้ที่ติดตาม การ์ดเลือกได้ (pinned contact)" ⇒ ทำตาม SPEC เพิ่มการ์ด
   นี้ต่อท้าย · **AccountContact ไม่มีคอลัมน์ `pinned`** (ต่าง AccountFinance/AccountLedger ที่ WO 0.3 เพิ่มให้)
   → ตามคำสั่ง WO 2.3 ห้ามเพิ่ม schema ⇒ โชว์ **top-5 ตามยอดค้าง** แทนการปักหมุด (ยอดค้าง = grandTotal−paidTotal
   ตรง ๆ ไม่ได้หักใบลดหนี้เหมือน receivablePayableSummary — เพื่อคง query budget ที่ 2)
4. ปุ่มสร้างด่วนฝั่งรายรับ (ไม่มี mockup อ้างอิง) ใช้ป้าย "+ สร้างใบแจ้งหนี้" (รายการ INVOICE จาก createDocMenuItems —
   ตัวเดียวกับ default ของการ์ด "เอกสารที่ออก" บนหน้าหลัก ที่เลือก INVOICE เพราะ "มีข้อมูลจริงทุกกรณี")
