## CONTROLLER-DECISION
- **CD-B1 — `qc-pos-p2.7` PY11 red (oracle false positive).** The order intent is not on DEV1's display (`qo.intentId` is null — the display's intent lookup filters `deviceId = DEV1`). The display then falls back to its own static PromptPay QR for the published amount (P2.10 `payQr`), and a static EMV QR is a pure function of (PromptPay id, amount): the shop QR for ฿80 and the order intent's static QR for ฿80 are byte-identical, so the check `qo.payload === x.intent.qrPayload` cannot pass for any static intent. The xReport half passes. Options: (a) ORACLE-EDIT PY11 to judge only `qo.intentId !== x.intent.id` (or `qo.status === "STATIC"`) — recommended; (b) make order QRs unique by adding an EMV tag-62 reference to static order payloads (changes the money QR format; bank-app acceptance unverified — not done).
- **CD-B2 — `qc-pos-p2.6` A6 red (66/67).** The availability consumer now also reaches the new builtin `QR_ORDER` (adapter `QR`, active) — correct per ruling 2 (`QR: local("QR")` is a no-op).
