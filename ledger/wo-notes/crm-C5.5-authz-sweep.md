## Owner decisions (behaviour unchanged) — one-line recommendation each
- **D1** AI memory (`remember_fact`/`forget_fact` write at once, by persona design): keep; it is behind `ai.chat.send` since the hotfix — optionally list memories on a settings page so owners can audit them.
- **D2** Reject AI proposals/plans (web + mobile, non-CRM kinds): apply the CRM C3.4 rule to every kind — reject only if the caller could confirm it (the per-kind key `KIND_ACCESS` in `proposals.ts`), at least `ai.chat.send`; same check on both doors.
- **D3** DNA answers / propose / interview (web + mobile): require `systems.system.create` (the apply key) — the facts drive the blueprint and the AI context; interview also spends AI credit (RV-3 family).
- **D4** Push token re-bind: keep the upsert but clear the row on logout and only re-bind when the caller's session registered it (needs an app change) — low value, low risk.
- **D5** Payment profile: OWNER-only, or MANAGER only with `unitAccess` `["*"]` (precedent: domain actions are OWNER-only); add a delegable key later if owners ask.
- **D6** Marketplace template install: also require `systems.system.create` (it creates systems exactly like DNA apply).
- **D7** Support cases / announcement dismiss / coupon test / credit ledger "more" / logo upload / image fetch / platform invoices: keep (low value, the pages already show the same data to members); if tightening, support cases → OWNER/MANAGER + case opener.
- **D8** Platform automation page: filter `boardId: null` so board rules stay with board ADMINs; hide webhook URLs from non-managers; SSRF guard for WEBHOOK rules in its own card.
- **D9** Attach unmatched inbound mail: require `crm.email.send` (every other e-mail write needs send/settings).
- **D10** Own CRM notification prefs: align the two doors (either both need `crm.contact.read`, or REST drops it) — no data exposure either way.
- **D11** Webhooks: register a `member` family guard (member events need `member.api.manage`) beside the CRM one, so empty "all events" endpoints and toggles from the platform/account pages cannot carry member PII events; list/pause stored `[]` endpoints for owner review (fix1 R2-4).
