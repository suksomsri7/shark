## 1. สรุปแนวคิด

- **ตัวช่วยเดียว (`ImportWizard`) ใช้ 3 เส้นทาง**: `account/import/documents?side=revenue|expense` ·
  `account/import/contacts` · `account/import/products` — ต่างกันแค่ `kind`/label ที่ส่งเข้า props
  ไม่ใช่ตัวเก่า `CsvImport.tsx`/`csv.ts` ของ WO Wave6-A (นั้นยังใช้อยู่กับ member/inventory เดิม ไม่แตะ) —
  แต่ยังคง**ใช้ตัวแยก CSV กลางเดียวกัน** (`parseCsv`/`columnIndex`/`cell` จาก `src/lib/core/csv.ts`) ไม่เขียนใหม่
- **สถาปัตยกรรมไฟล์** (ตาม fitness F5 ratchet — baseline raw-prisma 45 ไฟล์ เต็มโควตาพอดี ห้ามเพิ่มไฟล์ใหม่ที่แตะ prisma):
  - `import-shared.ts` — บริสุทธิ์ (ไม่แตะ prisma/next) ใช้ทั้ง client (`ImportWizard`) และ server (`import-actions.ts`):
    นิยามฟิลด์ (`IMPORT_FIELDS`) · เทมเพลต CSV (BOM+กัน injection) · auto-match คอลัมน์ · ตรวจแถวระดับรูปแบบ ·
    จัดกลุ่มแถวเอกสารด้วย "เลขอ้างอิง" · แปลงบาท→สตางค์
  - `import-actions.ts` — "use server" **ไม่แตะ prisma** (เหมือน editor-actions.ts) — เรียก DB ผ่าน `service.ts`/`product.ts`/`expense.ts` เท่านั้น
    แยกชั้น **action** (ผูก `loadAccountSystem`+`assertAccountCan` ผ่าน request/cookie) ออกจากชั้น **core**
    (`previewImportCore`/`runImportCore` รับ `tenantId`/`systemId` ตรง ๆ) — จำเป็นเพราะ QC script เรียกโดยไม่มี
    Next.js request context ไม่ได้ (เหมือนเหตุผลที่ WO 1.7 ทำ — ดู comment หัวไฟล์)
  - เพิ่ม field เสริม `source?`/`tags?`/`refType?`/`refId?` ให้ `createDocument` (service.ts) และ `createExpenseDoc`
    (expense.ts) — **optional ทั้งหมด ไม่ส่ง = พฤติกรรมเดิมเป๊ะ** (source MANUAL, tags [], ref null) กระทบ
    เฉพาะ WO 1.8 ไม่กระทบ WO อื่นที่เรียกสองฟังก์ชันนี้อยู่แล้ว (editor-actions.ts ไม่ส่ง field ใหม่)
  - เพิ่ม helper ใน service.ts: `findContactForImport` (เลขภาษี→ชื่อตรงเป๊ะ) · `findContactDuplicates`
    (เช็คซ้ำเป็นชุดก่อน insert) · `findExistingImportRefIds` (idempotency ของเอกสาร)
- **idempotency ของเอกสาร**: `refType="CSV_IMPORT"` · `refId = "${fileHash}:${rowKey}"` (`fileHash` = djb2 เบา ๆ ของเนื้อไฟล์
  ทั้งก้อน ไม่ใช่ cryptographic — พอสำหรับกันอัปโหลดไฟล์เดิมซ้ำ ไม่ใช่ dedupe เนื้อหาข้ามไฟล์) · `rowKey` = ค่า
  "เลขอ้างอิง" ของกลุ่ม หรือ `__row_<index>` ถ้าไม่มี — สโคป `systemId` เสมอ (นำเข้าไฟล์เดิมในอีกระบบไม่ติด idempotency ข้ามระบบ — ตรวจแล้วใน P11)
- **idempotency ของผู้ติดต่อ/สินค้า**: ไม่มีคอลัมน์ ref ให้ใช้ (AccountContact/AccountProduct ไม่มี refType/refId) —
  อาศัยกุญแจธรรมชาติแทน: เลขภาษี+สาขา (partial unique index เดิม) / เบอร์โทร normalize (เฉพาะแถวที่ไม่มีเลขภาษี — เลขภาษีแม่นกว่า) / SKU (unique index เดิม)
  ⇒ อัปโหลดไฟล์เดิมซ้ำ = สร้างซ้ำ 0 ราย เหมือนกันโดยผลลัพธ์ แม้ไม่มี ref column
- **เอกสารที่นำเข้า = ร่างเสมอ** (`status: DRAFT`, ไม่เรียก issue) — ผู้ติดต่อ/สินค้าเป็น "active" ทันที (ไม่มีแนวคิด draft สำหรับ 2 อย่างนี้)
- **แถวเอกสาร 1 แถว = 1 บรรทัด** จัดกลุ่มเป็น 1 เอกสารด้วยคอลัมน์ "เลขอ้างอิง" (`groupDocRows`) — ค่าว่าง = แถวนั้นเป็นเอกสารของตัวเอง (ไม่ปนกับแถวว่างอื่น)
- **ผู้ติดต่อไม่พบ → สร้างใหม่อัตโนมัติ** (เตือน ไม่ error) ตอนนำเข้าเอกสาร — dedupe ภายในไฟล์เดียวกันด้วย cache (ชื่อ+เลขภาษี) กันสร้างซ้ำ 5 ครั้งจาก 5 แถวของลูกค้าเดียวกัน
- **หน่วยไม่รู้จัก (สินค้า)** → เตือนแต่ยังสร้างสินค้า (unitId ว่าง ไม่ผูกมั่ว) — unitName เป็น FK ไม่ใช่ free text ต่างจาก AccountDocumentLine.unitName
- **แท็ก** `นำเข้า YYYY-MM-DD` (เวลาไทย Asia/Bangkok, ค.ศ.) — ติดทุกเอกสารที่สร้างในรอบเดียวกัน · หน้าสรุปผลโชว์แท็กให้ผู้ใช้ค้นหาเอง
  (⚠️ ยังไม่ได้ผูกกับตัวกรอง `tags` ของ `ListFilters`/`listDocumentsPaged` — ช่องนั้นมี UI แล้วแต่ query ยังไม่รองรับ เป็นหนี้เดิมนอกขอบเขต WO นี้)
- **CSV injection**: `neutralizeFormulaPrefix` เติม `'` นำหน้าเซลล์ที่ขึ้นต้นด้วย `= + - @` ก่อน export เทมเพลต (ไม่ได้ sanitize ฝั่ง import
  เพราะค่าตัวเลขถูก parse เป็น number ก่อนเข้า DB อยู่แล้ว ไม่มีทางเป็นสูตรดิบ · ค่าข้อความอย่างชื่อ/หมายเหตุเก็บเป็น string ธรรมดา
  ไม่เคยถูกเปิดใน spreadsheet โดยตรงจากระบบนี้)
- **ขอบเขต**: ≤5MB (เช็คทั้ง client ก่อนอ่านไฟล์ + server ซ้ำ) · ≤2,000 แถว (`capRows` ตัดส่วนเกินเงียบ ๆ ไม่ error) · preview ส่งรายละเอียดกลับ 20 แถวแรก
  แต่ตัวนับ (ok/warn/err) นับครบทุกแถวที่อ่านได้

## 4. บั๊กที่เจอระหว่างเขียน + แก้แล้ว

1. **เบอร์โทรซ้ำไม่ได้ถูกใช้ตัดสินใจข้าม** — `runImportCore` คำนวณ `dup.phones`/`seenPhone` ไว้แต่ลืมใส่ในเงื่อนไข `isDup`
   (มีแต่เช็คเลขภาษี) → import ผู้ติดต่อเบอร์ซ้ำสร้างซ้ำเงียบ ๆ แทนที่จะข้าม แก้โดยเพิ่ม `phoneDup` (เฉพาะแถวที่ไม่มีเลขภาษี — เลขภาษีเป็นกุญแจแม่นกว่า)
   จับได้จาก QC P9 (สร้างได้ 2 ราย แทนที่จะเป็น 1)
2. **สมมติฐานผิดของ QC เอง**: คาดว่า preview จะนับ 18 แถวถูกต้องเป็น "ok" ล้วน แต่จริง ๆ ทุกแถวที่ผู้ติดต่อยังไม่มีในระบบ
   ถูกเลื่อนเป็น "warn: ผู้ติดต่อไม่พบ (จะสร้างใหม่)" ตามที่ SPEC ระบุไว้จริง (`ok+warn=18` ไม่ใช่ `ok=18`) — แก้ที่ QC script ไม่ใช่โค้ดจริง
3. **`skipped` หลังนำเข้าไฟล์เดิมซ้ำ = 20 ไม่ใช่ 18** — เพราะ 2 แถว error เดิมก็ถูกนับเป็น `skipped` ซ้ำทุกรอบ (ผ่านเส้นทาง
   `hasErr && skipErrorRows` ไม่ใช่เส้นทาง idempotency) ไม่ใช่บั๊ก แต่เป็นพฤติกรรมที่ต้องเข้าใจถูกตอนอ่านเลข — แก้ที่ QC script

## 5. หนี้/ข้อจำกัดที่รู้ตัว (ไม่ใช่ scope WO นี้)

- ปุ่ม "นำเข้า" ใน `DocListPage` ชี้ไปหน้าเดียวกันทุกชนิดเอกสาร (ไม่กรองว่า QT/IV/RE ต่างกัน) — ผู้ใช้เลือกประเภทเอกสารเองในคอลัมน์ CSV
- แท็ก "นำเข้า YYYY-MM-DD" ยังกดค้นหาจากหน้ารายการไม่ได้ตรง ๆ (ตัวกรอง `tags` ใน `ListFilters` มี UI แต่ query ยังไม่ผูก — หนี้เดิมก่อน WO นี้)
- dedupe เลขภาษีของผู้ติดต่อเช็คเฉพาะ `branchCode="00000"` (สำนักงานใหญ่) — ตรงกับ use case นำเข้าทั่วไป แต่สาขาอื่นเลขภาษีเดียวกันจะไม่ถูกจับซ้ำ (ถูกต้องตาม partial unique index จริงที่แยกตามสาขา)
- `scripts/visual-acc-v2.mts` WO 1.8 section เขียนแล้วแต่ยังไม่ได้รันจริง (ต้อง build+serve) — Fable/เจ้าของต้องรัน
