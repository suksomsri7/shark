## ข้อตัดสินใจสำคัญ (อ่านก่อนแก้ต่อ)

1. **ไม่ import raw prisma** — fitness F5 baseline = 45 ไฟล์ และเต็มพอดี ⇒ `dashboard.ts` ใช้ `tenantDb({tenantId, systemId})`
   ซึ่ง inject ตัวกรอง tenant+system ให้ทุก query อัตโนมัติ (แข็งกว่าเขียน where เองด้วย)
2. **มี `$queryRaw` 4 ก้อน (ที่แรกของ `src/lib`)** — จำเป็น ไม่ใช่ความชอบ:
   - เงินรายเดือนต้อง group ตาม `AccountJournalEntry.periodKey` ซึ่ง **อยู่คนละตารางกับ line** → `groupBy` ของ Prisma ทำไม่ได้
     (ทางเลือกอื่น = ดึง entry+line ทั้งปีมารวมใน JS = 2–3 query + แถวเป็นหมื่น)
   - ปฏิทินต้อง group ตาม "วันตามเวลาไทย" → Prisma group ตามวันไม่ได้
   ทุกก้อนเป็น tagged template (parameterized) + เขียน `"tenantId" = … AND "systemId" = …` เองครบ (ข้อสอบ P0.3/P0.4 บังคับ)
3. **ไม่ compose `overviewStats + payableStats + agingReport×2` ตรง ๆ** — วัดจริงแล้วรวมกัน **11 query** (4+3+2+2)
   ⇒ บล็อกเดียวกินเกือบทั้ง budget · แทนที่ด้วยการอ่านเอกสารเปิดครั้งเดียว (2 query) แล้ว **ใช้ตรรกะเดิมทั้งดุ้น**:
   `isOverdue` (service.ts) + `agingBucket`/`emptyAging` (reports.ts — เปลี่ยนเป็น `export` ในรอบนี้ ไม่แก้พฤติกรรม)
   ข้อสอบ P4.12–P4.18 บังคับให้ผลลัพธ์ **เท่ากับของเดิมทุกช่อง** ⇒ ถ้านิยามของเดิมเปลี่ยน ข้อสอบแดงทันที
   (`pendingTasks` ใช้หลักเดียวกัน: 2 query แทน 6 · P7.2 บังคับให้เท่ากับ `service.pendingTasks`)
4. **`monthDelta` ของช่องทางเงินคิดจาก GL ไม่ใช่ผลรวม payment** — เพราะ `balance` มาจาก GL
   ถ้า delta มาจากอีกแหล่ง "ยอดต้นเดือน + delta ≠ ยอดวันนี้" (โอนระหว่างช่องทาง · ค่าธรรมเนียม · ยอดยกมา ไม่มีใน payment)
   ⇒ ต่างจากถ้อยคำใน WO ("payments grouped by financeAccountId") โดยตั้งใจ · ฝั่งปฏิทิน (§10.2) ยังใช้ payment ตามสเปค
5. **`CashAccount` ไม่มีช่อง `code`** — `AccountFinance` ไม่มีคอลัมน์รหัส และ `ledgerAccountId` ไม่ใช่ relation
   ⇒ จะได้รหัส GL ต้องยิงเพิ่มอีก 1 query (เกิน budget) และดึงจากก้อน GL ก็ได้ไม่ครบ (บัญชีที่ไม่มีรายการในงวดจะหาย)
   ส่ง `ledgerAccountId` ไปแทน · การ์ด §4 แสดง ชื่อ/ชนิด/ยอด/เคลื่อนไหว/ปักหมุด อยู่แล้ว
   (แถม: `financeBalances` คืน `pinned` เพิ่ม 1 ช่อง — additive ไม่กระทบผู้เรียกเดิม และประหยัด 1 query)
6. **เปอร์เซ็นต์ทุกตัวเป็น basis point (integer)** — `yoyBp` · `shareBp` (10000 = 100%) · `null` เมื่อฐาน = 0
   ⇒ ไม่มี float หลุดเข้าไปในผลลัพธ์เลย (ข้อสอบ P12 เดินทั้ง object เช็ค `Number.isInteger` ทุกค่า)
7. **`now` ฉีดได้ทุกฟังก์ชัน** (`opts.now`) — เฉลยตรึงไว้ที่ `2026-09-30T12:00:00+07:00` และเขียนลง `dashboard.now`
   ⇒ ข้อสอบไม่เน่าตามวันที่รัน (บทเรียน `feedback_oracle_rots_over_time`)
8. **นิยาม "ยอดขาย/รายจ่าย" ของการ์ดอันดับ**: OUT = `INVOICE` + `RECEIPT` ที่ไม่ได้แปลงมาจากใบอื่น (`sourceDocId = null`)
   กันนับซ้ำใบแจ้งหนี้→ใบเสร็จ · IN = `PURCHASE` + `EXPENSE` (PO/PTX เป็นทะเบียน ไม่ใช่ค่าใช้จ่าย)
9. **ชื่อสินค้าในการ์ด "ขายอะไรดีสุด" ใช้ `description` ของบรรทัด** (ชื่อ ณ วันขาย) — ไม่ join ทะเบียนสินค้า
   เพราะจะเพิ่มอีก 1 query และชื่อ ณ วันขายเป็นค่าที่ถูกต้องกว่าสำหรับรายงานย้อนหลัง
   (ตอนนี้ seed ไม่ผูก `productId` เลย ⇒ จัดกลุ่มด้วย description · POS จะส่ง line identity เข้ามาใน WO 4.2)

## บั๊ก/ข้อค้นพบระหว่างทำ (ส่งต่อให้ Fable)

1. 🔴 **`agingReport(direction: "OUT")` นับลูกหนี้ซ้ำเมื่อมีใบวางบิลรวม** — WO 1.7 ทำให้ `BILLING_NOTE` ที่ออกแล้ว
   มีสถานะ `AWAITING_PAYMENT` เหมือนใบแจ้งหนี้ลูก แต่ `agingReport` ไม่ได้กรองชนิดเอกสาร ⇒ ยอดลูกหนี้บวมสองเท่า
   ทันทีที่ร้านไหนใช้ใบวางบิล (ร้าน QC ยังไม่มี BN → ข้อสอบยังเขียว) · `dashboard.ts` **ตัด BN ออกแล้ว**
   ⇒ ควรมี WO เล็กแก้ `agingReport` (+ `overviewStats` ที่กรองแค่ `docType = INVOICE` จนมองไม่เห็น DN/BN)
2. 🔴 **กับดักเวลาไทยใน SQL**: คอลัมน์ของ Prisma เป็น `TIMESTAMP(3)` **ไม่มีโซน** (เก็บ UTC)
   เขียน `col AT TIME ZONE 'Asia/Bangkok'` เฉย ๆ = เลื่อนผิดทาง −7 ชม. (1 ก.ย. กลายเป็น 31 ส.ค. — เจอจริงในรอบแรก)
   ต้องเป็น `(col AT TIME ZONE 'UTC') AT TIME ZONE 'Asia/Bangkok'` · ข้อสอบ P0.4b เฝ้าไว้แล้ว
3. ⚠️ **`qc-all.mts` กวาด `scripts/qc-*.mts` ทั้งหมด** ⇒ ชุด `qc-acc-v2-dashboard` (และ `qc-acc-v2-seed-check` ของเดิม)
   ถูกรันบน CI ด้วย แต่ทั้งคู่ต้องมี `.env.qc` + ร้าน QC ที่ seed แล้ว → บน CI จะตก (ของเดิมเป็นแบบนี้อยู่ก่อนแล้ว)
   ถ้าจะให้ CI เขียว ต้องเพิ่มรายชื่อยกเว้นใน `qc-all.mts` — **ไม่ได้แก้ในรอบนี้ (นอกขอบเขต WO · Fable ตัดสิน)**
4. ℹ️ `seed-acc-v2-qc.mts` เขียนทับ `acc-v2-expected.json` ทั้งไฟล์ ⇒ **seed ใหม่ทุกครั้งต้องรัน**
