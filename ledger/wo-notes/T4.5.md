## สิ่งที่ทำ (ทางลบเดิมไม่เปลี่ยน: ขอลบ → รอ 30 วัน → purge — ไม่ลบเร็วขึ้น ไม่ลบมากขึ้น)
1. **หน้าที่เก็บเอกสาร** (`src/lib/pdpa/retention.ts`): ต่อสมุด — จำนวนใบสำคัญ · รายการล่าสุด · "ต้องเก็บถึงอย่างน้อย" = วันปิดบัญชีของรอบที่มีรายการล่าสุด (จากเดือนเริ่มปีบัญชี) + ระยะเก็บ · ส่งออกล่าสุดเมื่อ
   คำเตือน `SHOP_RECORDS_RETENTION_DUTY` [V] (แจ้ง) · `SHOP_DELETE_WITHIN_RETENTION` [V · ต้องติ๊ก] ต่อสมุดที่ยังไม่ครบระยะ · `PAPER_ORIGINALS_KEEP` [U] (แจ้ง — K6)
2. **ขอลบร้าน** (`pdpa/actions.ts requestDeleteAction`): ยังไม่ติ๊ก = ไม่ขอลบ + ข้อความ (ไม่ใช่บล็อกกฎหมาย — ติ๊กแล้วผ่านเสมอ) · ติ๊กแล้ว = AuditLog `legal.warning.ack` (targetType Tenant) + log การลบ REQUESTED (คำเตือนที่ยืนยัน + สมุด/วันเก็บถึง/ส่งออกเมื่อ)
3. **ส่งออกก่อนลบ** (`account/books-export.ts` + route `GET /app/sys/{id}/account/export/books`): ZIP (เขียนเอง `core/zip.ts` แบบ STORE — ไม่เพิ่ม dependency) มี อ่านก่อน.txt (หน้าที่เก็บ + ต้นฉบับกระดาษ) · สมุดรายวัน.html / บัญชีแยกประเภท.html (พิมพ์ได้) · สมุดรายวัน.csv · ผังบัญชี.csv · เอกสาร.csv · ไฟล์แนบ.csv + ไฟล์แนบ/<เลขที่เอกสาร>/ — ดึงเฉพาะไฟล์บนคลังของ SHARK (`SHARK_BUNNY_CDN`) · ไฟล์ส่วนตัว (private://) / URL ภายนอก = อยู่ใน manifest พร้อมเหตุผล (กัน SSRF) · เพดาน 200 MB/ไฟล์ส่งออก · สิทธิ์ `account.report.view` · ทุกครั้งลง log EXPORTED
4. **log การลบ** ตาราง `TenantDeletionLog` (migration `20270103100100_acc_t45_tenant_deletion_log` · scope platform · ไม่มี FK) — REQUESTED · CANCELLED · EXPORTED · PURGED (ชื่อ/slug ร้านที่จำไว้ก่อนแถวร้านหาย) · PURGE_FAILED · trigger กันแก้/ลบ (ยกเว้นโหมด qc) · แสดงบนหน้าความเป็นส่วนตัว (เจ้าของ)
5. purge (`pdpa.ts purgeTenantRows`) ห่อแต่ละตารางในธุรกรรมที่ตั้ง `shark.ledger_purge` (ด่าน T4.4) — ลบเท่าเดิม
6. ลบบัญชีผู้ใช้ที่พาร้านเข้าช่วงลบ: ข้อความยืนยันบอกหน้าที่เก็บเอกสาร + log REQUESTED (via account-deletion)
- REST `GET /books/retention` (op `books.retention` · เลขา `account_books_retention`) — ไฟล์ ZIP ดาวน์โหลดทางจอเท่านั้น (REST ไม่ส่งไบนารี)
