## CONTROLLER-DECISION (read first — the oracle encodes my proposal for each)
1. **Facade + signatures.** `pos/index.ts` exports `orders = {ingestOrder, ingestInTx, sourceCancelledInTx, acceptOrder, rejectOrder, markPreparing, markReady, handOver, cancelOrder, payOrder, setPrepMinutes, setChannelOrderSettings, listOrders, getOrder}` (all from `pos/order.ts`). User functions = `(ctx: RegisterCtx, actor: RegisterActor, input)` → `{ok:true, …} | {ok:false, code, message(th), lineIndex?}` (never throw). `ingestInTx(tx, scope: {tenantId, unitId}, input)` (system resolved like `posSystemForSale`; no POS ⇒ `{ok:true, skipped:true}` never throws) · `sourceCancelledInTx(tx, scope: {tenantId, unitId}, {shopOrderId, reason?})` → `{ok:true, orderId: string|null, changed: boolean}`. `backfillWebPrices(opts: {tenantIds: string[]; dryRun: boolean}, client?)` lives in `pos/catalog.ts` (backfill style, **not** on the facade — F15.5) → `{written, webPriceConflict, conflicts: [{posProductId, shopProductIds}], …}` (plain object, may also carry `ok:true`).
2. **Ingest input keys** (`parseIngestInput`, unknown key ⇒ `VALIDATION`): `channelId | channelCode`, `externalRef?` (trimmed, ≤ 40), `idempotencyKey` (required, also for refless MANUAL — ruling 12), `lines` (1..100: `{productId, qty, choiceIds?, note?}` or custom `{name, unitPriceSatang, qty, note?}`), `customer {name, phone?, memberId?, partyId?}`, `fulfilment PICKUP|DELIVERY|DINE_IN`, `address?`, `note?`, `chatConversationId?`, `startStatus? NEW|ACCEPTED` (MANUAL default ACCEPTED, others NEW), `paymentState? UNPAID|PAY_ON_PICKUP` (DIRECT only), `prepMinutes?`. Result `{ok:true, orderId, duplicated, saleId: string|null}`.
3. **paymentState.** PLATFORM-payout channels are `PLATFORM_PAID` from ingest and **stay** `PLATFORM_PAID` after the accept sale (not `PAID`); `REFUNDED` after a void/cancel. DIRECT: `UNPAID`/`PAY_ON_PICKUP` → `PAID` (payOrder or shop confirm).
4. **Transition graph (ST7).** Allowed = NEW→ACCEPTED, NEW→REJECTED, **NEW→CANCELLED** (source cancel: shop cancel W4 / platform), ACCEPTED→PREPARING, PREPARING→READY, READY→HANDED, ACCEPTED|PREPARING|READY→CANCELLED. No ACCEPTED→READY shortcut (`markReady` needs PREPARING). Staff `cancelOrder` on NEW ⇒ `ORDER_STATE_INVALID` (use reject) — A6. `payOrder` only from ACCEPTED|PREPARING|READY (not pinned for NEW).
5. **Events (R10 · E1).** Exactly one outbox row per (order, type). Ingest emits `pos.order.received` (payload `status` = start status NEW or ACCEPTED); a startStatus-ACCEPTED ingest emits `received` **and** `accepted`; PREPARING emits nothing; READY → `ready`; HANDED → `completed`; REJECTED → `rejected`; CANCELLED → `cancelled` (also via void consumer / shop cancel, never twice — V3). Payload ⊇ `{orderId, channelId, channelCode, status}`. Suggested keys `pos.order.<type>#<orderId>` (not pinned).
6. **PosOrderEvent rows.** One per transition including ingest (`fromStatus null → toStatus NEW`); actor = user or null (auto). A1 pins the NEW path `NEW,ACCEPTED,PREPARING,READY,HANDED` / `null,NEW,ACCEPTED,PREPARING,READY`; startStatus-ACCEPTED rows are not pinned. `version` +1 per transition (A1 +4).
7. **Race (A2).** Loser of two parallel accepts ⇒ `ORDER_STATE_CHANGED` carrying `order` (fresh row/card, `order.status`). A later accept ⇒ `ORDER_STATE_INVALID` or `ORDER_STATE_CHANGED`. **xmin proof:** the PosOrder row, its ACCEPTED PosOrderEvent and the sale's PosSaleLine rows share one xmin (accept + sale + event one tx) ⇒ nothing may update the PosOrder row after commit (e.g. writing `saleId` in a second tx).
8. **Permissions (CD8).** accept / markPreparing / markReady / handOver / setPrepMinutes / setChannelOrderSettings = `pos.order.accept` · reject + cancelOrder = `pos.order.reject` (+ `pos.sale.void` when a PAID sale exists) · ingest (MANUAL/CHAT, incl. startStatus ACCEPTED) and payOrder = `pos.sale.create` · custom lines = `pos.sale.priceOverride` · listOrders/getOrder = `pos.sale.read|create`. OWNER/MANAGER by role. Refusal code `PERMISSION_DENIED`.
9. **Atomic refusals.** A sale refusal at accept leaves the order NEW with the same version, no event/outbox/sale (S8). A startStatus-ACCEPTED ingest whose sale is refused writes **no order row** (S8 second half). Paused/invalid/conflict refusals write nothing.
10. **Scope.** Unknown/other-tenant/other-unit id ⇒ `ORDER_NOT_FOUND` for getOrder/accept/reject (A5).
