## Hunt answers
1. **Existing writers vs the new CHECKs:** checked every create/update of `HrPayAdjustment` in src: payroll.ts :188 (manual, explicit fields), :1360 (CRM `createManyAndReturn`, fields `{…scope, employeeId, periodKey, kind, amountSatang, note, requestedById, crmCommissionId}`), and the updateMany calls at :254/:263/:659/:774/:816/:828/:1132/:1301/:1503. Those updates write only `runId`/`status`/`periodKey`/decision fields. None writes `sourceType`/`sourceRef`, so no existing path can break the CHECKs. CRM rows have `sourceRef` null, so the new partial unique never fires, and `skipDuplicates` (ON CONFLICT DO NOTHING with no target) still only swallows the crmCommissionId conflict. Probe D shows that ON CONFLICT with no target also silently swallows a source-unique duplicate. That is right for future idempotent writers, but H2.9 must still tell "duplicate" apart from "created", as the CRM path does with `made.length === 0`.
2. **Tenant access to HrLawTable:** shops can read it through tenantDb, which is intended. Writes are also possible from a tenant context, and no caller exists today (F1). No AI tool, outbox consumer, route or action names it.
3. **Source race:** probe A, 10 lanes × 3 rounds on separate pg connections ⇒ 1 row and 9 × 23505 each round. Probe B: after REJECTED, the same ref ⇒ 23505 (ruled Q14) and a new ref ⇒ ok. Other tenant, same ref ⇒ ok. A second system in the same tenant ⇒ conflict (by design, X2.1).
4. **engineVersion:** no reader anywhere in `src/**` (grep `engineVersion` = 0). `createPayrollRun` does not write it. A value of 2 would change no payroll path.
5. **PDPA:** `ytdJson`/`filingJson`/`bankFileKey`/`lawRowIds`/`HrReviewNote`/`HrOnboardingTask`/`HrWorkEntry` have 0 hits in `src/**` apart from scope.ts. The whole-row readers (`listRuns`, `payslipData` → `loadPayslipForViewer` → slip page; `listAdjustments` → `payroll-ui.tsx`) are server components using named fields, with no spread, no `JSON.stringify`, and no client prop of the row. The outbox payloads in payroll.ts are `{runId, periodKey[, adjustmentIds]}` only. Actions return only `{ok, reason}`. F16.1 gains ytdJson/filingJson/bankFileKey. Review-note body/score have no reader or DTO (left for H4.4, Q12).
6. **Lock duration:** see F4. Fast defaults, and short scan locks from the validated CHECKs and the non-concurrent indexes.
7. **C3.3 ORACLE-EDIT:** see F3. Today's invariant still holds (X4.5 + S1.10). As a tripwire for future migrations it is weaker.
