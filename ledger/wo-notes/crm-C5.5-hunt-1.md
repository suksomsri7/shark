### Authorization table (UI action ↔ service ↔ REST op/tool) — extract of the full pass
Method: an awk map of every `*-actions.ts` `session(systemId, key)` → service call, plus a dump of `CRM_OPS` (`scripts/pending/c55/list-ops.mts`, 123 ops). The services enforce `need()`/`crmCan` themselves (contacts, deals, activities, companies, portal, automation, tracking, objects), so a weaker door can only come from (1) a door whose key differs from the service's, or (2) a surface that does not call the service as the user (the automation runner = OWNER). Results:
- REST = service key for every write op: 65 write/danger ops checked. AI tools are generated from the same ops (`crm/api/tools.ts`, reads = asker ∩ read set, writes = proposals run as the confirming human).
- Mobile `/api/mobile/crm/*` calls the services with the session actor.
- UI stricter than REST: activity reschedule and delete (L55-3).
- Automation weaker than every human door: H55-2.
- Webhook endpoint egress has no visibility rule: L55-4.
- Permission registry: every static key used by an op, action or service is in `ALL_KEYS` (`crm.contact.archive`/`.restore` are action names mapped to `crm.contact.delete` at `contacts.ts:1152`).

## Held under attack
- **C5.4-A outbox lease.** The lease is per claim; DONE is written only from PENDING; FAIL is written only while holding its own lease. Webhook delivery reservation uses a deterministic PK per event×endpoint; `$sharkEventId` is never returned by any op (grep: `payloadJson` read only in `webhooks/service.ts`). The v1 automation once-per-event claim does advisory lock + findFirst + create in one tx. The REST idempotency takeover is a CAS on createdAt. All code-read; this agrees with hunter A. (H55-1 is the one new hole in this area.)
- **CRM facade viewer (L1-M3).** `findContactsForLink`/`findContactByPartyId`/`findLatestDealForContact`/`setContactPartyId`/`listPartyIdsWithContact` fail closed when no viewer is passed. The `"system"` viewer cannot be reached from user input. `setContactPartyId` writes conditionally on the partyId it read and refuses a different canonical Party. Code-read.
- **Member history (L1-m5/H1).** `listActivity` + `listHistory` hide `crm`/`crm.object` rows from CUSTOMER through the shared constant, for both list and count. Code-read.
- **C5.4-B key-guard.** The per-request creator check runs on `/api/v1/crm/*` and `/api/v1/teams/*` (same config). `/api/v1/ai/tools/*` with a key gets no viewer, so reads are refused and writes become proposals executed with the confirming human's membership; the guard therefore cannot be bypassed there. There is no rotate action on the CRM page, so the mint guard cannot be bypassed by rotation (the account rotate path is out of scope, B-H2).
- **C5.4-B v1 gate.** `isCrmV1Closed` fails closed; the `uiVersion` default is 1 when the key is missing (`settings.ts:40`), so prod v1 shops are unchanged.
- **C5.4-D.** REST dispatch wakes only on non-GET < 400. `deleteDeal` stops sequences only for closed deals, and outside the tx (logs WARN). The member branch of `consents.set` `ifChanged` reads and writes under the CrmContact lock, then the Customer lock (same order as `revokeOnMember`). `keepCloseDate` covers same-kind closed moves only.
- **C5.4-E sanitize (prod-exposed core).** Decode once, then escape fully. Tried:
  - `java&#115;cript:` and `java&#9;script:` (the decoded tab is stripped before the scheme check, so it is refused);
  - `javascript&colon;` (not decoded, so there is no scheme and it is refused);
  - `&#0;` (kept literal);
  - `"`-breakout via `&quot;` in href and img src (re-escaped);
  - the `<a title=">" href=…>` split (text only);
  - idempotence (sanitize∘sanitize = sanitize).

  No hole found for member, kanban or chat callers.
- **C5.4-E composer vars.** Contact values are HTML-escaped and substituted after linkify, so they never become links. The subject is rendered as text and then goes through `cleanSubject`. The templateId path still escapes caller `vars`.
- **C5.4-E notify-senders.** Every sender goes through `notifyStaff` (accepted membership + read key + canSee of the ref). Bodies carry counts and id links only. The outage notice is once per shop per Thai day, under an advisory lock.
- **C5.4-E company lifecycle correction.** It is manager/owner only, allows only the CUSTOMER→PROSPECT path, and is refused while a WON deal exists. There is no REST door.
