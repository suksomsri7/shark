- Options for the ruling:
  A. **Visitor ticket via new mint endpoint + postMessage** (recommended): new sealed kind `{k:"vt",t,s,v,x,j}` with its own key label; `POST /t/v` behind preGate+consent-current (returns an opaque same-shape body always); tracker answers a `postMessage` request from the `/f` iframe (origin-checked both ways) with a fresh ticket; PublicForm sends it; crm-source verifies+burns → latestConsentedSessionId.   C. **Serve /f on the shop's own host** (custom domain via proxy `x-shark-host`) so the host cookie is first-party: no token, but needs custom-domain infra per shop; not generic.
  D. Third-party/partitioned cookie (SameSite=None / CHIPS) on APP_URL: blocked/unreliable in Safari/Firefox — not recommended.
  E. Accept the gap: binding happens only via e-mail click (EMAIL_CLICK) and forms hosted at APP_URL opened directly (same-site as nothing) — document it.
