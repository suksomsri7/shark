- Form: embed = `<iframe src="${APP_URL}/f/<token>">` (forms/service.ts:390) · `/f/[token]/page.tsx` takes no searchParams · `actions.ts:19-25` reads `sd_vid` from ITS OWN request cookie (APP_URL host) → never the shop-site cookie → `submissionWebSessionId` (forms/crm-source.ts:35) → `latestConsentedSessionId` (tracking.ts:727) → bridge `crm-bridges/forms.ts:191-199` → `identify(... by FORM)`. QC C2.6-S9.2 pins "cookie only, never a caller-supplied vid".
- Verdict: the existing ticket carries a contactId, not a visitor id, and there is no way for the tracker to obtain a server-signed ticket (no secret in JS, /t/e returns nothing, /t/s is publicly cached). Wiring = new ticket kind + new mint endpoint + tracker DOM/postMessage + form plumbing ⇒ **new design → ruling needed** (options in the handback / below).
- Options for the ruling:
  A. **Visitor ticket via new mint endpoint + postMessage** (recommended): new sealed kind `{k:"vt",t,s,v,x,j}` with its own key label; `POST /t/v` behind preGate+consent-current (returns an opaque same-shape body always); tracker answers a `postMessage` request from the `/f` iframe (origin-checked both ways) with a fresh ticket; PublicForm sends it; crm-source verifies+burns → latestConsentedSessionId. No schema. Cost: new endpoint + JS protocol + X7 "identical bytes" exception + QC. Security: proves only knowledge of the vid (+Origin), same strength as the raw vid S1 removed, but site-bound/short/single-use.
  B. Same ticket, **decorate `a[href^=APP/f/]` / `iframe[src^=APP/f/]`** with `sd_vt=` instead of postMessage: simpler JS, but ticket in URL (logs/referrer), iframe reload after lazy load, 15-min expiry vs long page sessions.
  C. **Serve /f on the shop's own host** (custom domain via proxy `x-shark-host`) so the host cookie is first-party: no token, but needs custom-domain infra per shop; not generic.
  D. Third-party/partitioned cookie (SameSite=None / CHIPS) on APP_URL: blocked/unreliable in Safari/Firefox — not recommended.
  E. Accept the gap: binding happens only via e-mail click (EMAIL_CLICK) and forms hosted at APP_URL opened directly (same-site as nothing) — document it.
- Adjacent risk seen (not fixed, not in scope): `identify()` updateMany (tracking.ts:999) binds ALL unbound sessions of the visitor incl. ones whose consent was revoked (consentVersion null); `latestConsentedSessionId` checks `not null`, not the current version.
