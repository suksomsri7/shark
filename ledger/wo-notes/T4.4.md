## 2. โหมดของฐาน (production vs ทดสอบ)
- ชุดทดสอบเดิม ~120 ชุด (ทุกเลน) ล้างฟิกซ์เจอร์ด้วย `deleteMany` สมุดรายวัน/AuditLog ตรง ๆ — แก้ทุกชุดไม่ได้ (ของเลนอื่น) ⇒ โหมดของ **ฐาน**:
  - migration ตั้ง `account_ledger_guard_mode()` = `'strict'` (production · ค่าเริ่มที่ปลอดภัย: ลืมตั้ง = กันเต็ม ไม่ใช่ปล่อย)
  - ฐานทดสอบสลับเป็น `'qc'`: `bash scripts/iso.sh pnpm exec tsx scripts/acc-ledger-guard-mode.mts qc` (ผ่าน loadQcEnv — ด่าน prod เด็ดขาด) ·
    `acc-qc-migrate.mts deploy` เรียกให้เองหลัง deploy (ฐานเลนนี้) · CI (`.github/workflows/ci.yml`) มีขั้นหลัง migrate deploy
  - ฐาน QC ของเลนอื่น (POS qc4 · SVC · CRM · member) **ต้องรันคำสั่งเดียวกันหลัง migrate** มิฉะนั้นชุดที่ล้างสมุดรายวันจะแดง `LEDGER_GUARD:` — SQL ตรง:
    `CREATE OR REPLACE FUNCTION public.account_ledger_guard_mode() RETURNS text LANGUAGE sql STABLE AS $$ SELECT 'qc'::text $$;`
  - ฟังก์ชัน/trigger ไม่อยู่ในสคีมา Prisma ⇒ `pnpm drift` ไม่เห็น (ไม่เพิ่ม drift)
- ข้อสอบโหมดเข้มบนฐาน qc: `SET LOCAL shark.ledger_guard = 'strict'` ในธุรกรรมของข้อสอบ

## 4. รายงานการแก้ไขของบัญชี (ใหม่)
- `account/audit-trail.ts listAccountChanges(ctx, {from, to, kind, actorId, take, cursor})`: แหล่ง = AuditLog ของร้าน (`account.*` · `legal.warning.ack`) + การกลับรายการในสมุดรายวัน (JV ที่ `reversalOfId` ไม่ว่าง · จำนวนเงิน) + การเข้าระบบของสมาชิกร้าน (`auth.*` ของ userId ที่เป็นสมาชิก)
- แต่ละแถว: เวลา · ใคร (ชื่อ/อีเมลจากสมาชิก · API key · ระบบ) · ทำอะไร (ป้ายไทย) · เอกสาร/รายการ (เลขที่) · จำนวนเงิน (ถ้ามี) · **เหตุผล** (after.reason → before.reason → voidReason ของเอกสาร/รายการชำระ) · ช่องทาง
- กรองตามสมุด: เป้าหมายที่ระบุสมุดได้ (เอกสาร · รายการชำระ · JV · เช็ค · 50 ทวิ) ต้องเป็นสมุดนี้ · แถวระดับร้าน (ไม่มีสมุด) แสดงเฉพาะร้านที่มีสมุดเดียว
- จอ `/account/reports/audit-trail` (ตัวกรองช่วงวัน · ชนิด: ทั้งหมด/ยกเลิก-กลับรายการ/คำเตือนที่กดยืนยัน/เข้าระบบ · CSV) · REST `GET /audit/changes` (op `audit.changes` · สิทธิ์ `account.journal.view`) · เลขา `account_audit_changes` (skill account)

## 5. เหตุผลยกเลิก (G2)
- จอ: ทุก action ยกเลิกเอกสาร/รายการชำระ/รายการชำระกลุ่ม ต้องมีเหตุผล (voidDocumentAction · voidExpenseDocAction · voidPaymentAction · voidVendorPaymentAction · voidPaymentV2Action · voidGroupPaymentAction — สองตัวหลังเลิกเติม "ยกเลิกการชำระ" ให้เอง) (ว่าง = ข้อความ "กรุณาระบุเหตุผลการยกเลิก" — ความครบของร่องรอย ไม่ใช่บล็อกกฎหมาย) · กล่องยืนยันตั้ง `required`
- AuditLog ของการยกเลิกเก็บ `after.reason` ทุกทาง (เดิม voidDocumentAction/voidPaymentAction ไม่เก็บ)
- REST: documents.void · payments.void · payments.void-group · journal.reverse · cheques.void · wht.unmark-filed บังคับอยู่แล้ว · `payment-requests.cancel` ไม่เปลี่ยน (ลิงก์ชำระเงินยังไม่เป็นรายการบัญชี)
- ทางระบบ (POS ยกเลิกบิล · หอ · cron) ส่งเหตุผลของระบบเอง ไม่เปลี่ยน
