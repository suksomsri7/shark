## CONTROLLER-DECISION
- **CD-P210-1 pairFailCount attribution.** A wholly wrong code hashes to no row, so a failure cannot be attributed to a display. The oracle pins only the lock semantics (row with `pairFailCount = 5` refuses its right code with the same `PAIR_CODE_INVALID`; re-enable resets to 0 and the new code works) by setting the counter with SQL, plus the per-IP limiter. Rule how failures increment (rec: keep the column + lock check, rely on the per-IP limiter and the 10-min TTL for brute force; 32⁸ ≈ 1.1·10¹² codes).
- **CD-P210-2 `changed:false` fast path vs time/intent-derived changes.** Oracle reads R4 + ruling 6 as: never answer `changed:false` when the view differs from what was delivered at `sinceSeq` — stale 120 s → idle, done 20 s → idle, intent PENDING→PAID (DS2, PY1). Simplest builder: skip the fast path when the state is time-expired or carries an `intentId`.
- **CD-P210-3 `showPoints=false` also hides `done.pointsEarned`** (oracle reading of ruling 3 "points"). Confirm or drop that clause of CT2.
- **CD-P210-4 static PromptPay QR** amount = `pay.roundSatang` (the dialog's current round, as `InterimPayDialog.tsx:1144–1149`); foreign intent → static QR (not null).
- **CD-P210-5 caps:** > 20 lines = truncate + `moreCount` (not reject); a string > 80 chars = reject **or** truncate (both accepted); 16 KB is measured on the input JSON.
- **CD-P210-6 RegisterScreen/InterimPayDialog = additions only** (0 removed/modified lines; every added line inside `POS P2.10 ▸ … ◂`). If `onDisplayPay` wiring needs a changed line (e.g. single-line JSX), that is a pin change for the controller.
- **CD-P210-7 re-enable while paired:** the old token stays valid until the new code is exchanged (not tested); after the exchange the old token is `DISPLAY_NOT_PAIRED` (tested).
- No existing pin turns red by this design; the only expected ORACLE-EDIT is `qc-pos-p1.18.mts:312` (pre-approved).
