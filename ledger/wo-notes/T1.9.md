# T1.9 — ร้านจด VAT ขายแบบไม่มี VAT · รายงานอ่านบัญชีตาม mapping · JV มือแตะบัญชี VAT ติดป้าย (ปิด E13 · E7)

เลน 1 · branch session/account-fix · ต่อจาก T1.1 (รายงานภาษีขาย) · T1.3 (ภ.พ.30 อ่าน mapping VAT_OUTPUT/VAT_INPUT แล้ว) · T1.7 (บริบทการยืนยัน)

## 1. ขายไม่มี VAT ในสมุดที่จด VAT
- นิยาม (pure `saleWithoutVatWarnings` ใน legal-gate.ts):
  สมุด `vatRegistered` + เอกสารขายที่เป็นรายได้ (INVOICE · RECEIPT/TAX_INVOICE ที่ไม่ได้มาจากใบแจ้งหนี้ · DEPOSIT_RECEIPT · DEBIT_NOTE)
  + ทั้งใบ `vatMode = NONE` และมีบรรทัดที่ไม่ได้ติดป้ายยกเว้น (vatRateBp < 0 = ยกเว้น)
  ⇒ `SALE_WITHOUT_VAT_REGISTERED` [V · ต้องยืนยัน] อ้าง ม.80/1 · ม.81 · common-vat-invoice.md §1 §9 §21
- บรรทัดอัตรา 0% (vatRateBp = 0 ในใบที่มี VAT) = ติดป้ายแล้วว่า 0% · บรรทัด < 0 = ยกเว้น → ไม่เตือน (เป็นรายการที่ร้านระบุเหตุผลแล้ว)
- ด่าน: ใน `issueDocumentInTx` ผ่านบริบทการยืนยันของ T1.7 (`ambientLegalGateInTx`) — จอ/REST/AI ต้องยืนยัน · งานเบื้องหลัง
  (หอพัก · ระบบอื่นที่ออกเอกสารบัญชีเอง · seed) ไม่บล็อก ไม่ถาม แต่ขึ้นในรายงาน
  🔴 ทำไมไม่ใช้ `legalGateInTx` ตรง: ด่านนั้นบังคับทุกผู้เรียก (ไม่มี ack = โยน) ⇒ ระบบอื่นที่ออกเอกสารไม่มี VAT (หอพัก ฯลฯ) จะพังทั้งที่ไม่มีคนให้ถาม
- จอ: หน้าเอกสารร่างแสดงคำเตือนล่วงหน้าพร้อมช่องติ๊ก (ที่เดียวกับคำเตือน T0.4)

## 2. รายงาน "รายได้ที่ไม่มี VAT"
- `revenueWithoutVat(ctx, {from, to})` (ไฟล์ใหม่ `revenue-novat.ts`): เอกสารขายที่ออกแล้ว + บิล POS (TAX_INVOICE_ABB) ในช่วงเดือน
  ต่อบรรทัด VAT 0: หมวด `EXEMPT` (ยกเว้น · มีเหตุผล) · `ZERO_RATED` (0%) · `UNTAXED` (ใบไม่คิด VAT — ไม่มีเหตุผล)
  ยอด = ยอดบรรทัด (หลังส่วนลดบรรทัด) · ใบลดหนี้ = ติดลบ · สรุปรายเดือน × หมวด
- จอ `/account/reports/revenue-novat` + CSV · REST `GET /reports/revenue-without-vat` (+ เครื่องมือเลขาอ่าน)
- สมุดไม่จด VAT: รายงานยังเปิดได้ แต่บอกว่าไม่เกี่ยว (ทุกบรรทัดเป็น UNTAXED โดยธรรมชาติ)

## 3. รายงานภาษีอ่านบัญชีตาม mapping
- กวาด: reports.ts pp30 (ใช้ mapping แล้ว T1.3) · sales-tax-report (รับ outputLedgerId จาก mapping แล้ว · ป้ายข้อตรวจ "2200" ตายตัว → ใช้รหัส/ชื่อตาม mapping) ·
  หน้า ภ.พ.30 หัวตาราง "(2200)/(1150)" → รหัส+ชื่อบัญชีตาม mapping · wht/dashboard/period-close ไม่มีรหัส VAT ตายตัว ·
  gl.ts เงินเดือน (2130) = ฝั่งโพสต์ (ไม่ใช่รายงาน · นอกขอบเขต — จดไว้)
- ทดสอบ: สมุดที่ย้าย mapping VAT_OUTPUT/VAT_INPUT ไปบัญชีอื่น (รหัสใหม่) ได้ยอดภาษีขาย/ซื้อ/ภ.พ.30 เท่ากับสมุดปกติ

## 4. JV มือแตะบัญชีภาษี
- `MANUAL_JV_VAT_ACCOUNT` [V · ไม่ต้องยืนยัน — แจ้งให้ทราบ] (ม.87 · common-vat-invoice.md §18 §19) แสดงในฟอร์ม JV ล่วงหน้า + ผลของ REST journal.create
  (คำเตือนแบบไม่ต้องยืนยันส่งกลับใน `warnings` ของผล) — ไม่บล็อก
- รายงานภาษีขาย: แถวที่มาจาก JV มือ (source MANUAL) ติดป้าย "รายการปรับปรุงมือ" (`manual: true`) · รายงานภาษีซื้อเหมือนกัน ·
  กระทบยอด ภ.พ.30: แยกบรรทัด "รายการปรับปรุงมือ" (ยอดภาษีขาย/ซื้อที่มาจาก JV มือ) ใน `ret.reconcile.manual`

## skill เงียบ → เลือก
- การระบุเหตุผลของรายการยกเว้น/0% ต่อบรรทัด: ใช้ป้ายอัตราที่มีอยู่ (−1 = ยกเว้น · 0 = 0%) ไม่เพิ่มช่องเหตุผลอิสระ (least surprise) · ค่าตั้งใหม่ไม่มี
- คำเตือน JV มือแตะบัญชีภาษี = แจ้งให้ทราบ (ไม่ต้องยืนยัน) เพราะ JV ปรับปรุงเป็นงานปกติของนักบัญชี · ถ้าลงเดือนที่ยื่นแล้วจะได้ FILED_PERIOD_VAT_CHANGE (ต้องยืนยัน) ของ T1.7 อยู่แล้ว
