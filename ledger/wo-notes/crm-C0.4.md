## 7. ช่องโหว่ที่เจอและปิดในใบนี้ (สำคัญที่สุดของใบ)
ผู้ตรวจด้านความปลอดภัยเจอ **BLOCKER 3 ข้อ ซึ่งเป็นบั๊กเดียวกันใน 3 หน้ากาก**: *เส้นทางไฟล์ที่เก็บในฐานข้อมูลไม่เคยถูกผูกกับร้านเจ้าของแถว และด่านกันไต่โฟลเดอร์เป็นแบบ blacklist* — **ผู้คุมงานยืนยันเองทั้ง 3 ข้อก่อนสั่งแก้**
1. **อ่านไฟล์ข้ามร้าน** — เส้นทางดาวน์โหลดตรวจว่า "แถวนี้เป็นของร้านฉัน" แล้วไปดึงไฟล์ตาม `path` ในแถวนั้น · แต่ `path` ไม่ได้มาจากเซิร์ฟเวอร์เสมอ: `kanban/links.ts:370-377` เขียน `path` จาก `storageKey` ที่ลูกค้าส่งมาทาง API แชท v1 โดยไม่ตรวจอะไรเลย ⇒ ปลูกแถวในร้าน A ที่ชี้ไปไฟล์ร้าน B ได้
2. 🔴 **ลบไฟล์ข้ามร้าน — ใช้โจมตีได้จริงบน production ตอนนี้ (ของเดิม ไม่ใช่ของใบนี้ แต่ใบนี้เป็นเจ้าของไฟล์จึงปิดที่นี่)** · `deleteStoredPath` รับ `tenantId` มาแต่**ใช้แค่ในบรรทัด log** · ด่านคือ `^t/<ร้านอะไรก็ได้>/` · ผู้เรียกจริงส่งค่าที่ลูกค้ากำหนดได้: `chat/retention.ts:222` (url จาก API แชท) และ `member/privacy.ts:1382` (`cdnUrl` ที่ kanban ให้ลูกค้าเลือกได้) ⇒ ร้าน A แปะ URL โลโก้สาธารณะของร้าน B เป็นไฟล์แนบ → รอบล้างข้อมูลทำงาน → **ไฟล์ของร้าน B ถูกลบ** · คอมเมนต์ในโค้ดที่ `retention.ts:214-216` เขียนข้อสมมติผิดไว้ตรง ๆ ว่า "ข้ามร้านเป็นไปไม่ได้อยู่แล้ว — path ฝัง tenantId ไว้"
3. **ด่าน `..` เป็น blacklist จึงเลี่ยงได้ด้วย `%2e%2e`** — ผู้คุมงานรันพิสูจน์เองด้วยตัวแปลง URL ตัวเดียวกับที่ `fetch()` ใช้: `t/A/private/%2e%2e/%2e%2e/%2e%2e/t/B/private/secret.mp3` ถูกคลี่เป็น `/zone1/t/B/private/secret.mp3` และใส่อีกชุดหนึ่งจะ**ทะลุออกนอกโซนที่เก็บไฟล์** ขณะที่ `"…%2e%2e…".includes("..")` เป็น `false`

**วิธีแก้ (ต้นเหตุเดียว)**: ตัวตรวจ allowlist ตัวเดียวใช้ทั้ง 4 จุด + `storagePathForTenant` ที่บังคับรหัสร้านให้ตรงเป๊ะและ fail-closed เมื่อไม่ส่งมา · builder พิสูจน์ทีละอินพุต **20/20** (รวม `%2e%2e` ทั้งขาอ่านและขาลบ · sentinel ที่ฝัง `%2e%2e` · แถวที่ปลูกไว้ · ไม่ส่ง tenantId)

**SHOULD-FIX ที่ปิดด้วย**: path ของไฟล์ส่วนตัวไปโผล่ใน `OpsEvent` (= แจกกุญแจถาวร เพราะ path 160 บิตคือการป้องกันทั้งหมด) → log `asset.id` แทน · ช่องทางที่ยังไม่ล็อกอินไม่มีเพดานเลยทั้งที่แพงที่สุด → เพิ่มเพดานต่อ IP ก่อนแตะฐานข้อมูล · `Content-Type` สะท้อนค่าที่ลูกค้าใส่มา → normalize ก่อนส่ง · `listAssets` ปล่อย sentinel ออกไป (แทนที่สตริงครั้งเดียวก็ได้ URL จริง) → คืน `cdnUrl: null` · ไม่มีตัวกันไฟล์ที่หลายแถวใช้ร่วมกัน → เพิ่ม · ลำดับลบ object ก่อนแถว (5xx แล้วลบแถวทิ้ง = ไฟล์เสียงกำพร้าในถังตลอดกาล)

**ORACLE-EDIT `C0.4-S3.16`** (ผู้คุมงานแก้เอง): ข้อสอบถอดสูตรลายเซ็นโดยลองเฉพาะกุญแจดิบ แต่ผู้คุมงานสั่งให้ติดป้ายกุญแจ (`private-file:v1:`) เพื่อกันลายเซ็นของเส้นทาง token อีก 4 เส้นใน C2.5/C3.5 กลายเป็นลายเซ็นไฟล์ที่ใช้ได้ ⇒ เพิ่มกุญแจติดป้ายเข้าไปในชุดที่ลอง **โดยคงกุญแจดิบไว้เป็นตัวแรก** (ถ้าใครถอดป้ายในอนาคต ข้อสอบยังจับได้) · 🔴 **ปฏิเสธทางลัดของ builder** ที่เสนอให้ถอดป้ายออก 1 บรรทัดเพื่อให้เขียวทันที — นั่นคือการลดความเข้มของโค้ดเพื่อให้ข้อสอบผ่าน (§2.9 ห้าม)
