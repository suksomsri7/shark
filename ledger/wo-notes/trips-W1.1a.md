## ข้อสังเกตความปลอดภัย (ไม่ใช่ข้อแดง — ขอให้ผู้ตรวจ/ผู้คุมตัดสิน)
1. **metadata อ่านโดยไม่ผ่านด่าน** (ใบสั่ง §2 สั่งไว้): เครื่องที่ถูกจำกัดแล้วยังทำให้เกิดคิวรี resolve ร้าน + ตราสินค้า + รายการสินค้า ต่อคำขอ และชื่อร้านยังขึ้นใน `<title>` ของหน้า "ถี่เกิน" (ใบสั่ง §6 ว่าหน้านั้น "ไม่มีข้อมูลร้าน") — ลดแล้วเท่าที่ทำได้โดยไม่เรียกด่านใน metadata (ข้อ 2 ด้านบน) · ทางปิดจริง = ให้ metadata ใช้ผลของ `open*` ร่วมกับหน้าผ่าน `cache()` (ต้องแก้ S-5 ที่ห้าม `openBook*(` ใน generateMetadata) หรือไม่ใส่ชื่อร้านในชื่อหน้า
2. **ก่อนถึงด่านมี 2–3 คิวรีเสมอ** (resolve ร้าน 2 + หาสินค้า 1) ตามลำดับบังคับ §5.4 — เครื่องที่เกินเพดานยังกินคิวรีชุดนี้ต่อคำขอ
3. **ความน่าเชื่อถือของหัว IP**: ลำดับ `x-real-ip → x-vercel-forwarded-for → x-forwarded-for` (เท่าหน้าโรงแรม) — ถ้าชั้นหน้า (proxy/CDN) ไม่เขียนทับหัวเหล่านี้ ผู้ใช้ปลอมหัวแล้วได้ถังใหม่ไม่จำกัด (พ้นเพดาน + ปั๊ม views) · ต้องยืนยันที่การ deploy จริง
4. ถังกันนับซ้ำ = 1 แถว `ChatRateBucket` ต่อ (หน่วย · วัน · ช่องทาง · ลิงก์ · เครื่อง) — โตตามจำนวนเครื่อง/วัน · ไม่ได้ตรวจว่ามีงานกวาดแถวเก่าของ `ChatRateBucket` หรือไม่
5. ด่านสร้างถังกันนับซ้ำแม้หน่วยที่ส่งมาไม่ใช่ของร้าน (แถวสถิติไม่เกิด · `counted=false`) — เกิดได้เฉพาะผู้เรียกฝั่งเซิร์ฟเวอร์ที่ส่ง id ผิด (หน้าใช้ id จากตัวแก้ร้านเท่านั้น)
