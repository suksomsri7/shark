## ข้อตัดสินใจสำคัญ (อ่านก่อนแก้ต่อ)

1. **ไม่มีไฟล์โมดูลใหม่ที่ import prisma** — fitness F5 baseline = 45 ไฟล์ และตอนนี้ **เต็มพอดี 45**
   ⇒ โค้ดที่แตะ DB ของ WO นี้อยู่ใน `service.ts` (ไฟล์ที่นับไปแล้ว) · ไฟล์ใหม่ 2 ไฟล์เป็น "บริสุทธิ์":
   - `recurring-shared.ts` — คณิตความถี่/ป้ายไทย/ตรวจ template (ไม่แตะ prisma/next → ใช้ฝั่ง client ได้)
   - `recurring-actions.ts` — `"use server"` เรียก service เท่านั้น (แบบเดียวกับ `import-actions.ts` ของ WO 1.8)
2. **ไม่เพิ่ม permission ใหม่** — ใช้ `account.doc.view` (ดูรายการกฎ) / `account.doc.create` (สร้าง/แก้/เปิด-ปิด/สั่งรันเอง)
   เหตุผล: กฎเอกสารประจำ = "เครื่องออกเอกสารแทนคน" สิทธิ์ที่ควบคุมคือสิทธิ์สร้างเอกสาร ถ้าเพิ่ม key ใหม่
   เจ้าของร้านทุกรายต้องไปติ๊กเพิ่มเอง = สิทธิ์หายเงียบ ๆ (บทเรียนเดียวกับ IMPLIES ของ WO 0.3)
3. **ไม่มี outbox event ใหม่** ⇒ ไม่ต้องลงทะเบียน consumer (บทเรียน `reference_outbox_new_event_needs_consumer`)
   แจ้งเตือนเขียน `AppNotification` ตรง ๆ แบบเดียวกับ `period-sweep.ts`/`sweepExpiringLots`
4. **ผู้รับแจ้งเตือนเป็นรายคน (G11)** — `recipientUserId` เสมอ ไม่ใช่ประกาศทั้งร้าน
   คัดผู้รับด้วย `evaluate()` ตัวเดียวกับทั้งระบบ (`selectAccountNotifyRecipients`) — fail-closed
5. **กันซ้ำ 2 ชั้นคนละแบบ**
   - เอกสารประจำ: `AccountRecurringRun @@unique([ruleId, periodKey])` = กุญแจจริงในฐานข้อมูล
   - เตือน: เนื้อความ (`title`+`body`) ของแต่ละ (ชนิด · เอกสาร · วัน) **ตายตัว** ⇒ กันซ้ำด้วยการนับ
     แถวเดิมที่ `title+body` ตรงกัน + `createdAt >= ต้นวันไทย` (ไม่ต้องแปะโค้ดกันซ้ำให้ผู้ใช้เห็นในข้อความ)
6. **วันที่คิดเป็น UTC เที่ยงคืน** เหมือนทั้งโมดูล (`new Date("YYYY-MM-DDT00:00:00.000Z")`) ส่วน "วันนี้/พรุ่งนี้"
   ของตัวเตือนคิดจาก **ปฏิทินไทย** (`Asia/Bangkok`) แล้วแปลงเป็น UTC เที่ยงคืนก่อนเทียบ
   (บทเรียน `reference_thai_date_getday_trap`: ห้ามใช้ `getDay()` ของเครื่องที่รันเป็น UTC)

## รายละเอียดที่ทำ

### A. Schema (additive ล้วน)

`prisma/schema/account.prisma` + `prisma/migrations/20260903190000_account_v2_recurring/migration.sql`

- `enum AccountRecurringFrequency { WEEKLY MONTHLY QUARTERLY YEARLY }`
- `model AccountRecurringRule` — id/tenantId/systemId/name/docType/contactId/templateJson/frequency/
  dayOfMonth/weekday/startDate/endDate/nextRunAt/lastRunAt/leadDays/autoApprove/active/createdByUserId
- `model AccountRecurringRun` — ruleId/periodKey/documentId/createdAt + `@@unique([ruleId, periodKey])`
- ลงทะเบียน `scope.ts` ทั้ง 2 ตัวเป็นแกน `sys()` (fitness F1.1 บังคับ)

### B. ตัวสร้าง (generator)

`runRecurringRules(now, opts?)` ใน `service.ts`
- เลือกกฎ `active` ที่ `nextRunAt - leadDays ≤ now` (คัดกรอง leadDays ฝั่ง JS เพราะเป็นค่าต่อแถว)
- `periodKey` คิดจาก **วันที่นัด (`nextRunAt`)** ไม่ใช่ `now` ⇒ "สร้างล่วงหน้า n วัน" ไม่ทำให้กุญแจเลื่อน
- สร้างร่างด้วย `createDocument`/`createExpenseDoc` **ตัวเดียวกับที่ `saveDraftAction` เรียก** +
  `applyEditorExtras` (reference/priceMode/tags) ⇒ ตัวเลขบนเอกสารประจำ = ตัวเลขที่ฟอร์มคิด
- `source=RECURRING` · `tags` มี "ประจำ" · `reference` = ชื่อกฎ (≤35)
- `autoApprove` → `issueDocument`/`issueExpenseDoc` (เส้นเดิม ห้ามเขียน posting ใหม่) · ออกไม่ผ่าน = **คงเป็นร่าง** + แจ้งเตือนพร้อมเหตุผลไทย
- บันทึก `AccountRecurringRun` (ชน unique = แข่งกัน → ลบร่างที่เพิ่งสร้างทิ้ง ไม่ทิ้งขยะ)
- เลื่อน `nextRunAt` ตามความถี่ · เลย `endDate` → `active=false`

### C. ตัวเตือน (reminders)

`runAccountReminders(now, opts?)` ใน `service.ts` — 5 ชนิด (`REMINDER_KINDS`):
| kind | เงื่อนไข | ข้อความ |
|---|---|---|
| `DUE_TOMORROW` | ครบกำหนดพรุ่งนี้ (ขาย IV/BN/DR · ซื้อ PUR/EXP/AP/DP) | "ครบกำหนดพรุ่งนี้" |
| `OVERDUE_TODAY` | `dueDate` = เมื่อวาน (พ้นกำหนด "วันแรก") | "พ้นกำหนดชำระแล้ว" |
| `PTX_AWAITING` | PTX `AWAITING_RECEIVE` และออกมาเกิน 7 วัน | "ใบกำกับภาษีซื้อยังไม่ได้รับ" |
| `CHEQUE_DUE` | เช็ค (ON_HAND/DEPOSITED/ISSUED) ถึงกำหนดใน ≤3 วัน | "เช็คถึงกำหนด" |
| `PP30_DUE` | วันที่ 5 ของเดือน (ก่อนกำหนดยื่น 10 อยู่ 5 วัน) | "ภ.พ.30 ใกล้ครบกำหนดยื่น" |
- ผู้รับ = คนที่มีสิทธิ์ `account.payment.record` ในร้านนั้น
- กันซ้ำ: `title`+`body` เดิมภายในวันไทยเดียวกัน → ไม่เขียนซ้ำ (รัน 2 รอบได้จำนวนเท่าเดิม)

### D. เตือนชำระลูกค้า (⋯ บนหน้าเอกสาร)

- `sendPaymentReminder()` (service) → อีเมลผ่าน `sendEmail` ของแกนกลาง + `writeAudit("account.doc.remind")`
- ใช้ลิงก์สาธารณะ `/r/<token>` เมื่อชนิดเอกสารรองรับ (IV/RE/DP) — BN ไม่มีลิงก์ ส่งเนื้อความอย่างเดียว
- ไม่มีอีเมล → ปุ่มจาง + เหตุผลไทย "ผู้ติดต่อยังไม่มีอีเมล — เพิ่มอีเมลในข้อมูลผู้ติดต่อก่อน"

### E. `pendingTasks()` (ให้ WO 2.1 เอาไปวาดการ์ด "งานที่รอคุณ")

คืน 6 ตัวเลข: `quotationAwaitingAccept` · `poAwaitingApproval` · `depositAwaitingDeduct` ·
`needsReview` · `purchaseTaxAwaiting` · `recurringDraftsAwaiting`

### F. cron

- `POST|GET /api/cron/account/recurring` และ `/api/cron/account/reminders` (`isCronAuthorized` เดิม)
- `scripts/acc-v2-cron-recurring.mts` — ตัวห่อสำหรับ VPS cron (เรียก service ตรง ไม่ผ่าน HTTP)

**บรรทัด crontab ที่ Fable ต้องติดตั้ง** (เวลาไทย = UTC+7 · เครื่อง VPS เป็น UTC):
```
# SHARK บัญชี V2 — เอกสารประจำ 06:10 ไทย (23:10 UTC ของวันก่อนหน้า)
10 23 * * * cd /root/projects/shark-in-th && /usr/bin/env pnpm tsx scripts/acc-v2-cron-recurring.mts recurring >> /var/log/shark-acc-cron.log 2>&1
# SHARK บัญชี V2 — เตือนครบกำหนด/เช็ค/ภ.พ.30 08:00 ไทย (01:00 UTC)
0 1 * * * cd /root/projects/shark-in-th && /usr/bin/env pnpm tsx scripts/acc-v2-cron-recurring.mts reminders >> /var/log/shark-acc-cron.log 2>&1
```
(หรือให้ Vercel Cron ยิง 2 route ข้างบนแทน — route กันด้วย `SHARK_CRON_SECRET` เดิม)

## ค้าง / ส่งต่อ WO ถัดไป

- การ์ด "งานที่รอคุณ" บนหน้าหลักยังไม่ถูกวาด — `pendingTasks()` พร้อมแล้ว รอ **WO 2.1/2.2**
- แจ้งเตือนเข้า **LINE ทีมงาน** (§0.3 ข้อ 4) ยังไม่ต่อ — ต้องผ่าน facade ของโมดูลแชทซึ่ง WO นี้ห้ามแตะ
  (`src/lib/modules/chat/**`) ⇒ จดไว้ให้ session แชท/WO 8.3 เชื่อม
- ฟอร์มกฎยังไม่รองรับ "หัก ณ ที่จ่ายต่อบรรทัด" (`whtRateBp`) — เอกสารประจำที่มี WHT ต้องแก้ในร่างเอง
- "เตือนชำระ" ส่งได้ทีละใบ (ยังไม่มีปุ่มเตือนทั้งชุดจากหน้ารายการ)
- `runRecurringRules` ไล่ **งวดละ 1 ใบต่อ 1 รอบ** สำหรับกฎที่ตั้งวันเริ่มย้อนหลัง (ตั้งใจ — กันออกใบรวดเดียว 12 ใบ
  แล้วเลขรันเรียกคืนไม่ได้) ⇒ กฎที่ย้อนหลัง 6 เดือนจะตามทันใน 6 วัน · ถ้าเจ้าของอยากได้ทีเดียวให้กดปุ่ม "สร้างรอบที่ถึงกำหนด" ซ้ำ
- เพดานต่อรอบ: กฎ 500 ตัว / ระบบบัญชี 200 ร้าน ต่อการรัน 1 ครั้ง (พอสำหรับตอนนี้ · โตกว่านี้ต้องทำ cursor)
- ตัวเตือนยิง query "เคยเตือนวันนี้ยัง" ต่อ (ผู้รับ × เรื่อง) — โอเคที่สเกลปัจจุบัน ถ้าร้านโตให้ย้ายไปนับเป็นชุดเดียว
