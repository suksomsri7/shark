## 1. ตัวคิดเดียว `pp30Return` (ไฟล์ใหม่ `account/pp30-return.ts` · ส่วน pure ใน `account/pp30-shared.ts`)
ช่อง (สตางค์ · ชื่อช่องตาม skill §19 — skill ไม่ให้เลขข้อของแบบทางการ ⇒ ระบบใช้ลำดับของตัวเอง ไม่อ้างว่าเป็นเลขข้อในแบบ):
| key | ช่อง | ที่มา |
|---|---|---|
| `salesTotal` | ยอดขายทั้งหมดในเดือน | = std + zero + exempt |
| `salesZero` | ยอดขายอัตราร้อยละ 0 | ฐานกลุ่ม 0% ของรายงานภาษีขาย T1.1 |
| `salesExempt` | ยอดขายที่ได้รับยกเว้น | ฐานกลุ่มยกเว้นของรายงานภาษีขาย T1.1 |
| `salesTaxable` | ยอดขายที่ต้องเสียภาษี | ฐานกลุ่มอัตรา > 0 ของรายงานภาษีขาย |
| `outputVat` | ภาษีขาย | ยอดเคลื่อนไหวสุทธิฝั่งเครดิตของบัญชี VAT_OUTPUT (mapping) ในเดือน — เท่ากับรายงานภาษีขาย (ข้อตรวจ) |
| `purchases` | ยอดซื้อที่มีสิทธินำภาษีซื้อมาหัก | ฐานของรายงานภาษีซื้อ (แถวที่มีภาษีซื้อ) |
| `inputVat` | ภาษีซื้อ | ยอดเคลื่อนไหวสุทธิฝั่งเดบิตของบัญชี VAT_INPUT (mapping) |
| `taxPayable` / `taxExcess` | ภาษีที่ต้องชำระ / ชำระเกิน เดือนนี้ | outputVat − inputVat (บวก/ลบ) |
| `creditBroughtForward` | เครดิตภาษียกมา | ข้อ 2 |
| `netPayable` / `netExcess` | ภาษีสุทธิต้องชำระ / ชำระเกินสุทธิ | (outputVat − inputVat) − creditBroughtForward |
| `excessChoice` | ชำระเกินสุทธิ: ยกไปเดือนหน้า / ขอคืน (ม.84) | ค่าตั้ง (ข้อ 6) · เลือกได้ตอนทำเครื่องหมายยื่น |
| `creditCarriedForward` | เครดิตยกไปเดือนถัดไป | = netExcess ถ้าเลือกยกไป · 0 ถ้าขอคืน |
- เดือนไม่มีรายการ: ทุกช่อง 0 แต่ออกแบบได้ (ม.83 "ไม่ว่าจะมีการขาย…หรือไม่") — เครดิตยกมายังส่งต่อ
- ฐานยอดขายมาจากรายงานภาษีขาย T1.1 (ตัวคิดเดียว) ⇒ ช่องยอดขายตรงรายงาน ม.87 เสมอ (T-ACC-03)

## 2. เครดิตยกมา (จำต่อเดือน)
ลำดับตัดสินของเดือน M:
1. ร้านแก้เอง (ตารางประวัติ `AccountVatCreditCarry` — แถวล่าสุดของเดือนนั้นมีผล · `amountSatang = null` = กลับไปใช้ค่าที่ระบบคิด) → ใช้ค่านั้น + ป้าย "ร้านแก้เอง"
2. เดือน M−1 ทำเครื่องหมายยื่นแล้ว → เครดิตยกไปของ **ยอดที่ยื่นล่าสุด** ของ M−1 (แบบเพิ่มเติมล่าสุด ถ้ามี ไม่งั้นต้นฉบับ)
3. ไม่งั้น คิดสดจาก M−1 (ภาษีขาย − ภาษีซื้อ − เครดิตยกมาของ M−1 เอง) ไล่ย้อนไปจนเจอเดือนที่ยื่นแล้ว/ร้านแก้เอง หรือก่อนเดือนแรกที่มีรายการบัญชี VAT (= 0) · เพดาน 120 เดือน
- คิวรีเดียว: ยอด VAT_OUTPUT/VAT_INPUT รายเดือน (groupBy periodKey) + แถวยื่น + แถวแก้เอง
- ทุกค่ามี `source` (`OVERRIDE` · `FILED` · `COMPUTED` · `NONE`) แสดงบนจอ + REST
- แก้เองไม่ลบประวัติ: ทุกครั้งเป็นแถวใหม่ (ใคร เมื่อไร เหตุผล) — หน้า ภ.พ.30 แสดงประวัติ

## 3. "ยื่นแล้ว" = ภาพตัวเลขที่ยื่น + แบบยื่นเพิ่มเติม
- `AccountVatFiling` (มีอยู่แล้ว · 1 แถว/เดือน = แบบต้นฉบับ) **เพิ่มคอลัมน์** `lines Json?` (ทุกช่องข้อ 1 ณ วันยื่น) · `creditBroughtForwardSatang Int @default(0)` · `excessChoice String?` · `netSatang Int?`
  - `markVatFiled` คิดตัวเลขจากสมุดเอง (ไม่เชื่อยอดที่ผู้เรียกส่งมา) · ยอดที่ส่งมา (เดิมบังคับ — ตอนนี้ไม่บังคับ) ถ้าไม่ตรงสมุด = ปฏิเสธ "ยอดไม่ตรงสมุด เปิด ภ.พ.30 ดูใหม่" (ความถูกต้องข้อมูล ไม่ใช่ด่านกฎหมาย)
  - แถวเก่า (ก่อน T1.3) `lines = null` ⇒ ตัวอ่านสร้างช่องจากคอลัมน์เดิม (ภาษีขาย/ซื้อ/ยอดสุทธิ) ส่วนที่ไม่มี = null "ไม่ได้บันทึก"
- ตารางใหม่ `AccountVatAdditionalFiling` (แบบยื่นเพิ่มเติม · หลายครั้งต่อเดือน `seq` 1,2,…): `lines` (ตัวเลขใหม่ทั้งชุด) · `diff` (ผลต่างต่อช่องเทียบยอดที่ยื่นล่าสุดก่อนหน้า) · ผู้ยื่น วันที่ หมายเหตุ
  - ผลต่าง = ตัวเลขจากสมุดตอนนี้ − ตัวเลขที่ยื่นล่าสุด · ไม่มีผลต่างเลย = ปฏิเสธ "ไม่มีอะไรต้องยื่นเพิ่มเติม"
  - ภาษีต้องชำระเพิ่ม > 0 ⇒ คำเตือน `PP30_ADDITIONAL_SURCHARGE` (ม.89/1 เงินเพิ่ม · เบี้ยปรับ · ระเบียบลด [S]) — ระบบ **ไม่คำนวณ** เงินเพิ่ม/เบี้ยปรับ
- ยกเลิกเครื่องหมายยื่น: เดือนที่มีแบบเพิ่มเติมแล้ว = ปฏิเสธ (ต้องไม่ทิ้งแบบเพิ่มเติมลอย ๆ) · ประวัติการยกเลิกแบบไม่ลบแถว = T1.7
- **ตะขอสำหรับ T1.7**: `vatFiledState(ctx, periodKey)` (ยื่นแล้วไหม · ยอดยื่นล่าสุด · ผลต่างกับสมุดตอนนี้) — T1.7 เรียกตัวนี้ตอนมีรายการลงเดือนที่ยื่นแล้ว · T1.3 ไม่ทำคำเตือนตอนลงรายการ

## 4. จอ ภ.พ.30 (`reports/pp30`)
- กล่องสรุปช่องทั้งหมด (ข้อ 1) แสดง **ยอดขาย/ยอดซื้อ + ภาษี** ไม่ใช่แค่ภาษี · ป้ายที่มาเครดิตยกมา + ปุ่มแก้ (ประวัติ)
- กำหนดยื่น: กระดาษวันที่ X · อินเทอร์เน็ตวันที่ Y จาก `filingDeadlineOf(ctx,"PP30",period)` (ตาราง T0.2) + คำเตือนของตาราง (เช่น ไม่มีแถวออนไลน์หลัง 31 ม.ค. 2570)
- กระทบยอด GL ผ่าน mapping: ภาษีขาย = ยอดบัญชี VAT_OUTPUT · ภาษีซื้อ = ยอดบัญชี VAT_INPUT (ชื่อ/รหัสบัญชีจาก mapping) · ยอดค้างในบัญชีพักภาษี (VAT_OUTPUT_UNDUE · VAT_OUTPUT_PENDING_INVOICE · VAT_INPUT_UNDUE) แสดงเป็นข้อมูล (ไม่เข้า ภ.พ.30 — E5/T1.2) · บัญชีรายได้ ↔ ยอดขาย = T1.9
- ยื่นแล้ว: กล่องยอดที่ยื่น vs สมุดตอนนี้ (ผลต่างต่อช่อง) + ปุ่ม "ยื่นแบบเพิ่มเติม" เมื่อมีผลต่าง + รายการแบบเพิ่มเติม
- คำเตือนทั้งหมดผ่าน `LegalWarnings` (ทะเบียนกลาง) · ไม่มี emoji (เดิมมี "✓" → AccountIcon)
- พิมพ์ + CSV: หัวรายงาน T1.1 + ทุกช่อง (ยอดขาย/ซื้อ/ภาษี/เครดิต) + กำหนดยื่น + กระทบยอด + สถานะยื่น/แบบเพิ่มเติม · รายงานภาษีขาย/ซื้อตามเดิม

## 5. REST / เลขา AI
- `reports.vat-pp30` (GET) คืนช่องใหม่ทั้งหมด (`return`) + เครดิตยกมา + กำหนดยื่น + กระทบยอด + สถานะยื่น + `warnings` (รูป T0.4) · `carryForwardSatang` ใน query = แทนค่าชั่วคราว (ของเดิม · ไม่บันทึก)
- `periods.vat-filed` (POST · มีอยู่) — ตอนนี้บันทึกภาพตัวเลขจากสมุด · ยอดในตัวคำขอไม่บังคับ · `excessChoice` · เปิดเป็นเครื่องมือเลขา (ข้อเสนอ → เจ้าของกด)
- ใหม่ `periods.vat-additional` (POST /periods/{key}/vat-additional) — ยื่นแบบเพิ่มเติม · คืนผลต่าง + `warnings` · เครื่องมือเลขา
- ใหม่ `periods.vat-credit-carry` (POST /periods/{key}/vat-credit-carry) — ร้านแก้เครดิตยกมา (`amountSatang` หรือ null = กลับค่าที่ระบบคิด · `reason` บังคับ) · เครื่องมือเลขา
- คำเตือนแบบ T0.4 (`LegalWarning`) ในผลตอบ — ไม่มีอะไรต้องกดยืนยัน (ไม่บล็อก)
