## 2. การออกแบบที่ใช้จริง
- **จองงานด้วย SQL คำสั่งเดียว** `INSERT … ON CONFLICT (source) DO UPDATE … WHERE "lastAlertAt" <= $now RETURNING` บนแถว `OpsAlertState` คีย์ `minute-job:lease:<name>` → ได้แถวคืน = ได้ lease · แล้ว**อ่านสถานะซ้ำ**ว่ายังถึงเวลาอยู่ไหม · **ไม่เขียน "รันแล้ว" ก่อนงานจบ** (บั๊ก M7 ของระบบสมาชิก)
- **กู้หลังพัง**: โพรเซสตายหลังจอง → ยังไม่มีแถว run/ok ⇒ สถานะไม่โกหก · รอบก่อน lease หมดเห็นว่า "ไม่ว่าง" จึงไม่รันซ้อน · รอบแรกหลัง lease หมด (15 นาที) หยิบใหม่และรันครั้งเดียว
- **งบเวลา 20 วิต่อรอบบังคับโดยตัวกระจาย** ไม่ใช่เชื่อใจงาน: งานถัดไปได้ "เวลาที่เหลือ" ไม่ใช่ 20 วิใหม่ · งานที่ไม่เคารพงบถูกตัดพร้อม `AbortSignal` · ตรวจงบซ้ำ**หลังจอง**ด้วย (ถ้าเหลือไม่พอ → ปล่อย lease คืน ไม่ถือค้าง 15 นาที)
- **ช่องเวลาตรึงนาฬิกา** `floor((now+7h)/P) > floor((lastRun+7h)/P)` (รายวันตัดที่เที่ยงคืนไทย) — ดู §7 ว่าทำไม
- นาฬิกาคือพารามิเตอร์ `now` อย่างเดียว · ปฏิเสธ `now` ที่ล้ำอนาคต > 60 วิ

## 7. สิ่งที่เจอและแก้
- 🔴 **BLOCKER ที่ข้อสอบมองไม่เห็นโดยโครงสร้าง** (ผู้ตรวจเจอ · ผู้คุมงานยืนยันกับโค้ด): ตัวเช็คแบบช่วงห่าง `now − lastRun ≥ P` + เวลาเริ่มของตัวรันที่แกว่ง 0.1–3 วิ ⇒ ถ้ารอบนี้บูตเร็วกว่ารอบก่อนเสี้ยววินาที (10:07:01.40 → 11:07:01.10 = 59:59.7) ถูกข้ามทั้งรอบ · โอกาส ~50% ⇒ **งานรายชั่วโมงเดินจริงทุก ~1.5 ชม. · งานรายวัน (ล้างข้อมูลตาม PDPA) ข้ามทั้งวัน · ไม่มีอะไรซ้ำ ไม่มีอะไรหาย แค่ช้าเงียบ ๆ** · ข้อสอบจับไม่ได้เพราะป้อน `now` เป๊ะ · แก้เป็นช่องเวลาตรึงนาฬิกา · พิสูจน์ด้วยคู่เวลาที่แกว่งจริงทั้งรายนาที/ชั่วโมง/วัน
- SHOULD-FIX ที่ปิด: ตัวรันเรียก `process.exit` ฆ่างานที่ถูกตัดกลางคำสั่งแล้ว lease ค้าง 15 นาที → รองานค้างก่อนออก (≤ 75 วิ) · ตรวจงบก่อนจองแทนที่จะตรวจหลัง → ตรวจซ้ำหลังจอง · `now` ล้ำอนาคตทำให้งานหยุดไปจนถึงเวลานั้นโดยแก้ได้แค่ลบแถวมือ → ปฏิเสธ · **สัญญาณชีพถูกเติมจากทั้งสองทาง ทำให้หน้าสถานะโชว์ "ปกติ" ได้ทั้งที่ cron บนเครื่องตาย** → เติมจากเส้น VPS เท่านั้น · **ฐานข้อมูลล่มแล้วตัวรันออก 0 เหมือน "ไม่มีงาน"** → ออก 1
- 🔴 **ความปลอดภัยของตัวรัน**: `process.loadEnvFile` ไม่ทับตัวแปรที่มีอยู่แล้ว ⇒ เปลือกคำสั่งที่มี `DATABASE_URL` ของ production ค้างอยู่ + `QC_ENV_FILE=.env.qc` = **รัน QC บน production** · แก้: ถ้าค่าที่มีอยู่ไม่ตรงกับไฟล์ QC → หยุดทันที (exit 4) · พิสูจน์แล้ว
- 🔴 **กับดักเครื่องมือของ RUN ทั้งหมด** (builder เจอ): `scripts/iso.sh` ไม่ส่งตัวแปรของผู้เรียกเข้า unit ⇒ `VAR=x bash scripts/iso.sh …` ไม่มีผล · ต้องใส่ `env` ข้างใน · รูปแบบที่ RUN นี้ใช้ถูกแล้ว — บันทึกใน `ledger/CRM-RUN.md` §4
