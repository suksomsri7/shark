### 1) `acc-v2-env.mts` — โหมด CI (ด่าน prod ยังเด็ดขาดเหมือนเดิม)

`loadQcEnv()` เดิม: ไม่มี `.env.qc` = ตายทันที · ตอนนี้:

- มี `.env.qc` → โหลดไฟล์ (`source: "file"`) — พฤติกรรมเดิมทุกอย่าง รวมทั้งบังคับ `APP_ENV=development`
- ไม่มีไฟล์ **แต่** มี `DATABASE_URL`+`DIRECT_URL` ใน env → `source: "ci"` · พิมพ์ `ℹ️ CI env — …` ให้เห็นใน log
  · ตั้ง `APP_ENV=development` ให้เอง (CI ไม่ได้ตั้งมา) · `APP_ENV=production` = ตาย
- ไม่มีทั้งสองอย่าง → ตายพร้อมวิธีแก้ทั้งฝั่ง dev และฝั่ง CI
- **ด่าน `ep-royal-night` (production branch) ทำงานทุกโหมด ไม่มีข้อยกเว้น** — โหมด CI ผ่อนแค่ "ไม่ต้องมีไฟล์"

เพิ่ม 2 ฟังก์ชัน (ใช้คีย์เสถียร ไม่ใช่ id):
- `resolveAccV2Scope(prisma)` → `{ tenantId, systemId }` จากชื่อร้าน `SIAM DIVE QC` + `AppSystem.type=ACCOUNT` · `null` = ยังไม่ seed
- `isAccV2SeedPresent(prisma)` → มีร้าน + ระบบบัญชี + **มี `AccountDocument` จริง** (seed ที่ล้มกลางทางจะไม่ถูกนับว่า "มีแล้ว")

### 2) `qc-all.mts` — seed ครั้งเดียวต่อ run

- ไฟล์ที่มีบรรทัด `// requires: acc-v2-seed` = ต้องมีชุดข้อมูล QC · qc-all อ่านจากตัวไฟล์ (ไม่มีรายชื่อฮาร์ดโค้ด
  ให้ลืมอัปเดต — บทเรียนเดียวกับที่ทำให้ 89 ชุดตกสำรวจ)
- ก่อนเริ่มยิงชุดของ shard นั้น ถ้ามีชุดที่ต้องใช้: `pnpm exec tsx scripts/seed-acc-v2-qc.mts --if-missing`
  แล้วถ้า seed ทำงานจริง (ไม่ใช่ข้าม) ต่อด้วย `scripts/acc-v2-expected-dashboard.mts` · พิมพ์เวลาที่ใช้
- **seed ล้ม ≠ ล้มทั้ง run**: ตั้ง `seedBlocked` แล้วชุดที่ต้องใช้ขึ้น ❌ พร้อมเหตุผลภาษาไทย
  (`seed ชุดข้อมูล QC ล้ม (scripts/seed-acc-v2-qc.mts) — ดู log ด้านบน`) · ชุดอื่นใน shard เดียวกันรันต่อตามปกติ
- ส่ง `env: process.env` เข้า spawn ทุกตัว (CI export `DATABASE_URL`/`DIRECT_URL` มาให้แล้ว)

### 3) `--if-missing` (กันเครื่อง dev เสีย diff)

seed สร้าง id ใหม่ทุกครั้ง (cuid) ⇒ ถ้า `pnpm qc:all` บนเครื่อง dev สั่ง seed ทุกรอบ
`scripts/acc-v2-expected.json` (ไฟล์ที่ commit) จะ dirty ทุกครั้ง **และร้าน QC ที่ WO อื่นกำลังใช้อยู่จะโดนลบทิ้งกลางคัน**
⇒ `--if-missing` ข้าม seed เมื่อ `isAccV2SeedPresent()` เป็นจริง **และ** เฉลยตรงกับ DB
(`E.tenantId/E.systemId` = ของจริงใน DB + มีคีย์ `dashboard`) · พิมพ์ `ACC_V2_SEED=skipped|missing|created` ให้ qc-all อ่าน

### 5) 🔴 บั๊กที่เจอระหว่างทำ — 12 ชุดจะ**พังตั้งแต่บรรทัดแรก**บน CI

12 ไฟล์เขียนไว้ว่า `process.loadEnvFile?.(process.env.QC_ENV_FILE ?? ".env");`
สมมติฐานเดิมคือ "บน CI ไม่เป็นไร เพราะ env ที่ export มาชนะไฟล์" — **จริงครึ่งเดียว**:

```
$ node -e 'process.loadEnvFile("/tmp/ไม่มีไฟล์นี้")'  → ENOENT: no such file or directory
$ FOO=from_shell node -e 'process.loadEnvFile("/tmp/t.env"); …'  → FOO=from_shell (env ชนะไฟล์ ✅)
```

`?.` กันแค่กรณี "ไม่มีเมธอด" ไม่ได้กันไฟล์หาย · CI ไม่มีทั้ง `.env` และ `.env.qc` ⇒ **โยน ENOENT ก่อน import ตัวแรก**
⇒ ครอบ `try { … } catch {}` ทั้ง 11 ไฟล์ (+ `qc-acc-v2-gl-inclvat.mts` ที่เขียน `process.exit(1)` ไว้ในกรณีนี้
เปลี่ยนเป็น "ตายเฉพาะเมื่อไม่มี `DATABASE_URL` ใน env ด้วย")
**ไม่แตะ** `acc-v2-cron-recurring.mts` / `backfill-acc-v2-phone-norm.mts` — เป็นงาน production ที่ต้องมี `.env` จริง ๆ
