## CONTROLLER-DECISION (the oracle encodes my proposal for each — rule before builder S starts)
1. **K2 `PIN_TAKEN` probe — which fix?** Q9 says "existence probe removed". Today `setStaffPin` refuses a PIN another person in the unit already uses (CD1 of P1.15 needs unique PINs so the anonymous PIN pad can match at most one row). Any distinct refusal on a well-formed, non-weak PIN still reveals that someone has it. **Proposal (preferred):** drop the uniqueness refusal. A colliding PIN is then accepted, and an anonymous `verifyStaffPin` that matches two or more rows returns `PIN_INVALID` (the lock screen sends `userId` — a P1.15U follow-up). **Fallback:** refuse a taken PIN with exactly the same `{code, message}` as a weak PIN. That still leaks for PINs not on the weak list. K2 accepts either shape. Either way, **`qc-pos-p1.15` PN3 (asserts `PIN_TAKEN`) and PN8 (the 7 codes include `PIN_TAKEN`) need an ORACLE-EDIT when K2 lands.** I did not edit that file, as the prompt instructed.
2. **K1 throttle parameters + storage.** Names `STAFF_PIN_DEVICE_THROTTLE_AFTER` (N) and `STAFF_PIN_DEVICE_THROTTLE_MS` (window) are exported from `register-shared.ts`. The oracle reads N, with a fallback of 10 when the export is missing. The rule: N wrong *anonymous* PINs on one device within the window ⇒ every further anonymous attempt on that device (even a correct PIN) gets `PIN_THROTTLED` until the window passes. Other devices are unaffected, and per-user `failedCount` does not move. Storage is the builder's choice (no migration, so AuditLog rows such as `pos.staff.pin_failed` {deviceId}, or an in-process map). The window expiry is **not** tested, because the storage is unknown. Named attempts (`userId` given) are not throttled by this rule, and they keep the per-row lock-out. Proposed N = 10, window 15 min.
3. **A5 MANAGER and `account.settings.manage`.** `evaluate()` lets a MANAGER pass every action at tenant level, so "MANAGER without account.settings.manage ⇒ PERMISSION_DENIED" (brief A1–A5) only works with an **explicit grant** rule (fail-closed, like `canViewPayroll`). The toggle needs OWNER, or both `permissions["account.settings.manage"] === true` (explicit, also for MANAGER) **and** `pos.settings.manage` on every unit linked to the POS. A5 encodes this: MGR (no grant) is refused, MGRA (MANAGER + explicit grant) and SACC (STAFF + both keys on U1+U2) pass.
4. **I11 test hook in production code.** To check that the backlog query really runs under `SET LOCAL statement_timeout`, `posIntegrationCards` takes `opts?: { now?: Date; statementTimeoutMs?: number; testDelayMs?: number }`. With `testDelayMs > 0`, it runs `SELECT pg_sleep(testDelayMs/1000)` inside the same transaction before the count. The oracle passes 50 ms timeout and 400 ms delay, so the timeout fires and `backlog` must be `null`. Alternative: an injected `deps.backlog` that throws (weaker — it does not prove the timeout is set). Please confirm the hook is acceptable.
5. **Staff tab permission (S1).** R10 does not state the read permission. **Proposal:** `posStaffOverview` needs `pos.settings.manage` at the unit (OWNER and MANAGER by role), because it lists names, roles and PIN state. A cashier with only `pos.sale.create` gets `PERMISSION_DENIED`. `posSettingsOverview` (R2) stays readable by cashiers.
6. **Approval list scope (S3).** `approvals` = active `POS_VOID/POS_REFUND/POS_DISCOUNT_OVER` policies that *apply to this POS at this unit*: global (`systemId null, unitId null`), `systemId = X`, or `unitId = U1`. Policies of another POS (Y) or of another unit, inactive ones and other entity types are excluded. `needsApproval` on void/refund/discount rows = an applicable active policy exists.
7. **roleMatrix STAFF count (S2).** `staff.total` = accepted STAFF memberships with access to the unit (`unitAccess` contains it or `"*"`). `staff.holders` = those of them for whom `evaluate(m, {action: permission, unitId})` is true (explicit key or `pos.*`). OWNER and MANAGER columns are `true` for every row that has a permission key. `discount` (caps shown separately) and `onlineOrders` (PLANNED P2.8) have `permission: null`.
8. **Card facts table (I12).** The 13 cards' `facts` keys, live flags and phases are in the names table below (from brief §6). The keys are the oracle's contract: please confirm the key names, or rename them now (an ORACLE-EDIT later costs a round).
9. **BOOKING / CHAT card determination.** I8 needs only `HR`/`BOOKING`/`AI` = PLANNED and `MARKETING`/`CHAT` = NO_SYSTEM, in a tenant that has HR, a BOOKING AppSystem **and** a BOOKING-type BusinessUnit, but no CHAT and no MARKETING system. With that fixture, either reading of "tenant has a booking system" passes. CHAT LINKED ("LINE sender configured for the tenant") is not tested, because there is no cheap fixture. Proposal: LINKED when an active `ChatChannel` of type LINE exists; OFF when there is a CHAT system but no LINE channel.
10. **PromptPay per unit writer (PP).** New `updatePosUnitPromptpay(ctx, actor, {unitId, promptpayId: string | null})` in `payment-settings.ts`. It is a money destination ⇒ OWNER only, and anyone else gets **`SETTINGS_SECTION_LOCKED`** (R16's OWNER-only code — the existing `updatePosPaymentSettings` keeps its `PERMISSION_DENIED`, so there is no ORACLE-EDIT of P1.6/P1.7). It validates with `isValidPromptPayId`, and the unit must be linked to the POS (else `NOT_FOUND`). `null` removes the entry. It writes only `settings.pos.payment.promptpayIdByUnit.<unitId>` (sibling `payment.*` keys kept). The audit section is `payment` with a masked value (the raw id never appears in AuditLog, H4/PP1).
11. **No-op definition (G5).** A patch whose parsed result equals the stored section ⇒ `{ok:true}`, no write, no audit. An empty patch `{}` is not tested.
12. **Default tab `general` (Q6)** is U work. The oracle has no check of `POS_SETTINGS_DEFAULT_TAB`.
13. **`receipt-send.ts` (LINE/e-mail receipt)** renders `locale: "th"` hard-coded. R12 names only the print path. Proposal: leave online/sent receipts on `th` (the public page has its own `?lang=` pair) and record a parity deviation. ST9 checks only `print/browser.ts` and `print/escpos.ts`.
