## หนี้/ที่ค้างส่งต่อ
1. **ใบเบิกของสินค้าที่ผูกคลัง ยังไม่ลง GL** — movement `sourceModule=ACCOUNT` ถูกกันไม่ให้ผ่าน `postMovementGl`
   โดยตั้งใจ (กฎ Dr5000/Cr1200 ของ bridge เป็นกฎ "ขาย" ไม่ใช่ "เบิกใช้ในกิจการ") ⇒ **WO 4.3** ต้องทำคู่บัญชี
   "ค่าใช้จ่ายที่ปรับปรุง" ตาม SPEC §8.4 แล้วเปิดการโพสต์ (ไม่งั้นมูลค่าคลัง 1200 บนงบไม่ลดตามของจริง — แต่เป็น
   หนี้เดิมตั้งแต่ก่อน WO นี้ ไม่ใช่ regression)
2. `invItemId` บน **MenuItem / RentalAsset / TicketType / SchoolCourse** = คอลัมน์เปล่า ยังไม่มีโค้ด wiring
   (ตามขอบเขต WO — MAP §F.10 ทำแค่ schema) ⇒ โมดูลเหล่านั้นยังสร้าง/แก้รายการของตัวเอง
3. **VAT ไม่ sync** จากคลัง (InvItem ไม่มีคอลัมน์ VAT) — ต่างจาก MAP §F.11
4. **กระจก `qtyOnHand` ล้าสมัยได้**: ถ้า POS/คลังขยับสต็อกเอง กระจกฝั่งบัญชีจะไม่อัปเดตจนกว่าจะมี sync ครั้งถัดไป
   ⇒ ทุกทางอ่านต้องใช้ `listProductsWithStock`/`productStockMap` (ทำครบแล้วในโมดูลบัญชี) · ถ้า 4.3 เพิ่มรายงาน
   สินค้าคงเหลือ ต้องใช้ทางเดียวกัน
5. `linkProductToItem` เขียน 2 ฝั่งคนละคำสั่ง (คนละระบบ scope) — ไม่ใช่ tx เดียว · ถอนคืนให้เมื่อขากลับล้ม
   และ `syncItemToAccountProduct` เยียวยาลิงก์ครึ่งใบให้อยู่แล้ว (ลิงก์ยุค `pos.setItemSalePrice` ก็ถูกเยียวยา)
6. หน้าจอ: WO นี้ใส่แค่ปุ่ม/ช่องขั้นต่ำในหน้า `/products` เดิม (ติ๊กติดตามสต็อก + ปุ่มผูก/เลิกผูก + ป้าย
   "ติดตามสต็อกในคลัง") — modal ตาม SPEC §8.2 (เลือกคลัง · จุดสั่งซื้อ · แสดงลิงก์ที่ผูก) = **WO 4.3**
7. `AccountProduct.warehouseId` ถูกเขียนตอนผูก และถูกใช้เป็น `locationId` ตอนเบิก/คืนแล้ว แต่ยังไม่มี UI ให้เลือก (4.3)
