## 1. หนี้สูญได้รับคืน
- ตาราง `AccountBadDebtRecovery` (migration `20270106000000_acc_t5c_etax_ts`) · บัญชีใหม่ 4920 "หนี้สูญได้รับคืน" (รายได้) · mapping `BAD_DEBT_RECOVERED`
- GL `postBadDebtRecovery`: Dr เงิน (ช่องทาง/บัญชีการเงิน) / Cr 4920 ในวันที่รับ · ไม่แตะลูกหนี้ ไม่เปิดใบเดิม · ยกเลิก = `reverseFor` (กลับรายการ ไม่แก้แถวที่ลงแล้ว)
- ยอดรับคืน ≤ ยอดที่ตัด (ไม่ยกเลิก) − ที่รับคืนแล้ว (ข้อมูลผิดรูป = ปฏิเสธ) · คีย์กันซ้ำ
- คำเตือน `BAD_DEBT_RECOVERY_INCOME` [V] แจ้ง · `BAD_DEBT_RECOVERY_VAT` [U] แจ้ง (เมื่อการตัดเคยปล่อย VAT บริการที่ยังไม่ถึงกำหนด — ระบบไม่แยกภาษีขายให้)
- ช่องทาง: จอ `/aging/bad-debt` (ใบที่ตัดแล้ว + รับคืนได้อีก + ฟอร์มรับคืน + ประวัติ + ยกเลิก) · REST `bad-debt.recover` `bad-debt.recovery-void` (danger) · `bad-debt.summary` เพิ่ม `writtenOffDocuments` `recoveries` · AI `account_recover_bad_debt` (ข้อเสนอ) `account_void_bad_debt_recovery` (อันตราย)
- ค่าเริ่มต้นที่ skill ไม่บอก: ลงรายได้ทั้งจำนวน (ไม่แยก VAT) · ไม่สร้างใบเสร็จ/ใบกำกับอัตโนมัติ

## 2. สถานะแสดงผล "ตัดหนี้สูญ"
- `bad-debt-shared.ts` `badDebtStatusOf` (pure): PAID และเงินจริง = 0 → "ตัดหนี้สูญ" · มีตัด + เงินจริง/ยังค้าง → "ตัดหนี้สูญบางส่วน" · ไม่แก้ `status` ในฐาน
- ใช้ที่: คอลัมน์สถานะรายการ (`StatusCell` / `rowStatusLabel`) · ป้ายหน้ารายละเอียด (`StatusBadge` label) · REST `badDebt { state, writtenOffSatang, label }` ทั้งแถวรายการและรายละเอียด
- รายการเอกสารอ่านรายการชำระทุกแถวที่ไม่ยกเลิก (ช่องทาง + ยอด) ในคิวรี include เดิม (ไม่เพิ่มคิวรี)
- รายงานลูกหนี้/อายุหนี้ใช้ยอดค้าง (grandTotal − paidTotal) อยู่แล้ว ⇒ ส่วนที่ตัดไม่นับเป็นหนี้ค้าง (ข้อสอบ C1.4)
- ยังไม่ทำ: แท็บ "ชำระแล้ว" ของหน้ารายการยังรวมใบที่ตัดหนี้สูญ (นับตามสถานะในฐาน) · ป้ายในโปรไฟล์ผู้ติดต่อ/แดชบอร์ดยังใช้ป้ายกลาง

## 3. วันประชุมใหญ่ → วันยื่นงบ
