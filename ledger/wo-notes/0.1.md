## หมายเหตุ/กับดักที่เจอ (อ่านก่อนแก้ของพวกนี้)
1. **ชื่อ Neon branch** — `scripts/neon-branch.mts` บังคับ prefix `wo-`/`ci-` ⇒ ชื่อจริงคือ **`wo-acc-v2-qc`**
   (BLUEPRINT เขียน `acc-v2-qc`). ⚠️ `pnpm neon:gc` ลบ branch `wo-*` ที่เก่ากว่า 24 ชม. — **ห้ามสั่ง gc ระหว่าง run นี้**
   ถ้าโดนลบ: `pnpm neon:create wo-acc-v2-qc` → อัปเดต 2 บรรทัดใน `.env.qc` → `migrate deploy` → seed ใหม่
2. **`.env.qc`** = ก๊อป `.env` ทั้งไฟล์ แล้วทับ `DATABASE_URL` / `DIRECT_URL` / `APP_ENV=development` / `APP_URL=http://127.0.0.1:3215`
   ถูก `.gitignore` ครอบด้วยกฎ `.env*` อยู่แล้ว (ยืนยันด้วย `git check-ignore -v .env.qc`) — ไม่ต้องเพิ่มบรรทัด
3. **`APP_ENV=development` มีผลกับชื่อคุกกี้** (`src/lib/env.ts` → `secureCookies`): dev = `shark_session` · https = `__Host-shark_session`
   `visual-acc-v2.mts` เลือกให้ตามโปรโตคอลของ `QC_BASE` แล้ว
4. **ยอดยกมาของช่องทางการเงิน 1 งวด = 1 ครั้ง** — `gl.postOpening` idempotent ต่อ `AccountOpening#<งวด>#OPENING`
   ⇒ ช่องทางทั้ง 4 ต้องตั้ง `openingDate` คนละเดือน (ม.ค./ก.พ./มี.ค./เม.ย. 2026) ไม่งั้นตัวที่ 2 สร้างไม่ได้
5. **ยอดยกมาคำนวณย้อนกลับ** — seed รู้แผนการรับ/จ่ายทั้งหมดก่อนแตะ DB → `ยอดยกมา = เป้าหมาย − เงินไหลตามแผน`
   (ค่าธรรมเนียม/WHT = 0 ทุกใบ เพื่อให้เงินสดเท่ากับยอดชำระเป๊ะ) แล้ว **อ่านกลับจาก `financeBalances` มา assert อีกชั้น**
6. **ยอดสุทธิบางค่าเป็นไปไม่ได้ในโหมดราคาแยก VAT** — `base + round(base×7%)` ข้ามบางเลข (เช่น 8,000,000 สตางค์)
   `docLines()` จึงแตกเป็น 2 บรรทัดให้ลงตัวแทน
7. 🐛 **บั๊กจริงที่เจอระหว่างทำ (ส่งต่อ WO 1.x)** — `gl.postDocument` เคส `PURCHASE`/`EXPENSE` เดบิตด้วย `line.amount`
   ซึ่งในโหมด **ราคารวม VAT (`vatMode: "INCLUDE"`)** คือยอด *รวม VAT* แล้ว แต่เครดิตเจ้าหนี้ด้วย `grandTotal`
   ⇒ Dr เกิน Cr เท่ากับ VAT → โพสต์ไม่ผ่าน (`ลงบัญชีไม่สมดุล: Σdebit 4794393 ≠ Σcredit 4500000`)
   ฝั่งขาย (INVOICE) ไม่พังเพราะใช้ `subTotal − discountAmount` (ฐานสุทธิ)
   ⇒ **ทุกวันนี้บันทึกซื้อ/ค่าใช้จ่ายแบบ "ราคารวมภาษี" ออกเอกสารไม่ได้เลย** · seed เลี่ยงด้วยการใช้ EXCLUDE ทั้งชุด
8. 🐛 **`/app/sys/<id>/account` ไม่มี `page.tsx`** (มีแต่ `layout.tsx`) ⇒ เปิดแล้ว 404
   แต่ `layout.tsx` มีลิงก์ `← ระบบบัญชี` ชี้ไปที่พาธนี้ = ลิงก์ตายบนทุกหน้าย่อยของบัญชี (เดสก์ท็อป)
   หน้าแรกจริงของระบบบัญชีคือ `/app/sys/<id>` (`SystemPage` → `AccountContent`) ⇒ `visual-acc-v2.mts` ใช้พาธนี้เป็น `hub`
   และเก็บ `account-root` ไว้เป็นหลักฐานภาพ 404 (ไม่นับเป็นข้อตก) · WO 0.2 ปิดไปแล้วแต่ยังไม่ได้แก้ข้อนี้ ⇒ ส่งต่อ **WO 0.4 (shell V2)**
9. **ข้อสอบเน่าตามเวลา** — `isOverdue()` อ่าน `Date.now()` ของเครื่อง ไม่ใช่ "วันนี้" ที่ตรึงไว้
   ⇒ ใบที่ตั้งใจให้พ้นกำหนดตั้ง dueDate ก.ค.–ส.ค. 2026 · ใบที่ยังไม่พ้นกำหนดตั้ง พ.ย.–ธ.ค. 2026
   `oracleValidUntil = 2026-10-31` อยู่ใน `acc-v2-expected.json` และมีข้อสอบ H1 คอยเตือน
10. **`visual-acc-v2.mts` มีทางถอยเรื่อง prisma** — ปกติใช้ `@/lib/core/db` (ตัวเดียวกับแอป) ซึ่งมี boot assert
    "ทุก model ใน schema ต้องอยู่ในทะเบียน `scope.ts`" · ระหว่างทำ WO 0.3 แก้ schema ค้างใน worktree เดียวกัน
    (schema มี `AccountContactGroup` แล้วแต่ client ยังไม่ generate) assert นี้โยน = สคริปต์ถ่ายภาพเดินไม่ได้
    ⇒ ถ้าโหลดไม่ได้ สคริปต์จะ **เตือนเสียงดังแล้วต่อ DB QC ตรง** เพื่อให้ถ่ายภาพจบ (กล้องไม่ควรถูกบล็อกด้วยเหตุนี้)
    `qc-acc-v2-seed-check.mts` **ไม่มีทางถอย** โดยตั้งใจ — มันต้องเรียก service จริงของแอปเท่านั้น
11. ⚠️ **worktree นี้ถูกใช้พร้อมกันหลาย WO** — ระหว่างทำ 0.1 มี WO 0.2/0.3 แก้ `service.ts` / `scope.ts` / schema อยู่ด้วย
    ผลคือ `next build` รอบแรกตกเพราะโค้ดของคนอื่น และ `tsx` โหลด db ไม่ได้อยู่ช่วงหนึ่ง
    ⇒ ถ้าเจออาการ `[scope] ลงทะเบียน model ที่ไม่มีใน schema` ให้รอ `prisma generate` ของ WO นั้นก่อน อย่าไปแก้ไฟล์เขา
12. **สคริปต์ทั้งชุดโหลด `.env.qc` ผ่าน `acc-v2-env.mts` เท่านั้น** · ด่าน: ไม่มีไฟล์ = ตาย · host มี `ep-royal-night` (prod) = ตาย · `APP_ENV≠development` = ตาย
    `import` แบบ static ที่ลงท้าย `.mts` typecheck ไม่ผ่าน (ไม่ได้เปิด `allowImportingTsExtensions`) ⇒ ใช้ `await import("./acc-v2-env.mts" as string)` แล้วประกาศชนิดเอง
