# T1.7 — "ยื่นแล้ว" มีผล (ภ.พ.30 + ภ.ง.ด.3/53) · ปิด E10 · G5

เลน 1 · branch session/account-fix · ต่อจาก T1.3 (`vatFiledState`) · ไม่บล็อกด้วยเหตุผลกฎหมาย (เตือน + ยืนยัน + บันทึกผู้ยืนยัน)

## ข้อเท็จจริงที่ออกแบบตาม
- ภ.พ.30 ของระบบคิดจาก GL ตาม `periodKey` ของรายการ (pp30-return) ⇒ "อะไรก็ตามที่เปลี่ยน VAT ของเดือน" = รายการ GL ที่ **ลงเดือนนั้น** และแตะบัญชีภาษี (mapping VAT_OUTPUT · VAT_INPUT · VAT_OUTPUT_UNDUE · VAT_OUTPUT_PENDING_INVOICE · VAT_INPUT_UNDUE)
- การยกเลิกเอกสาร/รับชำระกลับรายการ "ลงวันนี้" (G5) ⇒ ไม่แตะเดือนที่ยื่นแล้ว (ถูกต้องตาม ม.82/10 · §7) — ที่แตะคือ ออกเอกสารย้อนวันที่ · รับชำระย้อนวันที่ (ปล่อย VAT พัก) · JV มือลงเดือนนั้น · ใบกำกับซื้อที่ใช้สิทธิ์เดือนนั้น · ปล่อย VAT พักแบบลงวันที่ใบแจ้งหนี้
- ภ.ง.ด.3/53 คิดจาก "เอกสาร 50 ทวิ ฝั่งที่เราหัก (direction IN)" ตามวันที่ออก (wht.pnd) ⇒ ทั้งการออก 50 ทวิ ลงเดือนที่ยื่นแล้ว และ **การยกเลิก** 50 ทวิ ของเดือนนั้น (ยกเลิกจ่าย/เช็คเด้ง) เปลี่ยนรายการของเดือนนั้น

## 1. ด่านเดียวที่ชั้นลงบัญชี
- `gl.ts commitEntry` (คอขวดเดียวของทุกการลงบัญชี — ที่เดียวกับด่านงวดปิด/วันล็อก) เรียก `filedPeriodGuardInTx` (ไฟล์ใหม่ `filed-guard.ts`) หลังด่านงวดปิด:
  - บรรทัดแตะบัญชีภาษีตาม mapping (ไม่มี mapping → รหัสผังเริ่มต้น ทางเดียวกับ `vatLedgers`) และเดือนนั้นมี AccountVatFiling ที่ยังไม่ถูกยกเลิกเครื่องหมาย ⇒ คำเตือน `FILED_PERIOD_VAT_CHANGE` (ผลต่อภาษีขาย/ภาษีซื้อ/ยอดพัก)
  - บรรทัดแตะบัญชี WHT_PAYABLE และเดือนนั้นยื่น ภ.ง.ด.3 หรือ 53 แล้ว ⇒ `FILED_PERIOD_PND_CHANGE`
- 50 ทวิ ที่ถูกยกเลิกตามการยกเลิกจ่าย (`service.ts unwindPaymentInTx` — ทางเดียวของยกเลิกจ่าย/เช็คเด้ง ทั้งรับและจ่าย) และออก 50 ทวิ ตรง (`wht.ts`) เรียก `pndFiledGuardInTx` เดียวกัน
- การยืนยัน: บริบทเรียก (ambient · AsyncLocalStorage ใน `src/lib/core/legal-ambient.ts`) ถือรหัสที่ผู้ใช้ยืนยัน + ผู้ยืนยัน + ช่องทาง
  - มีบริบท + ยืนยันแล้ว ⇒ บันทึก AuditLog `legal.warning.ack` (T0.4 `recordLegalAckInTx`) ในธุรกรรมเดียวกับการลงบัญชี · ทำต่อ
  - มีบริบท + ยังไม่ยืนยัน ⇒ จดคำเตือนไว้ในบริบท แล้วโยน `LegalAckRequiredError` ในธุรกรรม (ยังไม่ได้เขียนอะไร) ⇒ ชั้นนอก (REST runner · server action · เครื่องมือเลขา) แปลงเป็นผลคำเตือนมาตรฐาน — แม้ service ชั้นกลางจะกลืน error เป็น `{ok:false, reason}` ก็ตาม (ตัวห่ออ่านคำเตือนจากบริบท)
  - **ไม่มีบริบท** (งานเบื้องหลัง: outbox POS · cron · ระบบอื่นที่ไม่มีคนกด) ⇒ ไม่บล็อก — ไม่มีใครให้ถาม · ยังปรากฏในรายการผลต่างหลังยื่น (ข้อ 2) เพราะรายการผลต่างอ่านจาก GL ไม่ได้อ่านจากบันทึกการยืนยัน
- ต่างจากงวดปิด (`assertPeriodOpen`) — งวดปิด = ความถูกต้องของข้อมูล ยังปฏิเสธเหมือนเดิม · ยื่นแล้ว = คำเตือน
- ช่องทาง: REST/AI = `runOpAsActor` ตั้งบริบทจาก `input.acknowledge` (op เขียนที่ลงบัญชีได้รับฟิลด์ `acknowledge` เพิ่ม) · จอ = server action ที่ลงบัญชีย้อนเดือนได้ ห่อด้วยบริบทจากช่อง `ack` ของฟอร์ม · ฟอร์มแสดงคำเตือนล่วงหน้า (ออกเอกสาร · รับชำระ · JV มือ · ปล่อย VAT พัก) เมื่อวันที่อยู่ในเดือนที่ยื่นแล้ว

## 2. รายการผลต่างหลังยื่น
- `filedPeriodDifferences(ctx, periodKey)`: รายการ GL ของเดือนนั้นที่ `createdAt` > เวลายื่นต้นฉบับ และแตะบัญชีภาษี — เอกสาร/ที่มา · ผลต่อภาษีขาย (เครดิตสุทธิ 2200) · ภาษีซื้อ (เดบิตสุทธิ 1150) · ยอดพัก · ใคร (ผู้ยืนยันจาก AuditLog ack ถ้ามี ไม่งั้นผู้ลงรายการ ไม่งั้น "ระบบ") · เมื่อไร · ยืนยันแล้วไหม
- ผลรวม = ผลต่างที่แบบเพิ่มเติม (T1.3) จะยื่น (ถ้ายื่นเพิ่มเติมแล้ว รายการหลังแบบเพิ่มเติมล่าสุดแยกให้เห็น)
- ภ.ง.ด.: 50 ทวิ (IN) ที่ออกลงเดือนนั้นหลังเวลายื่น + ที่ถูกยกเลิกหลังเวลายื่น
- แสดงบนหน้า ภ.พ.30 + REST `GET periods/{key}/filed-differences` (+ AI อ่านผ่าน REST เดียวกัน)

## 3. ยกเลิกเครื่องหมาย = เก็บประวัติ ไม่ลบแถว
- schema (additive): AccountVatFiling / AccountWhtFiling + `unmarkedAt` `unmarkedById` `unmarkReason`
- ยกเลิก = ตั้ง 3 ช่อง (แถว + ตัวเลขที่ยื่น + แบบเพิ่มเติมยังอ่านได้) · ทำเครื่องหมายใหม่ = ใช้แถวเดิม (unique systemId+periodKey) เขียนตัวเลขใหม่ — ภาพตัวเลขเดิมเก็บใน AuditLog ก่อนเขียนทับ
- ประวัติ = AuditLog `account.vat-filing.mark|unmark` / `account.wht-filing.mark|unmark` (ใคร · เมื่อไร · เหตุผล · ภาพตัวเลข) + อ่านผ่าน `filingHistory(ctx, kind, periodKey)` บนจอ/REST
- ตัวอ่านทุกตัว (vatFiledStates · checklist ปิดงวด · listVatFilings · wht list/validate) นับเฉพาะแถวที่ยังไม่ถูกยกเลิก
- ภ.ง.ด.: ยกเลิกยังล้างตราประทับ `whtFiledPeriodKey` ของ 50 ทวิ เหมือนเดิม (ตราประทับ = สถานะปัจจุบัน) · รายชื่อ 50 ทวิ ที่เคยประทับเก็บในภาพของ AuditLog
- เหตุผล: จอ/REST ขอ (ไม่บังคับที่ service เพื่อไม่ทำลายผู้เรียกเดิม · ว่าง = บันทึกว่าไม่ระบุ)
- ยังคงกติกา T1.3: มีแบบเพิ่มเติมแล้วยกเลิกเครื่องหมายต้นฉบับไม่ได้
