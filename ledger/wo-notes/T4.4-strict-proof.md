## 2. พิสูจน์แบบรันจริง — โหมด shadow
- `account_ledger_guard_mode()` = `'shadow'` (ฐานทดสอบเท่านั้น · ตั้งด้วย `scripts/acc-ledger-guard-mode.mts shadow` ผ่าน `loadQcEnv` ด่าน prod) — ด่านประเมินเหมือนโหมดเข้มทุกข้อ แต่ทุกคำสั่งที่ "จะถูกปฏิเสธ" ส่งเข้า `account_ledger_reject()` ซึ่ง **จดแถวลง `qc_ledger_guard_shadow` แล้วปล่อยผ่าน**: op · ตาราง · row id · คอลัมน์ที่เปลี่ยน · ข้อความ · `application_name` · `shark.qc_fixture` · `current_query()` · xid
- ตาราง log สร้างโดยสคริปต์เท่านั้น (ไม่มีใน migration) · ไม่มีตาราง ⇒ `account_ledger_reject` ปฏิเสธเหมือนโหมดเข้ม (fail closed: production ที่ถูกตั้งโหมดผิดก็ยังกัน) · ข้อสอบ G7.7–G7.10 ใน `qc-acc-v2-audit-trail`
- session ที่ `SET LOCAL shark.ledger_guard='strict'` = ปฏิเสธจริงเสมอ (ข้อสอบโหมดเข้มเดิมยังใช้ได้บนฐาน shadow)
- แยกที่มาของแถว: แต่ละชุดรันด้วย `PGAPPNAME=<ชื่อชุด>` · เซิร์ฟเวอร์ :3216 รันด้วย `PGAPPNAME=shark-server` (ทางคำขอจริง) · ฟิกซ์เจอร์ล้างร้านด้วย `DELETE FROM "<ตาราง>" WHERE "tenantId" = $1` / Prisma `deleteMany` — แอปไม่มี DELETE ใดบนตารางเหล่านี้นอกจาก purge (ตารางข้อ 1) ⇒ DELETE ทุกแถว = การล้างฟิกซ์เจอร์ (จำแนกด้วยข้อความคำสั่ง)
- ข้อจำกัด: แถว log อยู่ในธุรกรรมเดียวกับคำสั่ง — ธุรกรรมที่ rollback ภายหลังจะไม่ทิ้งแถว (คำสั่งนั้นไม่มีผลอยู่แล้ว)
- `qc-acc-v2-audit-trail` และ `qc-acc-v2-shop-delete` ไม่วิ่งในหน้าต่าง shadow (สองชุดนี้สลับฐานเป็น strict จริงเองแล้วคืน qc) — ทั้งสองรันแยกในโหมดปกติ และทางของระบบในช่วง strict ของมันคือหลักฐานโหมดเข้มจริง
- ผลรัน: ดู §5

## 3. ช่อง INSERT (ปิดแล้ว)
- AFTER INSERT ของหัวใบ จดรหัสลงค่าตั้งเฉพาะธุรกรรม `shark.ledger_new_entries` (64 ใบล่าสุด · `set_config(…, true)` — savepoint ที่ rollback คืนค่าเอง)
- BEFORE INSERT ของบรรทัด: `entryId` ต้องอยู่ในรายการนั้น ⇒ เพิ่มบรรทัดเข้ารายการที่ commit แล้ว (หรือแค่ถูกแก้ธง/กลับรายการในธุรกรรมนี้) = `LEDGER_GUARD: เพิ่มบรรทัดเข้ารายการที่ลงแล้วไม่ได้`
- เลือกแทน xmin: xmin ของหัวใบเปลี่ยนเมื่อถูก UPDATE (แก้ธงแล้วแทรกบรรทัดจะหลุด) และต้องแปลง xid ข้าม epoch · รายการ 64 ใบพอเพราะแอปสร้างบรรทัดต่อจากหัวใบทันทีเสมอ (nested create)
- ข้อสอบ G7.1–G7.6: SQL ตรง/Prisma create เข้า JV เก่า = ปฏิเสธ · แก้ธงแล้วแทรก = ปฏิเสธ · nested create = ยอม · สร้างแล้วแทรกทีหลังผ่าน savepoint = ยอม · savepoint ที่ rollback ไม่ค้างค่า · G3 (ทางจริงในโหมดเข้ม) ยังผ่าน
