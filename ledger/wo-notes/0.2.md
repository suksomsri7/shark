## A. ด่านสิทธิ์ระดับ page — เสร็จ ✅
**helper** `src/lib/modules/account/guard.ts`
- `loadAccountSystem(id, { can })` — เพิ่ม option (เดิมไม่มี · เรียกแบบเดิมยังได้เหมือนเดิมทุกอย่าง)
- `requireAccountPage(id, action)` — บรรทัดเดียวสำหรับหน้าที่ไม่ต้องใช้ ctx
- `ACCOUNT_PAGE_PERMISSIONS` — ทะเบียน route→action **แหล่งเดียว** (37 รายการ) ใช้เป็นเฉลยของด่านทดสอบ
- ไม่ผ่าน → `assertAccountCan` โยน `ForbiddenError` = พฤติกรรมเดียวกับหน้าที่มีด่านอยู่เดิม (ไม่คิดรูปแบบใหม่)

**ไฟล์ที่แก้ (23 ไฟล์)**
- เติม `{ can: … }` ให้ `loadAccountSystem` ที่มีอยู่แล้ว (15): `assets` `cheque` `contacts` `docs/[docType]`
  `docs/[docType]/[docId]` `documents` `finance` `finance/[financeId]/statement` `goods-issue` `print/[docId]`
  `products` `settings` `tax` `wht` `wht/[certId]/print`
- เติมด่านใหม่ทั้งบรรทัด (8 — เดิมไม่มีการตรวจใด ๆ ที่ชั้น page): `expense` `expense/[docId]` `purchase`
  `purchase/[docId]` `po` `po/[docId]` `asset-buy` `asset-buy/[docId]`
- ที่เหลือ 14 ไฟล์มีด่านอยู่แล้ว ไม่แตะ (`journal*` `ledger` `accounts` `periods` `reports/*` `aging` `tax/export`)

**การแมปสิทธิ์** — ระบบ **ยังไม่มี action ชนิด "read"** (permissions.ts:432-461 มีแต่ manage/view/create)
จึงแมปหน้าอ่านไปที่ action ที่ใกล้ที่สุด:
| กลุ่มหน้า | action | หมายเหตุ |
|---|---|---|
| เอกสารทุกชนิด (list/detail/print · รายรับ+รายจ่าย+PO+สินทรัพย์) | `account.doc.create` | หน้าเหล่านี้มีฟอร์มสร้างอยู่ในหน้าเดียวกันอยู่แล้ว |
| รายงาน + aging | `account.report.view` | ผ่าน `loadReport` เดิม |
| สมุดรายวัน/แยกประเภท | `account.journal.view` · JV มือ = `account.journal.adjust` | เดิม |
| ทะเบียน/ตั้งค่า | `.manage` ของหมวดนั้น | contact/product/document/finance/cheque/asset/chart/settings/wht/tax |
⚠️ ผลข้างเคียงที่ตั้งใจ: STAFF ที่เคย "ดูอย่างเดียว" โดยไม่มีสิทธิ์ใด ๆ ในโมดูลบัญชี จะเข้าหน้าไม่ได้แล้ว
(นี่คือรูรั่วที่ WO นี้สั่งปิด) · OWNER/MANAGER ไม่กระทบ

## C. listDocumentsPaged — เสร็จ ✅
- `listDocuments()` **คงเดิมทุกบรรทัด** (ยังไม่มี caller อื่นแล้ว แต่คงไว้ตามคำสั่ง) · ตัวใหม่ = `listDocumentsPaged()` แยกฟังก์ชัน
- รับ `{ docType, status, q, contactId, from, to, page, pageSize, sort, excludeOverdue }` คืน `{ rows, total, page, pageSize, pageCount, tabCounts }`
- `status` รับ `AccountDocStatus | AccountDocStatus[] | "OVERDUE" | "ALL"` — ที่ต้องรับ array + `excludeOverdue`
  เพราะแท็บเดิม "รอชำระเงิน" = (AWAITING_PAYMENT|PARTIAL) **และไม่พ้นกำหนด** ถ้ารับสถานะเดี่ยวอย่างเดียวจะเปลี่ยนพฤติกรรม UI
- `overdueWhere()` = เงื่อนไข SQL ที่ตรงกับ `isOverdue()` ทุกกรณี (รวมขา `AWAITING_ACCEPT` + `validUntil` ของใบเสนอราคา) — คิดใน DB ไม่ใช่ JS
- `tabCounts` = `groupBy(status)` 1 คำสั่ง + `count` ของ OVERDUE 1 คำสั่ง · นับบน where ที่ไม่รวมสถานะ ⇒ แท็บบวกกันได้เท่ากับ ALL
- pageSize ปริยาย 20 · เพดาน 100 · page/pageSize ต่ำกว่า 1 บีบเป็น 1
- `docs/[docType]/page.tsx`: เลิก `take: 500` + filter/sort ฝั่ง UI → ใช้ `?tab=&q=&page=` · หน้าตาคงเดิม
  เพิ่มเฉพาะ (ก) ช่องค้นหา 1 ช่อง (ลอกแบบจาก `documents/page.tsx` ที่มีอยู่แล้ว) (ข) แถบ "ก่อนหน้า/ถัดไป"
  ซึ่งจำเป็น ไม่งั้นแถวที่เกิน 20 เข้าไม่ถึง · การ redesign จริงอยู่ WO 1.1
