## 1. ลิ้นชักรายละเอียดบิล POS (จอ "บิล" → ลิ้นชัก)
- `BillDetail.lines[].vatTreatment` (ZERO_RATED | EXEMPT | ON_BEHALF · มาตรฐาน/บิลเก่า = ไม่มี) + `BillDetail.totals.vatGroups` (`storedVatGroups` ของ PosSale — ตัวเดียวกับใบเสร็จ)
- บรรทัด: ป้ายต่อท้ายชื่อแบบใบเสร็จ (`VAT_TREATMENT_MARK` — "(VAT 0%)" / "(ยกเว้น VAT)" / "(เก็บแทน)")
- ยอด: บิลผสม = แถวแบบใบเสร็จ (มูลค่าที่เสียภาษี + "รวม VAT 7%" เมื่อมียอดมาตรฐาน · ยอดขายอัตราร้อยละ 0 · ยอดขายที่ได้รับยกเว้น · เก็บแทน (ไม่ใช่มูลค่าขาย)) · บิลไม่มียอดเสียภาษี = ไม่มีแถว VAT · บิลเก่า = แถวเดิมทุกไบต์
- ข้อความ TH/EN ใน messages ของ POS (`pos.bills.drawer.*`) — คำเดียวกับใบเสร็จ

## 2. ตัวเลือกชนิด VAT ของ "รายการกำหนดเอง" บนจอขาย
- กล่อง CustomItemDialog: ตัวเลือก 4 ชนิด (ค่าเริ่มต้น = มาตรฐาน) · เลือก "เก็บแทน" ⇒ แสดงคำเตือน `VAT_COLLECTED_ON_BEHALF` จากทะเบียนกลาง (แบบแจ้ง เหมือนขายสินค้าที่ตั้งเก็บแทนไว้ — T1.8 §7) + ติ๊กยืนยันก่อนเพิ่ม (ไม่บล็อก: ติ๊กแล้วเพิ่มได้) · ไม่มีอะไรถูกเก็บถาวรนอกจากชนิดของบรรทัด (การยืนยันบันทึกที่บิลผ่าน audit ของ createSale — ไม่มีช่องทาง ack ของบิลใน T1.8 ⇒ บันทึกรหัสที่ยืนยันใน `PosSaleLine`? ไม่: ไม่เพิ่ม schema — บันทึกใน AuditLog ของบิลเมื่อมีบรรทัดเก็บแทนแบบกำหนดเอง (`pos.sale.onBehalfLine`) — **ดูข้อ 6 สิ่งที่ยังไม่ทำ ถ้าไม่ทัน**)
- ตะกร้า: บรรทัด custom มี `vatTreatment` → ส่งให้เซิร์ฟเวอร์ (register.ts รับอยู่แล้วตั้งแต่ T1.8) · ไม่ใช่มาตรฐาน = ยอดรอ quote ของเซิร์ฟเวอร์ (กติกาเดียวกับสินค้าไม่ใช่มาตรฐาน)
- บรรทัดในตะกร้าแสดงป้ายชนิด (เหมือนใบเสร็จ)

## 3. บิลวางบิล (ON_ACCOUNT · `posCreditInvoiceLayer`) ของบิลผสม
- บรรทัดใบแจ้งหนี้รับอัตราต่อบรรทัดจากชนิด (มาตรฐาน = อัตราสมุด · 0% = 0 · ยกเว้น = −1) + VAT ของใบ = VAT ของ JV (ถอดจากกลุ่มมาตรฐานเท่านั้น — ทางเดียวกับ ABB T1.8)
- บรรทัดเก็บแทน: ใบแจ้งหนี้ต้องเรียกเก็บยอดเต็ม (ลูกหนี้ 1100 ใน JV = ยอดบิลทั้งหมด · รับชำระจับคู่กับใบ) ⇒ คงบรรทัดไว้ในใบ **ผูกบัญชี COLLECTED_ON_BEHALF (2120) ที่ `accountId` + อัตรา −1 + ป้าย "(เก็บแทน — ไม่ใช่มูลค่าขาย)"** ·
  รายงานภาษีขาย (ต้นทาง PosSale) ตัดบรรทัดที่ผูกบัญชีเก็บแทนออกจากการแยกกลุ่ม (ฐานไม่เข้ายกเว้น) — skill §3: เก็บแทน "ไม่ใช่มูลค่าขาย" · ไม่มีที่อื่นอ่าน accountId ของเอกสารขายที่มาจาก POS (เอกสารนี้ไม่ลง GL เอง — JV เป็นของ PosSale)
- skill เงียบ: รูปแบบใบแจ้งหนี้ที่มีรายการเก็บแทน → ค่าเริ่มต้นระบบ = บรรทัดแยกมีป้าย (ไม่ซ่อนจากลูกค้า)

## 4. ยอดรวมฟอร์มเอกสารบัญชี (DocTotals) + ใบพิมพ์
- `computeDocTotals` คืน `rateGroups[]` (อัตรา · ฐาน · VAT) — อัตราจริงต่อบรรทัด (ไม่ระบุ = อัตราสมุด)
- ไม่มีบรรทัดเสียภาษี (ทุกบรรทัด 0%/ยกเว้น) ⇒ ไม่มีแถว "VAT 7%" (ไม่แสดง ฿0.00) · ใบผสม (มีกลุ่ม > 1 ที่ยอดไม่ 0) ⇒ แถวฐานต่อกลุ่ม: "มูลค่าที่เสียภาษี 7%" · "มูลค่าอัตราร้อยละ 0" · "มูลค่าที่ได้รับยกเว้น" แล้ว "VAT 7%"
- ใบพิมพ์ `/account/print/<docId>`: กติกาเดียวกัน (อ่านจากบรรทัดที่บันทึกแล้ว) · ใบรับมัดจำ/เอกสารที่ VAT 0 และไม่มีบรรทัดอัตราบวก = ไม่พิมพ์ "7%" ในคอลัมน์และแถว VAT (จอนอกข้อ 7 — แก้ใน T2.7 ด้วยตัวเดียวกัน)

## 5. ด่านเดือนที่ยื่นแล้ว (T1.7) กับ POS — step 0
- POS ลงบัญชีผ่านคิว (outbox) เสมอ · ตัวระบายคิวถูกปลุกจาก after() ของคำขอ ⇒ AsyncLocalStorage ของ `withLegalAck` (REST runner ห่อทุก op เขียน รวม /pos) ไหลไปถึง consumer
  ⇒ แก้ 2 ชั้น: (1) `drainOutbox` รัน consumer นอกบริบท (`outsideLegalAck`) (2) `filedPeriodGuardInTx` ถือ refType `PosSale` เป็นงานเบื้องหลังเสมอ (ไม่ถาม · ยังขึ้นใน "ผลต่างหลังยื่น")
- ข้อสอบ: posvat ข้อ F — ทำเครื่องหมายยื่น ภ.พ.30 เดือนปัจจุบัน แล้วขาย/คืนบิล POS ในบริบทยืนยันที่ไม่มีรหัส ⇒ ลงบัญชีครบ ไม่มีข้อผิดพลาด

## 6. ข้อสอบ (posvat เพิ่ม)
- A1 ลิ้นชัก: `getBillDetail` ของบิลผสมคืน vatTreatment ต่อบรรทัด + vatGroups ตรงเฉลยมือ · บิลเก่าไม่มีคีย์
- A2 รายการกำหนดเองชนิดยกเว้น/เก็บแทนผ่าน createSale → ยอดกลุ่มของบิลตรงเฉลยมือ
- A3 วางบิลบิลผสม → ใบแจ้งหนี้: อัตราต่อบรรทัด · VAT ใบ = VAT JV · บรรทัดเก็บแทนผูก 2120 · รายงานภาษีขายไม่นับเก็บแทนเป็นยกเว้น
- A4 `computeDocTotals` ยกเว้นล้วน ⇒ ไม่มีกลุ่มอัตราบวก · ผสม ⇒ ฐานต่อกลุ่มตรงเฉลยมือ
