**Findings**
- **F1 Medium (pool/availability)** `offline-sync.ts:243-324`. The interactive tx keeps its connection idle-in-transaction for the whole catalog walk, while every read goes through `db` (`:263` + `register.ts` `Promise.all(regChildViews(db…))` fan-out). With pg-adapter defaults (max 10, `connectionTimeoutMillis` 0, `core/db.ts:23`), ≥10 snapshot issues at once in one process (shop-wide reconnect, many tenants on 15-min timers) take all 10 connections as txs. Their nested reads then wait with no limit until the 120 s tx timeout fires ⇒ every DB call in that process, sales included, stalls for up to 120 s, then the snapshot returns INTERNAL. Below 10, each issue still holds 2+ connections. Smallest fix: cap in-flight issues per process (a module semaphore, e.g. ≤3, returning `BUSY` before `$transaction`), or run the walk on `tx` (cast to `RegDb`; the readers do not call `$transaction`).
- **F2 Medium (security, needs a controller ruling)** `LockScreen.tsx:194/257` → `use-offline-register.ts:264`. A verifier is written for **any** role that unlocks online, OWNER/MANAGER included. Their PIN is also the manager-approval PIN online (discount over cap · override). Anyone at the shared till can read the PBKDF2-310k hash of a 4–6-digit PIN from IndexedDB (devtools) and brute-force it offline in seconds to minutes on a GPU ⇒ they can approve their own over-cap discounts. Smallest fix: call `rememberUnlock` only when `r.role === "STAFF"`. Managers then cannot unlock offline; the copy already says "unavailable".
- **F3 Low** `use-offline-register.ts:98,144`. Flag-off and `DEVICE_REVOKED/NOT_FOUND` wipe only the snapshot. The PIN verifier stays in IDB indefinitely, and the `!enabled` wipe only runs when a snapshot exists. Fix: call `forgetOfflineUnlock(d)` unconditionally when `!enabled`, and in the revoke branch.
- **F4 Low (privacy)** `shifts/page.tsx:49`. Every manager load of the Shifts page ships up to 500 tenant members' name/**email** to the client, even with the flag off and no rows. Fix: load names only when the flag is on or rows exist, or have `listOfflineRejected` return display names for the rows it lists.
- **F5 Low** `RegisterScreen.tsx:1896-1925`. When an online `unknown` bill moves to the queue, `totals` come from the snapshot (`:1902`) but `payMethods`/`expectedGrandTotal` come from the online quote. Nothing checks Σ payMethods == `totals.grandTotalSatang`. A mismatch gives an inconsistent temporary slip (total ≠ paid), and the bill is parked at sync. The server stays safe (it recomputes, and the same key ⇒ DUPLICATE if it had committed). Fix: move the bill only when the sums are equal; otherwise leave it in `unknown`.
- **F6 Low** `use-offline-register.ts:131,169`. A refresh at a `priceValidUntil` edge is dropped silently when a fetch is already running (`snapBusy`) or gets RATE_LIMITED. If the replacement snapshot carries the same pvu string, the edge effect does not re-arm, so the next try is the 15-min tick. Result: up to ~15 min of `PRICES_EXPIRED` refusals after the grace window. It is a refusal, never a stale sale. Fix: schedule one retry at `snapNextAt`.
