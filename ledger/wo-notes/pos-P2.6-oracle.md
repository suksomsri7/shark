## CONTROLLER-DECISION (read first — the oracle encodes my proposal for each)
1. **Facade + signatures** — exactly the names table below. User-facing KDS functions are register-style `(ctx: RegisterCtx, actor: RegisterActor, input)` → `{ok:true,…} | {ok:false, code, message(th)}` (never throw). System functions take raw `(tenantId, unitId, …)`. `catalog.setAvailability` is register-style too (returns refusals, does not throw `CatalogError`) and sits on the `catalog` facade of `pos/index.ts` with `availabilityFor`.
2. **Round items of register/online rounds keep `saleId = null`, `settledAt = null`** (K1). The link is `RestaurantOrder.posSaleId`. Reason: P2.4's `pos.sale.voided` consumer unlinks items whose `saleId` = the voided POS sale; setting it on kitchen items would make two consumers fight over the same rows, and cooking ≠ billing (CD4).
3. **Every path into ACCEPTED creates the round in the same tx**: `acceptOrder`, auto-accept, and an ingest whose startStatus is ACCEPTED (MANUAL default per P2.8 CD2) — K7 checks the explicit accept (xmin) and the MANUAL default ingest (round exists). A PLATFORM accept sale (`sourceId` = order id) never gets a second round (heal requires `sourceId` null).
4. **Counts.** Station tab `openCount` = tickets on that board (state NEW/COOKING/READY). `kitchenBacklog` `open` = tickets NEW+COOKING (not yet ready) — this is the number auto-accept compares with `autoAcceptMaxOpen` (any station ≥ N ⇒ skip). `servedToday` counts SERVED tickets of the station (today's bizDate); `last.no` = dailyNo of the most recently served ticket.
5. **Ticket readyAt = max(item.readyAt)** over non-cancelled items; `avgMinutes` = `avgReadyMinutes` over tickets of the station with every item readyAt set (READY or SERVED), sentAt = round `createdAt`. Board `targetMinutes` (top-level) is free; per-ticket `targetMinutes` is pinned (R8).
6. **Printer keys are added only when present in the input**: `parsePrinterConfig(undefined|null|{}|{paper})` keeps exactly the 6 old keys (no `kitchenSlip`/`kitchenStationIds`); readers default absent ⇒ off/[]. This keeps `qc-pos-p1.10` PC1/G4 (exact key-set `eqCfg`) identical — ruling 8 + 15 (P3, L4). Alternative (defaults always present) needs an ORACLE-EDIT of p1.10 PC1/G4.
7. **`autoAcceptMaxOpen` writer = new `kdsSetAutoAcceptMax(ctx, actor, {maxOpen: int ≥ 1 | null})`** in `pos/kds.ts` (perm `restaurant.kitchen.pause`, writes through a restaurant `*InTx`/facade function). `menu.updateSetting` cannot take the new key: its signature is pinned by L1 (= p2.4 L3 table).

9. **`availabilityFor(tenantId, unitId, productIds)`** → `Record<productId, boolean>` (a `Map` is also accepted) using the same truth as `rowAvailable` (MENU live from `MenuItem`, others `unavailableUnitIds`).
