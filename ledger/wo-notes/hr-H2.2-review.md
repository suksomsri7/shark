### MAJOR-1 — Q-1 ruling: 8 engine refusals still collapse to generic `failed`
`src/lib/modules/hr/roster-board-shared.ts:88-105` (`ROSTER_MSG`) + `roster-board.ts:344` (`fail`).
Unmapped `ROSTER_TEXT` reasons the engine actually returns (grep of `RosterRefusal(`/`refuse(` in roster.ts):
`entryNotFound` ("ไม่พบกะนี้ในตาราง — กรุณารีเฟรช") · `entryChanged` · `employeeNotFound` · `range` · `rangeOrder` · `date` · `note` · `tooMany`.
(Also only theoretical through the custom-time path: `TIME_RULE_TEXT.shiftRange/shiftMidnight/badInstant`. `badDay` has the same bytes as `ROSTER_TEXT.date`, so mapping `date` covers it. `note` is unreachable — the core never forwards `note`.)
Scenario: two managers on the board; A removes a chip, B drags the stale chip → engine says `entryNotFound` → B sees "บันทึกตารางกะไม่สำเร็จ — กรุณาลองใหม่"; retrying can never succeed. The engine's own text ("…กรุณารีเฟรช") tells the user what to do.
Smallest fix: add 8 codes (e.g. `entryNotFound entryChanged employeeNotFound range rangeOrder date note tooMany`) to `ROSTER_MSG` with byte-identical th values, plus `hr.roster.msg.*` in th/en. `ROSTER_MSG_CODE_OF` is derived, so nothing else changes.
⚠ This needs an ORACLE-EDIT: `qc-hr-h2.2.mts:675` S2.3 asserts range > 31 days ⇒ `failed` and that `เลือกช่วงวัน` does not appear; `:59` `CODES` (used by S6 msg parity and X2.1 `:740` "refused with codes") is built from the oracle's `ENGINE_TEXT`. Both have to accept the wider list. S2.3 should switch to a thrown error or malformed input to keep its "failed" control.

### MEDIUM-1 — picker / entry-sheet writes can be sent twice
`roster-ui.tsx:765` (shift buttons), `:790-795` (custom time save), `:879` (change shift), via `run()` `:271-282`.
`run` has no in-flight guard, and the sheet stays open until the server answers. Scenario: the manager taps `เช้า` and then quickly `บ่าย` (correcting a mis-tap) → two `addEntry` calls → two entries in one cell, both unpublished. Tapping the same shift twice gives a confusing `dup` error after the first call already worked. (ConfirmDialog flows are safe: `useFormStatus` disables them. DnD/keyboard ops are queued, which is correct.)
Smallest fix: a `busy` ref/state in `RosterBoard`. `run` returns early while it is set, and the sheet buttons get `disabled={busy}`.

### MINOR
- m1 `roster-ui.tsx:219-226,263` — `suppressClick` is set on every active drop. It is cleared only by the next chip `click`. When the pointer is released over a different cell (the normal case), the browser sends the click to a common ancestor, not to the chip. So the user's next chip tap after a drag does nothing. Fix: clear it in a `setTimeout(0)` after `up`, or only set it when `e.target` is inside the source chip.
- m2 `roster-ui.tsx:338` — a non-past cell with a leave overlay and no entry gets no `+` button. Adding a shift on a leave day is then possible only by drag (not by tap at 390, not by keyboard). The brief says leave never blocks (ON_LEAVE info). This difference is not declared. Fix: drop the `!cell.leave` condition and render `+` under the leave chip.
- m3 `roster-ui.tsx:162-163` — chips with temporary ids (`tmp-opN`, copy not yet confirmed) can be dragged, opened or removed. The resulting server call carries `tmp-…` ⇒ `entryNotFound` ⇒ generic error and rollback. Fix: when `e.id.startsWith("tmp-")`, make the chip non-editable.
- m4 `roster-ui.tsx:102-107` vs `:148` — `unconfirmed` is filtered only after `await action`. If the revalidated `board` prop effect runs first, a copy op is re-applied on a board that already holds the real row, so a duplicate chip (same id after `confirmOp`) can show until the final `router.refresh()`. This depends on ordering and could not be verified without a browser. Fix: filter `unconfirmed` before `setLocal(confirmOp…)`, or make `applyOne(copy)` a no-op when `realId` already exists.
- m5 a11y: the sheets (`:652-688`) have no Esc close, no initial focus and no focus return to the chip/cell that opened them. Brief R11 asks for focus to stay on the moved chip. That is done for moves (`focusId`), not for sheets.
- m6 parity, not declared: the header desc lists `b.shifts.slice(0,4)`, so HQC also shows the night QC shift `ดึก 22–06` (mockup lists 3) (`:397`). The seed does not create the brief Q14 "แพร PENDING vacation Sat–Sun" leave (`seed-hr-qc.mts` §9d), so the dashed leave chip / `รออนุมัติ` will not appear in the 2.2 screenshots unless มิ้นท์'s leave happens to fall in the week (notes §6 hedge). Either add the leave or declare it in the notes.
- m7 `roster.ts` D-R3m path (`:855`) — the zero-candidate marker still goes through `writeAudit`, which swallows errors. Accepted by ruling 3 and declared in the notes. It is listed only so nobody reads A as covering it.
- m8 `removedSinceLastPublish` — the anchor comes from the app clock (`new Date()`), while `createdAt` of the removal audit comes from whichever process inserted it. Cross-instance clock skew of a few ms could misclassify a removal that lands within the skew window after the anchor. That is negligible, but worth a comment.
