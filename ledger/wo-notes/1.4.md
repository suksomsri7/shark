## 2. สิ่งที่พบจากการอ่านโค้ดเดิม (ก่อนแก้)

- `service.recordPayment` มีครบแล้ว: amount/wht/fee/สถานะ/`postPayment` (Dr เงิน + Dr 1160 + Dr 6500 / Cr 1100)

### ต่างจาก g2 โดยตั้งใจ (จดตามกติกา parity)
1. **ยังมี stepper + ส่วนหัว/รายการ/สรุปยอดของฟอร์มเต็ม** — g2 วาดเฉพาะบล็อก F แต่ SPEC §5.2 A/B/C/E บังคับให้ทุกฟอร์มมีครบ
   (g2 เป็นภาพ "โฟกัสส่วน F") ⇒ เก็บโครงเต็มไว้ แล้วเติมการ์ดหัวของ g2 เป็นบล็อกสรุปเพิ่ม
2. **มีช่อง "อัตรา %" แยก** จาก dropdown ประเภทเงินได้ (g2 วาด `ม.40(8) 3%` ในกรอบเดียว) — ต้องแก้อัตราเองได้ตาม SPEC §5.2 F
3. **เลขเอกสารภาษีถูกหัก ฝั่งขายใช้ prefix `WTI-`** ตาม g2 · **ฝั่งซื้อคง `WHT-` เดิม** (ไม่เปลี่ยนเป็น `WTO-`)
   เพราะเลขรัน 50 ทวิ ของ prod เดินมาแล้วด้วย prefix นี้ — เปลี่ยนกลางคัน = เลขเอกสารภาษีไม่ต่อเนื่อง
4. **เช็ค + ค่าธรรมเนียมธนาคารพร้อมกัน = ปฏิเสธ** (ยังไม่รองรับ) — เช็คพักที่ 1040 ยังไม่มีเงินเข้าธนาคารให้หักค่าธรรมเนียม
5. `paidTotal` ของ "ใบเสร็จที่ออกจากใบแจ้งหนี้" ยังเป็น 0 (เงินตัดที่ใบแจ้งหนี้) — สถานะใบเสร็จ = ชำระแล้ว ถูกต้องแล้ว
   แต่หน้าเอกสาร §5.3 ควรโชว์ยอดจากใบต้นทาง → ส่งต่อ WO 1.5

## 4. บั๊ก/ช่องโหว่ที่ปิดในใบนี้

1. 🔴 **ใบเสร็จที่แปลงจากใบแจ้งหนี้เคยลง JV ซ้ำ** — `gl.postDocument case RECEIPT` โพสต์ "ขายสด"
   (Dr เงิน / Cr รายได้ / Cr 2200) ทั้งที่ IV ตั้งลูกหนี้+รายได้+VAT ไปแล้ว ⇒ **รายได้และภาษีขายถูกนับ 2 เท่า**
   แก้: ถ้า RECEIPT มี `sourceDocId` เป็น INVOICE → ข้ามการโพสต์ (เงินลงผ่าน `postPayment` ของ IV แทน) · ด่าน P1.15
2. 🔴 **ยกเลิกการรับ/จ่ายเงินของใบมัดจำ ไม่กลับ JV** (หนี้จาก 1.2 §8.1 · มีทั้ง 2 ขา) — JV ของใบมัดจำผูกกับ
   *ตัวเอกสาร* (`AccountDocument#id#ISSUE`) ไม่ใช่ payment ⇒ เงินสด + หนี้มัดจำค้างในบัญชีตลอดไป
   แก้: `voidPayment`/`voidVendorPayment` กลับรายการเอกสารด้วยเมื่อใบมัดจำอยู่สถานะ AWAITING_DEDUCT · ด่าน P7.10–P7.14
3. 🔴 **โพสต์ใหม่ไม่ได้หลังกลับรายการ** — คีย์ `…#ISSUE` ถูกใช้ไปแล้ว ⇒ รับเงินมัดจำรอบ 2 จะถูก `alreadyPosted`
   กลืนเงียบ ๆ (เงินเข้าแต่ไม่ลงบัญชี) แก้ด้วย event `ISSUE:R<n>` ตามจำนวนครั้งที่กลับรายการ · ด่าน P7.15–P7.17
4. 🔴 **ยกเลิกการรับชำระไม่ยกเลิกใบภาษีถูกหัก** ⇒ เครดิตภาษี 1160 หายจาก GL แต่ใบยัง ISSUED · ด่าน P7.8–P7.9
5. 🔴 **ใบ WTI (ถูกหัก) หลุดเข้า ภ.ง.ด.3/53** — `wht.pnd` เดิมกวาด WHT_CERT ทุกใบ ไม่ดู direction
   ⇒ พอมีใบฝั่งขายเกิดขึ้น จะกลายเป็น "ภาษีที่ต้องนำส่ง" ทั้งที่เป็นเครดิตของเรา แก้ด้วย `direction: "IN"` · ด่าน P1.34 / P4.21
6. **ยกเลิกรับเงินมัดจำที่ถูกหักไปแล้ว** และ **คืนมัดจำใบที่ถูกหักแล้ว** = ปฏิเสธ (กันมัดจำติดลบ) · ด่าน P7.22
7. **กันบันทึกซ้ำ**: `idempotencyKey` ต่อ payment + ตรวจ **ก่อน** ด่านสถานะ (ยิงซ้ำหลังเอกสาร PAID ต้องคืนผลเดิม ไม่ใช่ error) · P8
