## 2. ข้อมูล (schema เพิ่มอย่างเดียว · migration `20261230000000_acc_t18_pos_vat_treatment` · ฐานของเลนนี้เท่านั้น)
- enum `PosVatTreatment { STANDARD ZERO_RATED EXEMPT ON_BEHALF }`
- **สินค้า: ใช้ช่องเดิม `PosProduct.vatRateBp`** (สำเนาจาก `AccountProduct.vatRateBp` · 0 = 0% · −1 = ยกเว้น · null/บวก = มาตรฐาน = อัตราของสมุดตอนขาย) + ช่องใหม่ `PosProduct.collectedOnBehalf Boolean @default(false)` (เก็บแทน — ชนะ vatRateBp)
  · ชนิดที่จอ = `productVatTreatment({vatRateBp, collectedOnBehalf})` ตัวเดียว · สินค้าที่ผูกคลัง/สมุด: อัตรามาจากสมุด (กติกาเดิม — แก้ที่ระบบบัญชี) แต่ธงเก็บแทนตั้งที่ POS ได้
- `PosSaleLine.vatTreatment PosVatTreatment?` — สำเนาตอนขาย · **null = บิลเก่า/ผู้เรียกที่ไม่ส่ง = มาตรฐาน**
- `PosSale.zeroRatedSatang / exemptSatang / onBehalfSatang Int @default(0)` — ยอด (รวมในราคา · หลังเกลี่ยส่วนลดระดับบิล) ของแต่ละกลุ่ม · ใบ REFUND = ส่วนที่คืน
  · ยอดที่เสีย VAT = `grandTotal − zero − exempt − onBehalf` · ฐาน = ยอดที่เสีย VAT − `vatSatang` ⇒ **บิลเก่า (0/0/0) อ่านเหมือนเดิมทุกสตางค์**

## 3. ตัวคิด (บริสุทธิ์ · `src/lib/money/vat-lines.ts` · pos และ account ใช้ตัวเดียว)
`splitBillVat({ lines:[{lineTotal, treatment}], serviceCharge, grandTotal, rateBp })`:
1. ส่วนลดระดับบิล D = Σ lineTotal + ค่าบริการ − grandTotal (ท้ายบิล + คูปอง + สิทธิ์สมาชิก) → เกลี่ยแบบ largest remainder ตามยอดบรรทัด **ยกเว้นบรรทัดเก็บแทน (น้ำหนัก 0 — ลดไม่ได้)** · ส่วนที่เกิน Σ บรรทัดที่ลดได้ไปลดค่าบริการ (กติกาเดิม P5.1 MA1) ⇒ ไม่มีบรรทัดเก็บแทน = `lineNets` เดิมเป๊ะ
2. ค่าบริการ = กลุ่มมาตรฐาน (ค่าบริการของร้าน — skill ไม่ได้พูดถึง ⇒ เลือกแบบไม่แปลกใจ: เสีย VAT ตามอัตราร้าน · ไม่คิดจากบรรทัดเก็บแทนบนจอขาย)
3. กลุ่ม: มาตรฐาน = Σ net บรรทัดมาตรฐาน + ค่าบริการสุทธิ · 0% · ยกเว้น · เก็บแทน
4. VAT = `splitIncludedVat(ยอดกลุ่มมาตรฐาน, อัตรา)` (สูตรเดิม · ครั้งเดียวต่อกลุ่ม) · กลุ่มอื่น VAT 0
5. ผลรวมตรวจ: Σ net + ค่าบริการสุทธิ = grandTotal เสมอ · zero + exempt + onBehalf + ยอดมาตรฐาน = grandTotal
- ผู้ใช้: `createSale` (เก็บ vatSatang + 3 ยอด) · ใบคืน `refund.ts` · สะพานบัญชี `pos/account-bridge.ts` · `account/index.ts applyExternalSale/applyExternalRefund` · ตัวคิดราคาบนจอ `pricing-shared.ts priceCart`
- มัดจำ (P2.9b): VAT ของบิล = VAT กลุ่มมาตรฐาน − VAT ของมัดจำที่ใช้ (กติกาเดิม แต่ฐานเป็นกลุ่มมาตรฐาน)

## 4. ใบคืน / ยกเลิก
- บรรทัดใบคืนคัดลอก `vatTreatment` จากบรรทัดเดิม · ยอดคืนต่อบรรทัด = สูตรเดิม (net จากข้อ 3.1)
- VAT ใบคืน (บิลที่มีกลุ่มอื่น > 0): ใบที่ทำให้ครบ = VAT ที่เหลือ · บางส่วน = min(VAT ที่เหลือ, ส่วนของยอดมาตรฐานที่คืน — อัตราเดิมถ้ายังถอดได้ตรง ไม่งั้นตามสัดส่วน) · บิลมาตรฐานล้วน = ทางเดิมทุกไบต์
- ใบคืนเก็บ 3 ยอดของส่วนที่คืน · ยกเลิกบิล = กลับ JV ทั้งก้อน (ทางเดิม — ถูกเองเพราะ JV ขายแยกถูกแล้ว)

## 5. ลงบัญชี (facade `account/index.ts` · ไม่แตะ reports.ts / sales-tax-report.ts / pp30)
- `applyExternalSale` รับ `lines[].vatTreatment` (ไม่ส่งทุกบรรทัด = ทางเดิมทุกไบต์): VAT = ตัวคิดข้อ 3 จากบรรทัด (ยอดหลังเกลี่ย) · Cr 2200 เฉพาะกลุ่มมาตรฐาน · รายได้ = ยอด − เก็บแทน − VAT (0%/ยกเว้นเข้ารายได้ปกติ)
  · **เก็บแทน → Cr บัญชีตาม mapping ใหม่ `COLLECTED_ON_BEHALF`** (ผังใหม่ `2140 เงินรับแทนบุคคลอื่น (เก็บแทน)` · LIABILITY) — ไม่ใช่รายได้ ไม่อยู่ในฐาน VAT
  · เอกสาร (ABB / TAX_INVOICE เต็มรูปจากบิล): บรรทัด 0% = vatRateBp 0 · ยกเว้น = −1 · **บรรทัดเก็บแทนไม่อยู่ในเอกสารบัญชี** (ยอดเอกสาร = ยอดขาย ไม่รวมเก็บแทน) + หมายเหตุ "เก็บแทน ฿x นอกมูลค่าขาย" · VAT เอกสาร = VAT ของ JV (ส่ง `vatSatang`)
  ⇒ รายงานภาษีขาย T1.1 + ภ.พ.30 T1.3 (`rateGroupsOf` อ่านอัตราต่อบรรทัด + VAT จาก GL) ได้กลุ่ม 7% / 0% / ยกเว้น ถูกโดยไม่ต้องแก้ตัวรายงาน
- `applyExternalRefund` (ใบลดหนี้ของใบคืน) แบบเดียวกัน: Dr 2140 ส่วนเก็บแทนที่คืน · ใบลดหนี้มีอัตราต่อบรรทัด ไม่มีบรรทัดเก็บแทน
- ใบกำกับเต็มรูปที่ขอทีหลัง (`supersedeAbbWithTaxInvoice`) คัดบรรทัดจาก ABB เดิม ⇒ อัตราต่อบรรทัดตามไปเอง (ตรวจในข้อสอบ)
- ผู้ขายอื่นที่ใช้ทางขาย POS (โรงแรม/หอพัก/บริการ) ไม่ส่งชนิด ⇒ null ⇒ ทางเดิมทุกไบต์ · ไม่แตะตัวตรวจกฎหมายของโมดูลเหล่านั้น

## 6. ใบเสร็จ / ใบกำกับอย่างย่อ (จอ · 80 มม. HTML + ESC/POS · หน้าใบเสร็จลูกค้า /r/<token>)
- ท้ายใบ (เมื่อบิลมีกลุ่มอื่น > 0): "มูลค่าที่เสียภาษี" + "ภาษีมูลค่าเพิ่ม 7%" (เฉพาะเมื่อมียอดมาตรฐาน) · "ยอดขายอัตราร้อยละ 0" · "ยอดขายที่ได้รับยกเว้นภาษีมูลค่าเพิ่ม" · "เก็บแทน (ไม่ใช่มูลค่าขาย)"
  · บิลไม่มีบรรทัดเสียภาษีเลย: **ไม่พิมพ์ "VAT 7% ฿0.00"** · บิลเก่า/มาตรฐานล้วน = แถวเดิม
- ต่อบรรทัด: ป้ายต่อท้ายชื่อ "(VAT 0%)" / "(ยกเว้น VAT)" / "(เก็บแทน)" เฉพาะบรรทัดที่ไม่ใช่มาตรฐาน (checklist E11)
- ชนิดใบ: เดิมใบที่ VAT = 0 เป็น "ใบเสร็จรับเงิน" (P1.13 F1) — คงเดิม (บิลยกเว้นล้วนไม่ออกเป็นใบกำกับ)

## 7. คำเตือน (ทะเบียนกลาง · ต่อท้ายรายการเท่านั้น)
- `VAT_COLLECTED_ON_BEHALF` [V] · ack: true — ตั้งสินค้าเป็น "เก็บแทน" (ฟอร์มสินค้า POS · REST สินค้า) ต้องกดยืนยัน · ข้อความ = 4 ข้อของ §3 + ภาษีซื้อของรายจ่ายที่ทดรองใช้เป็นภาษีซื้อของร้านไม่ได้ · อ้าง กค 0706/พ./625 ฯลฯ
- ขายบรรทัดเก็บแทน: จอขายแสดงคำเตือนเดียวกันแบบแจ้ง (สินค้าถูกยืนยันไว้แล้วตอนตั้ง) — ไม่บล็อก
- รายงาน: ยอดเก็บแทนต่อเดือน = บรรทัด "เก็บแทน (นอกยอดขาย)" ในรายงานยอดขายของ POS + ยอดเคลื่อนไหวบัญชี 2140 ในสมุดบัญชี

## 9. ที่ skill ไม่ได้บอก → เลือกแบบไม่แปลกใจ (ค่าเริ่มต้นระบบ)
- ค่าบริการ (service charge) ของบิลที่มีของยกเว้น = เสีย VAT อัตราร้าน · คิดจากบรรทัดที่ไม่ใช่เก็บแทน
- ปัดเศษต่อกลุ่มอัตราของบิล (ไม่ปัดต่อบรรทัด) — [U] §20
- ส่วนลดระดับบิล/คูปอง/สิทธิ์สมาชิก ไม่ลดบรรทัดเก็บแทน (skill: "ลดไม่ได้") · ส่วนลดที่เกินยอดที่ลดได้ = ปฏิเสธบิล (VALIDATION)
- ป้ายต่อบรรทัดบนใบย่อ — skill ไม่กำหนดรูปแบบ ⇒ ข้อความสั้นในวงเล็บ
- ร้านไม่จด VAT: ชนิด 0%/ยกเว้นไม่มีผล (ไม่มี VAT อยู่แล้ว) · เก็บแทนยังลง 2140 (ไม่ใช่รายได้)
- ยังไม่ทำ (งานต่อ): ที่แนบหลักฐานการจ่ายต่อบรรทัดเก็บแทน · คำเตือนยอดเก็บแทนไม่ตรงต้นทุนจริง (POS ไม่มีต้นทุนจริงของรายการ)
