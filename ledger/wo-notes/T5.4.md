## 1. สิ่งที่สร้าง

### 1.1 ตารางค่ากฎหมาย e-Tax (`SYSTEM_ETAX_TS_ROWS` ใน `th-tax-2569.ts` · แสดงในการ์ดตั้งค่า พร้อมที่มา/ป้าย/วันที่ตรวจ)
`ETAX_TS_CC_ADDRESS` csemail@etax.teda.th · `ETAX_TS_MAX_BYTES` 3,000,000 · `ETAX_TS_TO_MAX` 1 · `ETAX_TS_DOCS_PER_MAIL` 1 · `ETAX_TS_FILE_FORMAT` PDF/A-3 · `ETAX_TS_SUBJECT_DATE` DDMMYYYY พ.ศ. · `ETAX_TS_VALIDATION_URL` https://validation.teda.th
— ร้านทับได้: ที่อยู่สำเนาถึง · รูปวันที่ในหัวเรื่อง (ค่าที่ต่างจากตาราง = คำเตือน SHOP_DIFFERS_FROM_DEFAULT)

### 1.2 ค่าตั้ง (เครื่องยนต์ค่าตั้ง · ชั้นสมุดบัญชี · กลุ่ม "e-Tax")
`account.etax.tsEnabled` (ปิด) · `account.etax.tsAutoOnIssue` (ปิด) · `account.etax.tsSenderEmail` · `account.etax.tsCcAddress` (ว่าง = ตามตาราง) · `account.etax.tsSubjectDateFormat` · `account.etax.tsEligibility` (UNDECLARED / LISTED = ร้านยืนยันเองว่าได้รับประกาศรายชื่อและแจ้งอีเมลแล้ว — ระบบตรวจกับกรมฯ ไม่ได้)

### 1.3 ไฟล์ PDF (`etax-pdf.ts` · ตัวสร้างหลังอินเทอร์เฟซ `EtaxPdfGenerator`)
- ข้อมูล = `loadPrintView` (ข้อมูลพิมพ์ที่ตรึงตอนออก T2.9 · ใบเดียวกับหน้าพิมพ์) → `pdfkit` (มีอยู่แล้วในล็อกไฟล์ผ่าน @react-pdf — เพิ่มเป็น dependency ตรง) โหมด `subset: "PDF/A-3b"` = XMP `pdfaid:part 3 / conformance B` + OutputIntent sRGB + ฝังฟอนต์ Sarabun (SIL OFL 1.1 · มีในโปรเจกต์) แบบ subset · ไม่มีรหัสผ่าน · ไม่มีหัวกระดาษ/ปุ่มของเว็บ · ตัดบรรทัดไทยด้วย Intl.Segmenter วัดความกว้างจริง
- **สถานะความสอดคล้อง PDF/A-3**: เครื่องนี้ไม่มีตัวตรวจ PDF/A (veraPDF) และระบบห้ามเรียกเครือข่ายตอนทดสอบ ⇒ ตรวจได้แค่โครงสร้าง (XMP part/conformance · OutputIntent · ฟอนต์ฝังครบ · ไม่เข้ารหัส · ข้อความไทยถอดกลับได้) — **ไม่อ้างว่าผ่าน PDF/A-3** · ทุกความพยายามส่งเก็บข้อความ `pdfConformance` และคำเตือน ETAX_TS_PDFA_NOT_VALIDATED [S]

### 1.4 ช่องทางส่ง (`etax-transport.ts` · อินเทอร์เฟซ `EtaxMailTransport`)
- นอก production (`APP_ENV` ≠ production) **ทุกครั้ง** = `CAPTURE` (ไม่ยิงเครือข่าย · เก็บหัวจดหมาย/ไฟล์ในแถวความพยายาม) — แม้มีกุญแจ Resend
- production: ต้องส่ง **จากอีเมลที่ร้านแจ้งกรมฯ** (ข้อ 5(2)) — อีเมลกลางของแพลตฟอร์ม (Resend โดเมน shark.in.th) ส่งในนามกล่องอีเมลของร้านไม่ได้จนกว่าโดเมนของร้านจะยืนยันกับผู้ให้บริการส่ง ⇒ ค่าเริ่ม `NONE` = บันทึกความพยายามเป็น "ล้มเหลว: ยังไม่มีช่องทางส่งจากอีเมลที่ร้านแจ้ง" · เปิด Resend ได้เมื่อ env `ETAX_TS_TRANSPORT=resend` (เจ้าของแพลตฟอร์มยืนยันโดเมนผู้ส่งแล้ว) — **ยังไม่ทดสอบกับระบบจริง**

### 1.5 สถานะบนเอกสาร (คำนวณจากแถวล่าสุด · ไม่แตะ `AccountDocument.etaxStatus`)
ยังไม่ส่ง · รอส่ง (QUEUED) · ส่งแล้ว รอไฟล์ประทับเวลา (SENT) · ได้ไฟล์ประทับเวลาแล้ว (STAMPED — ร้านอัปโหลดไฟล์ที่ระบบตอบกลับ · เก็บไบต์ + sha256 · ระบบไม่อ่านลายเซ็นในไฟล์) · ล้มเหลว + เหตุ (FAILED)
+ สถานะแจ้งให้ทราบ: ชนิดเอกสารไม่อยู่ในประกาศ · ผู้ซื้อไม่มีอีเมล · ผู้ซื้อไม่มีเลข 13 หลัก · ยกเลิกแล้ว (ใบใหม่ส่งแทน)
- ส่งซ้ำ = แถวใหม่ (attemptNo+1) · "ส่งไฟล์ประทับเวลาซ้ำให้ผู้ซื้อ" (ข้อ 7) = ถึงผู้ซื้อคนเดียว ไม่สำเนาระบบประทับเวลา แนบไฟล์ประทับเวลาเดิม
- ใบที่ยกเลิก (VOIDED/CANCELLED) ส่งไม่ได้ (ไม่ใช่เหตุผลกฎหมาย — ใบไม่มีผลแล้ว) · ใบที่ออกแทนใบที่ส่งแล้ว: หัวเรื่อง `[..][INV][ใหม่][เดิม]` + คำเตือน ETAX_TS_REPLACE_DATE ถ้าวันที่เท่าใบเดิม (ข้อ 6 ให้ลงวันที่ใบใหม่)
- ทุกการกระทำลงประวัติเอกสาร (AuditLog `account.etax.ts.*`) + รอยกดยืนยันคำเตือน (`legal.warning.ack`)
- อัตโนมัติตอนออก: event `account.document.issued` → ถ้าเปิดค่าตั้ง + ชนิดตรง + มีอีเมลผู้ซื้อ + ร้านยืนยันสิทธิ์แล้ว = ส่ง (ไม่ยืนยัน = ไม่ส่งอัตโนมัติ · ไม่ถามแทนร้าน)

### 1.6 ไฟล์ที่เก็บ
ตาราง `AccountEtaxFile` (bytea + sha256 · trigger ห้ามแก้) — **ไม่ใช้ storage กลาง (Bunny) ในงานนี้**: เป็นการเรียกเครือข่ายภายนอกที่ห้ามในชุดทดสอบ และไฟล์ภาษีควรอยู่กับสมุดในฐานข้อมูล (สำรองพร้อมกัน) — ย้ายไป storage ส่วนตัวภายหลังได้หลังอินเทอร์เฟซเดียวกัน

### 1.7 จุดต่อขยายผู้ให้บริการ (e-Tax Invoice & e-Receipt)
การ์ด "ผ่านผู้ให้บริการ" ปิดไว้ "ต้องมีคีย์ผู้ให้บริการ" · ใช้ทะเบียน `platform/etax/provider.ts` เดิม (ทุกตัว NOT_CONFIGURED) · ไม่มีพฤติกรรมปลอม

## 4. ผลจริง / สิ่งที่ยังไม่ใช่ของจริง
- จริง: สร้าง PDF ฝั่งเซิร์ฟเวอร์ (pdfkit · ไม่มีเบราว์เซอร์) · หัวเรื่อง/ผู้รับ/สำเนา/ไฟล์แนบตามประกาศ+คู่มือ · บันทึกความพยายาม + ไฟล์ + sha256 · สถานะบนเอกสาร · อัปโหลดไฟล์ประทับเวลา · ส่งไฟล์ประทับเวลาซ้ำ · อัตโนมัติตอนออก (outbox) · ประวัติเอกสาร + รอยยืนยัน
- ไม่ใช่ของจริง: **ไม่มีการส่งอีเมลจริง** ในทุกสภาพแวดล้อมที่ทดสอบ (CAPTURE) · production ค่าเริ่ม = ไม่มีช่องทาง (NONE → FAILED พร้อมเหตุ) · ทาง Resend ยังไม่เคยทดสอบกับระบบประทับเวลา · ระบบไม่อ่าน/ตรวจลายเซ็นเวลาในไฟล์ที่อัปโหลด · ไม่รับอีเมลตอบกลับอัตโนมัติ
- PDF/A-3: **ไม่ได้ผ่านตัวตรวจมาตรฐาน** — ตรวจได้เฉพาะโครงสร้าง (pdfaid 3/B · OutputIntent sRGB · ฟอนต์ฝังครบ + ToUnicode · ไม่เข้ารหัส) · ไม่ได้ทำ: ฝัง XML · tagged PDF · ตรวจ veraPDF / validation.teda.th
- ข้อความไทย: สระอำแตกเป็นนิคหิต+สระอา ก่อนวาง (หน้าตาเหมือนเดิม) ⇒ คัดลอกข้อความได้ถูก (NFKC) · ลำดับวรรณยุกต์ใน `pdftotext -layout` เพี้ยนได้ (`-raw` ถูก)
