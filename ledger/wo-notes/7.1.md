- **ไม่สร้างไฟล์ `attachments.ts` ใหม่ตามชื่อใน WO** — ขยาย `src/lib/modules/account/attachment.ts` (ไฟล์เดิม, ใช้ raw `prisma` อยู่แล้ว, นับใน fitness F5.1 baseline ไปแล้ว) แทน เพื่อไม่แตกโมดูลซ้ำซ้อน (listAttachments/createAttachment/moveAttachment เดิมอยู่ที่นี่แล้ว, doc-detail.ts พึ่งอยู่แล้ว) — ไม่เพิ่มไฟล์ใหม่ที่แตะ prisma (F5.1 ไม่ขยับ)
- upload orchestration (อ่าน FormData/File → uploadFile() storage → createAttachment) อยู่ที่ชั้น action (`documents/actions.ts` เดิม) ตาม pattern เดียวกับ `uploadDocAttachmentAction` ใน editor-actions.ts — ไม่ยัด next/File เข้า attachment.ts
- storage: Bunny จริงเปิดอยู่แล้วบน `.env.qc` (`SHARK_BUNNY_ZONE/KEY/CDN` ตั้งครบ) — ไม่ต้องทำ local-disk fallback
- docTypeHint: เก็บเป็น string อิสระ — ถ้าผูกเอกสารแล้ว คำนวณป้ายจาก `editorDefOf(linkedDocType)` (side+label จริง) เสมอ (ไม่ใช้ hint ที่ตั้งไว้ตอนยังไม่ผูก) · ถ้ายังไม่ผูก ใช้ hint ที่ตั้งเอง/เดา (ค่าที่รองรับ: "REVENUE"|"EXPENSE"|"GENERAL" หรือรหัส AccountDocType ตรง ๆ ถ้าระบุเจาะจง)
- status: UNLINKED (default, documentId=null) → LINKED (documentId ตั้ง) → NOT_ACCOUNTING (ผู้ใช้บอกว่าไม่ใช่เอกสารบัญชี) → ARCHIVED (ลบนุ่ม) — เปลี่ยนได้ทุกทิศทางผ่าน action เฉพาะ
- ผูก/แยก/เปลี่ยนประเภท/ย้ายโฟลเดอร์/ลบ = client component เดี่ยว `DocumentRowMenu.tsx` (ต่อแถว, ถือ state modal เอง) + `AttachmentLinkCell.tsx` (คอลัมน์เอกสารที่ผูก, dropdown 2 ทาง "สร้างบันทึกค่าใช้จ่าย"(ลิงก์ prefill `?attachmentId=`) / "แนบกับเอกสารที่มีอยู่"(เปิด modal ค้นหา)) — bulk ย้ายโฟลเดอร์/ลบ ผ่าน `DocTableSelectionAction` → query param `?bulkIds=&bulkOp=` → modal ยืนยันที่หน้าอ่าน searchParams (pattern เดียวกับ `MarkFiledModal` WO 5.4)
- seed: ไม่สร้างเอกสารใหม่ที่กระทบยอด — ผูกไฟล์กับ EXP ใบแรกของ OPEN_BILLS (สยามแก๊ส ค่าอากาศอัด ก.ค. 45,000.00 — บันทึกค่าใช้จ่าย, docType EXPENSE) ที่มีอยู่แล้ว (แก้ 2 บรรทัดให้ capture doc.id กลับมาเป็น fixtures.firstOpenBillId เฉย ๆ ไม่กระทบเลขอื่น) + ผูกอีกไฟล์กับ fixtures.invNattapholId (IV เดิม) · เพิ่มผู้ใช้พนักงานคนที่ 2 ("นภา") เป็น STAFF membership สำหรับโชว์ผู้อัปโหลดคนละคน (ไม่กระทบตัวเลขบัญชี)

`RowActions.tsx`/`DocMoreMenu.tsx` เปลี่ยนไปเรียก `PortalMenu` แทนการวาด `absolute` เองในที่เดิม — ยังคง testid/

**บั๊กที่เจอระหว่างเขียน (2 ตัว) + แก้แล้ว:**
- (ก) **`mounted` gate ทำเมนู "เปิดจริงแต่มองไม่เห็น"**: โค้ดแรกมี `useState(false)` + `useEffect(setMounted(true))`
  ก่อน `createPortal` (คิดว่าต้องกัน SSR) — แต่คอมโพเนนต์นี้ mount เฉพาะตอนคลิกฝั่ง client เท่านั้น ไม่มีทาง render
  บนเซิร์ฟเวอร์เลย ⇒ การ์ดนี้ไม่จำเป็นและเป็นบั๊กจริง: รอบ render แรก (`mounted=false`) คืน `null` (ไม่มี
  `<div ref={menuRef}>` ให้จับ) → `useLayoutEffect` (deps ว่าง) รันครั้งเดียวตอนนั้น เจอ `menuRef.current=null` แล้ว
  return ทิ้งเงียบ ๆ (ไม่ setStyle) → พอ `mounted=true` render รอบ 2 มี div จริงแล้ว แต่ `useLayoutEffect` ไม่รันซ้ำ
  อีก (deps ว่าง) ⇒ เมนู "เปิด" จริง (ข้อความอยู่ใน DOM จริง ผ่านด่านตรวจ innerText) แต่ค้างตำแหน่งเริ่มต้น
  `top:-9999px;left:-9999px` ตลอดไป (มองไม่เห็นบนจอ/ในภาพ) — จับได้ด้วยสคริปต์ debug ชั่วคราว (เขียน+ลบทิ้งแล้ว
  ไม่ commit) ที่ dump `getAttribute("style")` ของเมนูหลังคลิก — แก้โดยเอา `mounted` ออกทั้งหมด
- (ข) **`resize` ปิดเมนูเองตอนถ่ายภาพเต็มหน้า**: ตอนแรกปิดเมนูทุกครั้งที่มี `resize` (ตั้งใจให้ถูกต้องตามหลัก UX
  ทั่วไป) — แต่ `puppeteer` `page.screenshot({fullPage:true})` ขยาย viewport แนวตั้งชั่วคราวก่อนกดชัตเตอร์เสมอ ⇒
  ยิง `resize` event จริง ⇒ เมนูที่เพิ่งเปิดถูกปิดเองก่อนถ่ายภาพทุกครั้ง (พิสูจน์บั๊กด้วยภาพไม่ได้เลย) — แก้โดยปิด
  เมื่อ "ความกว้าง" เปลี่ยนเท่านั้น (บันทึก `window.innerWidth` ตอนเปิด เทียบตอน resize) เพราะการขยาย viewport ของ
  fullPage screenshot เปลี่ยนแค่ความสูง ไม่เปลี่ยนความกว้าง ส่วนการหมุนจอ/ปรับหน้าต่างจริงมักเปลี่ยนทั้งคู่จึงยังปิดถูก
- (ค) **overflow มือถือ 4px ใหม่ (StatusTabs เป็น flex item)**: หลังเพิ่ม pill badge หน้าคลังเอกสารมือถือเกิด
  ล้นแนวนอน 4px (เดิม 0px) — สาเหตุ: แถว `flex` ที่มี `StatusTabs` + ปุ่ม list/grid toggle อยู่ด้วยกัน ทำให้
  `StatusTabs` เป็น flex item ที่มี `min-width:auto` ปริยาย (ไม่ยอมหดต่ำกว่าความกว้างเนื้อหาแท็บเลื่อนแนวนอนของมัน
  เอง) ⇒ ดัน parent ให้กว้างเกิน viewport แทนที่จะปล่อยให้แท็บ scroll ในตัวเอง (`overflow-x-auto` ของ StatusTabs
  เองใช้งานไม่ได้เพราะ parent ดันกว้างไปก่อน) — แก้ด้วย `min-w-0` บน root div ของ `StatusTabs.tsx` (defensive เฉย ๆ
  ไม่กระทบหน้าที่ไม่ได้วาง StatusTabs ในแถว flex)
