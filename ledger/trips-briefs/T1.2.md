## 3. ตัวช่วยบริสุทธิ์ `departure-view-core.ts` (ข้อสอบเรียกตรง)
```ts
export const DEPARTURE_CELL_STATES = ["CANCELLED","PAST","DEPARTED_TODAY","FULL","CLOSED","BELOW_MIN","GUARANTEED","LOW","OPEN"] as const; // ลำดับ = ลำดับตัดสิน
export type DepartureCellState = (typeof DEPARTURE_CELL_STATES)[number];
export function departureCellState(
  d: { status: string; capacity: number; sold: number; held: number; reserved: number; minPax: number | null; localDate: string; startsAt: Date | string },
  c: { now: Date; today: string; lowAtOrBelow: number | null },
): DepartureCellState
export function calendarWeekDays(start: string): string[]        // 7 วันต่อกัน (ข้ามเดือน/ปีได้) · start ผิดรูป ⇒ []
export function calendarMonthDays(month: string): string[]       // "YYYY-MM" → ทั้งสัปดาห์ที่ครอบเดือน เริ่มวันจันทร์ (28–42 วัน) · ผิดรูป ⇒ []
export function defaultWeekStart(today: string): string          // = today − 1 วัน (ภาพ 11: ดู ณ พฤ. 12 แสดงตั้งแต่ พ. 11)
```
ตารางตัดสิน (บนลงล่าง ตัวแรกที่จริงชนะ) — `left = publicLeftOf(d)` · `started = startsAt ≤ now`:
1. `status = CANCELLED` ⇒ `CANCELLED` (แม้ผ่านแล้ว)
2. `started` ⇒ `localDate = today` ? `DEPARTED_TODAY` ("ออกเรือแล้ว" :19) : `PAST` ("เดินทางแล้ว" :18)
3. `left ≤ 0` ⇒ `FULL` (**จากตัวนับ** — สถานะ OPEN ที่ที่นั่งหมดก็เต็ม · สถานะ FULL ที่ยังมีที่ ⇒ ไม่เต็ม ไปข้อถัดไปโดยถือว่า OPEN)
4. `status = CLOSED` ⇒ `CLOSED`
5. สถานะ (FULL ที่ยังมีที่ถือเป็น OPEN) `= OPEN` ∧ `minPax ≠ null` ∧ `sold < minPax` ⇒ `BELOW_MIN` (**ก่อนเวลาตัดสินก็นับ** — ภาพ :23 :31 :39 ณ 12 พ.ย. · ธง "เลยเวลาตัดสิน" = `needsDecision` แยก)
6. `status = GUARANTEED` ⇒ `GUARANTEED`
7. `lowAtOrBelow ≠ null` ∧ `lowAtOrBelow > 0` ∧ `left ≤ lowAtOrBelow` ⇒ `LOW` ("เหลือ N" :22)
8. ที่เหลือ ⇒ `OPEN` ("เปิดขาย" :24)
- `lowAtOrBelow` = ค่าตั้ง `trips.public.showLeftAtOrBelow` (ทะเบียน · resolve ที่ {unit, product}) — **ห้ามตัวเลขในโค้ด**
- ไฟล์นี้ไม่มี I/O · ไม่อ่านนาฬิกาเครื่อง (`now` มาจากผู้เรียก) · ห้าม `getDay/getDate/getHours/getMonth/getFullYear` แบบเวลาเครื่อง (ใช้ UTC ของวันที่ล้วน หรือ `utcToLocal`)

## 6. ต่ำกว่าขั้นต่ำ: `decideBelowMin` (`departure-desk.ts` · ส่งออกทาง facade)
`decideBelowMin(ctx, input, opts?) → { ok: true, decision, status } | { ok: false, code, message, … }`
- input strict: `{ unitId, departureId, decision: "RUN" | "CANCEL" | "MERGE", reason?: string (trim 3–500 · **บังคับเมื่อ CANCEL**), targetDepartureId?: ID (**บังคับเมื่อ MERGE** · ห้ามส่งเมื่อไม่ใช่) }` — ผิด ⇒ `INVALID_INPUT`
- ด่าน: `gateUnit(ctx, unitId, "status")` ของ T0.3 (ลำดับด่านเดียวกัน · ไม่มี `departure.status` ⇒ `FORBIDDEN`)
- อ่านรอบ (หน่วยนี้ · ไม่มี ⇒ `NOT_FOUND`) → ต้องเป็น BELOW_MIN ตามตาราง §3 ณ `now` (OPEN ∧ minPax ∧ sold < minPax ∧ ยังไม่เริ่ม) ไม่งั้น `NOT_BELOW_MIN` (ไม่เขียน)
- `RUN` ("ออกขาดทุน") ⇒ `setDepartureStatus(ctx, { unitId, departureId, status: "GUARANTEED" }, opts)` — รหัสของ T0.3 ส่งต่อตามเดิม
- `CANCEL` ⇒ `cancelDeparture(ctx, { unitId, departureId, reason }, opts)` — มีคน ⇒ `HAS_BOOKINGS` ของ T0.3 (ไม่เปลี่ยนอะไร)
- `MERGE` ("รวมรอบ"):
  1. `used = sold + held + reserved > 0` ⇒ `MERGE_NEEDS_BOOKINGS` (ไม่เขียน · ข้อความ "รวมรอบที่มีคนจองต้องย้ายการจอง — เปิดใช้เมื่อมีระบบการจอง (T1.6)")
  2. เป้า: หน่วยอื่น/ไม่มี ⇒ `NOT_FOUND` · ไม่ผ่านกติกาเป้า §4.2 (วันเดียวกัน · ไม่ใช่ตัวเอง · state ที่รับได้ · ยังไม่เริ่ม) ⇒ `MERGE_TARGET_INVALID`
  3. `cancelDeparture(ctx, { unitId, departureId, reason: "รวมรอบกับ {ชื่อไทยของเป้า} {HH:MM}" + (" · " + reason ถ้ามี) ตัดที่ 500 }, opts)` — เป้าไม่ถูกแตะ · event/audit มาจากบริการ T0.3
- รหัสใหม่ `DEPARTURE_DESK_ERROR_CODES = ["NOT_BELOW_MIN","MERGE_NEEDS_BOOKINGS","MERGE_TARGET_INVALID"]` (+ รหัสของ T0.3 ส่งผ่าน) · ทุกรหัสมีข้อความไทยในบริการ + `errors.<CODE>` ใน messages สองภาษา
- พร้อมกัน: 10 คำขอ CANCEL รอบเดียว ⇒ สำเร็จ 1 ที่เหลือ `NOT_BELOW_MIN|FORBIDDEN_TRANSITION|BAD_STATE|BUSY` · RUN กับ MERGE ชนกัน ⇒ ไม่ throw · ผลสุดท้าย GUARANTEED หรือ CANCELLED · ตัวนับไม่เปลี่ยน (ยอมรับ: RUN แล้ว CANCEL ที่ผ่านด่านก่อนหน้าได้ทั้งคู่ เพราะ T0.3 ยอม GUARANTEED → CANCELLED — จดใน wo-notes)
- ไม่มี event ใหม่ (ใช้ `trips.departure.status_changed` / `.cancelled` ของ T0.3) · การ์ดงานบนบอร์ดร้านตาม CC §J.2 `trips.minPaxCheck` = **หนี้ X.2** (ใบนี้ไม่แตะ kanban)
