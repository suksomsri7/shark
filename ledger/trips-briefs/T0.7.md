## 0. ขอบเขต — และทำไมใบนี้ต้องแยก (T0.7a ทำตอนนี้ · T0.7b รอเจ้าของ)

**ใบสั่งนี้ทำตามคำตอบเจ้าของ 13 พ.ย. 2569 (OQ17 · OQ9 · OQ12 ฉบับใหม่บน `session/trips` — ข้อความใน worktree นี้ยังเป็นฉบับเก่า):** (ก) **POS ไม่อนุญาต** — T0.7 ไม่แก้ POS และไม่พึ่งการรับมัดจำ/งวดผ่าน POS · เอกสารเงินของทริป (ใบรับมัดจำ/งวด · ใบกำกับ · ใบลดหนี้) ออกผ่านบัญชี V2 · เงินสดหน้าร้านของทริปอยู่นอกลิ้นชัก/กะ POS (หนี้ N-4 คงอยู่ — ใบนี้เปิดข้อมูลกระทบยอด §6.5) (ข) ตัวรับของโรงแรม = L1.9 เท่านั้น ไม่เกี่ยวใบนี้ (ค) route ไฟล์กลาง = อนุญาตให้ T0.8 · ใบนี้อ้างไฟล์ด้วย id อย่างเดียว ไม่แก้ route
**POS อยู่นอกขอบเขตจนกว่าเจ้าของสั่งเป็นอย่างอื่น — ไม่มีใบใดของ T0.7 ที่รอ POS**

**ข้อสรุปการแยก (แกนบัญชี):** facade บัญชี V2 วันนี้ **ไม่มี** ทางออกเอกสารรับเงินที่มีบรรทัดเงินเก็บแทนนอกฐาน VAT แบบหนี้สิน ไม่มีใบรับมัดจำที่ไม่ผูก POS และไม่มีใบลดหนี้อ้างใบรับของทริป (หลักฐานทีละข้อ §2.2) · การเพิ่มฟังก์ชันที่ขาดต้องเขียน JV + ผังบัญชีแบบ lazy (CC :762) ซึ่งใช้ตัวช่วยภายในของ `account/gl.ts` — ระบุได้แค่ "รูปฟังก์ชัน facade ที่ต้องการ" (§21 · รอผู้คุมตัดสิน) แต่ไม่ปลอดภัยพอจะสั่งสร้างในใบเดียวกับเงินฝั่ง trips ⇒ **แยกบนแกนบัญชี: T0.7a (ใบนี้) = สมุดเงินฝั่ง trips · สถานะ · คำนวณ/บันทึกยกเลิกและคืนเงิน · event · ข้อมูลเอกสาร ‖ T0.7b (ใบอนาคต §21) = เอกสารบัญชี V2 + JV + ตัวรับสลิป** · T0.7a จดทุกแถวเงิน `postingStatus = 'UNPOSTED'` ให้ T0.7b ออกเอกสารย้อนด้วยคีย์เดิม (CC :740 "ไม่มีสมุด… ออกเอกสารย้อนเมื่อผูกสมุด (คีย์เดิม)") · ถ้าผู้คุมไม่อนุญาตฟังก์ชัน facade ใหม่เลย ทางสำรอง = เอกสารออกภายหลังด้วยมือในบัญชี V2 จากข้อมูล `tripMoneySummary` + event `trips.payment.received`/`trips.refund.done` (ไม่ต้องแก้ T0.7a)

## 16. ค่าคงที่ (ทุกข้อมีข้อสอบลบ)
1. ต่อการจอง: `paidSatang = Σ RECEIVED.amount` · `refundedSatang = Σ REFUNDED.amount` · `paidSatang ≤ payable` · Σ `TripPaymentDue.paidSatang` (ทุกแถว) = `paidSatang` · `Σ REFUNDED + Σ RETAINED = paidSatang` เมื่อ CANCELLED ด้วยคำขอคืนเงิน
2. ต่อใบรับ: `amount = vatable + pt` · `vat = receiptVatSatang(vatable)` · REFUNDED+RETAINED ของใบนั้น = ใบนั้นทุกช่อง · tender กลุ่มเดียวกัน
3. ต่องวด: `0 ≤ paidSatang ≤ amountSatang` · Σ pt ของ RECEIVED ของงวด ≤ `passThroughSatang` และ = เมื่อ PAID · สถานะตรงกับยอด

5. คำขอเปิดไม่เกิน 1 ต่อการจอง · ยอดคืนไม่เกินที่รับ (ต่อใบ · ต่อกลุ่ม tender · รวม) · ทุกแถวเงิน `postingStatus 'UNPOSTED'`
