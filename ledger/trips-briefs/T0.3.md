## 2. เวลาและเขตเวลา (🔴)
1. เขตเวลาร้าน = `BusinessUnit.settings.timezone` (ว่าง/ผิด ⇒ `Asia/Bangkok` แบบ `normalizeTimezone`) · ไม่มีค่าตั้งเขตเวลาใน TD
2. เก็บ `startsAt` `endsAt` `cutoffAt` เป็น UTC · `localDate` = วันของร้าน (@db.Date) **ตั้งครั้งเดียวตอนสร้าง ไม่เปลี่ยนตลอดชีวิตแถว** — แก้เวลาใช้ `departTimeMin` (นาทีจากเที่ยงคืนของ `localDate`) ⇒ ข้ามวันไม่ได้ (ย้ายวัน = T1.2/T0.6) · เปลี่ยนเขตเวลาร้านภายหลังไม่แก้แถวเดิม
3. `localToUtc(tz, ymd, minutes)`: Bangkok = บวกลบ 7 ชม. (แบบ `bkkAt`) · เขตอื่น = Intl (รองรับ DST) · เวลาที่ไม่มีจริง (ช่วงกระโดด DST) ⇒ เลื่อนไปข้างหน้าเท่าช่วงกระโดด · เวลาซ้ำ (ช่วงย้อน) ⇒ ตัวแรก (แบบ Temporal `compatible`)
4. วันในสัปดาห์จาก `"YYYY-MM-DD"` ด้วย `Date.UTC(...).getUTCDay()` · **ห้าม** `getDay getDate getHours getMinutes getMonth getFullYear setHours` (ตัวอ่านตามเครื่อง) ในไฟล์ของใบ
5. "วันนี้" ของร้าน = `utcToLocal(tz, now).ymd` · `now` มาจากผู้เรียก (งาน/ข้อสอบส่ง `opts.now`) · action ไม่รับ `now`

## 4. ค่าคงที่ (ทุกข้อมีข้อสอบลบ)
1. **ผังสถานะรอบ** (CC §G ไม่มีตารางรอบ ⇒ ใบนี้กำหนด · §11 ข้อ 1):
| จาก → ถึง | ผู้กระทำ | เงื่อนไข |
|---|---|---|
| OPEN → GUARANTEED | STAFF · SYSTEM (`runMinPaxCheck`: ถึงเวลาตัดสินและ `sold ≥ minPax`) | `startsAt > now` |
| GUARANTEED → OPEN | STAFF | `startsAt > now` |
| OPEN/GUARANTEED/FULL → CLOSED | STAFF ("ปิดรับจอง") | — |
| CLOSED → OPEN | STAFF | `startsAt > now` |
| OPEN/GUARANTEED → FULL · FULL → OPEN/GUARANTEED | SYSTEM เท่านั้น (T0.4 · และ §4 ข้อ 4) | STAFF ขอ ⇒ FORBIDDEN_TRANSITION |
| ทุกสถานะยกเว้น CANCELLED → CANCELLED | STAFF ผ่าน `cancelDeparture` เท่านั้น | **ไม่มีที่ใช้อยู่** (§4 ข้อ 5) |
| CANCELLED → ใด ๆ · CLOSED → GUARANTEED | ไม่มี | FORBIDDEN_TRANSITION |
   ทุกการเปลี่ยน = CAS `UPDATE … SET status=$to, version=version+1 WHERE id AND tenantId AND unitId AND status=$from AND version=$v` · 0 แถว ⇒ อ่านซ้ำแล้วคืน BAD_STATE/FORBIDDEN_TRANSITION (ไม่ throw) · event + audit ใน tx เดียวกัน
2. **ขอบเขต (X1)** ตามแบบ T0.2 §4 ข้อ 1: ข้ามร้าน/หน่วย/ไม่มีสิทธิ์เข้าหน่วย ⇒ NOT_FOUND (ข้อความเดียวกับ id ที่ไม่มี) · หน่วยไม่ใช่ TRIPS ⇒ UNIT_NOT_TRIPS · id ลูก (สินค้า ตัวเลือก กฎ รอบ ทรัพยากร) ต้องเป็นของหน่วยที่ส่ง · SQL ดิบใส่ `"tenantId"` + `"unitId"` เองทุกคำสั่ง
