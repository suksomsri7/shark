## 4. `tokens.ts` — กุญแจและแฮช
- `SESSION_SECRET` อ่าน **ตอนเรียก** · ไม่มี/ยาว < 32 ⇒ `BUSY reason SERVER_KEY_MISSING` ทุกสภาพแวดล้อม (ไม่มีกุญแจสำรอง)
- `agentAuthHash(label, data) = "v1:" + hex(HMAC-SHA256(K_label, data))` · `K_label = HMAC-SHA256(SESSION_SECRET ดิบ, "shark:agent-auth:v1:" + label)` (ข้อสอบคำนวณเอง)
| label | data | ใช้ที่ |
|---|---|---|
| `login-target` | อีเมล normalize | `AgentLoginCode.target` |
| `login-code` | `${codeId}:${code}` | `AgentLoginCode.codeHash` |
| `session` | token เต็ม (รวม `ag_`) | `AgentSession.tokenHash` |
| `invite` | token | `AgentAccount.inviteTokenHash` |
| `ip` · `ua` | ค่าดิบ | `AgentSession.ipHash` `uaHash` |
| `rate` | ค่าดิบ | ส่วนท้ายคีย์ rate limit (ไม่มีอีเมล/IP/clientKey ดิบในคีย์) |
| `email-tag` | อีเมล normalize | เทียบอีเมลคำเชิญ (ร้าน + เพื่อน) |
- token session = `"ag_" + base64url(randomBytes(32))` (46 ตัว · `AGENT_SESSION_TOKEN_RE`) — แบบ `cs_` `cp_` ของ `customer-session.ts:41,558` · ไม่ตรงรูป ⇒ ปฏิเสธก่อนแฮช
- token เชิญของร้าน = `base64url(HMAC-SHA256(K_"invite-token", tenantId + ":" + agentAccountId + ":" + inviteExpiresAt.getTime()))` (ส่งซ้ำด้วยคีย์เดิมได้ token เดิม · ออกใหม่ = token ใหม่ · เบี่ยงจาก CC J.3.2 "สุ่ม" ตามแบบ T0.6 — บันทึกใน CC §5.8)
- รหัสล็อกอิน = `randomInt(0, 1_000_000)` 6 หลัก
- token เพื่อนร่วมทีม (ไม่มีตาราง): `P.S` · `P = base64url(JSON {v:1, i: identityId, r: role, b: AgentUser.id ของผู้เชิญ, m: agentAuthHash("email-tag", email).slice(3,27), e: หมดอายุ unix วินาที, n: 16 ไบต์สุ่ม})` · `S = base64url(HMAC-SHA256(K_"teammate-token", P))` · ตรวจ timing-safe · `now` ของผู้เรียก · อายุ `teammateInviteTtlMin` (48 ชม.) · **ตอนใช้**: ผู้เชิญ `b` ยัง ACTIVE + ตัวตนเดียวกัน + บทบาท **ปัจจุบัน** ให้ `r` ได้ (OWNER เชิญ OWNER · OWNER/ADMIN เชิญอื่น) ไม่งั้น `INVITE_INVALID` (มติ R1 ข้อ 9)
- **ห้าม**: token/รหัส/อีเมล/แฮช ลง event · audit · ops log · ข้อความ error · console

### 5.2 ขอรหัส (`requestAgentLoginCode`) — ไม่มี oracle ว่ามีบัญชี

### 5.3 ยืนยันรหัส · session · ประตู
- **ยืนยัน**: rate limit `agent:verify:c:` (`verifyPerClient`) + `agent:verify:k:<codeId hash>` (`verifyPerCode` · fail closed) · `target` ต้องตรง · **คำสั่งเดียว** `UPDATE "AgentLoginCode" SET attempts = attempts + 1 WHERE id = $1 AND "usedAt" IS NULL AND attempts < $max AND "expiresAt" > $now RETURNING "codeHash"` ⇒ 0 แถว/แฮชไม่ตรง = `INVALID_CODE` · ถูก ⇒ ใน tx เดียว: `SET "usedAt" = $now WHERE id = $1 AND "usedAt" IS NULL` (ต้อง 1 แถว) **+ `SET "usedAt" = $now` ให้รหัสอื่นที่ยังไม่ใช้ของ target เดียวกัน** (มติ R1 ข้อ 2) · ล้มทุกแบบ = รหัส/ข้อความเดียวกัน

### 5.4 `clientKey` (มติ R1 ข้อ 5 · บทเรียน T0.8)
1. บริการตรวจ `AGENT_CLIENT_KEY_RE` (`^[A-Za-z0-9_:.-]{8,128}$`) ไม่ตรง ⇒ `VALIDATION` · ไม่ใช่ตัวตนที่เชื่อถือ · บริการไม่รับ IP/อีเมลดิบในช่องนี้
2. **A1.2b สร้างที่เซิร์ฟเวอร์เท่านั้น**: หลัก = `"d:" + agentAuthHash("rate", deviceId)` · `deviceId` สุ่มจากเซิร์ฟเวอร์ในคุกกี้ httpOnly `__Host-shark_agent_dev` (ตั้งตอน GET หน้าล็อกอิน · อายุ 1 ปี) · สำรอง (ไม่มีคุกกี้) = `"ip:" + agentAuthHash("rate", IP)` ลำดับหัว `x-real-ip → x-vercel-forwarded-for → x-forwarded-for[0]` · ไม่มีทั้งคู่ ⇒ ปฏิเสธ (`RATE_LIMITED`) **ห้ามถัง "unknown" ร่วม** · ห้ามมาจาก body/query/หัวที่ไคลเอนต์ตั้ง
3. ถังต่อเครื่อง = ความเป็นธรรมเท่านั้น · การป้องกันจริง = ต่ออีเมล (`codePerTarget` + `codePerTargetDay`) + ต่อรหัส (`codeMaxAttempts` + `verifyPerCode`) + ถังต่อ IP **60 ครั้ง/ชั่วโมง** (`codePerIp`)
### 5.5 คุกกี้ (สัญญาของ A1.2b · มติ R1 ข้อ 4)
