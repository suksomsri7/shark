### 7.3 ผลของการเปลี่ยนสถานะ
- CAS ได้ 1 แถว ⇒ ok · 0 แถว ⇒ อ่านใหม่: สถานะปัจจุบัน = ปลายทางของ action นี้ (+ reason ตรง) ⇒ `{ ok, replayed: true }` (ไม่มี audit/event ซ้ำ) · อื่น ⇒ `BAD_STATE` (ไม่เขียน)

## 8. ร้านมองไม่เห็นร้านอื่น — กติกาที่ข้อสอบตรวจทุกข้อ (ร้าน A กับ B · ตัวตน X สมัครทั้งสองร้าน)
1. DTO/รายการของ A ไม่มีค่าใดของ B (ชื่อ · อีเมลติดต่อ · เลขใบอนุญาต · id บัญชี · tenantId · สมาชิกที่อยู่แค่ B) และไม่มีคีย์ใน `NEVER_SHOW_TO_SHOP_KEYS`

3. รหัสผิดพลาด/ข้อความที่ A ได้ไม่ขึ้นกับสถานะของ X ที่ B (เชิญด้วยรหัส X ที่ร้าน D = ผลชุดคีย์เดียวกับตัวตนใหม่) · เชิญด้วยอีเมลไม่แตะตาราง global
4. event/audit ของ A: payload `{ agentAccountId }` เท่านั้น · audit `after` ⊂ `{ from to reason actorKind fields idem body }` ไม่มีชื่อ/อีเมล/เบอร์/เลขภาษี/token/รหัส · ops log ไม่มีอีเมล/token/รหัส/ชื่อ
5. ผู้ใช้เอเจนซี่เห็นเฉพาะร้านที่ตัวเองเป็นสมาชิก active · ประตูของร้านที่ไม่ใช่สมาชิก = ผลเดียวกับร้านที่ไม่มีจริง
6. ตาราง global อ่าน/เขียนเฉพาะใน `agency/entry.ts` + `platform/agent-auth.ts` (F17.1) · `accounts.ts` ได้แค่ข้อมูลที่ entry.ts คืน (ชื่อแสดง · สถานะ · รหัสสาธารณะ) — ระวัง F17.1: ห้ามเขียน property ชื่อ `.agentUser` `.agentSession` ฯลฯ ในไฟล์อื่น

## 9. ผู้ใช้และบทบาท (ตัวช่วยใหม่ใน `entry.ts` · ส่งออกทาง facade)
