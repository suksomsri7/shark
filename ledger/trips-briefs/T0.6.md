- tx: ชั้น 0 INSERT `SellBasket` (OPEN · channel · `unitIds` · `publicTokenHash` = sha256hex(token) สำหรับ PUBLIC · `expiresAt` = เวลาหมดช้าสุดของ hold · `idempotencyKey` = คีย์ namespace ของ hold `pub:/st:` · `requestHash` = `holdRequestHash(คำขอ canonical)`) → PUBLIC: `acquireHoldCapInTx({capKey, mode:"HOLDS", add: จำนวนบรรทัด, limit: policies.holdCap})` → `assertProductSellableInTx` ทุกสินค้าไม่ซ้ำ **เรียง id** → `reserveInTx(HOLD)` ทีละแถวตาม `sortCapacityRows` → `insertHoldInTx` ต่อบรรทัด (คีย์ `${idempotencyKey}_${i}` · `basketId` · ต้องตามหลัง reserveInTx(HOLD) ของรอบ/จำนวนเดียวกัน) → 2h
- ซ้ำคีย์เดิม + คำขอเดิม = คืน Hold เดิม · คำขอต่าง = `IDEMPOTENCY_CONFLICT` · token ที่เคยใช้กับตะกร้าอื่น = `VALIDATION BASKET_TOKEN_USED` · `holdIds` เรียงตามบรรทัด · `expiresAt` = ช้าสุด
### 5.4 `confirmTrips(ctx, req, opts)` → `BookingRef[]` (`tripSellable.confirm`) — ลำดับในธุรกรรม (บังคับ · r2 §d ข้อ 2 3 5)
1. นอก tx: ข้อ 3 5 6 7 · บรรทัดต้องจับคู่กับ hold (รอบ + จำนวน) ไม่งั้น `VALIDATION HOLD_MISMATCH` · X1/X3 · `initialBookingStatus` · party (`bookerPartyId`: STAFF ส่ง `booker.partyId` ของร้านตัวเองได้ · อื่น `safeFindOrCreate`)
2. tx: **ชั้น 0** `SellBasket FOR UPDATE` (ไม่ใช่ OPEN ⇒ ดูกันซ้ำ §5.5) → PUBLIC: `rekeyHoldsToContactInTx(holdIds, "contact:"+contactKey, policies)` (**ก่อน** แปลงเสมอ · เกิน X10 ⇒ `HOLD_LIMIT`)
3. `assertProductSellableInTx` ทุกสินค้า **เรียง id** → **1a** `reserveInTx(op "CONVERT")` ทีละรอบเรียง id
4. **2a** ต่อ hold เรียงตาม id รอบ: CAS ผูก `bookingId` (id การจองสร้างฝั่งแอปล่วงหน้า) → ตาม `hold` ของ §3: `CONVERT` = `convertHoldInTx` (PUBLIC ส่ง `capKey = "contact:"+contactKey` = ค่าหลัง rekey) · `SHOP_CONFIRM` = CAS `purpose`→SHOP_CONFIRM `expiresAt` = now + X2 ชม. (WHERE ACTIVE ∧ expiresAt > now) · `KEEP` = คงไว้
5. **2c** `nextBookingCodeInTx` ต่อการจอง → **2b** INSERT `TripBooking` (1 แถวต่อบรรทัด · ผูก `basketId`) + `TripBookingItem` ต่อบรรทัดของ snapshot + `TripPassenger` ขั้นต่ำ (ชื่อ · `itemId` ของที่นั่งประเภทนั้น · `formStatus` `PENDING` · เกินจำนวนที่นั่ง ⇒ `VALIDATION TOO_MANY_PASSENGERS`)
6. โค้ดส่วนลด: `redeemPromosInTx` ต่อการจอง (เรียง id การจอง · ภายในเรียง ruleId) ด้วยยอดจาก snapshot → แต้ม/คูปอง provider (ถ้ามี) หลังโค้ด
7. **2h** outbox + audit → CAS `SellBasket` OPEN→CHECKED_OUT
- **hold หมดเวลา**: ทั้งก้อน rollback ⇒ `HOLD_EXPIRED` (ค่าเริ่ม `onExpired:"FAIL"`) · `REHOLD` = **ธุรกรรมใหม่**: ชั้น 0 → สินค้า → 1a ล็อกทุกรอบเรียง id → ปล่อย hold เก่าที่ยัง ACTIVE (`releaseHoldInTx` reason `REHOLD` · ถูกตัวกวาดไปแล้ว = ข้าม) → `reserveInTx(HOLD)` → `insertHoldInTx` (คีย์ `rh_<holdIdเดิม>`) → ทำข้อ 4–7 · ที่ไม่พอ ⇒ `SOLD_OUT` ไม่เขียนอะไร
- **ตัดสิทธิ์โค้ดไม่ผ่าน** (`PROMO_EXHAUSTED/PER_CONTACT/INACTIVE/EXPIRED`): rollback ทั้งก้อน (เลขจองคืน · hold ยัง ACTIVE) ⇒ คืน `PRICE_CHANGED` `details.reason` = เหตุนั้น + `details.quote` = Quote ใหม่ของคำขอเดิม **ไม่มีโค้ด** (ลูกค้าต้องยืนยันราคาใหม่เอง · ไม่เดินต่อเงียบ)
### 5.5 กันซ้ำของ confirm (CC :351 · ไม่มีคอลัมน์ใหม่)
- คีย์ namespace `pub:<tokenHash>:<key>` / `st:<userId>:<key>` เก็บที่ `SellBasket.idempotencyKey` + `requestHash` ตอน CAS OPEN→CHECKED_OUT (แทนคีย์ของ hold) · ตะกร้า CHECKED_OUT + คีย์/แฮชเดิม ⇒ คืน BookingRef เดิม · คีย์เดิมแฮชต่าง ⇒ `IDEMPOTENCY_CONFLICT` · คีย์อื่น ⇒ `STATE_CONFLICT BASKET_CHECKED_OUT`
- `publicToken` = base64url(HMAC-SHA256(กุญแจเซิร์ฟเวอร์, `trips-booking:v1:<bookingId>`)) ≥ 128 บิต · เก็บเฉพาะ `publicTokenHash` = sha256hex(token) · production ไม่มีกุญแจ ⇒ throw (แบบ `holdCapKeyHash`) · คืนซ้ำได้ตอน replay (§11 ข้อ 4)

## 16. มติผู้คุม (12 พ.ย. 2569 · ชนะทุกข้อด้านบนเมื่อขัดกัน)
1. **§11 ทุกข้อ: ใช้ค่าที่ผู้ร่างเสนอ** ยกเว้นที่ระบุด้านล่าง
2. snapshot: เพิ่มฟิลด์ `promo` + `providers` ใน `snapshot.ts`/`pricing.ts` ได้ **แบบเพิ่มอย่างเดียว** (S-15) · ยอดที่ตัดสิทธิ์โค้ด = ค่าจาก snapshot
3. `resolvedMinor`: ให้ T0.5 รับได้จริง — เพิ่ม `resolvedMinor` (optional · int4) ใน `OPTS.overrideApprovals` ของ `pricing.ts` และส่งต่อถึง `pricing-core` ที่ตรวจอยู่แล้ว · ทำแบบเพิ่มบรรทัดถ้าทำได้ · ถ้าต้องแก้บรรทัดเดิม **ให้แก้ แล้วแจ้งเป็นข้อแย้ง S-15** (ผู้คุมจะ ORACLE-EDIT) · T0.6 ต้องส่ง `resolvedMinor` ทุกครั้ง และปฏิเสธคำอนุมัติที่ไม่มีค่านี้
4. เส้น import `trips→party` และ `trips→approval`: ผู้คุมเพิ่มใน `scripts/fitness.mts` แล้ว · ห้ามเพิ่มเส้นอื่น · Party สร้างนอก tx (find-or-create · ซ้ำได้ไม่เพิ่มแถว)
5. token ลิงก์ลูกค้า: HMAC(กุญแจเซิร์ฟเวอร์ · ป้ายแยกโดเมน `trips.booking.token.v1` · bookingId) ≥ 128 บิต · เก็บเฉพาะ sha256 · **production ไม่มีกุญแจ ⇒ ล้ม (fail-closed) ห้ามถอยไปค่าคงที่** · หนี้สัญญา J.3.2 (เดิม "สุ่ม") + การเพิกถอน/ออก token ใหม่ต้องมีคอลัมน์รุ่น (ใบ W1.x)
6. `quoteExpiresAt` จากไคลเอนต์เป็นตัวกัน UX เท่านั้น — ตัวกันจริงคือลายนิ้วมือราคา · ห้ามใช้ค่านี้ตัดสินเรื่องเงิน
7. หลัง rekey ค่า capKey ที่ส่งให้ `convertHoldInTx` คือของผู้ติดต่อ (`contact:<key>`) ไม่ใช่ของตะกร้า
8. ทารก (`countsCapacity=false`): เก็บเป็น SEAT ได้ แต่ตัวนับ sold นับเฉพาะประเภทที่ใช้ที่นั่ง

## 17. มติผู้คุมรอบแก้ (13 พ.ย. 2569 · ชนะ §0–§16 เมื่อขัดกัน)
- **คำอนุมัติราคาแก้มือ**: ผูกด้วย `tripPriceOverrideEntityId({unitId, departureId, itemRef, unitMinor, resolvedMinor, qty})` (คำนำหน้า `tpo2_`) · entityType `trips.price_override` · APPROVED · ใช้กับ 1 รายการบน 1 บรรทัด · `amountSatang` (ถ้ามี) = unitMinor × qty · ใช้ครั้งเดียว: แถว audit `trips.approval.consumed` (targetId = approvalId) ใน tx เดียวกับการจอง หลัง advisory lock · เฉพาะ STAFF · เพิ่ม `requestBindings` ใน facade ของ approval (อ่านอย่างเดียว)
- **เลื่อนวัน/แก้การจอง**: snapshot ใหม่ใช้ `policy` ใหม่ · ยกมาเฉพาะ `cancelLadder` `cancelMinimumLadder` `shopCancelRefundBpByReason` (§5.6 เดิมผิด) · sha256 ของ snapshot เก่าใน audit · มีโค้ดส่วนลด ⇒ `PROMO_ON_CHANGE` เว้นแต่ `dropPromo: true` · PART_PAID/PAID ⇒ `NOT_SUPPORTED` จน T0.7 · ที่นั่งเดิมนับจาก snapshot · idempotency (key hash + body hash ใน audit · ค้นย้อน createdAt − 24 ชม.)
- **hold ที่ผูกการจอง**: ปล่อย/แปลง/ต่อเวลา จากภายนอก ⇒ `HOLD_HAS_BOOKING` · ทางของการจอง = `convertHoldForBookingInTx` / `releaseHoldForBookingInTx` (ไม่อยู่บน facade)
- **อนุมัติ PENDING ที่ไม่มียอดต้องจ่ายตอนจอง** ⇒ CONFIRMED (แปลง hold + event) · มียอด ⇒ HOLD

- เลขจอง: จัดสรรเรียง (คำนำหน้า, งวด) · ตัวเลือกปิด ⇒ ปฏิเสธทุกเส้นทาง · โค้ดส่วนลดล็อกเรียง ruleId ทั้งตะกร้า
- ข้อความ: ปฏิเสธตัวควบคุม C0/C1/DEL · ตัวกลับทิศ · U+2028/9 · surrogate เดี่ยว · ตัด ZWSP/BOM · NFC · ผู้จองหา Party ไม่ได้ ⇒ `BUSY BOOKER_UNAVAILABLE`
