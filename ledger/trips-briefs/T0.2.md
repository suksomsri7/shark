## 2. ชนิดและรูปข้อมูล (ใน `products-core.ts` · zod v4 `z.strictObject` ใน `products.ts`)
```ts

type Fail = { ok: false; code: TripProductErrorCode; message: string /* ไทย ไม่โทษผู้ใช้ */; missing?: PublishMissing[] };
type I18n = { th: string; en?: string | null; zh?: string | null }; // เก็บเฉพาะภาษาที่มีข้อความ (trim แล้วว่าง = ไม่มี)

const CONTENT_SECTIONS = ["title","summary","itinerary","includes","meeting"] as const;
const PROSPECTUS_ITEMS = ["OPERATOR_LICENSE","DURATION","PRICE_PAYMENT","VEHICLE","ITINERARY","ACCOMMODATION_MEALS","GUIDE","MIN_PAX","INSURANCE"] as const; // ม.26 (T58)
type PublishMissing = "TITLE_TH" | "OPTION" | "SEAT_PAX_TYPE";
const TRIP_PRODUCT_ERROR_CODES = ["INVALID_INPUT","NOT_FOUND","FORBIDDEN","UNIT_NOT_TRIPS","SLUG_TAKEN","CURRENCY_NOT_ALLOWED","CURRENCY_MISMATCH",
  "SOURCE_NOT_SUPPORTED","PUBLISH_INCOMPLETE","BAD_STATE","CONFIRM_REQUIRED","AGE_RANGE","AGE_OVERLAP","PAX_CODE_TAKEN","UNKNOWN_PAX_TYPE",
  "LAST_ACTIVE_OPTION","LAST_SEAT_PAX_TYPE","PASS_THROUGH_FLAGS","TAX_KIND_MISMATCH","LOCALE_DISABLED","BUSY"] as const;
```
ที่เก็บเนื้อหา (คอลัมน์ CC :141): `title` = I18n · `body` = `{ summary?: I18n; itinerary?: I18n; includes?: I18n; photoFileIds?: string[] }` (รูปอัปที่ T1.1) · `meetingPoint` = `{ text: I18n; lat?: number; lng?: number } | null` (= ส่วน `meeting` — จุดนัดพบ + ของที่ต้องเตรียม) · `disclosure` = `{ accommodationMeals?: I18n; guides?: I18n } | null` (ข้อมูลชี้ชวนที่กรอกมือ)

**DTO** (`getProduct`/`getProductBySlug` คืน `{ok:true, product}`)
```ts
ProductDTO = { id; unitId; slug; productType; sourceKind; status; currency; deepDive; crossBorder; title: I18n; body; meetingPoint; disclosure;
  options: OptionDTO[]; paxTypes: PaxTypeDTO[]; extras: ExtraDTO[];                // เรียง sortOrder แล้ว createdAt
  content: Record<ContentSection, Localized>; translation: { locale: string; missing: ContentSection[] }; createdAt; updatedAt }

PaxTypeDTO = { id; code; label: I18n; display: Localized; ageMin: number|null; ageMax: number|null; band: Band; countsCapacity; active; sortOrder }
ExtraDTO   = { id; productId: string|null; kind; basis; mandatory; priceMinor; currency; commissionable; discountable; passThrough; taxKind;
  stockItemId: string|null; name: I18n; note: I18n|null; display: Localized; active; sortOrder; commissionPct: number;
  paxPrices: Record<string /* code ประเภทคนของสินค้า */, number /* minor */> | null }   // null = ใช้ priceMinor ราคาเดียว

```
- `content`/`display` = `localize(i18n, locale)` (ปริยาย th): มีภาษาที่ขอ ⇒ `{text, locale, fallback:false}` · ไม่มี+มีไทย ⇒ `{ไทย, "th", true}` · ขอไทย ⇒ fallback false · ไม่มีทั้งคู่ ⇒ `{null, ที่ขอ, false}`
- `translation.missing` = ส่วน (ลำดับ `CONTENT_SECTIONS`) ที่มีไทยแต่ไม่มีภาษาที่ขอ · ขอไทย ⇒ `[]` (จอ 16 "ยังไม่แปล 2 ส่วน")

## 4. ค่าคงที่ (ทุกข้อมีข้อสอบลบ)
1. **หน่วยต้องเป็น TRIPS ของร้าน**: หน่วยร้านอื่น/ไม่มี/ผู้กระทำเข้าไม่ได้ ⇒ `NOT_FOUND` (ข้อความเดียวกับ id ที่ไม่มีจริง · X1) · หน่วยของร้านแต่ชนิดอื่น ⇒ `UNIT_NOT_TRIPS` · id ลูกต้องเป็นของหน่วยที่ส่งมา (ไม่ใช่ ⇒ NOT_FOUND)
2. **เปิดขาย** ต้องมี: `title.th` · ตัวเลือก active ≥ 1 · ประเภทคน active ที่ `countsCapacity` ≥ 1 ⇒ ไม่ครบ `PUBLISH_INCOMPLETE` + `missing` ตามลำดับ `TITLE_TH OPTION SEAT_PAX_TYPE` · ไม่ต้องมีราคา (T0.5) · ชี้ชวนไม่บล็อก
3. สินค้า ACTIVE: ปิดตัวเลือก active ตัวสุดท้าย ⇒ `LAST_ACTIVE_OPTION` · ปิด/ตั้ง `countsCapacity=false` ของประเภทคนใช้ที่นั่งตัวสุดท้าย ⇒ `LAST_SEAT_PAX_TYPE`
4. **ช่วงอายุ**: `ageMin > ageMax` ⇒ `AGE_RANGE` · ช่วงที่ใช้จริง (`effectivePaxBand` กับ T27 ที่ `{unitId, productId}`) ของประเภทคน active ที่ source ≠ NONE ห้ามซ้อนกัน (ปิดทั้งสองข้าง · ติดกัน 11|12 ได้) ⇒ `AGE_OVERLAP` · ตรวจตอนสร้าง/แก้/เปิดใช้คืน
5. **เก็บแทน (passThrough)** ⇒ `commissionable=false` `discountable=false` `taxKind="NONE"` — ส่งธงขัด ⇒ `PASS_THROUGH_FLAGS` (ไม่แก้ให้เงียบ ๆ) · `taxKind` ต้อง `NONE` ⇔ passThrough ⇒ ไม่ตรง `TAX_KIND_MISMATCH` (CHECK ของ T0.1 เป็นด่านที่สอง)
6. **ไม่มีการลบแถว** (มติ §11 ข้อ 8 · T0.1 §7 ข้อ 21): สินค้าออกด้วย ARCHIVED · ตัวเลือก/ประเภทคน/รายการเสริมออกด้วย `active=false` · **ถูกอ้างถึง** (ใช้ในข้อ 7) = สินค้ามีแถวใน `TripDeparture` `TripSchedule` `TripPrice` `TripPriceRule` `TripBooking` · A1.3 เพิ่ม `AgentRate` ภายหลัง
7. **X9 เก็บสินค้า**: ถ้าสินค้า ACTIVE อยู่ หรือ **เคยเปิดขาย** หรือถูกอ้างถึง ⇒ ต้อง `confirm: true` + `reason` (ตัดช่องว่างแล้ว ≥ 10 ตัวอักษร) ไม่งั้น `CONFIRM_REQUIRED` · ร่างที่ไม่เคยเปิดขายและไม่ถูกอ้าง = เก็บได้ทันที · "เคยเปิดขาย" = มีแถว AuditLog `trips.product.publish` ของสินค้านั้น (เขียนใน tx เดียวกับ CAS — ไม่มีคอลัมน์ `publishedAt` · §11 หมายเหตุ) · audit `after = {status, reason, referenced: bool, wasPublished: bool}` · ไม่แตะรอบ/การจองเดิม
7a. **ราคาต่อประเภทคน `paxPrices`** (มติ §11 ข้อ 4): คีย์ = `code` ของประเภทคน **active ของสินค้าเดียวกัน** (ตัวที่ใช้ที่นั่งหรือไม่ใช้ก็ได้ — ทุกประเภทคนเกี่ยวกับค่าธรรมเนียมได้) ไม่งั้น `UNKNOWN_PAX_TYPE` · ค่า int ≥ 0 สกุลเดียวกับรายการ · ว่าง `{}` = INVALID_INPUT · ใช้ได้เฉพาะรายการของสินค้า · `priceMinor` ยังบังคับ (ราคาตั้ง/สำรอง) · ธงเก็บแทนข้อ 5 ใช้เหมือนเดิม · ปิดใช้ประเภทคนทีหลังไม่ลบคีย์ (T0.5 ข้ามคีย์ที่ปิด)
8. **slug ไม่ซ้ำต่อร้าน** (ข้ามหน่วย · `@@unique([tenantId, slug])`) ⇒ `SLUG_TAKEN` · จับ P2002 คืนรหัส ห้าม throw · ร้านอื่นซ้ำได้
9. สกุล: TOUR/ATTRACTION = `THB` (CHECK T0.1) · LIVEABOARD ∈ T3 ที่ `{unitId}` (สร้าง) / `{unitId, productId}` (แก้) ⇒ ไม่ใช่ `CURRENCY_NOT_ALLOWED` · ไม่ส่ง = ตัวแรกของ T3 · รายการเสริมของสินค้า = สกุลสินค้า (`CURRENCY_MISMATCH`) · รายการระดับหน่วย (`productId=null`) ∈ T3
10. `sourceKind=SUPPLIER` ⇒ `SOURCE_NOT_SUPPORTED` (S1.1) · `vesselId` `formSpec` ไม่อยู่ใน input (strict)
11. สถานะ = CAS `updateMany({where:{id, status: from}})` count 1 ไม่งั้น `BAD_STATE` · event + audit ในธุรกรรมเดียวกับ CAS
12. **พร้อมกัน**: สร้างตัวเลือก (sortOrder) · จัดลำดับ · สร้าง/แก้ประเภทคน (ตรวจซ้อน) = ธุรกรรมที่ล็อกแถวสินค้า `SELECT … FOR UPDATE` (ผ่าน `tenantDb(...).$transaction` + `$queryRaw` ที่ใส่ `tenantId` เอง) · 40P01 ⇒ ลองใหม่ 1 ครั้ง แล้ว `BUSY`
13. ภาษาที่เขียนได้ = T2 `trips.general.customerLocales` ที่ `{unitId}` (ค่าเริ่ม `[th,en]`) ⇒ ไม่อยู่ `LOCALE_DISABLED` · `title.th` ลบไม่ได้
