## 2. สถานะ (ไม่เพิ่มสถานะการจอง)
- **รอบ:** `OPEN/GUARANTEED/FULL/CLOSED → CANCELLED` (STAFF) ด้วยทางใหม่ · เขียน `cancelKind` + `cancelDecideBy` + `cancelOptions` (§7) · ทางเดิม (รอบว่าง) เขียน `cancelKind` = null
- **การจองในรอบยกเลิก — สถานะคำนวณ `cancelChoiceStateOf`** (บริสุทธิ์ · ใช้ทั้งจอ งาน ข้อสอบ):
| state | เงื่อนไข (การจองที่ `departureId` = รอบยกเลิกที่ `cancelKind` ไม่ null) |
|---|---|
| `PENDING_CHOICE` | สถานะ ∈ CONFIRMED/PART_PAID/PAID · ไม่มีคำขอคืนเงินเปิด · ไม่มีแถวตัดสิน |
| `REFUNDING` | มีคำขอคืนเงินเปิด (REQUESTED…FAILED) ของทาง "ร้านยกเลิกรอบ" |
| `REFUNDED` | CANCELLED หลังคำขอ DONE |
| `CANCELLED_NO_MONEY` | CANCELLED โดยทางนี้ ไม่มีเงินรับ |
| `MOVED` | (ไม่อยู่ในรอบแล้ว) — รู้จาก audit `trips.booking.cancel_choice` choice MOVE |
- ทางออกต่อการจอง: `PENDING_CHOICE → MOVED` (ย้าย) · `→ REFUNDING → REFUNDED` (คืนเต็ม · ผู้เลือก/ระบบ) · `→ CANCELLED_NO_MONEY` (ไม่มีเงิน · ผู้เลือก "คืน" หรือเลยเส้นตาย) · คำขอที่ถูกถอน (`withdrawTripRefund`) ⇒ กลับ `PENDING_CHOICE` (ถ้ายังไม่เลยเส้นตาย — เลยแล้ว ⇒ งานยื่นใหม่ครั้งถัดไป)
- การจอง HOLD/PENDING ของรอบ: ณ จังหวะยกเลิก ⇒ ปล่อยที่ + `CANCELLED` (ไม่มีเงิน · เหตุ `DEPARTURE_CANCELLED`) · ถือที่ (TripHold ACTIVE) ⇒ ปล่อย · รายการรอ ⇒ ปิด
- **รอบที่เริ่มแล้ว** (`now ≥ startsAt`) ⇒ `DEPARTURE_STARTED` (ยกเลิกทั้งรอบไม่ได้ · เป็นเรื่องเหตุระหว่างทริป T1.5) · การจองที่ TRAVELLED/NO_SHOW ไม่มีวันอยู่ในรอบยังไม่เริ่ม (ปิดทริปหลังจบเท่านั้น) ⇒ ข้อสอบตรวจว่าทางใหม่ปฏิเสธเมื่อพบ (ฟิกซ์เจอร์ตรง)

## 3. เงิน (ทุกตัวเลขเป็นสตางค์ · ไม่ลงบัญชีในใบนี้ — ทางโอนคืนเดิมลงบัญชีนอก tx ตาม §H.0)
### 3.1 ย้ายรอบ (MOVE_DATE)
- ไปรอบอื่นของ**สินค้าเดียวกัน** ที่ขายได้ ณ ตอนย้าย (ไม่ยกเลิก · ยังไม่เริ่ม · ที่พอ) · ภายใน X16 `moveFreeWithinDays` นับจากวันเดินทางเดิม (เกิน ⇒ ร้านใช้ทางเปลี่ยนวันปกติ)
- **ราคาเดิมทั้งก้อน** (C5): snapshot เงินเดิม (payable · งวด · ตารางยกเลิก · เก็บแทน) คงไว้ — ไม่คิดราคาใหม่ · ส่วนต่างราคาของรอบใหม่ร้านรับไว้ · งวดคงรูปเดิม เลื่อนเฉพาะ dueAt ตาม `retimeTripDuesInTx` (`booking.ts` changeImpl `:1785`)
- เงินไม่ขยับ: `paidSatang` เดิมตามการจองไป · ไม่มี TripMoneyEvent ใหม่ · กระทบยอด: moved value = paid − refunded ณ ตอนย้าย
### 3.2 คืนเงินเต็ม (REFUND_100 · ผู้เลือก/ระบบ)
- ยอดคืน = **paid − refunded ทั้งหมด** (ทุกบรรทัด รวมเก็บแทน **แม้มี TripPassThroughEvidence**) · ไม่หัก deductions · ไม่สนค่า `shopCancelRefund` ที่ต่ำกว่า 100 ใน snapshot (C3) — ทาง `fullRefund: true` ของ `refundQuoteFromSnapshot` คืนยอดแยกบรรทัดตาม snapshot (VAT/เก็บแทน) เพื่อให้ทางโอนคืนเดิมออกเอกสารถูก
- เหตุ (`reasonKind`) = `cancelKind` ของรอบเสมอ (ผู้เรียกเลือกเองไม่ได้) · `choice` = MONEY (มติ 7)
- จ่ายบางส่วน: คืนเท่าที่รับ · งวดที่ยังไม่จ่าย ⇒ ปิดตามทางเดิมของคำขอ DONE · จ่าย 0 ⇒ ไม่ยื่นคำขอ: `CONFIRMED → CANCELLED` ทันที (SYSTEM/STAFF · `state.ts:44`) + ปล่อยที่ (`CANCELLED_NO_MONEY`)
- อนุมัติ: คำขอของทางนี้ **อนุมัติอัตโนมัติ** (ยอดตรงสูตร 100% · ไม่ผ่าน X12) โดย actor SYSTEM `trips.departureCancel.autoApprove` (C4) · โอนคืนจริง = STAFF ทางเดิม (`executeTripRefund`) — จอแสดง "ต้องโอนคืน n รายการ ฿…"
### 3.3 การจองผ่านเอเจนซี่
- ผู้ตัดสิน = เอเจนซี่ (R4 · CC :705) · ใบนี้: ร้านบันทึกแทนพร้อมเหตุผล (พอร์ทัล A2.2 ทำทางเอเจนซี่เอง) · อีเวนต์ `recipient: "AGENT"` + `agentAccountId`
- `collectMode = AGENT` (เอเจนซี่เก็บเงินลูกค้า · ร้านรับ 0): คืน ⇒ `CANCELLED_NO_MONEY` ฝั่งร้าน · ยอดที่เอเจนซี่ต้องคืนลูกค้า/ยอดค้างระหว่างร้านกับเอเจนซี่ = สมุด A1.5 (**หนี้** — ไม่มีสมุดวันนี้) · คอมฯ: คิดเมื่อปิดทริป (A1.7) ⇒ รอบยกเลิกไม่มีคอมฯ ค้างให้ดึงคืน · ข้อสอบตรวจว่า `commissionSatang` ไม่ถูกนับเป็นต้นทุนของรอบ (a1 นับ 0 ให้ CANCELLED อยู่แล้ว)
- ร้านเก็บเงินผ่านลิงก์ (`collectMode = SHOP` + `agentAccountId`): คืนลูกค้าตาม 3.2
### 3.4 กระทบยอด (ข้อสอบ RC)
- ต่อการจอง: `paid(ก่อนยกเลิก) = refund(ทางนี้) + movedValue + 0(เครดิต)` และ `refunded − refunded(ก่อน) = refund`
- ต่อรอบ: Σ paid ของการจองที่ถูกกระทบ = Σ คืน + Σ ย้าย · ที่นั่ง: `sold` ของรอบยกเลิก ลดตามทุกทางออก · = 0 เมื่อทุกการจองจบ · `held = reserved = 0` หลังยกเลิก

### 5.1 `cancelDepartureWithBookings(ctx, { unitId, departureId, expectedVersion, kind: EXTERNAL|MIN_NOT_MET|SHOP_FAULT, reason (3–500), idempotencyKey }, opts?)`

## 8. งานเลยเส้นตาย `runDepartureCancelDefault(now, opts)` (T1.6b · CC :114 · ชื่อค่าคงที่ CC :936)

- idempotent: รันซ้ำ/สองเครื่องพร้อมกัน ⇒ ยื่นครั้งเดียว (คีย์ unique ของ TripRefundRequest + ล็อกแถว) · ชนกับร้านกดเลือกวินาทีเดียวกัน ⇒ ผู้ได้ล็อกก่อนชนะ อีกฝ่าย `STATE_CONFLICT` (ไม่มีคำขอ 2 ใบ · ไม่ย้ายแล้วคืน) · ร้านถอนคำขอของงานหลังเส้นตาย ⇒ งานรอบถัดไปยื่นใหม่ (ไม่วนไม่สิ้นสุด: ถอนได้เมื่อ "ย้าย" ในธุรกรรมเดียวกันเท่านั้น — C7)
- ลงทะเบียนใน `minute-jobs.ts` แบบงานเดิม (signal · deadline)

- **OQ-ข** ใครยกเลิกรอบที่มีคนจ่ายแล้วได้ — ค่าปลอดภัย: ผู้มีสิทธิ์ "เปิด/ปิดรับ…ยกเลิกรอบ" **และ** "อนุมัติคืนเงิน" (เจ้าของ/ผู้จัดการ/ผู้ที่ติ๊กให้) · ระดับ "ทัวร์: ใช้งาน" ทำไม่ได้
- **OQ-ค** เหตุคลื่นลม: หักค่าใช้จ่ายจริงที่มีหลักฐานจากเงินคืน (ประกาศข้อ 6 อนุญาต) ไหม — ค่าปลอดภัย: ไม่หัก คืนเต็มเสมอ (รวมค่าอุทยานที่ซื้อไปแล้ว — ร้านรับไว้)
- **OQ-ง** เส้นตายเลือก — ค่าปลอดภัย: T22 2 วัน นับเป็นสิ้นวันเวลาร้าน · ถ้าเส้นตายเลยวันเดินทางเดิมไม่เป็นไร (รอบยกเลิกแล้ว)
- **OQ-จ** เครดิตร้าน — ค่าปลอดภัย: ไม่มีในรุ่นแรก (มติ 7) · จอแสดง 2 ทางเลือก

**ถึงผู้คุม (เลขพร้อมข้อแนะนำ)**
- **C1** เก็บข้อมูลการยกเลิกที่ไหน — แนะนำ 3 คอลัมน์บน TripDeparture + CHECK + ดัชนีบางส่วน (§7)
- **C2** คีย์สิทธิ์ยกเลิกรอบที่มีคน — แนะนำ `departure.status ∧ refund.approve` ไม่เพิ่มคีย์ (เพิ่มคีย์ใหม่ = แตะ permissions/levels/staff 3 ไฟล์กลาง)
- **C3** ยอดคืน = 100% ของเงินที่รับเสมอ (ไม่ใช้ค่า `shopCancelRefund` < 100 ใน snapshot · เก็บแทนจ่ายออกแล้วก็คืน) — แนะนำรับ (ขั้นต่ำตามกฎหมาย [V] ต่างกันแค่เรื่องหักข้อ 6 ซึ่งเลือกไม่หัก)
- **C4** อนุมัติอัตโนมัติคำขอของทางนี้ (ผู้ยกเลิกรอบมี refund.approve อยู่แล้ว · ยอดตายตัว) — แนะนำรับ · โอนเงินจริงยังเป็นคนบันทึก
- **C5** ย้ายแบบราคาเดิมทั้งก้อน (ไม่คิดราคาใหม่ · ส่วนต่างร้านรับ) — แนะนำรับ (ไม่งั้น `PRICE_CHANGED_AFTER_PAYMENT` ทำให้ย้ายการจองที่จ่ายแล้วไม่ได้เกือบทุกครั้ง)
- **C6** เส้นตายเลยเวลาออกเดิมได้ไหม — แนะนำได้ (รอบยกเลิกแล้ว ไม่มีเหตุให้รีบ)
- **C7** ถอนคำขอของงานเลยเส้นตาย — แนะนำให้ทำได้เฉพาะในธุรกรรม "ย้าย" (ไม่งั้นงานยื่นใหม่วน)
- **C8** แยก T1.6a/T1.6b ตาม §0.2 — แนะนำรับ · a ไม่นับ b นับ
- **C9** ORACLE-EDIT ที่คาด (t1.2 HAS_BOOKINGS ของ desk · ขอบเขต t0.7/w1.3/t1.7) ทำโดยผู้คุมหลังงานเข้า
