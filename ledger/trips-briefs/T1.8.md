| ช่องทางของการจอง | ผู้รับ |
|---|---|
| WEB · LIFF · EMBED (และช่องทางสาธารณะ/ภายนอกอื่นทั้งหมด: AGENT_* · API · CHAT_AI) | **ทาง ก เท่านั้น**: ผู้ติดต่อจาก `ChatLinkCode` (`purpose "TRIP_BOOKING"` · `refId` = การจอง · `usedAt` ไม่ว่าง · `usedByChatContactId`) ของร้าน — ส่ง `chatContactId` อย่างเดียว · ผู้ติดต่อมี Party ที่ไม่ใช่ผู้จอง (หลัง resolveCanonical ทั้งคู่) ⇒ ไม่ใช้ · ไม่มีรหัส ⇒ `NO_RECIPIENT` |
| COUNTER · POS | ทาง ก ก่อน → ทาง ข: `party.resolveCanonical(bookerPartyId)` ⇒ ส่ง `partyId` (ประตูเลือกผู้ติดต่อ LINE บน OA ของหน่วย · ไม่มี ⇒ แถว `NO_CHANNEL`) |
- **ห้ามจับคู่ Party จากเบอร์/อีเมลที่พิมพ์ในทุกทาง** — เหตุ: พิมพ์เบอร์คนอื่น/พิมพ์ผิด ⇒ ข้อความ + ลิงก์ token ไปหาเจ้าของเบอร์ ซึ่งผ่านการยืนยันเบอร์ของหน้าแก้เองแล้วยกเลิก/แก้การจองได้
- การจองเอเจนซี่: ผู้รับคือลูกค้า (ตามตารางนี้ + A32) · การแจ้งเอเจนซี่ = A2.2

### 4.5 กุญแจ · precheck ถาวร · กรณีพิเศษ
- **กุญแจ (R2):** id ทุกตัวผ่าน `keyId(id)` = แทนตัวเลข 0–9 ด้วย `A`–`J` (id ของ trips/outbox เป็นตัวพิมพ์เล็ก+ตัวเลข ⇒ แปลงกลับได้ไม่ชนกัน) · id ที่มีอักขระนอก `[a-z0-9_-]` ⇒ `BAD_STATE` (ไม่ส่ง) · วันที่ก็แปลงแบบเดียวกัน ⇒ **กุญแจไม่มีตัวเลขเลย** จึงไม่มีวันตรง `TH_PHONE_RE`
  - `trips:<B>:confirmation` · `trips:<B>:reminder1Day:<DEP>:<YMD>` · `trips:<B>:paymentDue:<DUE>:<EVT>` (EVT = `evt.id` ของ outbox · R3 · ไม่ต้องรู้ d)
- **precheck หลัง claim (R4)** ยับยั้งเฉพาะข้อเท็จจริงถาวร ⇒ `SKIPPED_PRECHECK_<เหตุ>` จบ: `STATUS` (สถานะหมดสิทธิ์) · `DEP_CANCELLED` · `ERASED` · `TOO_LATE` (เลยวันก่อนเดินทาง/เลยกำหนดงวด) · `MOVED` (การจองไม่อยู่บน `departureId`/`travelDate` ของกุญแจแล้ว) · `PAID` (งวดจ่ายครบ) — **ตัวกั้นชั่วคราว (คำขอคืนเงินเปิด) อยู่ในตัวกรองก่อน claim เท่านั้น** ⇒ คำขอถูกปฏิเสธภายหลัง ⇒ เตือนยังส่งได้
- เลื่อนวัน/ย้ายรอบ ⇒ กุญแจเตือนใหม่ · ยืนยันไม่ส่งซ้ำ · ยกเลิก/หมดเวลา/รอบยกเลิกระหว่างคิว ⇒ precheck
- ซ้ำ/พร้อมกัน/งานซ้อน ⇒ SENT ครั้งเดียว (claim) · โพรเซสตาย ⇒ ยึดต่อหลัง 2 นาที + Retry-Key เดิม
- **เปิดใช้ครั้งแรก**: งานไม่เริ่ม "ครั้งแรก" ของ confirmation/paymentDue (ลองซ้ำเฉพาะกุญแจที่มีแถวอยู่แล้ว) ⇒ การจองเก่าไม่ได้ข้อความย้อนหลัง · และสวิตช์ค่าเริ่มปิด

### 4.6 งาน `trips.customerMessages` (ทุก 15 นาที · ไฟล์ข้ามร้าน `jobs.ts` · tenantIds · signal/deadline · หมุนลำดับร้าน · `reportFailures`)
