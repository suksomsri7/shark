## 4. กติกาแถวราคา
### 4.1 `normalizeAgentRate` (zod strict · ช่องแปลก ⇒ `BAD_INPUT` · เงิน/อัตรา = จำนวนเต็มเท่านั้น ไม่มีทศนิยม ไม่มี NaN/Infinity/สตริงตัวเลข)
| โหมด | ช่องบังคับ | ช่องต้องว่าง (null) | ความหมาย |
|---|---|---|---|
| `COMMISSION_PCT` | `valueBp` 0–10000 | `valueMinor` `markupCapBp` `paxTypeId` | คอมฯ % ของฐาน (ฐาน = บรรทัด commissionable ไม่รวมเงินเก็บแทน · T0.5) · `minSellMinor` ต้อง null |
| `COMMISSION_FIXED` | `valueMinor` 0–2,147,483,647 (สตางค์ต่อที่นั่งที่จ่ายเงิน) · `currency = "THB"` (CHECK) | `valueBp` `markupCapBp` `paxTypeId` `minSellMinor` | คอมฯ บาทต่อที่นั่ง |
| `NET` | `valueMinor` (ราคาเน็ตต่อหน่วย ในสกุลของแถว) | `valueBp` `markupCapBp` | เอเจนซี่ส่งร้าน = เน็ต (+ เงินเก็บแทน) · `minSellMinor` ไม่บังคับ |
| `MARKUP` | `valueMinor` (เน็ต) + `markupCapBp` 0–`markupCapBpMax` | `valueBp` | ลูกค้าจ่าย ≤ เน็ต × (1 + เพดาน) · `minSellMinor` ไม่บังคับ |
- ผิดคู่ช่อง ⇒ `MODE_VALUE_MISMATCH` · `COMMISSION_FIXED` สกุลไม่ใช่ THB ⇒ `CURRENCY_MISMATCH` · โหมดคอมฯ ที่ใส่ `paxTypeId` ⇒ `PAX_RATE_COMMISSION` (`Level` ของ T0.5 มีอัตราเดียวต่อการจอง) · `cabinTypeId` ไม่ null ⇒ `CABIN_RATE_NOT_SUPPORTED` (L1.3) · `productKind ≠ "TRIP"` ⇒ `KIND_NOT_SUPPORTED` (TICKET = K1.6 · HOTEL = L-28 ปฏิเสธ)
- `NET`/`MARKUP`: `minSellMinor` ไม่ null ต้อง ≥ `valueMinor` ไม่งั้น `MIN_SELL_BELOW_NET` · วันที่ต้องเป็นวันจริง · `bookTo < bookFrom` หรือ `travelTo < travelFrom` ⇒ `BAD_RANGE` · `priority` 0–`priorityMax` (ปริยาย 0) · `currency` ปริยาย `"THB"` รูป `^[A-Z]{3}$` · `active` ปริยาย true
- **ช่วงพิเศษ** = แถวที่มีขอบวันอย่างน้อยหนึ่งช่อง (`bookFrom`/`bookTo`/`travelFrom`/`travelTo`) — DTO แสดง `specialPeriod: true`
- บริการตรวจเพิ่มกับฐาน (§7): สินค้าเป็น `TripProduct` ของร้านนี้ที่ไม่ ARCHIVED · `optionId`/`paxTypeId` เป็นของสินค้านั้น ไม่งั้น `PRODUCT_NOT_FOUND` · `currency` ≠ สกุลของสินค้า ⇒ `CURRENCY_MISMATCH`
### 4.2 ตัวกันช่วงซ้อน (หนี้ O3 ของ A1.1 · ข้อสอบ K-4 R-8)
`rateRowsConflict(a, b)` = ทั้งคู่ `active` · **ทั้งคู่เป็นช่วงพิเศษ** (แถวไม่มีขอบวันกับแถวช่วงพิเศษไม่ถือว่าซ้อน — ช่วงพิเศษชนะตาม §5.2 ข้อ 2 · แถวไม่มีขอบวันสองแถวมิติเดียวกันชนคีย์ NND อยู่แล้ว) · card เดียวกัน · `(productKind, productId, optionId, paxTypeId, cabinTypeId)` เท่ากัน (null = null) · `priority` เท่ากัน · ช่วงวันจองซ้อน **และ** ช่วงวันเดินทางซ้อน (ปิดสองด้าน · null = ไม่จำกัด · ติดกัน `to = D` กับ `from = D+1` ไม่ซ้อน · `to = D` กับ `from = D` ซ้อน) ⇒ บริการปฏิเสธ `VALIDATION reason RATE_OVERLAP` · ต่าง `priority` ซ้อนได้ (ตัว priority สูงชนะ)
- rate card สองใบของเจ้าของเดียวกันที่ `ACTIVE` ทั้งคู่ · `priority` เท่ากัน · ช่วง `validFrom..validTo` ซ้อน ⇒ ปฏิเสธตอน ACTIVATE / ตอนแก้ช่วงของใบที่ ACTIVE ด้วย `CARD_OVERLAP`

## 5. ตัวเลือกชั้นเอเจนซี่ (บริสุทธิ์ · กติกาเดียว ใช้ทั้ง port และเครื่องลองคิด)
### 5.1 card ที่เข้าเกณฑ์ของชั้น

- `bookYmd` = `q.at` ในเขตเวลาของหน่วย · `travelYmd = q.travelDate`
- ผล = `{ ...built.input, policySnapshot }` (snapshot ก้อนเดียวกับที่ใช้สร้าง `terms`) · `built.ok === false` ⇒ throw `Error("AGENCY_PRICING_SETTINGS_INVALID")` (ไม่คืน null — ไม่งั้นการจองผ่านลิงก์จะถูกคิดราคาแบบไม่มีเอเจนซี่เงียบ ๆ) · ข้อผิดพลาดฐานข้อมูล = throw ต่อ (ไม่กลืน)
- อ่านอย่างเดียว: ไม่มี INSERT/UPDATE/outbox/audit ใน `load`
- จุดติดตั้ง: `platform/sellables.ts → sellableFor("TRIP")` (ทุกทางเข้าพอร์ทัล/API/หน้าจองสาธารณะผ่านจุดนี้ · CC :44) + เครื่องลองคิดเรียกเองก่อนใช้

## 9. เครื่องลองคิด (ภาพ 10 `:59–68` "ลองคิดราคา ก่อนบันทึก")
```ts
tryAgentPrice(ctx, {
  agentAccountId; unitId; productId; slotId; pax: { paxTypeId; qty }[] (≤ tryPaxLines); extras?: { extraId; qty }[];
  at?: string /* ISO · วันจองสมมติ · ปริยาย opts.now ?? ตอนนี้ */; agentDiscountSatang?; actualSaleSatang?;

```
- สิทธิ์ `agency.rate.view` · บัญชีต้องมองเห็นได้ · บัญชีสถานะ `ACTIVE`/`SUSPENDED`/`PENDING` ลองคิดได้ (ร้านตั้งราคาก่อนอนุมัติ) — เครื่องลองคิด **ไม่ผ่าน `agencyPricingPort.load`** สำหรับด่านสถานะ แต่ใช้ตัวโหลดข้อเท็จจริงตัวเดียวกัน
- **ความเท่ากันกับเส้นทางจริง (ข้อสอบ TP)**: (1) `installAgencyPricingPort()` (2) `inp = trips.loadPricingInput(ctxเอเจนซี่, line, opts)` โดย `ctxเอเจนซี่ = { tenantId, unitId, channel: "AGENT_PORTAL", actor: { kind: "AGENT", agentAccountId }, now: at }` (3) มี `draft` หรือบัญชีไม่ ACTIVE หรือมี `actualSaleSatang` ⇒ แทน `inp.agency` ด้วยผลของ `buildAgencyPricingInput(facts')` (facts' = ข้อเท็จจริงเดิม + card ร่าง `id "draft"` `status ACTIVE` `version 0` ของชั้นที่ระบุ · ตัด `replacesCardId` ออก) + `policySnapshot` เดิม (4) `trips.resolveTripPrice(inp)` — **ห้ามมีสูตรเงินใน agency** · ไม่มี draft + บัญชี ACTIVE ⇒ ผล `priced` ต้อง **เท่ากันทุกไบต์** กับ `trips.quoteTripLine(ctxเอเจนซี่, line)` ที่ `now` เดียวกัน (ยกเว้น `cancelMinimumLadder` ที่ quote เติม — ให้เติมเหมือนกันหรือเทียบโดยตัดคีย์นี้) · มี draft ⇒ เท่ากับผล quote หลังบันทึก draft นั้นจริง
- แถวร่างผ่าน `normalizeAgentRate` + ตรวจสินค้า/ตัวเลือก/ประเภทคน/สกุลกับฐานเหมือน §4.1 + ตัวกันช่วงซ้อนกันเองในร่าง (ผิด ⇒ `VALIDATION` reason เดียวกับตอนบันทึก) · **ไม่เขียนฐาน** (ไม่มี audit · ไม่มี version เปลี่ยน · ข้อสอบ TP-5)
- ผลล้มของตัวคิด (`BELOW_MIN_SELL_PRICE` · `DISCOUNT_OVER_CAP` · `VALIDATION COMMISSION_EXCEEDS_PAYABLE` …) ⇒ `AgencyFail` `code "VALIDATION"` + `reason` = รหัส/เหตุของ trips ตรงตัว · สินค้า/รอบมองไม่เห็น ⇒ `NOT_FOUND`
- `termSources` = `policySnapshot.sources` (ป้าย "เริ่มต้น/ปรับ" ของภาพ `:45–55`) + `trace` (ป้าย "ตามระดับ B / ปรับเฉพาะราย" `:27–31` และบรรทัด `:65` "← ระดับ B") — นี่คือ "ป้ายที่มาของค่า" ฝั่งบริการ · การจัดวาง = A1.3b
- ตัวอย่างบังคับ (ภาพ `:60–67` · ฟิกซ์เจอร์ `AGENCY_CASE_2ADULTS`): ราชา 2 ผู้ใหญ่ · ระดับ B · ค่าเริ่มทุกตัว ⇒ ขาย 7,000.00 · อุทยาน 1,200.00 · เก็บลูกค้า 8,200.00 · คอมฯ 1,050.00 · หัก ณ ที่จ่าย 31.50 · เอเจนซี่ส่งร้าน **7,181.50** · เอเจนซี่จด VAT (X26 ไม่ตั้ง) ⇒ **7,108.00** · X26 = `INCLUSIVE` ⇒ **7,179.44** (CC §H.4)

- **R1:** รับการแยก A1.3a (บริการ) / A1.3b (จอ) · ตัวนับ RUN นับ A1.3 เมื่อ A1.3a รับ · A1.3b นอกตัวนับ
