## 3. สัญญา
### 3.1 รหัสผล/เหตุใหม่ (ไม่มีรหัสใหม่)
- `HOLD_LIMIT` + `details = { reason: "PUBLIC_UNPAID_SHARE", retryAfterSec }` · `retryAfterSec` = จำนวนเต็ม ≥ 1 = ceil((expiresAt ที่เร็วสุดของ hold ที่นับ − ctx.now)/1000) · **ไม่มีจำนวนที่นั่ง/ตัวนับใน details** · `messageTh` จาก `REASON_TH` เช่น "ที่นั่งรอบนี้ถูกลูกค้าคนอื่นถือไว้ชั่วคราวระหว่างรอชำระ ลองใหม่ในอีกไม่กี่นาที" (ห้ามคำว่า "เต็ม" · ต่างจากข้อความ SOLD_OUT/HOLD_LIMIT เดิม)
- **hold ที่นับ** (ทุกเงื่อนไขพร้อมกัน · `ctx.now` เท่านั้น ห้าม `now()`): `tenantId` `unitId` `departureId` ของรอบ · `status='ACTIVE'` · `"expiresAt" > $now` · `channel = ANY(PUBLIC_CHANNELS)` · `purpose IN ('PAYMENT','SHOP_CONFIRM')` (Q3) — รวม hold ที่ผูกการจอง HOLD/PENDING แล้ว (ยังไม่จ่าย) · ไม่รวม CONVERTED/EXPIRED/RELEASED · ไม่รวม hold ของพนักงาน (COUNTER) · ไม่รวม WAITLIST_OFFER
- ลำดับตรวจตอนถือ (ใน `phase1HoldInTx` หลัง 1a): `blockOf` → SOLD_OUT (`publicLeftOf < qty`) → **เพดาน** → D.1(1) · ตะกร้าหลายบรรทัดรอบเดียวกันต้องนับรวมกัน (แนะนำ: `reserveHoldsInTx` รวม qty ต่อรอบแล้วเรียก `reserveInTx(HOLD)` ครั้งเดียวต่อรอบ · `insertHoldsInTx` คงแถวละบรรทัด ⇒ held = Σ hold ACTIVE)
- ไม่ตรวจซ้ำตอนยืนยัน (ที่นั่งถูกนับไปแล้วตอนถือ) · `getAvailability`/`listAvailability` ไม่เปลี่ยน (ที่ว่างจริงตาม R2)

### 3.3 ลำดับล็อกและจุดตรวจ (ห้ามเปิด connection ที่สองใน tx · ห้ามอ่านค่าตั้งใน tx)
- **ถือ (PUBLIC · holdTrips):** 0 INSERT SellBasket → 0 advisory ตะกร้า → สินค้า FOR SHARE → ต่อรอบเรียง id: [TRY advisory · นับ X10] → 1a `FOR UPDATE` → `blockOf` → SOLD_OUT → **นับ hold (SELECT ไม่ล็อก ใต้ล็อก 1a)** → UPDATE held → 2a INSERT hold · ถูกต้องเพราะทุกเส้นทางที่ INSERT hold PUBLIC ของรอบ X ทำขณะถือล็อกแถว X (placeHold · holdTrips · REHOLD) ⇒ นับ+เพิ่มเป็นลำดับเดียว · ไม่มีล็อกใหม่ ⇒ ไม่มีวงรอใหม่
- **ยืนยัน:** 0 SellBasket FOR UPDATE → 0 rekey (PUBLIC · เดิม) → สินค้า FOR SHARE → 1a รอบเรียง id → **1a′ ตรวจขายได้** (`assertDeparturesSellableInTx`: `gateOfTx` ได้ tz · `lockDeparture` ซ้ำแถวที่ถืออยู่ = ไม่รอ · `blockOf(..., fullIsOpen=true)` · ค่าตั้งจาก `P.policies` ที่โหลดก่อน tx) → 2a ผูก/แปลง hold → advisory คำอนุมัติ → **P ผู้จอง** (`safeFindOrCreate(tenantId, {name, phone, email}, tx)` — findFirst ≤ 3 + INSERT บน tx เดียวกัน · Party ไม่มี unique ⇒ ไม่รอใคร) → 2c เลขจอง → 2b → 2d → โค้ดส่วนลด → 2h → ตะกร้า CAS
- จุดตรวจ 1a′ อยู่ **ต้น `finalizeCoreInTx`** (ครอบ confirm FAIL/REHOLD · bookNow · finalizeTripsInTx) · ผล: PUBLIC ที่ hold หมดเวลา + รอบปิด ⇒ `HOLD_EXPIRED` (rekey ชั้น 0 ตัดก่อน · ไม่เปลี่ยนลำดับเดิม) · STAFF ⇒ `SLOT_CLOSED` ก่อนผูก hold ⇒ ไม่เข้า REHOLD
- `prepareCore`: ตรวจ partyId ของ STAFF ได้เหมือนเดิม (นอก tx · อ่านอย่างเดียว) · ไม่มี `safeFindOrCreate` · `PreparedConfirm.booker = { partyId } | { name, phone: string|null, email: string|null }` (แช่แข็ง · ลงทะเบียน WeakSet เดิม) · หา/สร้างไม่ได้ ⇒ `BUSY BOOKER_UNAVAILABLE` (rollback)
- `confirmTrips` ยืนยันซ้ำคีย์เดิมบนตะกร้า CHECKED_OUT = ผลเดิม (ไม่ตรวจรอบซ้ำ) · `convertHold` (จ่ายเงิน) ไม่เปลี่ยน (T0.4 §11 ข้อ 9)

## 8. คำถามเปิด (เรียงตามผลกระทบ · ค่าปริยาย + เหตุผล)
- **Q4 ค่าเริ่ม 50% หรือ 100% (ปิด):** 50 — กันกั๊กตั้งแต่วันแรก (ร้านนำร่องไม่ต้องจำตั้ง) · ต้นทุน = ORACLE-EDIT §7 · ทางเลือก 100 = ไม่มีผลจนร้านตั้ง (ผิดเจตนา R7)
- **Q1 สูตร:** ceil บนความจุทั้งหมด (ตามโรงแรม `HOTEL_WEB_HOLD_CAP` 5,000 bp ปัดขึ้น · `platform/hotel-web.ts:166,741`) + ข้อยกเว้นตะกร้าแรก — ไม่มีข้อยกเว้น ⇒ กลุ่ม > ครึ่งรอบ (Liveaboard 20 ที่ กลุ่ม 12) จองออนไลน์ไม่ได้เลย · ราคาของข้อยกเว้น: ผู้กั๊กคนแรกถือได้สูงสุด `BOOK_MAX_SEATS` (10) ต่อการถือ (ถังต่อรอบ 3/ชม. ของ W1.2a จำกัดซ้ำ) · ทางเลือก: ฐาน `capacity − reserved` (เมื่อมีโควตาเอเจนซี่ A1.4)
- **Q2 ตรวจรอบตอนยืนยันกับพนักงาน:** ใช่ตามช่องทาง COUNTER — สอดคล้องกติกาถือ/จองหน้าร้านเดิม (`capacity.ts:622` · `bookTripsNow` ถือผ่าน phase1) · ทางเลือก "PUBLIC/AGENT เท่านั้น" = พนักงานยืนยันหลังร้านปิดรอบได้ (ไม่มีมติรองรับ)
- **Q3 นับ hold `SHOP_CONFIRM` ของ PUBLIC:** ใช่ — ถือนานกว่า (X2 ชม.) จึงกั๊กได้หนักกว่า · W1.2a ปิดสินค้า SHOP_CONFIRMS บนหน้าสาธารณะอยู่แล้ว (R8) จึงไม่มีผลกับนำร่อง
- **Q5 ชั้นคีย์ U·P (ไม่มี DEPARTURE):** ร้านตั้งต่อสินค้าได้ (Liveaboard ต่างจากเดย์ทริป) · ต่อรอบ = ซับซ้อนเกินจำเป็น
- **Q6 ชื่อ reason/ไม่บอกจำนวน:** `PUBLIC_UNPAID_SHARE` + `retryAfterSec` อย่างเดียว — ไม่ให้คนนอกอ่านจำนวนที่ถือของรอบ
- **Q7 ลำดับ HOLD_EXPIRED ก่อน SLOT_CLOSED สำหรับ PUBLIC:** คงลำดับ rekey เดิม — W1.2a ตอบ HOLD_EXPIRED ด้วยปุ่มถือใหม่ ซึ่งจะได้ SLOT_CLOSED จากการถือทันที · ย้าย rekey ไปหลัง 1a = ใบที่แก้ลำดับ (หนี้ T0.7)

- tx แยกให้ Party = connection ที่สอง (BLOCKER T0.4)

W1.2a รหัสจอ `SLOT_BUSY` (§3.4 · ก่อน M1) · Party ซ้ำเมื่อสองการจองพร้อมกันใช้เบอร์ใหม่เดียวกัน (มีมาก่อน · ไม่มี unique) · ย้าย rekey หลัง 1a (T0.7) · เพดานฐาน `capacity − reserved` เมื่อ A1.4

## มติผู้คุม
### มติผู้คุม (14 พ.ย. 2569) — ปล่อยผู้สร้าง
- **R1 (Q1–Q7): ใช้ค่าปริยายของผู้ร่างทุกข้อ** — เพดาน = `ceil(ความจุ × % / 100)` บนความจุทั้งหมด + ข้อยกเว้นตะกร้าแรก (ยังไม่มี PUBLIC ถือไม่จ่ายบนรอบ ⇒ ถือได้แม้เกินเพดาน · กลุ่มใหญ่/เรือเล็กยังจองออนไลน์ได้) · ค่าเริ่ม 50 ทุกแม่แบบ (คีย์ X31 `trips.public.unpaidHoldMaxPct` ชั้น U·P) · ตรวจรอบยังขายได้ตอนยืนยันกับทุกผู้กระทำตามช่องทางของตน · นับ hold `SHOP_CONFIRM` ของ PUBLIC ด้วย · details ของเหตุใหม่มีแค่ `reason` + `retryAfterSec` (ไม่บอกจำนวนที่ถือ) · ลำดับ HOLD_EXPIRED ก่อน SLOT_CLOSED ของ PUBLIC คงเดิม
- **R2:** รับทางที่เลือกทั้ง 3 เรื่อง (เพดานใน `phase1HoldInTx` หลังล็อกแถวรอบ · `assertDeparturesSellableInTx` ที่ต้น `finalizeCoreInTx` · สร้าง Party ใน tx เดียวกันผ่าน client ของ tx) · **ห้ามเปิดการเชื่อมต่อเส้นที่สองใน tx** (BLOCKER เดิมของ T0.4) · ไม่มี migration
- **R3:** ORACLE-EDIT ข้อสอบเดิมตามรายการ §7 ผู้คุมทำตอนรับงาน — ผู้สร้างรัน regression ทั้งชุดแล้วรายงานข้อที่แดงจริงทีละข้อ (ปล่อยแดง ไม่แก้ข้อสอบ)
- **R4:** ผู้สร้างห้าม build / commit / แก้ข้อสอบ · แตะได้เฉพาะไฟล์เจ้าของ §2 ตามเพดานบรรทัดที่ใบระบุ
- **งานตามหลังเมื่อใบนี้และ W1.2a อยู่บน session/trips ทั้งคู่ (ผู้คุมออกใบเล็ก):** แพลตฟอร์มหน้าจองแปลง `HOLD_LIMIT` เหตุ `PUBLIC_UNPAID_SHARE` เป็นรหัสจอ `SLOT_BUSY` + ข้อความไทย/อังกฤษ ("ที่นั่งถูกถือชั่วคราว ลองใหม่ในอีกไม่กี่นาที") · ข้อสอบ w1.2 ที่นับ Party หลังยืนยันล้มคาด 0 · ด่าน `getAvailability` ก่อนยืนยันในแพลตฟอร์มคงไว้เป็นทางลัด
