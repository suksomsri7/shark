## 2. ชนิดร่วม
- ทุกฟังก์ชันบริการ = `(ctx: SellCtx, input) => Promise<SellResult<T>>` (CC :261 :318) · ฟังก์ชัน `*InTx` = `(tx, ctx, input)` ทำงานใน tx ผู้เรียก **ไม่ commit/ไม่เปิด tx เอง** · ไม่ throw ยกเว้นบั๊ก (`class CapacityAbort extends Error { code: SellErrorCode }` จับในตัวห่อแล้วแปลงเป็น `SellResult`; ใน `*InTx` ผลปฏิเสธจากตัวนับ **โยน** `CapacityAbort` ต่อให้ผู้เรียก rollback · สำเร็จคืน `{ok:true, value}`)
- `ctx.now` = นาฬิกาเดียวของทุกการตัดสิน (หมดเวลา · ปิดรับ · เพดาน · rate limit) · ไม่มี ⇒ `new Date()` · **ห้าม `now()` ของฐาน** ในเงื่อนไข (§D.6 :501 เขียน `now()` — ใบนี้ใช้ `$now` จาก ctx · §12)
- zod v4 `z.strictObject` · ช่องแปลก/ชนิดผิด/`qty` ไม่ใช่ int 1–50 = `VALIDATION` · `idempotencyKey` `[A-Za-z0-9_-]{8,100}` (CC :351)
- รหัสพลาด = `SELL_ERROR_CODES` เท่านั้น · `messageTh` ไทย ไม่มีข้อมูลของคนอื่น · ข้ามร้าน/หน่วย/ไม่มีจริง = `NOT_FOUND` ข้อความเดียวกันทุกกรณี (X1) · hold ไม่ใช่ของร้าน/หน่วย = `HOLD_NOT_FOUND`
- `ctx.unitId` ต้องเป็นหน่วย TRIPS ของ `ctx.tenantId` และรอบ/hold ต้อง `unitId = ctx.unitId` · SQL ดิบใส่ `"tenantId"` + `"unitId"` เองทุกคำสั่ง
- ผู้กระทำ: `PUBLIC` (ช่องทาง WEB LIFF EMBED CHAT_AI เท่านั้น · อื่น = VALIDATION) · `STAFF` (สิทธิ์ตรวจที่ action) · `SYSTEM` (งาน/consumer) · `AGENT` ⇒ `FORBIDDEN` `details.reason = "AGENCY_NOT_ENABLED"` จน A1.4 (ค่าตั้ง A16/A17 ยังไม่มีทะเบียน · §11 ข้อ 3)

## 4. ค่าคงที่ (ทุกข้อมีข้อสอบลบ)
1. **ตัวนับ = คำสั่งเดียวต่อแถว** `UPDATE "TripDeparture" SET <ช่อง> = <ช่อง> ± $n … WHERE <เงื่อนไขทั้งหมด> RETURNING …` ผ่าน `tx.$queryRaw` · ทุกผลผ่าน `expectRows(rows, "<รหัส>")` (0 แถว ⇒ `throw new CapacityAbort(code)` ⇒ rollback) · **ห้าม** อ่านค่าแล้วเขียนค่าใหม่ (`SET "held" = ${x}`) · ห้าม `tripDeparture.update*` แตะ `sold|held|reserved` · คำสั่งตาม D.1 ตรงตัว (+ `"tenantId"` `"unitId"` + `"version" = "version" + 1` + `"updatedAt" = now()`)
2. ค่าคงที่ข้อมูล (ทุกขณะ · ข้อสอบสุ่มอ่านระหว่างยิงพร้อมกัน): `0 ≤ sold, held, reserved` · `sold + held + reserved ≤ capacity` · `held = Σ(qtyPublic+qtyAllot)` ของ hold ACTIVE ของรอบ · hold เปลี่ยนสถานะจาก ACTIVE ครั้งเดียวเท่านั้น
3. **FULL** (T0.3 §4 ข้อ 1 ให้ใบนี้): ในคำสั่งเดียวกับตัวนับ `"status" = CASE WHEN "status" IN ('OPEN','GUARANTEED') AND <sold ใหม่> + <held ใหม่> >= "capacity" THEN 'FULL' … END` (เกิดได้เฉพาะ reserved = 0 · เอเจนซี่ยังถือจากโควตาได้) · คำสั่งที่ปล่อยที่: `FULL` ⇒ `GUARANTEED` ถ้า `minPax` ไม่ null และ sold ใหม่ ≥ minPax ไม่งั้น `OPEN` (สูตรเดียวกับ T0.3 §4 ข้อ 4) · ไม่มีคำสั่งที่สองสำหรับสถานะ
4. **ลำดับล็อก §D.5**: ชั้น 0 (advisory เพดาน) → 1a รอบ (หลายรอบเรียง id) → 1b → 2a hold (เรียง id) → 2a′ รายการรอ → 2b การจอง → 2h outbox · ห้ามขอล็อกชั้นต้นหลังชั้นท้าย · 40P01/55P03 ⇒ ลองใหม่สูงสุด 3 ครั้ง แล้ว `BUSY` (ไม่ throw)
5. **ตัวกวาด §D.4**: อ่านครบกำหนดไม่ล็อก (`status='ACTIVE' AND "expiresAt" <= $now ORDER BY "departureId", id LIMIT 200` · ใช้ดัชนีบางส่วน) → tx ละรอบ: 1a lock รอบ → CAS `UPDATE "TripHold" SET status='EXPIRED' WHERE id = ANY($ids) AND status='ACTIVE' AND "expiresAt" <= $now RETURNING …` → คืนตัวนับด้วยผลรวมของแถวที่ CAS ได้จริงเท่านั้น (คำสั่งเดียว) → `TripBooking` ที่ผูก สถานะ `HOLD` หรือ `PENDING` → `EXPIRED` (CAS · version+1 · เรียง id) → OFFERED ของ hold นั้น → EXPIRED → เสนอคนถัดไป → outbox · วนหน้าจนหมดหรือ `signal`/`deadline` · ร้านที่ล้มไม่บล็อกร้านอื่น · สองรอบซ้อน = ผลเดียว (X5)
6. **ระยะถือแยกตาม purpose** (M-3 · N-9): SHOP_CONFIRM/SUPPLIER_REQUEST มีเวลาของตัวเอง ⇒ ตัวกวาดไม่ปล่อยตามเวลาจ่ายเงิน (ข้อสอบ: +16 นาทียังอยู่ · +X2 ชม. หลุด)
7. **เพดานถือ §D.6**: PUBLIC นับ `capKey` (basket) แบบ HOLDS ≤ X10 · เอเจนซี่ (A1.4) แบบ SEATS ≤ A17 · ไม่นับ: STAFF · WAITLIST_OFFER · ย้าย · นับเฉพาะ ACTIVE ที่ `expiresAt > $now` · นับ+INSERT ใต้ advisory lock เดียวกัน · `capKeyHash` = `holdCapKeyHash(capKey)` ทุกแถว (STAFF = `st:<userId>` · SYSTEM = `sys:<job>` · WAITLIST_OFFER = `waitlist:<waitlistId>` — ไม่ถูกนับ · ไม่ปนกับ basket ใด)
