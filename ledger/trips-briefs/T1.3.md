- `outstandingOf` = สถานะใน `BOOKING_OWES_STATUSES` ? `max(0, payable − paid)` : 0
- `moneyStateOf` (ตัวแรกที่จริงชนะ): `collectMode = "AGENT"` ∨ `agentAccountId ≠ null` ⇒ `AGENT_COLLECTS` · `refunded > 0` ⇒ `REFUNDED` · `paid = 0` ∧ (สถานะ `EXPIRED`/`CANCELLED` ∨ `payable = 0`) ⇒ `NONE` · `paid ≥ payable` ⇒ `PAID` · `paid > 0` ⇒ `PART_PAID` · ที่เหลือ `UNPAID`
- `bookingBadgeOf`: `attention` ไม่ว่าง ⇒ `{ kind: attention[0], shape: "alert" }` · `HOLD`/`PENDING` ⇒ `dashed` · `CONFIRMED`/`PART_PAID`/`PAID` ⇒ `solid` · อื่น (`EXPIRED CANCELLED TRAVELLED NO_SHOW` · ไม่รู้จัก) ⇒ `muted` · `kind` = สถานะเดิม
- `listWindowOf` (วันตามเขตเวลาร้าน · `today` = YMD): `upcoming {today, null}` · `today {today, today}` · `tomorrow {+1, +1}` · `next7 {today, today+6}` · `past30 {today−30, today−1}` · `all {null, null}` · `when`/`today` ผิด ⇒ `null` (ข้ามเดือน/ปีถูก)
- `bookingCodeQuery`: trim + ตัวใหญ่ ตรง `/^[A-Z]{1,4}-\d{4}-\d{4,}$/` (= `BOOKING_CODE_RE` ของ numbering — ห้าม import ค่า ⇒ เขียนซ้ำ ข้อสอบเทียบ source) ⇒ คืนตัวใหญ่ · ไม่ตรง ⇒ `null`
- `parseAmountSatang`: ตัด `,` และช่องว่าง · `/^\d+(\.\d{1,2})?$/` · คิดด้วยจำนวนเต็ม (ไม่ผ่าน float · แบบ `bahtToSatang` ของ T1.1) · ผล 1..2,147,483,647 ไม่งั้น `null` (0 ⇒ null)
- `maskPhone`: เอาตัวเลขล้วน · ขึ้นต้น `66` ยาว 11 ⇒ `0` + 9 หลักท้าย · ยาว ≥ 9 ⇒ `"<3 ตัวแรก>-xxx-<4 ตัวท้าย>"` (ภาพ :62 `081-xxx-5523`) · 7–8 ⇒ `"xxx-<4 ตัวท้าย>"` · 1–6 ⇒ `"xxx"` · ว่าง/null ⇒ `null`
- `intentKey` = `` `${prefix}_${seed}_${h}` `` · `h` = FNV-1a 32 บิต (hex 8 ตัว) ของ `JSON.stringify(parts)` · prefix/seed ตัดเหลือ `[A-Za-z0-9]` (prefix ≤ 12 · seed ≤ 40) · ผลตรง `/^[A-Za-z0-9_-]{8,100}$/` (รูปคีย์ของ CC §C ข้อ 3) · ค่าเดียวกัน ⇒ คีย์เดียวกัน · ส่วนใดเปลี่ยน ⇒ คีย์ใหม่
- ไฟล์นี้ไม่มี I/O · ไม่อ่านนาฬิกา (`Date.now` / `new Date()` ไม่มีอาร์กิวเมนต์ ห้าม) · ไม่ใช้ `getDay/getDate/getHours/getMonth/getFullYear`

## 4. ตัวโหลดจอ (`booking-screens.ts` · ส่งออกทาง facade) — ข้อสอบเรียกตรง
ทุกตัว `(ctx: { tenantId; actorUserId }, input, opts?: { now?: Date })` · ด่านลำดับเดียวกับ T1.1/T1.2 (`tripsUnitGate` → `NOT_FOUND`/`UNIT_NOT_TRIPS` → สิทธิ์ ⇒ `FORBIDDEN`) · input zod **strict** (⇒ `INVALID_INPUT`) · ของหน่วย/ร้านอื่น ⇒ `NOT_FOUND` · คืน `{ ok: true, vm } | { ok: false, code, message }` ไม่ throw · **ไม่เขียนฐานเลย** (ไม่มี audit/outbox/งวดร่างถูกเขียน) · บริการที่ต้องการ `SellCtx` สร้างจากด่าน: `{ tenantId, unitId, channel: "COUNTER", actor: { kind: "STAFF", userId: actorUserId }, now, locale: "th" }`

## 5. จอ (ภาพ 18) — แสดงผลเท่านั้น
- **ความกว้าง**: เปลือกแอปที่ 1440 เหลือเนื้อหา ≈ **1,087–1,104 px** (แถบซ้าย ~290 + ขอบ) — ออกแบบสำหรับค่านี้ · ตารางเต็มความกว้าง (ภาพวางแผงจองหน้าร้าน 450 px ข้างตาราง — ใบนี้ไม่มีแผงนั้น) · ความกว้างขั้นต่ำของตาราง: เลขจอง 128 + ลูกค้า·ช่องทาง 176 + ทริป 200 + ยอดรวม 112 + เงิน 136 + สถานะ 148 = **900** + ช่องไฟ ≈ 940 ≤ 1,087 ⇒ ไม่เลื่อนแนวนอนที่ 1440 · ถ้าวางรายละเอียดเป็นคอลัมน์ข้าง (≥ 420 + gap 24) ตารางเหลือ 1,087 − 444 = 643 < 940 ⇒ **รายละเอียดเป็นลิ้นชักทับด้านขวา** (`trips-bk-detail` · `role="dialog"` · กว้าง `min(100vw, 600px)` · หัวตรึง (เลขจอง + สถานะ + ปิด) · เนื้อหาเลื่อน · แถบปุ่มตรึงล่าง) ไม่ใช่คอลัมน์ที่สอง · **2 คอลัมน์ในจอนี้ = ห้าม** จนกว่าเนื้อหา ≥ 1,384 (= 940 + 24 + 420)
