## 4. พฤติกรรม
### 4.1 ก · รอบเต็ม (หน้าสินค้า `t/[productSlug]`)
- `BookFullVM = { want: number | null; left: number; date: string; nearby: { date: string; left: number; href: string }[]; sameDay: { title: BookText; left: number; href: string }[]; contact: BookContact }`
- **มีก้อนเมื่อ** (ตัดสินใน platform): (1) วันที่เลือก (`d`) มีรอบ และ**ไม่มีรอบใดขายได้เพราะเต็ม** (ทุกรอบที่ไม่ปิดเพราะเหตุอื่นมี `publicLeft = 0`) หรือ (2) URL มี `e=SOLD_OUT` (ถือเกินที่ว่าง) — `want` = ผลรวมจำนวนคนประเภทที่นับที่นั่งจาก `n.*` ที่ตรวจรูปแล้ว (ไม่มี/ผิดรูป ⇒ `null`) · `left` = ที่ว่างของรอบที่ระบุด้วย `t` (หรือรอบเดียวของวัน · หลายรอบไม่มี `t` ⇒ มากสุดของวัน)
- **วันใกล้เคียง** (`nearby`): สินค้าเดียวกัน · ช่วง **วันที่เลือก −7 ถึง +7** (ยึดวันที่เลือก ไม่ยึดวันนี้ · อ่าน `listAvailability` ครั้งเดียว 15 วัน) · ตัดวันที่เลือก · ตัดวันที่ไม่มีรอบขายได้ (saleBlock ≠ null · เลยปิดรับ · ผ่านไปแล้ว ตามนาฬิกาของคำขอ) · ต้องมีรอบที่ `publicLeft ≥ max(want, 1)` · `left` = มากสุดของวันนั้น · เรียง |ห่าง| น้อยก่อน แล้ววันก่อนก่อน · **ไม่เกิน 2 วัน** · `href` = `bookSelectHref` ไปหน้าสินค้าเดียวกัน `d=<วัน>` + `m` + `lang` + `n.*` เดิม (ไม่มี `t`)
- **ทริปอื่นวันเดียวกัน** (`sameDay`): สินค้าอื่นของ**หน่วยเดียวกัน** ที่ลูกค้าเห็นได้ (ACTIVE · เผยแพร่ · `bookSaleState = OPEN`) · มีรอบวันเดียวกันที่ขายได้และ `publicLeft ≥ max(want, 1)` · เรียงเวลาออกรอบแรก แล้ว slug · **ไม่เกิน 3** · อ่านไม่เกิน `BOOK_SAMEDAY_SCAN_CAP = 20` สินค้า (เรียง slug) · `href` = หน้าสินค้านั้น `d=<วัน>` + `lang` (ไม่ส่ง `n.*` — ประเภทคนต่างสินค้า) · **ไม่มีราคาในก้อนนี้** (ภาพเขียน "ราคาเท่ากัน" / "฿3,200" — ไม่แสดง เพราะต้องเสนอราคาต่อรายการ · C-4)
- ไม่มีวันใกล้เคียงและไม่มีทริปวันเดียวกัน ⇒ ข้อความ `full.none` + ช่องทางติดต่อร้าน (X30 · ไม่มีช่องทาง ⇒ รูปไม่มีช่องทาง · มติ L8)
- **ไม่มีปุ่มฝากชื่อรอ** ใน a (W1.4c) · ไม่มีคำว่า LINE
- ด่าน: ทุกอย่างอยู่ในเส้นเปิดหน้าเดิม (`openBookProduct`) — ถังอ่านถูกกิน**ครั้งเดียว**ต่อการเปิดหน้า (มติ L6 ของ W1.3) · อ่านล้ม ⇒ ไม่มีก้อนทางเลือก (`nearby: []` `sameDay: []`) ไม่ทำให้หน้าล่ม

### 4.2 ข · ถือที่หมดเวลา (หน้า `my/[token]` สถานะ EXPIRED)
- `BookExpiredVM = { heldUntilDate: string | null; heldUntilLocal: string | null; now: { state: "OPEN" | "LOW" | "FULL" | "CLOSED"; left: number } | null; rehold: { href: string; partial: boolean } | null; full: BookFullVM | null }` · อยู่ใน `vm.expired` เฉพาะเมื่อ `vm.state = "EXPIRED"` (สถานะอื่น ⇒ `null`)
- `heldUntil*` = `expiresAt` ล่าสุดของ `TripHold` ทุกสถานะของการจองนี้ (เวลาร้าน) · ไม่มี ⇒ null (ข้อความรูปไม่มีเวลา)
- **เงิน (ข้อความ):** แสดง "ระบบยังไม่ได้รับเงินสำหรับการจองนี้ ที่นั่งถูกปล่อยคืนแล้ว" เฉพาะเมื่อ `paidSatang = 0` (การจอง EXPIRED มีเงินไม่ได้ตาม `money.ts:130` — เงื่อนไขนี้กันไว้ถ้า W1.4b เปิดทาง) · ห้ามเขียน "ไม่มีการตัดเงิน" (ระบบไม่รู้ว่าลูกค้าโอนหรือยัง · OQ31)
- **ตอนนี้ (`now`):** ที่ว่างของ**รอบเดิม**ตอนนี้ (`getAvailability` WEB) — `CLOSED` = รอบปิด/ยกเลิก/เลยปิดรับ/ออกแล้ว
- **ถือที่ใหม่ (`rehold`):** **ลิงก์ GET** (ไม่ใช่ฟอร์ม · ไม่มี action ใหม่ · C-2) ไปหน้าสินค้าเดิม `d` = วันเดิม · `t` = ตัวอ้างรอบเดิม (`bookPublicRef` slot) · `n.<CODE>` จากบรรทัด SEAT ของ snapshot · `x.<ref>` ของรายการเสริมที่ยังเปิดขาย · `z` เขตรับส่งที่ยังเปิด · `lang` · ราคาใหม่คิดที่หน้าสินค้าตามปกติ (หน้า checkout มีด่าน PRICE_CHANGED เดิม)
  - `partial = true` เมื่อมีบางรายการเดิมจับคู่ไม่ได้ (ประเภทคนปิด · รายการเสริมเลิกขาย · เขตรับส่งปิด) ⇒ ตัดรายการนั้นออกจากลิงก์ + ข้อความ `res.reholdPartial`
  - `rehold = null` เมื่อ: สินค้าไม่ขายสาธารณะแล้ว (`bookSaleState ≠ OPEN`) · รอบเดิม `CLOSED` · การจองผ่านเอเจนซี่ (`collectMode AGENT` / channel `AGENT_*` / agentAccountId — เอเจนซี่จัดการเอง) · snapshot อ่านไม่ได้
  - รอบเดิม FULL ⇒ ยังมีลิงก์ (หน้าสินค้าจะแสดงก้อนรอบเต็มให้) **และ** `full` = ก้อนเดียวกับ §4.1 (ยึดวันเดิม · `want` = ที่นั่งของการจองเดิม) แสดงบนหน้านี้ด้วย
  - ลิงก์**ไม่มี** token ของการจองเดิม · ไม่ส่งชื่อ/เบอร์/อีเมลไปหน้าใหม่ — ลูกค้ากรอกใหม่ (ภาพเขียน "ข้อมูลที่กรอกไว้ยังอยู่ครบ" — ไม่ทำ · C-3)
- **โอนไปแล้ว?** ก้อน `res.expiredPaidTitle` + `res.expiredPaid` (ข้อความเดิม · ติดต่อร้าน + รหัสการจอง) + `res.expiredPaidHow` "ร้านจะตรวจรายการโอนของคุณ และยืนยันการจองถ้ายังมีที่ว่าง หรือคืนเงินเต็มจำนวน" (ไม่มีระยะเวลา · ⚖️ OQ76)
- การจองที่ข้อมูลผู้จองถูกลบแล้ว (piiPurgedAt) ยังแสดงก้อนนี้ได้ (ไม่มีข้อมูลบุคคลในก้อน)
- การจองที่ CANCELLED/ENDED/อื่น ⇒ ไม่มีก้อนนี้ (คงจอเดิม)

# W1.4b — แบบเสนอ (รอมติ C-6 C-7 · ยังไม่มีข้อสอบ)
- **บริการ** `acceptTripPaymentAfterExpiry(ctx STAFF, { bookingId, amountSatang, tender, reference?, idempotencyKey })` (สิทธิ์ `trips.payment.record`) ใน `money.ts` (บล็อกรั้ว) — การจอง `EXPIRED` · `paidSatang = 0` · ไม่มีแถวเงิน · `collectMode SHOP` · THB · ไม่ถูกลบข้อมูลผู้จอง (ถูกลบ ⇒ `STATE_CONFLICT BOOKER_PURGED` เหมือน `payableStatusGate`)
- **ธุรกรรมเดียว** ตามลำดับล็อก D.5: 1a ล็อกรอบ → ลองถือที่เท่าเดิมแบบ STAFF (ไม่นับเพดานลูกค้าออนไลน์ · ตรวจรอบขายได้แบบพนักงาน) → **ได้**: 2a hold ใหม่ (PAYMENT) → 2b การจอง `EXPIRED → HOLD` (CAS version) → รับเงินด้วยตัวเดียวกับ `payTx` (HOLD → PART_PAID/PAID แปลงที่นั่ง) → event `trips.booking.paid_after_expiry {outcome: "REHELD"}` · **ไม่ได้** (เต็ม/ปิด/ออกแล้ว): บันทึก `RECEIVED` บนการจอง EXPIRED + คำขอคืนเงินเต็มจำนวน (`by SYSTEM` · reasonKind ใหม่ `LATE_PAYMENT` หรือ `SHOP` — C-7) + event `{outcome: "REFUND"}` — ไม่มีการคืนเงินอัตโนมัติ (ร้านโอนคืนเอง · SHARK ไม่ถือเงิน — ข้อความต้องไม่บอก "ระบบคืนเงิน")
- ราคา = snapshot เดิม (ยอดที่ลูกค้าโอนตาม QR เดิม) · ยอดไม่เท่าค้างชำระ ⇒ ตาม `payTx` เดิม (น้อยกว่า ⇒ PART_PAID ตามงวด · มากกว่า ⇒ VALIDATION)
- **หน้าลูกค้า:** ถือใหม่ได้ ⇒ PAY/VOUCHER ตามเดิม (รหัสเดิม · token เดิม) · คืนเงิน ⇒ ก้อน "ได้รับเงิน ฿X หลังหมดเวลาถือที่ และรอบนี้ไม่มีที่ว่างแล้ว ร้านจะคืนเงินเต็มจำนวน" + สถานะคำขอคืนเงินแบบ W1.3 (QUOTED/APPROVED/DONE)
- **จอร้าน:** ปุ่มบนรายละเอียดการจอง EXPIRED (T1.3) ⇒ ฟอร์มยอด/ช่องทาง/อ้างอิง → ผล (ถือใหม่ได้ · คืนเงิน)
- **ต้องแก้สัญญา:** G.1 เพิ่มแถว `EXPIRED → HOLD` (STAFF · ไม่มีเงินก่อนหน้า) และ "เงินบนการจอง EXPIRED มีได้เฉพาะคู่กับคำขอคืนเงิน" · H.8 ค่าคงที่เงินรวมกรณีนี้ · ⚖️ คืนเงินที่ได้รับโดยไม่มีสัญญาผูก (หลักลาภมิควรได้ ป.พ.พ. ม.406 [U] — `LEGAL-TRIPS-TH.md` ยังไม่มีหัวข้อนี้ · ต้องให้ทนายดู)
