## 0. Premise
H2.2 gives the H2.1 engine a screen. R2 **Page guard (F16.3) and who sees what.** Page imports `hrViewerOf` (privacy) + `hrScopeOf` (scope); `canReadRoster(v)` = OWNER ∨ MANAGER ∨ `hr.employee.create` (same set as H2.1 R2 reader) else `notFound()` (404, Q1). `canWrite` = OWNER ∨ `hr.employee.create` evaluated (MANAGER passes) — a reader that cannot write gets the grid read-only (no buttons, no drop targets; today no HQC user is in that set — rule kept for future keys). R3 **URL state.** `?week=YYYY-MM-DD` any day ⇒ normalised to its Bangkok Monday (pure `mondayOf`); missing/invalid ⇒ the week containing today (`thaiDateKey(new Date())` on the server, passed down as `todayKey` — the client never reads the clock). `?unit=<unitId>|all`: all-branch viewer ⇒ chips `ทุกสาขา` + every unit of `unitsForScope` (default Q2); restricted viewer ⇒ only its units (one unit ⇒ a static label, no chips); a unit outside scope ⇒ falls back to the default (no refusal page, no leak of the unit's existence). Every engine call gets `{from: monday, to: monday+6}` (7 days ≤ 31) and `unitId` = selected unit or none for `all`.
R4 **Board loader `loadRosterBoard(ctx, viewer, {week, unit, todayKey}) → RosterBoardDto | null`** (null = not a reader). Calls `listRoster` once, `listShifts(ctx,{scope})` (active, shop-wide + scoped units), `listHolidays` for the week's year(s) and the overlay (R6). **Rows** = active, non-ENDED employees in scope on **any** day of the week (union of `unitWhere(scope, day)` over 7 days, then the selected unit: home unit = U or a borrowing into U overlapping the week) ∪ employees owning an in-scope entry of the week (shown even if ENDED since, read-only). Sort (Q3): home-unit rows by `createdAt` asc, then borrowed-in rows. **Row DTO (whitelist):** `{employeeId, name, initial, position|null, probation: boolean, borrowed: boolean, homeUnitName|null (only when borrowed), cells[7], weekMin, shiftCount, leaveDays, warn: boolean}` — never `payType`, rate, salary, national id, SSO, bank, address, phone/email, `pinCode/pinHash`, `linkedUserId`, leave reason, entry `note` (Q13, Q17). **Cell** = `{day, state: "work"|"off"|"out"|"past", entries: EntryDto[], leave?: {status:"APPROVED"|"PENDING", label}}` — `out` = not in the selected unit / outside employment that day (renders `—`), `off` = in unit, no entry (renders `หยุด`). **EntryDto** = `{id, shiftId, label, kind: "m"|"a"|"c"|"x", start:"HH:MM", end:"HH:MM", overnight, paidMin, published, source}` (`start/end` from the entry snapshot, so overrides show their own times). **Day DTO** = `{key, dow, label:"จ. 5", weekend, past (key < todayKey), headcount (distinct employees with an entry starting that day), holiday?: {name, shopOpen}}`. Plus `title`, `desc` parts, `units`, `unitSel`, `canWrite`, `todayKey`, `monday`, `prevMonday`, `nextMonday`, `shifts: [{id, label, kind, startMin, endMin, crossesMidnight, unitId}]`, `unpublishedCount`, `warnings` (engine rows, ids + numbers only), `rulePanel` (R8), `totalMin`, `notes` (holiday lines).
R5 **Shift kinds and labels (Q5).** `kind` from `HrShift.colour`: `shift-1` → `m` (ink outline on surface), `shift-2` → `a` (line/surface-2 fill), `shift-3` → `c` (ink fill, surface text), anything else / null → `x` (ink-soft dashed outline); no new CSS token, no hex. R6 **Leave overlay (new, read-only, F5).** `rosterLeaveOverlay(ctx, viewer, {from,to}, employeeIds)` in `roster-board.ts`: `HrLeave` rows with `status IN (PENDING, APPROVED)` overlapping the week for the given (already scoped) ids, via `tenantDb(ctx)`; per covered day `{employeeId, day, status}`; label = policy name (or category label) for viewers with `hrAccessOf(v).readLeave`, else `ลา`; status sub-label `รออนุมัติ` for PENDING, none for APPROVED. **Never** `reason`, attachment, `filedById`, days/hours.
