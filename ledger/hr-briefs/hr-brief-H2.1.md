R4 **Generate from template (`source TEMPLATE`).** For each in-scope employee with `active && employmentStatus ≠ ENDED` (PROBATION included) and each day in range inside `[startDate, endDate ?? contractEndAt ?? ∞]`: weekday via `bkkParts`-equivalent of `bkkMidnight(day)`; template row missing or `dayOff` ⇒ nothing; else resolve the shift (Q2 default: active `HrShift` with the same `startMin/endMin`, `crossesMidnight=false`, unit = entry unit first, then shop-wide, lowest `sortOrder`, then id; none ⇒ skipped `NO_SHIFT`, no shift is auto-created). **Never overwrites:** an employee-day that already has any entry (any source, published or not) is skipped `EXISTS` — Q8 decides whether unpublished TEMPLATE rows are refreshed. Closed holiday (R6) ⇒ skipped `HOLIDAY`. Snapshot = the shift's `startMin/endMin/breakMin/crossesMidnight` at write. Idempotent: second run ⇒ `created: 0`, zero writes. One audit row `hr.roster.generate` `{systemId, unitId, from, to, created, skipped}` (counts only).
R5 **Manual ops (`source MANUAL`).** `addEntry`: employee active/not ENDED (`"พนักงานคนนี้พ้นสภาพแล้ว — จัดกะไม่ได้"`), date inside employment (`"วันนี้อยู่นอกช่วงการจ้างของพนักงานคนนี้"`), shift active + same system (`"กะนี้ปิดใช้แล้ว — เลือกกะอื่น"`; a `sys2` shift id ⇒ `"ไม่พบกะนี้ — กรุณารีเฟรช"`, FK does not check the system — review §2.1), snapshot from the shift, optional time override (Q7) validated by `shiftTimesProblem` (`crossesMidnight` derived), duplicate `(employeeId,date,shiftId)` ⇒ `"พนักงานคนนี้มีกะนี้ในวันนั้นแล้ว"` (23505/P2002 is the race guard).
