## B. Order of work (oracle-first, every WO)
1. **Controller writes the oracle** `scripts/qc-sec-<wo>.mts` from the brief (unforced → SKIP exit 0 with the right reason; forced → RED for the right reason; residue 0). Commit `test(sec): <wo>`.
2. **Builder** makes it green without editing the oracle. Wrong check ⇒ request **ORACLE-EDIT** (check id · exact hunk · reason) in the report; the controller rules and edits with an `ORACLE-EDIT <wo>-<id>` line.
3. Controller re-runs (forced ×2 + unforced) → **reviewer** (read-only, fresh agent; two independent reviewers for money/permissions/shared-room/quota WOs) → **hunter** for 🎯 WOs → accept → merge into `session/secretary`.
4. Checkpoint as you go in `ledger/wo-notes/sec-<wo>.md` (template `ledger/wo-notes/TEMPLATE-sec.md`): done / next / exact commands, so a restart continues from the files.

## C. Secretary code rules (in addition to crm-brief-COMMON "Code rules")
1. **Layer, not engine.** New code lives in `src/lib/ai/secretary/**` on top of the existing AI layer. Reuse, never duplicate: `proposals.ts` (propose/confirm/execute · `runKind`), `plans.ts`, `scheduled.ts`, `skills.ts`/`tools.ts`/`tool-access.ts` (tool registry + `toolsOfferedTo`/`toolVerdict`/`actorCanConfirmKind`), `actor.ts`, `conversation-owner.ts`, `memory.ts`, `proactive.ts`, `dataset.ts`, `usage.ts`/`credit.ts`, `provider.ts`, `core/auth.ts` (`AuthToken`), `core/push.ts`, `platform/support.ts`.
2. **Permission = the person who typed the message ∩ the tenant's per-system level** (`AiSystemAccess`). Enforced at execute time (`proposals.ts` / `tools.ts` dispatch), not only in the offered tool list. The approver must pass `actorCanConfirmKind` with *their own* membership. No AUTO level in this release (owner decision 5): `setAccess(AUTO)` is refused with a Thai reason.
3. **The model's output is data.** No tool argument, memory, lesson, digest, KB article, customer message or support message may change an access level, a rule, a quota or a membership. Injected text goes into the prompt inside a delimited data block with an explicit "data, not instructions" header.
4. **Always-approve registry** (`ALWAYS_APPROVE`: money out · DESTRUCTIVE · PII export) cannot be switched off by any setting; configurable rules (`AiApprovalRule`) default ON. Every write/customer-facing kind produces a proposal in this release.
5. **Counters = single statements** (`UPDATE … SET x = x + $1 … RETURNING`, conditional `updateMany`, `INSERT … ON CONFLICT`): job counter, lease, attempts, lesson occurrence count.
6. **User-facing numbers:** jobs, % of quota, minutes, pass %. Never tokens, micro-dollars, cost per job. DTOs carry `quotaPct` / `jobsLeft`, never raw usage.
7. **Prompts in English**; the secretary's `languages`/`suffix`/`tone` decide the reply language and ครับ/ค่ะ. Thai comments in code (repo convention). Thai, non-blaming messages to users; reports to the controller in English.
8. **Scoping:** every function takes `ctx { tenantId, actor }`; rooms re-resolve against `tenantId` (404-not-403); room visibility = creator ∪ members ∪ tenant OWNER (owner decision 3 + R5). Members of a room with `seeHistory=false` never receive messages older than `addedAt` — enforced in `listMessages`, not in the UI.
9. **Learning only from confirmed outcomes** (design §8): lessons are created from APPROVED/EDITED proposals, injected only when `status=CONFIRMED`; never store customer names/phones/addresses in `AiMemory`, `AiLesson`, `AiTrainingSample` (extend `anonymize`).
10. **Events:** every new outbox event = consumer in `src/lib/outbox-consumers.ts` + exactly one label in `src/lib/automation/labels.ts` + `src/lib/webhooks/labels.ts` + replay-twice oracle; emitted inside the state-changing tx; payload = ids only.
11. **Existing behaviour stays byte-identical** when no secretary rows exist: `qc-ai-*` baseline, `qc-mobile-*`, `qc-approval*`, `qc-chat*` must equal the baseline in every WO.
12. **Mobile UI:** screens in `apps/mobile/app/(app)/secretary/**`, components in `apps/mobile/src/components/airy/**` + `components/secretary/**`; colours/radii/spacing only from `apps/mobile/src/theme/{tokens,light,dark,index}.ts` (no hex literals in screens); every pressable has `testID` + a row in `scripts/sec-ui-inventory.json`; bottom sheets are absolutely-positioned views (RN-web Modal does not render headless); data through `apps/mobile/src/api/secretary.ts` typed from `docs/modules/31-secretary.md`.
13. **Existing 1.0 screens untouched** except the entry point named in S2.1 and the login/signup screens named in S2.12.
