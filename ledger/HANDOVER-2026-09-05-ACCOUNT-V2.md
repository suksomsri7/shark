## 3. ของที่ยังไม่ทำ / ทำได้ไม่เต็มร้อย (รวมจาก wo-notes ทุก WO — จัดกลุ่มตามหมวด)

> "ค้าง" ทุกข้อด้านล่างไม่ใช่บั๊กที่หลุดโดยไม่รู้ตัว — เป็นสิ่งที่ทีมงานเห็นแล้วแต่ตัดสินใจเลื่อนไปทำทีหลังหรือไม่ทำในรอบนี้ (มีเหตุผลกำกับทุกข้อ)

### 🕓 ประกาศไว้ล่วงหน้าว่ายังไม่ทำในรอบนี้ (ไม่ใช่ของหลุด)
- **e-Tax Invoice ส่งจริง** และ **DBD e-Filing ส่งจริง** — ต้องสมัครผู้ให้บริการภายนอกก่อน (งาน ops ไม่ใช่โค้ด)
- **Bank feed อัตโนมัติจากธนาคาร** — ตอนนี้ต้องอัปโหลด statement เอง (ไฟล์ CSV) แล้วระบบจับคู่ให้
- **มูลค่าสินค้าคงเหลือแบบ FIFO เต็มรูป** — ตอนนี้ตัดแค่จำนวน ยังไม่คิดต้นทุนอัตโนมัติแบบ FIFO
- **e-WHT (ยื่นหัก ณ ที่จ่ายทางอิเล็กทรอนิกส์)** — ตอนนี้ export ไฟล์ให้เอาไปยื่นเว็บสรรพากรเอง
- **Smart Insight (คำแนะนำภาษีอัตโนมัติจาก AI)** — ยังเป็นแค่หัวข้อจางในหน้าตั้งค่า

### เอกสาร/ใบต่าง ๆ
- **ใบรวมจ่าย (RPR)** ยังไม่มีหน้ารายการ/หน้ารายละเอียดของตัวเอง — เพราะโฟกัสรอบนี้อยู่ที่ทำให้สร้างได้ก่อน
- **หน้าตั้งใบเบิก/คืนสินค้า/ใบปรับต้นทุน (CA)** ยังไม่มีหน้ารายละเอียดและแก้ร่างไม่ได้หลังบันทึก — ของใหม่ในเฟส 4 เน้นให้ "สร้างได้ถูกต้อง" ก่อน "แก้ไขสะดวก"
- **ยกเลิกใบวางบิล/ใบรวมจ่าย** ที่มี WHT พร้อมกัน หรือ **จ่ายพร้อมค่าธรรมเนียมเช็ค** พร้อมกันหลายอย่าง — เคสซ้อนกันหลายชั้นยังไม่ครอบทุกทาง
- **แปลงร่างส่วนลด** เอกสารเก่าบางใบปัดเศษไม่ลงตัว (ต่างได้สูงสุด 1 สตางค์ต่อ 1 หน่วยสินค้า) — เป็นข้อจำกัดทางคณิตศาสตร์ของการปัดเศษ ไม่ใช่บั๊ก

### ผู้ติดต่อ/ลูกค้า
- **แชท (LINE) ยังไม่เชื่อมชื่อผู้ติดต่อกับ Party อัตโนมัติ** — ทำได้ครึ่งทาง (คอลัมน์พร้อมแล้ว) ต้องให้ทีมแชทเชื่อมต่ออีกฝั่ง — ทำไม: เพื่อไม่ให้แตะโค้ดโมดูลแชทข้ามทีมโดยไม่ได้คุยกันก่อน
- **รหัสไปรษณีย์ไม่กรอกอัตโนมัติจากอำเภอ/จังหวัด** — ยังไม่ได้ผูกฐานข้อมูลรหัสไปรษณีย์
- **ผู้ติดต่อที่เบอร์เดียวกันแต่ไม่อยากรวมกัน** กด "ไม่ใช่คนเดียวกัน" ถาวรไม่ได้ (เตือนซ้ำทุกครั้ง) — ต้องเพิ่มตารางเก็บการตัดสินใจนี้ต่อคู่ ยังไม่ได้ทำ
- **การ์ดแต้มสะสม/ประวัติการจอง/ประวัติแชท** ในโปรไฟล์ผู้ติดต่อยังไม่เชื่อมจริง (เห็นแต่โครง)

### สินค้า/คลัง/POS
- **บิล POS ยังไม่โยงไปที่ "ช่องทางเงิน" ในหน้าบัญชี** — เห็นว่ามีรายได้เข้าแต่ยังไม่เห็นว่าเงินไปอยู่ช่องไหน (ต้องเพิ่มการบันทึกการชำระของบิล POS)
- **ไม่มีตัวกันเอกสาร POS ซ้ำ** ถ้าระบบยิงซ้ำ (เช่น retry) อาจสร้างเอกสารซ้ำได้ — ความเสี่ยงต่ำเพราะมี idempotency key ชั้นอื่นกันอยู่แล้ว แต่ยังไม่มีดัชนีกันซ้ำระดับฐานข้อมูล
- **ยกเลิกสินค้าจัดชุด (bundle) ไม่คืนสต็อกส่วนประกอบ** — เคสที่ยังไม่ครอบ

### การเงิน
- **กระทบยอดธนาคาร**: ยังไม่รองรับไฟล์ TIS-620 (encoding เก่าของบางธนาคาร) รับแค่ UTF-8 · ปุ่ม AI ช่วยแนะนำการจับคู่ยังไม่ทำงานจริง (โครงมีแล้ว)
- **เช็ครับ/จ่าย**: ฟอร์มสร้างยังไม่มีช่องเลือกผูกกับเอกสาร (ฟังก์ชันหลังบ้านรองรับแล้วแต่หน้าจอยังไม่มีปุ่มให้เลือก)
- **ใบ 50 ทวิ**: ชื่อผู้รับเงินยังไม่แยกคำนำหน้าชื่อ (นาย/นาง) ออกจากชื่อ — ใช้ชื่อเต็มเป็นสตริงเดียว

### บัญชี
- **งบทดลอง "งวดก่อน"** แสดงเป็นยอดยกมาสะสม ยังไม่ใช่ยอดเคลื่อนไหวเฉพาะงวดนั้นเทียบกัน (ต้องระวังตอนอ่านเทียบเดือน)
- **ยังไม่มีตัวกรองแยกตามสาขา** ในรายงาน (ระบบยังออกแบบเป็น 1 ระบบบัญชี = 1 ชุดบัญชี)
- **พิมพ์งบการเงินใช้ปุ่มพิมพ์ของเบราว์เซอร์** (window.print) ยังไม่มี PDF generator ของตัวเอง

### คลังเอกสาร
- **ยังไม่มีถังขยะ/กู้คืนไฟล์ที่ลบ** ในคลังเอกสาร
- **รับอีเมลเข้ากล่องขาเข้าอัตโนมัติ (inbox@...)** ยังทำไม่ได้ — ต้องสมัครผู้ให้บริการรับอีเมล (เช่น Postmark/Mailgun) ก่อน แล้วมาต่อสาย (ดูหัวข้อ env vars)
- **อ่านไฟล์ PDF ด้วย AI** ยังไม่รองรับ (รองรับแค่รูปภาพ) — ต้องมีตัวแปลง PDF→รูปก่อน

### มือถือ
- **ตารางงบดุล/กำไรขาดทุน/กระแสเงินสด** บนมือถือยังไม่ตรึงคอลัมน์แรกไว้ตอนเลื่อน (งบทดลอง/ภ.พ.30 ทำแล้ว)
- **ตารางในหน้าใบวางบิล/ใบรวมจ่าย (รายการย่อย)** บนมือถือยังเป็นตารางเลื่อน ไม่ใช่การ์ด

### อื่น ๆ
- **`pnpm audit` เจอช่องโหว่ 32 รายการ** — ทั้งหมดเป็นของ library ที่ next.js/prisma พึ่งพา (transitive) ไม่ใช่โค้ดของทีม รอ upstream อัปเดต
- **สีเข้ารหัสตรง (hex) หลงเหลือ 23 บรรทัด** ในกราฟ/ป้ายสถานะบางจุด — ใส่ allowlist กันลามไปที่อื่นแล้ว ของเดิมยังไม่ได้แก้ทั้งหมด

## 4. หลักฐาน QC ก่อนปิด run (ทำจริง เห็นภาพจริง ไม่ใช่แค่รายงานจาก AI)

- **`pnpm qc:all` เขียว 227/227** ครอบ **46 ชุดทดสอบอัตโนมัติ** (`qc-acc-v2-*.mts`) — ทำบัญชีจำลองครบเดือนจริง (ลูกค้า/สินค้า/เอกสารตามตัวเลขที่รู้คำตอบล่วงหน้า) เทียบทุกยอดเป๊ะ ไม่ใช่แค่ "รันผ่านไม่ error"
- **ตรวจความปลอดภัย (WO 9.2): 20 ข้อ** — พบและปิดช่องโหว่จริง 11 ข้อ ที่สำคัญที่สุดคือ **รับชำระเงินซ้อนกันพร้อมกัน 2 ครั้งเคยจ่ายเงินซ้ำ 2 เท่าได้** (ตอนนี้ล็อกแถวกันแล้ว), ลิงก์ขอใบกำกับสาธารณะเคยขอได้แม้ปิด/หมดอายุแล้ว, ช่องโหว่แทรกสูตร Excel ในไฟล์ export 4 จุด, ไม่มีการจำกัดจำนวนครั้งเรียก API (rate limit) เลย — เพิ่มแล้ว 6 จุด
- **ประสิทธิภาพ (WO 9.3)**: ทำเครื่องมือวัด 29 หน้าที่ใช้บ่อย — จากที่เกินงบ (จำนวน query มากเกินไป) 14 หน้า แก้เหลือ 0 หน้า, เพิ่ม index ฐานข้อมูล 2 ตัว
- **ตรวจภาพหน้าจอจริง (visual QC)**: ถ่ายภาพหน้าจอจริงเทียบกับภาพที่เจ้าของอนุมัติไว้ — **coverage ล่าสุด 34 เฟรม** (จากทั้งหมด f1–f14 รอบแรก + g1–g20 รอบสอง) ตรวจทั้งเดสก์ท็อป (1440px) และมือถือ (390px) — บางจุดตีกลับให้แก้จนภาพตรง 100% ก่อนปิด ไม่ใช่ "ใกล้เคียงพอ"

## 5. ถ้า session ใหม่ต้องมาทำต่อ (วิธีกลับมาต่อได้โดยไม่เริ่มใหม่)

1. `cd /root/projects/shark-accounting && git pull --rebase`
2. อ่าน `ledger/ACCOUNT-V2-RUN.md` หัวตาราง "WO ปัจจุบัน" — จะบอกว่า WO ไหนกำลังทำ ทำถึงขั้นไหน ติดอะไรอยู่
3. อ่าน `ledger/wo-notes/<WO>.md` ของ WO ที่ค้าง — มีรายละเอียดทุกขั้นที่ทำไปแล้ว
4. `git status` — ถ้ามีไฟล์ dirty แปลว่าเป็นงานค้างของ WO นั้น (ห้ามลบทิ้งแล้วเริ่มใหม่)

6. เอกสารอ้างอิงอื่น: พิมพ์เขียว `docs/design/account-v2/BLUEPRINT-ACCOUNT-V2.md`, สเปคหน้าจอ `docs/design/account-v2/DESIGN-SPEC-V2.md`, ผังเมนู `docs/design/account-v2/SITEMAP.md`, สเปคฟังก์ชันเต็ม `docs/modules/12-account.md` (อัปเดตแล้วให้ตรง V2 ในรอบนี้), มาตรฐาน UI `docs/UI_STANDARD.md`
