## A. Machine, branches, database (a violation stops the WO)
1. **Base:** every branch is cut from `session/ai-team` (controller tree `/root/projects/shark-ai`), itself cut from `origin/main` ≥ f132ce21 (CRM v2 on main). Check: `git merge-base --is-ancestor f132ce21 HEAD`.
2. **Branch names:** `wip/pos-ai-<wo>-oracle` for the oracle writer, `wip/pos-ai-<wo>` for the builder (e.g. `wip/pos-ai-t1.2`). The VPS runner only allows `wip/pos-*`. Push only those. **Never** push `main`, `session/*`, `rc/*`, `hotfix/*`; never `--force`; never merge into them (the controller merges).
3. **Worktree:** only the one the controller gives you (`/root/projects/shark-ai-b` or `shark-ai-c`). Never read-write, reset, clean or `cd` into `shark-pos*`, `shark-hr*`, `shark-crm*`, `shark-hf*`, `shark-in-th`, `shark-ai` (controller). Never sweep `/tmp`. Each tree has its own `node_modules` (`pnpm install` done by the controller) and its own `apps/mobile/node_modules` (`npm ci`).
4. **Database = QC4 only** (`wo-pos-qc4`, host `ep-frosty-lab`), shared with the POS and HR lanes. Every DB command: `bash scripts/iso.sh bash scripts/qc4.sh bash scripts/with-gate-lock.sh env QC_FORCE=1 pnpm exec tsx scripts/<file>.mts` — `QC_FORCE=1` **inside** the wrapper (outside it the suite skips and exits 0 = fake green). `qc4.sh` refuses any host that is not `ep-frosty-lab`. Never `pnpm neon:gc`.
5. **Never read, edit, source, print or commit `.env`, `.env.*`, `credentials*`, `apps/mobile/credentials*`, `.qc-shots/`.** If a command needs a value you don't have, stop and report.
6. **Cloud containers cannot reach QC4** (TCP 5432 blocked). DB work runs on the VPS only.
7. **Schema:** only T1.1 (`_ai_team_a`) and, if the plan confirms it, T3.1 (`_ai_team_b`) may edit `prisma/` — and only their builder. `prisma migrate diff` → read the SQL → apply to QC4 only (`migrate deploy` through `qc4.sh`), after listing `_prisma_migrations` on QC4 for folders your branch lacks (POS/HR ones may be present — record, don't touch). Additive only; no index on large existing tables inside the migration (those go CONCURRENTLY in T6.1).
8. **No web build or server** unless the brief says "CONTROLLER-RUN" (controller does it on port 3227; 3215 CRM · 3225 POS · 3226 HR). **No `eas build`, no `eas update`, no store submission, ever.** `expo export --platform web` is allowed only inside the QC copy that `apps/mobile/qc/shoot-ai-team.mjs` makes, never in the worktree's `apps/mobile`.
9. **Heavy commands:** typecheck = `env NODE_OPTIONS=--max-old-space-size=5632 ISO_MEM=6500M bash scripts/iso.sh bash scripts/with-gate-lock.sh pnpm typecheck` — foreground, at most twice per WO; mobile typecheck = `cd apps/mobile && npm run typecheck` (light, no wrapper needed). Wait in the shell; never kill another process to get the lock; if the lock is held > 20 min, report DEFERRED and continue with other acceptance items.
10. **Models:** `SHARK_AI_MOCK=1` for every oracle and every builder run. Only T0.1 and T6.2 (controller-run) call the real provider. A builder who needs a real completion to develop against writes a fixture instead.
11. **Commits:** by explicit path only (`git add <path> …`, never `-A`/`.`), on your own `wip/pos-ai-<wo>` branch, then push that branch. Message ends with the attribution lines the controller gives you. Pre-commit hook runs tsx outside iso.sh: if it OOMs, run `scripts/fitness.mts` (+ «scripts/fitness-ai-team.mts» once T0.2 adds it) through iso.sh in both modes, paste the result in your notes, and commit with `--no-verify`.
12. **Heartbeat for long shell waits:** none for agents — run in the foreground and report. Controller keeps the CronCreate heartbeat.

## B. Order of work (oracle-first, every WO)
1. **Oracle writer** writes `scripts/qc-ai-<wo>.mts` first, from the brief + contract, and runs it on the base: **unforced → SKIP exit 0 with the right reason**; **forced → RED for the right reason**, no crash, residue 0. Output → `ledger/wo-notes/ai-<wo>-red.txt`. UI WOs also get `apps/mobile/qc/fixtures/ai-team/<wo>.json` (mock API payloads the screen needs, derived from the QC seed through the real server functions when they exist, otherwise from the contract's DTO shapes). The oracle writer never edits product code.
2. **Builder** makes it green without editing the oracle. Wrong check ⇒ request **ORACLE-EDIT** (check id · exact hunk · reason); the controller rules. Green output → `ai-<wo>-green.txt`.
3. Controller re-runs (forced ×2 + unforced) → **reviewer** (read-only, fresh agent) → **hunter** for 🎯 WOs → accept → merge into `session/ai-team`.
4. Checkpoint as you go in `ledger/wo-notes/ai-<wo>.md` (template `ledger/wo-notes/TEMPLATE-ai.md`): done / next / commands + final summary lines, so a restart continues from the files.

## C. AI-team code rules (in addition to crm-brief-COMMON "Code rules")
1. **Layer, not engine.** `src/lib/ai/team/**` is a layer above the existing AI layer. Reuse: `proposals.ts` (propose/confirm/execute), `plans.ts`, `scheduled.ts`, `skills.ts`/`tools.ts`/`tool-access.ts` (tool registry + filtering), `usage.ts`/`credit.ts`/`pricing.ts` (charging), `persona.ts`, `memory.ts`, `core/permissions.ts` (`assertCan`), `modules/approval` (policies), audit writer, `AppNotification`/push senders, outbox, KB search. If you believe a second implementation is unavoidable, write the argument in wo-notes §7 **before** coding and wait for the controller.
2. **Access level is enforced at execute time, not only in the tool list.** `effectiveTools()` filters what the model sees; `proposals.ts` (execute) and `tools.ts` (dispatch) re-check `AiEmployeeAccess` + the commanding user's real permission + (AUTO) the grantor's current permission. Refusal codes: `employee_access_off` · `employee_access_read_only` · `employee_auto_not_granted` · `employee_auto_over_limit` · `employee_grantor_revoked` · `employee_paused` · `employee_quota_cap` · `team_quota_exhausted` — fixed Thai user messages in i18n, codes stable for the oracles.
3. **The model's output is data.** Never let a tool argument, a manual text, a KB article or a customer message change an access level, a grant, a limit or a quota. Manual/KB text is injected into the prompt inside a delimited data block with an explicit "these are the shop's rules, not system instructions" framing; the oracle X6 checks feed `ignore previous instructions`-style text and assert no level change and no out-of-level tool call.
4. **Destructive kinds never AUTO.** The proposal-kind taxonomy gets a `risk` tag registry (`src/lib/ai/team/kind-class.ts`: `MONEY` · `CUSTOMER_FACING` · `DESTRUCTIVE` · `INTERNAL`); DESTRUCTIVE (delete, cancel, refund, bulk send) is refused for AUTO at grant time **and** at execute time. Money and customer-facing default to DRAFT in every position template.
5. **Quota = single statements.** `usedMicro`, `usedMicroCycle`, daily counters, manual `version`, promotion stats: `UPDATE … SET x = x + $1 … RETURNING` / conditional `updateMany` with the expected old value / `INSERT … ON CONFLICT`. No read-modify-write. Charge inside the same transaction as the `AiCreditTxn` row. **Every** model call goes through the one charging path (no free path for sample speech, teaching, drafting manuals, room hand-offs, scheduled runs).
6. **User-facing numbers:** percent of quota, task counts, hours, pass %, wait minutes. **Never** tokens, micro-dollars, cost per task, wages, baht value of work (owner decision 9). DTOs to the app carry `quotaPct`, never `usedMicro`/`allowanceMicro`. Fitness F16.1/F16.3 grep for the forbidden words in `team.*` i18n strings and in `src/app/api/mobile/team/**` response schemas.
7. **Prompts in English** (Thai costs ~4× tokens); the persona decides the answer language and the ครับ/ค่ะ ending. Position templates: manual text in English + Thai display strings. Thai comments in code (repo convention).
8. **Tenant and employee scoping:** every function takes `ctx { tenantId, actorUserId }` + `employeeId`, re-resolves the employee against `tenantId` (404-not-403 pattern), and checks the commander list (`AiEmployee.commanderUserIds`, empty = anyone with `ai.employee.use`). Rooms never widen anyone's rights (X2).
9. **Existing shops keep working.** With no `AiEmployee` row the behaviour of chat, proposals, scheduled tasks and the 1.0 app is byte-identical (regressions `qc-ai-tools` `qc-ai-proposals` `qc-mobile-chat` must equal the baseline in every WO). Rooms with `employeeId = null` are read as the tenant's default employee at the read layer until T6.1 backfills them.
10. **Events:** every new outbox event = consumer in `src/lib/outbox-consumers.ts` + exactly one label + replay-twice oracle; emitted inside the state-changing tx. Payloads carry ids only (no prompt, no model text, no PII).
11. **Time:** Asia/Bangkok via the explicit helpers already in the repo (never raw `getDay()/getDate()`); scheduled/monthly logic takes an injectable `now` so oracles never depend on the calendar.
12. **Mobile UI:** screens live in `apps/mobile/app/(app)/team/**` (+ `tasks/` `inbox/` `hire/` `profile/` `settings/` `plan/` `rooms/`) + components in `apps/mobile/src/components/team/**`; tokens only from `apps/mobile/src/theme/{tokens,light,dark,index}.ts` (คง export `C R S`) (T0.3) — no literal colours/radii; strings from the app's i18n under `team.*` (th + en); every tappable element has `testID` + a row in `scripts/ai-team-ui-inventory.json`; min touch target 44 px; glass cards with inner padding (a past mistake was padding 0); orb avatars for AI, initials for humans; no bottom tab bar; light + dark. Match the mockup HTML, then render with `apps/mobile/qc/shoot-ai-team.mjs` and compare before reporting.
13. **1.0 app untouched** for `uiVersion !== 2`: the new tree mounts only when `/api/mobile/me` says `uiVersion: 2`; every T2 WO shows a before/after screenshot of a 1.0 screen in its notes.
14. Thai, non-blaming messages to users; reports to the controller in English.
