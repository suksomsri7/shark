# C2.5 — E-mail engine (decision C4) — the largest and most exposed work order of the run
Read `crm-brief-COMMON.md` first. Contract: CRM-RUN §2 "C2.5". Spec: blueprint §5.6, §11.4, mockups 08 (centre), 15. Split between two builders if the controller wishes: (a) transport + inbound + tracking, (b) UI + templates + settings.

## Facts
- `src/lib/core/email.ts`: `sendEmail(to, subject, text)` — text only, never throws, no id returned; env `RESEND_API_KEY`, `EMAIL_FROM`. MANY callers — its behaviour must not change.
- Inbound: `src/app/api/email/inbound/route.ts` (secret header `X-Inbound-Secret`, 10 MB cap, always 200 after the gate, accepts Resend and Cloudflare shapes) → `src/lib/platform/kanban-email-in.ts#ingestInboundEmail` (dedupe `email:<messageId>`, 20 attachments × 10 MB). Plus-address pattern to copy: `src/lib/modules/kanban/boards-email.ts` (`งาน+<key>@` / `tasks+<key>@`, 8-char base32 key, rotate).
- No bounce webhook, no verified-domain model (table `EmailDomain` arrives in C2.0).

## Deliverables
1. `src/lib/core/email.ts`: NEW `sendEmailRich({from?, fromName?, replyTo?, to[], cc?, bcc?, subject, html, text?, headers?, attachments?}) → {ok, providerId?, error?}`; `sendEmail` untouched. Header values are rejected if they contain CR/LF (X6).
2. `emails.ts`: `resolveRouting` (shop settings × per-user override; from-domain only when `EmailDomain.status=VERIFIED`, else `{slug}@shark.in.th` with the staff display name) · `sendEmail` (opt-out/bounce/consent check at SEND time → `EMAIL_BLOCKED`; pixel + link wrapping per switches; `List-Unsubscribe` + one-click unsubscribe; Message-ID/In-Reply-To/References; copy-to; scheduled send as a minute job with LEASE) · `ingestInbound` for prefix `crm+<key>@` routed from the existing inbound route BEFORE the board handler (board mail must keep working) — 6 matching cases, 3-layer threading, BCC capture, stranger→lead switch, auto-reply/bulk detection, attachments stored PRIVATE · tracking `GET /t/o/[token].gif`, `GET /t/c/[token]` (302 ONLY to the URL stored for that token; bot filter) · unsubscribe page · Resend webhook route with signature verification (delivered/bounced/complained) · templates · user settings · rotate inbound key · domain verify flow (DNS records shown; status polled) · test send.
3. UI: `/emails` inbox (incl. "unmatched"), thread view, composer (template, attach, schedule), `/settings/email` (mockup 15) incl. per-user override table.
4. **Rendering inbound HTML**: sanitize with the existing allowlist sanitizer (`src/lib/core/sanitize.ts`) AND render inside `<iframe sandbox>` (no scripts, no same-origin), remote images blocked by default with a "show images" click; attachments are download-only links from C0.4.
Events `crm.email.sent/received/opened/clicked/replied/bounced`.

1. **`CrmEmailMessage.messageId` is globally unique in C2.0** (migration `crm_v2_b`, already deployed — the oracle must not change it). One customer mail BCC'd to two shops must therefore still land once per system ⇒ the builder stores a **system-scoped** value that still *contains* the RFC Message-ID (e.g. `<systemId>:<rfcId>`), and dedupe is "one row per (system, RFC Message-ID)". Checks `C2.5-X4.1` (replay + parallel ⇒ one row, one activity, one event, attachment uploaded once) and `C2.5-X4.4` (two systems ⇒ one row each). Controller: accept, or have C6.1 relax the unique index.
2. **Every outgoing CRM e-mail carries an unsubscribe link** — `<APP_URL>/u/<token>` in the body *plus* `List-Unsubscribe` + `List-Unsubscribe-Post: List-Unsubscribe=One-Click` (RFC 8058) — including 1-to-1 sales mail and replies, not only marketing. Reason: Gmail/Yahoo bulk-sender rules and PDPA. The unsubscribe link is never wrapped by click tracking and survives `trackingOptOut`. Checks `C2.5-S2.3`, `C2.5-X8.2`. Controller: accept, or restrict the footer to non-transactional mail (then ORACLE-EDIT those two checks).
3. **`CRM_EMAIL_DEFAULTS` gains `fromAddr`** (blueprint §4.5 lists `fromMode` but no address to use in `DOMAIN` mode) and fixes `retentionDays: 730`, `allowUserOverride: true`. Settings live in `AppSystem.settings.crm.email`, written with the single-statement `jsonb_set` pattern; other `settings.crm` keys must survive (`C2.5-S1.*`, `C2.5-U.1`).
4. **Outbox payloads of `crm.email.*` carry ids only** — `{ emailId, contactId?, dealId?, companyId?, threadKey, sequenceStepId? }`. In particular the **clicked URL stays in `CrmEmailEvent`** and never enters an outbox payload, an `OpsEvent` or a log line, alongside the usual no-address/no-subject/no-body rule (X8).
