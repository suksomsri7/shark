## วิธีสร้างคีย์ API ใช้งานจริง

1. เข้าเมนูบัญชี (สมุดบัญชีของร้าน) → **ตั้งค่า › การเชื่อมต่อ**
2. เลื่อนไปหัวข้อ **"แอปภายนอก / API"**
3. กรอกชื่อคีย์ (เช่น "ระบบขายหน้าร้าน" หรือ "AI ผู้ช่วยบัญชี")
4. เลือก **ชุดสิทธิ์ (bundle)**:
   - **อ่านอย่างเดียว** — ให้แอปที่แค่ดูรายงาน
   - **ออกเอกสารและรับเงิน** (ค่าเริ่มต้น) — ให้แอปขายที่ต้องออกใบแจ้งหนี้/รับเงินแทนได้
   - **งานบัญชีเต็มรูปแบบ** — ให้สำนักงานบัญชี/โปรแกรมบัญชีภายนอก
   - **การกระทำที่ย้อนกลับยาก** — ติ๊กเฉพาะถ้าจะให้แอปนั้นยกเลิกเอกสาร/รวมผู้ติดต่อได้เอง (ควรระวัง)
   - **ตั้งค่าและนำเข้าข้อมูล** — สำหรับงานย้ายข้อมูลเข้าระบบ
   - กางรายการ "สิทธิ์รายตัว" เพื่อติ๊กเพิ่ม/ลดเองได้ ไม่ต้องใช้ทั้งชุด
5. เลือกวันหมดอายุ (30 / 90 / 365 วัน — ค่าเริ่มต้น — หรือไม่หมดอายุ)
6. กด "สร้างคีย์" → **คีย์เต็มโชว์ครั้งเดียว** คัดลอกเก็บทันที (ปิดหน้าแล้วดูซ้ำไม่ได้ ต้องหมุนคีย์ใหม่แทน)
7. คีย์ผูกกับสมุดบัญชีเล่มนี้เล่มเดียวเสมอ — ถ้าร้านมีหลายสมุดบัญชี ต้องสร้างคีย์แยกต่อเล่ม
8. หมดอายุ/เลิกใช้ → กด "เพิกถอน" ในตารางคีย์เดิม, หรือ "หมุน" เพื่อออกคีย์ใหม่แทนที่ตัวเดิมทันที

## ตัวอย่างเรียกจริง (curl)

**1) ทดสอบคีย์ใช้ได้ไหม**
```bash
curl -sS https://shark.in.th/api/v1/account/ping \
  -H "Authorization: Bearer <API_KEY>"
# → {"data":{"ok":true,"systemId":"...","keyName":"..."},"requestId":"req_..."}
```

**2) ดูใบแจ้งหนี้ที่ยังไม่ได้จ่าย (อ่าน)**
```bash
curl -sS "https://shark.in.th/api/v1/account/documents?type=INVOICE&tab=awaiting&page=1&pageSize=20" \
  -H "Authorization: Bearer <API_KEY>"
```

**3) ออกใบแจ้งหนี้ใหม่ (เขียน — ต้องมี Idempotency-Key กันยิงซ้ำ)**
```bash
curl -sS -X POST https://shark.in.th/api/v1/account/documents \
  -H "Authorization: Bearer <API_KEY>" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{
    "type": "INVOICE",
    "contactId": "<contact-id>",
    "lines": [{ "description": "ค่าบริการ", "qty": 1, "unitPriceSatang": 100000 }]
  }'
# 100000 สตางค์ = 1,000.00 บาท (เงินทุกช่องเป็นสตางค์เสมอ)
```

สัญญาเครื่องอ่านได้เต็ม (ทุกช่อง/ทุก error): `GET https://shark.in.th/api/v1/account/openapi.json` (ไม่ต้องใช้คีย์)

## Webhook ทำงานยังไง

1. ในหน้าเดียวกับที่สร้างคีย์ (ตั้งค่า › การเชื่อมต่อ › แอปภายนอก / API) กด "เพิ่ม webhook" → ใส่ URL ปลายทาง + ติ๊กเหตุการณ์ที่อยากรับ (เช่น "เมื่อออกเอกสารบัญชี", "เมื่อลูกค้าจ่ายผ่านลิงก์ขอชำระเงิน")
2. ได้ **secret โชว์ครั้งเดียว** — เก็บไว้ตรวจลายเซ็น
3. ทุกครั้งที่เกิดเหตุการณ์ (ในธุรกรรมเดียวกับที่บันทึกลงบัญชีจริง — ไม่มีทางได้ webhook หลอกที่ไม่มีอะไรเกิดขึ้นจริง) SHARK จะ `POST` ไปที่ URL นั้นพร้อม header `X-Shark-Signature` (HMAC-SHA256 ของ secret + เนื้อ body)
4. ปลายทางต้องตรวจลายเซ็นก่อนเชื่อ body เสมอ — ตัวอย่างโค้ดตรวจอยู่ใน `docs/api/ACCOUNT-API.md` หัวข้อ "Webhooks"
5. ถ้าปลายทางไม่ตอบ 2xx ภายใน 5 วินาที ระบบ retry ให้อัตโนมัติสูงสุด 5 ครั้ง

## AI agent ใช้คู่มือนี้ยังไง

- `GET /api/v1/ai/skills/account` คือ "เมนูเครื่องมือ" ที่ AI agent ใดก็ได้ (ไม่ใช่แค่ของ SHARK) อ่านแล้วรู้ทันทีว่ามีคำสั่งอะไรบ้าง แต่ละคำสั่งรับอะไร/สิทธิ์อะไร — เหมือนส่งคู่มือให้พนักงานใหม่อ่านครั้งเดียวแล้วทำงานได้เอง
- agent เรียกคำสั่งอ่านได้ทันที (เช่น ดูยอดค้างรับ, ดูรายงาน) ส่วนคำสั่งเขียน (ออกใบแจ้งหนี้, ยกเลิกเอกสาร) agent เรียกได้แต่ระบบจะ**ไม่ทำทันที** — สร้างเป็นข้อเสนอ (proposal) ให้เจ้าของ/พนักงานเห็นในแอปแล้วกดยืนยันเองก่อน ระบบถึงจะทำจริง (คนละสิทธิ์กับ AI — ใช้สิทธิ์ของคนที่กดยืนยัน)
- คนนอก (เช่น โปรแกรมบัญชี/ทีมพัฒนาของสำนักงานบัญชี) ก็ใช้คู่มือเดียวกันนี้ต่อระบบของตัวเองได้ผ่านคีย์ API ธรรมดา ไม่ต้องผ่าน AI เลยก็ได้

## ของที่ยังรอเจ้าของ (ไม่ได้บล็อกการใช้งาน API — แต่บางฟีเจอร์ยัง fallback ไม่เต็มรูป)

1. **`BEAM_MERCHANT_ID` / `BEAM_API_KEY` / `BEAM_WEBHOOK_SECRET`** — ไม่มีแล้วลิงก์ขอชำระเงิน (PromptPay) จะ fallback เป็น QR แบบนิ่งที่ต้องกดยืนยันมือ แทนที่จะยืนยันอัตโนมัติเมื่อลูกค้าจ่าย
2. **`DBD_API_KEY` / `DBD_API_URL`** — ไม่มีแล้วปุ่มตรวจเลขผู้เสียภาษีนิติบุคคล (กรมพัฒนาธุรกิจการค้า) จะจางในหน้าเพิ่มผู้ติดต่อ และ API `contacts.lookup-tax-id` จะตอบ `503 upstream_unavailable`
3. **โครงสร้างรับอีเมลเข้ากล่องขาเข้า (`inbox@...`)** — ต้องสมัครผู้ให้บริการรับอีเมล (เช่น Postmark/Mailgun inbound) ก่อนจึงจะต่อสายให้บิลที่ส่งเข้าอีเมลไหลเข้ากล่องขาเข้าบัญชีอัตโนมัติได้
4. **ลบ tenant ทดสอบที่ค้างอยู่บน prod 3 ราย** (`QC7 บัญชี` ×2 จากการทดสอบ 16 ก.ค. + `QC ลบพื้นหลัง`) — ไม่ใช่ข้อมูลลูกค้าจริง ไม่กระทบใคร แต่ควรลบให้สะอาด
5. **Sharky (บอท Telegram) token ตอบ 401** — ค้างจากงานอื่นนอก run นี้ ยังไม่ได้แก้ในรอบนี้

## งานถัดไป (หลัง run นี้)

**AI ในแอป SHARK** ใช้สกิล `account` ที่เพิ่งสร้างนี้เป็นฐาน — ให้เจ้าของ/พนักงานคุยกับผู้ช่วย AI ในแอปแล้วสั่งงานบัญชีได้ตรง ๆ (เช่น "ออกใบแจ้งหนี้ให้ลูกค้า A 5,000 บาท") โดย AI เรียกเครื่องมือ 36 ตัวเดียวกับที่เอกสารนี้อธิบาย — ของที่ทำไว้แล้วจาก run นี้ (WO E1/E2): tool ครบ, persona "นักบัญชี", golden test cases 12 ข้อ — เหลืองาน UI/UX ในแอปแชท (การ์ดยืนยัน, ปุ่มเลือกทางเลือก) และเปิดใช้จริงกับผู้ใช้
