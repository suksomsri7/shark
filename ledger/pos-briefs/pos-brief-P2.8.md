## 2. Rules (server, oracle-tested)
- **R1 Model.** `PosOrder {id, tenantId, systemId, unitId, channelId, channelCode, adapter, externalRef (≤40), code ("<prefix>-NNNN" per unit/day, shown when no externalRef), status, paymentState, fulfilment PICKUP|DELIVERY|DINE_IN, customer {name, phone?, memberId?, partyId?} snapshot, address?, note?, chatConversationId?, shopOrderId?, totalSatang, prepMinutes?, receivedAt, acceptBy?, acceptedAt?, readyAt?, handedAt?, closedAt?, rejectReason?, saleId?, acceptedByUserId?, createdByUserId?, version}` · `PosOrderLine {orderId, productId?, name, qty, unitPriceSatang, listPriceSatang?, priceSource?, priceRuleId?, options Json (choice snapshots), note?, lineTotalSatang}` · `PosOrderEvent {orderId, type, fromStatus, toStatus, actorUserId?, payload Json? (raw adapter payload for P3), at}`. Unique `(tenantId, channelId, externalRef)` (X1) and `(tenantId, idempotencyKey)`. Scope `sys()` (unit filter in code).
- **R2 States.** `NEW → ACCEPTED → PREPARING → READY → HANDED` (= completed) · `NEW → REJECTED` · `ACCEPTED|PREPARING|READY → CANCELLED` (platform/customer). Every transition = `UPDATE … WHERE id AND status = from AND version = v` (one winner; loser ⇒ `ORDER_STATE_CHANGED` with fresh row) + one `PosOrderEvent` + one outbox event in the same tx. Illegal transition ⇒ `ORDER_STATE_INVALID`. `paymentState` = `PLATFORM_PAID` (payout PLATFORM) · `PAY_ON_PICKUP` · `UNPAID` (awaits confirm; P2.7 replaces with intents) · `PAID` (sale exists) · `REFUNDED`.
- **R3 Ingest (one door).** `ingestOrder(ctx, actor|null, {channelId|channelCode, externalRef?, idempotencyKey, lines:[{productId|name+unitPriceSatang (custom, needs pos.sale.priceOverride), qty, choiceIds?, note?}], customer, fulfilment, note?, startStatus?})`: replay of `(channel, externalRef)` or key ⇒ same order, `duplicated:true`, nothing written; same key/ref with different lines ⇒ `IDEMPOTENCY_CONFLICT`. Channel must be this unit's, active, not archived (`CHANNEL_INVALID`); `pausedUntil > now` ⇒ `CHANNEL_PAUSED` for WEB/CHAT/API (MANUAL allowed — staff already accepted on the tablet). Prices via `resolvePrices(channel, at=now)` once, **snapshot** on the line (CD3); refusals mapped (`CHANNEL_NOT_SOLD`/`PRICE_NOT_SET` + lineIndex). Options via the register option rules (P1.2) ⇒ `OPTIONS_INVALID`. ≤ 100 lines. No stock reservation (CD5).
- **R4 Adapters** (`pos/order-adapters.ts`, C-7 interface `{code, accept, reject, setReady, syncMenu?, setAvailability?, setStoreStatus?}`; MANUAL/WEB/CHAT = no-op pushes; registry keyed by `SalesChannel.adapter`). **MANUAL** (`pos.sale.create`): staff form; default `startStatus ACCEPTED` (platform tablet already accepted) — PLATFORM payout ⇒ R6 runs in the same call. **WEB**: `shop/service.ts createOrder` calls the POS facade `orders.ingestInTx(tx, …)` inside its existing tx (marked `// POS P2.8 ▸ … ◂`, shop owner note): channel WEB of the shop unit, `externalRef = ShopOrder.code`, `shopOrderId`, paymentState UNPAID; **no POS ⇒ skipped, never throws** (qc-shop SH-5.2 tenant). `shop.order.paid` consumer (`outbox-consumers.ts:1066` compose, marked) sets `saleId = posSaleId`, `paymentState PAID` (idempotent); `cancelOrder` hunk calls `orders.sourceCancelledInTx` (PENDING ⇒ CANCELLED). **CHAT** (`pos.sale.create`): staff form with channel CHAT + optional `chatConversationId`/`partyId`/`memberId` (validated tenant-local; no chat import), starts NEW/UNPAID or PAY_ON_PICKUP. P3 API adapters: same ingest + `PosOrderEvent.payload` raw + signature check in the webhook route (P3).
- **R5 Accept / reject / progress** (`pos.order.accept` / `pos.order.reject`, new keys, OWNER/MANAGER + STAFF by grant): `acceptOrder({id, prepMinutes?})` (default `channel.prepMinutes ?? 15`, 1..180) · `rejectOrder({id, reasonCode OUT_OF_STOCK|CLOSING|TOO_BUSY|OTHER, note?})` (NEW only; WEB ⇒ consumer cancels the ShopOrder via `shop.cancelOrder` at the composition root — event `pos.order.rejected`) · `markPreparing`, `markReady`, `handOver` (READY → HANDED; DIRECT+unpaid ⇒ `ORDER_UNPAID`) · `cancelOrder({id, reason})` after accept (sale exists ⇒ needs `pos.sale.void`, voids it via the bills void path with reason, P1.15 approval rules apply). `setPrepMinutes`. Other tenant/unit id ⇒ `ORDER_NOT_FOUND` (404-not-403).
- **R6 Sale creation (CD2).** PLATFORM payout channel ⇒ sale **on accept**, in the accept tx: `createSale({sourceModule:"POS", sourceId: orderId, idempotencyKey:"posorder-<id>", channelId, channelRef: externalRef ?? code, payMethods:[{PLATFORM, grandTotal}], lines from snapshot with productId, options, priceSource/priceRuleId/listPriceSatang, itemId (tracked PRODUCT) and components = P2.3 expansion of the **current** recipe, soldByUserId = accepter, memberId?, shiftId = open shift of the accepting device or null})` — no service charge (P2.1 CD8), no tip, no discounts. DIRECT channels ⇒ `payOrder({id, idempotencyKey, payMethods, cashReceivedSatang?})` (CASH needs device + open shift, else `SHIFT_REQUIRED`; tenders = register pay types minus PLATFORM; Σ = total) or, for WEB, the shop's own confirm (ECOM sale stays, linked by R4). Accept replay ⇒ same sale (key), sale refusal ⇒ order stays NEW, nothing written. Stock is cut by createSale after commit (`service.ts:785–790`). Void of an order sale anywhere (bills drawer, approval) ⇒ consumer on `pos.sale.voided` sets `paymentState REFUNDED` + status CANCELLED if not HANDED (idempotent); refunds never change order status.
- **R7 Channel order settings** `setChannelOrderSettings(ctx, actor, {channelId, autoAccept?, prepMinutes? 1..180|null, pausedUntil? ≤ now+24h|null})` (`pos.order.accept`; not via `saveChannel` — P2.1 parser untouched). `autoAccept` on ⇒ ingest (non-MANUAL) runs R5 accept + R6 as `actor null` (soldByUserId null, audit "auto"). "พักรับอัตโนมัติเมื่อครัวค้าง > N" = PLANNED (P2.6, needs `kds.stationQueue`). `adapterConfig` refuses secrets (only `{version, note?}` keys) until P3.1 defines encryption.

- **R9 Storefront reader switch (dual-read, CD4).** Storefront list + `createOrder` price = `resolvePrices(WEB)` for ShopProducts with `posProductId` when the shop unit resolves a POS; else `ShopProduct.priceSatang` (today). Price parity: a one-off idempotent `backfillWebPrices` + dual-write in `catalog-legacy` create/updateShopProduct write a `(WEB, null)` channel row = `ShopProduct.priceSatang` whenever it differs from the row's base (all-branch row because shop units are usually not linked to POS — P2.2 deviation 3); two shops selling one shared row at different prices ⇒ counter `webPriceConflict`, those products keep the ShopProduct price. `confirmOrderPaid` passes `productId` (+ priceSource) on lines but **never `itemId`** (shop cuts stock itself `:278–301`; createSale would cut again `service.ts:789`). `ShopOrderLine.posProductId` written at createOrder.
