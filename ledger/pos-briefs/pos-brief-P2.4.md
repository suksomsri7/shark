## 2. Rules (server, oracle-tested)
- **R1 Scope.** All table functions take `RegisterCtx` + actor and run `regScope` (unit must be linked to this POS). Table/session/order item of another unit/tenant ⇒ `TABLE_NOT_FOUND` (404-not-403), nothing read/written. POS reaches restaurant data only through a new explicit facade `restaurant/index.ts` (tx-taking functions, marked `// POS P2.4 ▸ … ◂`, lazy `import()` against the restaurant→pos cycle) + one fitness edge `pos→restaurant` (CD1).
- **R2 Floor** `registerTables(ctx, actor)` (needs `pos.sale.create` or `pos.sale.read` at the unit) → zones, tables `{id, name, zoneId, seats, state, guestCount, openedAt, unpaidSatang, unsentCount, readyCount, member{name, tier}?, openedByStaff, flags{callStaff, billRequested, payNotified}, dirtySince?, reservation?}` + summary (`used/total`, guests, avg minutes, Σ unpaid). State precedence: INACTIVE > BILL_REQUESTED (REQUEST_BILL/PAY_PROMPTPAY pending) > DINING (OPEN session) > NEEDS_CLEARING (`dirtySince` set) > RESERVED (reservation within hold window) > FREE. `unpaidSatang` = Σ snapshot `lineTotal` of unpaid non-cancelled items (not today's paid-inclusive total).
- **R3 Open** `registerOpenTable(ctx, actor, {tableId, guestCount?, memberId?})` (`restaurant.session.open`): get-or-create under `pg_advisory_xact_lock(hashtext(tableId))` ⇒ 10 parallel opens = 1 OPEN session; INACTIVE ⇒ `TABLE_INACTIVE`; opening clears `dirtySince`; memberId validated by the register member gate.
- **R4 Draft round = held cart bound to the session (CD6).** `holdRegisterCart` accepts `tableSessionId`; ≤ 1 HELD cart per session (partial unique; second hold = update of the same row with `version`); product/custom lines only (no coupon/memberChoices/billDiscount ⇒ `VALIDATION`); session not OPEN ⇒ `TABLE_SESSION_CLOSED`. `listHeldCarts` excludes table drafts (P1.5 unchanged).
- **R5 Send round** `registerSendTableRound(ctx, actor, {tableSessionId, heldCartId})` (`restaurant.order.create`): ONE tx = claim the draft (`HELD→RECALLED`, one winner; replay ⇒ `ALREADY_RECALLED`) + re-price lines with the register resolver (table's channel; P2.2 resolver when merged) + `restaurant.createOrderInTx(tx, …)` (DINE_IN, `placedByUserId`, lines `{productId, menuItemId?, qty, choiceIds, note, unitPrice, optionsTotal}`). MENU rows keep MenuItem stock/86/station rules (refusals mapped: ITEM_UNAVAILABLE/OUT_OF_STOCK ⇒ `PRODUCT_UNAVAILABLE` + lineIndex, BAD_OPTIONS ⇒ `OPTIONS_INVALID`); non-MENU rows get `menuItemId null`, `stationId = PosProduct.stationId ?? first station of the unit` (`ensureDefaultStations`). Price snapshot frozen at send (CD3). Legacy `createOrder` = thin wrapper, same statements; it now also writes `productId = MenuItem.posProductId` inside the same INSERT (S2.42 counts unchanged).
- **R6 Bill quote** = `quoteRegisterCart` with new key `tableSessionId` (+ `lines` must be `[]` ⇒ else `VALIDATION`): server builds lines from the session's unpaid, non-cancelled items in `createdAt` order — `productId` (item.productId ?? MenuItem.posProductId ?? none), name snapshot, qty, `unitPriceSatang = unitPrice + optionsTotal` (server snapshot, never re-priced, no `priceOverride` needed), `options` from `RestaurantOrderItemOption`, `itemId`/`components` from the **current** PosProduct exactly as register meta (`register.ts:1372–1374` + P2.3 expansion). Line/bill discounts, member (cart ?? `session.memberId`), coupon, service charge (POS settings, CD7), VAT, channel (Q4) = normal register math. Empty ⇒ `TABLE_EMPTY`. Result adds `table {sessionId, tableName, itemIds, itemsHash}`. Held drafts are not billed (U warns "มีรายการยังไม่ส่งครัว").
- **R7 Bill submit** = `submitRegisterSale` + `tableSessionId` + `expectedTableItemsHash`: key lookup first (replay ⇒ original sale); then ONE tx: claim `UPDATE RestaurantOrderItem SET saleId, settledAt WHERE id IN (…) AND saleId IS NULL AND kdsStatus <> 'CANCELLED'` (count ≠ n or hash ≠ ⇒ `TABLE_ITEMS_CHANGED`, rollback) → `regCreateSale(saleInput, tx)` (`sourceModule:"POS"`, `sourceId: sessionId`, shift/device/staffToken/tip/intents as today — no new createSale field, no new call site) → if nothing unpaid and no HELD draft: session CLOSED + `RestaurantTable.dirtySince = now()`. Two devices paying one table ⇒ exactly one sale, loser writes nothing. `consumeSaleInventory` after commit (existing).
- **R8 Void / refund.** Any void of a table sale (bills drawer, approval consumer, legacy `voidCheckout`) ⇒ restaurant consumer on `pos.sale.voided` (CD5): unlink items with that saleId, reopen the session if the table has no other OPEN session (same rule as `order.ts:546–554`), idempotent (replay = 0 rows). Refunds never touch table data.
- **R9 Close / clear / requests.** `registerCloseTable` (`restaurant.session.close`): unpaid ⇒ `TABLE_HAS_UNPAID`; empty ⇒ CANCELLED, draft discarded. `registerClearTable` (`restaurant.table.setStatus`) clears `dirtySince`. Cancel item = existing `cancelOrderItem` rules via facade (`restaurant.order.cancelItem`, paid ⇒ refused). Requests list/ack/done via facade (`restaurant.request.ack|done`).
- **R10 Reservations (if Q2 = in).** `RestaurantReservation` CRUD (`restaurant.session.open` to seat, new key only if Q2 says so): `{tableId?, name, phone?, partySize, at, holdFromMinutes (default 15), status BOOKED|SEATED|CANCELLED|NO_SHOW}`; seat ⇒ opens the table (R3) and marks SEATED; RESERVED state on the floor between `at − hold` and `at + 30 min`; opening a reserved table by someone else ⇒ allowed with `reservationOverridden` flag (no block).

- **R12 Refusals & messages.** New register codes `TABLE_NOT_FOUND TABLE_INACTIVE TABLE_SESSION_CLOSED TABLE_EMPTY TABLE_ITEMS_CHANGED TABLE_HAS_UNPAID` (+ existing VALIDATION/PERMISSION_DENIED/PRODUCT_UNAVAILABLE/ALREADY_RECALLED); `refusalMessageKey` → `pos.register.errors.*`; screen strings `pos.tables.*` th + en; ST7 = 0 Thai literals under `src/components/pos/**`, `src/app/app/sys/[id]/pos/**`. ## 5. Rulings proposed (controller decides)
- **CD1 Data stays restaurant-owned; UI moves.** Smallest path that keeps every restaurant suite green: no model move, restaurant module stays the writer, POS calls a new explicit facade (`restaurant/index.ts`) + fitness edge `pos→restaurant` (hot file, one marked line). Alternative (move models/writers into `pos/table.ts`) rewrites every restaurant door and the QR/KDS readers — not worth it in P2.
- **CD2 Rounds stay `RestaurantOrder`** so KDS, QR guest orders, guest bill and service requests keep working unchanged; table mode only adds `productId` to items.
- **CD3 Price frozen at send** (today's restaurant behaviour, Odoo-like): happy-hour/channel price applies when the round is sent, the bill never re-prices. Alternative: re-price at bill (simpler, but a price change mid-meal changes what the guest ordered).
- **CD4 Table bill = normal register sale** (`sourceModule "POS"`, `sourceId` = session) ⇒ bills drawer, void/refund, receipt, shift, reports, BOM, member, channel work unchanged; createSale contract untouched; no new call site.
- **CD5 Void sync by consumer** on `pos.sale.voided` (covers drawer/approval/AI/legacy uniformly) instead of patching each void path.
- **CD6 Unsent round = `PosHeldCart.tableSessionId`** (one per table) — reuses P1.5 hold/recall/expiry, gives "ยังไม่ส่งครัว N" on every device.
- **CD7 One service-charge source in table mode = POS settings** (`register.ts:1380`); `RestaurantSetting.serviceChargeBps` keeps feeding the legacy checkout only; U shows a warning when the two differ (Q3).
- **CD8 Permissions reuse `restaurant.*` keys** for table operations and `pos.sale.create` (+ register rules) for paying; no new key (unless Q2 wants `restaurant.reservation.manage`).
