## 0. Flag
`settings.pos.offline.enabled` (`posOfflineEnabled`, default false) is read by the register / shifts / settings pages and passed down. **Flag off = today's pixels**: register banner `pos-reg-offline-banner` and "ชำระได้เมื่อออนไลน์" unchanged; IndexedDB is not created; the settings card changes only in the two CD-P34U-1 places (§6); the Shifts card is not drawn unless rows exist.

## 1. Device store (ruling 2 · R4 · R13)
IndexedDB `shark-pos-off:<systemId>:<unitId>` (`offline-store.ts`): `meta` (snapshot record `{userId, deviceId, fetchedAt, snapshot}` · `seq` · per-device `salt` · `unlock` verifier) · `queue` (key = idempotencyKey; `queued` | `parked`) · `synced` (real receipt numbers, 24 h / 100 rows). Every write goes through `offlineStoreSafe` (drops `managerPin managerUserId pin phoneLast4 cost* member* giftCard` at every level). The queue is append-only: rows leave only on server OK/DUPLICATE (→ `synced`) or become `parked` on REJECTED (read-only, never resent). Snapshot is bound to the session user + device: another user / flag off / `OFFLINE_DISABLED|DEVICE_REVOKED|DEVICE_NOT_FOUND` ⇒ wiped; `STAFF_TOKEN_INVALID` ⇒ snapshot + PIN verifier wiped (queue kept); a session-user change also wipes the verifier.

## 2. Selling offline (ruling 3 · 19ง)
Offline + flag on (not table mode) ⇒ `offlineSellGate` (enabled · device ACTIVE · snapshot ≤ 24 h · ≤ pvu + 15 min · queue < 300 · clock). Banner `pos-reg-offline-live-banner`: `offline.since` · `offline.sell` · `offline.pending {count}` · `offline.ref {ref}` (last OFF number) · `offline.keepOpen` ("อย่าปิดหรือรีเฟรชหน้านี้ขณะออฟไลน์") + badge; gate refusal ⇒ `pos-reg-offline-gate` text instead. Cart: chips `pos-reg-offline-chip-{points,coupon,card,promptpay}` (aria-disabled) + `offline.chipsNote`; totals = `offlineCartTotals(snapshot, cart)`; walk-in only (member/coupon/tax buyer ⇒ `offline.walkInOnly`); over-cap discount ⇒ `offline.discountOver`; refused lines ⇒ `offline.cartRefused`. Pay row `pos-reg-offline-pay-cash` "ชำระเงินสด ฿x" + `pos-reg-offline-pay-transfer` "โอน" replace `pos-reg-pay` (mobile bar pay / F4 open the cash sheet).
Sheet `pos-reg-offline-pay` (derived): tender radio `pos-reg-offline-tender-{cash,transfer}` · cash `pos-reg-offline-received` (baht → satang integer, `offlineBahtToSatang`) + quick `pos-reg-offline-quick-<i>` + change · transfer `pos-reg-offline-reference` (optional, ≤ 60) · `pos-reg-offline-confirm` "บันทึกบิล ฿x". Confirm ⇒ `cartToSubmitInput` with the bill's own key, `payMethods [{CASH|TRANSFER, total}]`, `expectedGrandTotalSatang = total`, `offlineSaleRefusal` = null required ⇒ `enqueueOffline` (OFF ref `offlineRef(code, nextOfflineSeq(local, server))` in one IDB transaction; same key ⇒ same row). Queue row: `{offlineRef, idempotencyKey, soldAt (device clock), shiftId (last known), staffToken (item level), sellerUserId (token user, else session user), snapshotHash, sale}` + display fields (lines, totals, payments, tender, change). An online `unknown` bill that is offline-sellable moves into the queue with its key (toast `offline.unknownMoved`).

## 3. Done + slip (ruling 4 · R12)
`pos-reg-offline-done` (closes only by `pos-reg-offline-next`): total · `pos-reg-offline-done-no` OFF ref · tender · change · note. `pos-reg-offline-slip` ⇒ `offlineSlipOf(rec)` = `offlineSlipPayload` ⇒ `printReceipt` (title `OFFLINE_SLIP_TITLE`, no `/r/` QR, not ABB; first print of a cash bill kicks the drawer; auto-print when the device printer is paired). After sync: bills list `pos-reg-offline-bill-reprint-<ref>` ⇒ `reprintReceiptAction` (real receipt).

## 4. Sync (ruling 5 · R11)
`use-offline-register.ts`: leader tab via `navigator.locks.request("shark-pos-off-sync:<sys>:<unit>", {ifAvailable})` (no Web Locks = single tab); triggers = `online` event · heartbeat/status ok (`offKickRef`) · 30 s timer; `offlineBatches` (soldAt, ref; ≤ 50) ⇒ `POST /api/pos/sync {systemId, unitId, deviceId, items}` (only `OFFLINE_ITEM_KEYS`) ⇒ `classifyOfflineResult` per item. Whole-batch failure (network · non-2xx · `ok:false` incl. BUSY) ⇒ keep + backoff 30 s × 2ⁿ ≤ 5 min. Snapshot: `POST /api/pos/sync/snapshot` on load · each pvu edge (≥ 15 s after) · every 15 min online; `RATE_LIMITED`/errors ⇒ backoff ≥ 60 s. Badge `pos-reg-offline-badge` "รอซิงก์ n" = local `queued` only (+ "รอผู้จัดการ m"); status bar `pendingSync` = local queue when flag on (server `pendingSyncCount` stays 0 — p1.3 S4.1). Online with queue / sync in last 15 min ⇒ strip `pos-reg-offline-sync-strip` (`data-state` waiting|syncing|done). Bills list `pos-reg-offline-bills`: queued / parked (reason via `offlineRefusalMessageKey` + `parkedHint`) / synced ("ได้เลขจริง {no}") · `pos-reg-offline-bills-sync` · **no void/refund** for unsynced bills (`offline.bills.noVoid`).

## 5. Guards + lock PIN (rulings 6–7)
Shifts: `countQueuedOnDevice` (read-only, never creates the DB; parked rows not counted) ⇒ `pos-shift-close-offline-blocked` "ซิงก์ก่อนปิดกะ — … {count} บิล" + `pos-shift-close-submit` disabled; re-read just before `closeShiftAction`. Lock (flag on): online unlock success (pin · set-own-PIN · manager override) ⇒ `rememberOfflineUnlock(userId, pin)` = PBKDF2-SHA256 310 000 iterations, 16-byte per-device salt, 32-byte hash, fails 0. Offline lock ⇒ list = the holder only, `pos-lock-offline-note` (`data-state` holder|locked|unavailable), pad only for the holder whose token is unexpired; no staff switch, no manager path (`pos-lock-forgot` disabled); wrong ⇒ `offline.lock.invalid {left}`; 5 fails ⇒ locked until an online unlock rewrites it. Idle lock unchanged. P3.5U-F2 folded: `OUTSIDE_HOURS` without a window ⇒ `lock.schedule.offSchedule`.
