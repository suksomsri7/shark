## 2. Rules (server, oracle-tested)
- **R1 Ticket model (CD1).** Kitchen round stays `RestaurantOrder` (+ items); **ticket = (RestaurantOrder, stationId)**. Additive `RestaurantOrder` columns: `posSaleId?`, `posOrderId?`, `channelCode?`, `channelName?`, `externalRef?` (≤40), `targetMinutes?` with partial uniques on `posSaleId` and `posOrderId` (one round per sale/order). `RestaurantOrderItem` unchanged (P2.4 ST1 pin). Source (derived, pure `kds-shared.ts`): `TABLE` (sessionId + placedByUserId) · `QR` (sessionId, placedBy null) · `REGISTER` (posSaleId) · `ONLINE` (posOrderId) · `LEGACY` (else: staff TAKEAWAY/PICKUP page). All writes through new tx functions in `restaurant/*` re-exported by `restaurant/index.ts` (marked `// POS P2.6 ▸ … ◂`); POS never writes restaurant rows directly.
- **R2 Kitchen routing.** A sale/order line goes to the kitchen iff its product is MENU (station = `MenuItem.stationId` of that unit, matched by `posProductId`) or a non-MENU row with `PosProduct.stationId` set and that station is a non-archived `KdsStation` of the unit (Q4); everything else (bottled water, retail beans) never makes a ticket. A unit with **0 non-archived stations ⇒ no tickets at all** (cafés/shops unchanged). Table rounds keep P2.4 R5 (default station) — P2.6 does not re-route them.
- **R3 Register tickets (CD3).** After a register sale commits (normal and intents paths; **not** when the submit carries `tableSessionId`), `kds.ticketForSale(tenantId, unitId, saleId)` builds one TAKEAWAY round from the **sale lines** (name snapshot, qty, `PosSaleLineOption.choiceName` list, `note`, `productId`, station per R2), `posSaleId` set, `placedByUserId = soldByUserId`, `dailyNo` from the restaurant counter (= "คิว N"); idempotent via the partial unique (replay/parallel ⇒ one round); **never refuses a paid sale**: MENU counters are decremented with a floor at 0 through a new catalog-legacy function (auto-86 when it reaches 0, event R9), not the hot-path `consumeMenuStock`. A failure is logged and healed by `kds.healMissingTickets(unitId)` (PAID POS sales of the last 12 h with kitchen lines, no round, `sourceId` null) run on each board read (≤ 20 per call). Sale `VOIDED` before healing ⇒ no ticket.
- **R4 Online tickets.** `orders.acceptOrder` (and auto-accept) creates the round **in the accept tx** via the facade (`posOrderId`, `channelCode/Name`, `externalRef`, `targetMinutes = PosOrder.prepMinutes`, type PICKUP or DELIVERY by fulfilment, DINE_IN ⇒ PICKUP), independent of payment state (DIRECT orders cook before paying). Accept replay ⇒ same round. Kitchen refusal never blocks accept (no counter check; floor-at-0 rule as R3).
- **R5 Ticket states (pure, CD2).** Over non-cancelled items of (round, station): all SERVED ⇒ `SERVED` (off the board, counted) · all ≥ READY ⇒ `READY` · all NEW ⇒ `NEW` · else `COOKING`. `lineDone` = items READY/SERVED while the ticket is COOKING ("เสร็จ 1/2"). Round with every item CANCELLED ⇒ no ticket.
- **R6 Actions** (`pos/kds.ts`, all `(ctx, actor, input)` with unit scope like `RegisterCtx`): `kdsStart({orderId, stationId})` NEW→COOKING for the ticket's NEW items · `kdsLineDone({itemId})` → READY · `kdsTicketDone({orderId, stationId})` all NEW/COOKING → READY · `kdsServed({orderId, stationId})` READY→SERVED (+ `maybeCompleteOrder` semantics) · `kdsRecall({orderId, stationId})` READY|SERVED → COOKING (clears readyAt/servedAt; same bizDate only, else `TICKET_TOO_OLD`; round COMPLETED → CONFIRMED) · `kdsRush({orderId, rush})` (`setOrderRush` semantics). **No paid-item lock** in these functions (cooking ≠ billing); CANCELLED items never move. Forward moves are idempotent (already at/after target ⇒ `{ok:true, changed:0}`); concurrent taps ⇒ one effective change (conditional `UPDATE … WHERE kdsStatus IN (…)`). Foreign/other-unit ids ⇒ `TICKET_NOT_FOUND` (404-not-403), nothing written. Legacy `advanceItem/recallItem` untouched (L-pins).
- **R7 Board reader** `kdsBoard(ctx, actor, {stationId | "expo"})` → `{stations:[{id, name, nameEn, openCount}], tickets:[{orderId, stationId, no, source, label (tableName | channelName · externalRef | "ซื้อกลับ"), channelCode?, isRush, state, sentAt, elapsedSec, targetMinutes, remainingSec, late, warn, lines:[{itemId, qty, name, options[], note, done, cancelled}], doneCount, lineCount, staffName?, queueNo?, readyAt?}], servedToday:{count, last:{no, label, at}?}, pending:[{name, qty}] (Σ qty NEW+COOKING by name, top 8), avgMinutes, targetMinutes, paused, eightySix:[{productId, name, at, source}], serverNow}`. Columns ordered: NEW by sentAt; COOKING rush first then `remainingSec` asc ("เรียงตามเวลาที่เหลือก่อนเลยเป้า"); READY by readyAt. Expo = READY tickets of all stations grouped by round. Today = Bangkok bizDate of the round (`bizDateBkk`). Polling contract 6 s (no new realtime).
- **R8 Timers (CD5).** `targetMinutes` = round.targetMinutes (online prepMinutes) ?? max `MenuItem.prepMinutes` of the ticket's lines ?? `RestaurantSetting.kdsCriticalMins`; `warn` when `remainingSec ≤ 120`, `late` when elapsed ≥ target (header black, "เลยเป้า N นาที"); `avgMinutes` = floor mean of (first readyAt − createdAt) of tickets of this station that reached READY today (0 when none). Pure functions in `kds-shared.ts`, clock injected.
- **R9 Availability (86) writer (CD6).** `catalog.setAvailability(ctx, actor, {productId, unitId, available, source: "KDS"|"MANUAL", note?})` in `catalog.ts` (F15.1): MENU row ⇒ `MenuItem.isOutOfStock` of that unit via catalog-legacy (release also clears a `stockQty ≤ 0` block only if `available:true` and `resetCounter:true` is passed — Q5); non-MENU ⇒ `unavailableUnitIds` (same SQL as `updateProduct`); `PosAvailabilityMark` row upserted on 86 / deleted on release (when, who, source → "ครัวแจ้ง 11:00", KDS 86 list); audit `pos.product.availability`; **one outbox event `pos.product.availability` {productId, unitId, systemId, available, source, at} in the same tx, only when the effective state flips** (replay ⇒ no event). Also emitted (source `STOCK`) by the R3/R4 floor-at-0 path and (source `MANUAL`) by legacy `setMenuItemStock`/`resetMenuItemDailyStock` when they flip `isOutOfStock`/counter-sold-out — **not** by the frozen hot path (`createOrder`/`cancelOrderItem`, S2.42) — gap closes when QR moves in P2.7 (Q6). Choice-level 86 stays restaurant-only.
- **R10 86 → every channel of the unit.** Register tiles/quote already obey (`rowAvailable`, `PRODUCT_UNAVAILABLE`); table rounds obey via the register resolver; QR via `MenuItem`; **P2.8 ingest refuses an unavailable product with `PRODUCT_UNAVAILABLE` + lineIndex** (new check, Q11); reader `availabilityFor(unitId, productIds)` for the storefront/09. - **R11 Online progress (CD7).** In the same tx as a KDS move: first ticket of a `posOrderId` round leaving NEW ⇒ `orders.kitchenProgressInTx` moves the PosOrder ACCEPTED→PREPARING; every kitchen item of the round READY/SERVED ⇒ PREPARING→READY (versioned, one `PosOrderEvent`, `pos.order.ready` once; system actor "kds"). Recall never moves a PosOrder back. PosOrder `CANCELLED`/`REJECTED` (or its sale voided) ⇒ consumer cancels the round's NEW/COOKING/READY items (`cancelReason` "ออเดอร์ถูกยกเลิก"). Reader `kitchenProgress(posOrderIds[]) → {orderId, done, total}` for 09 "ครัวกำลังทำ x/y".
