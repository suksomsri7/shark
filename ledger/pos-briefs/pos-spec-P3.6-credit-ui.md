## 2. Server surface (CD-P36U-2)
- Writer pair (the only new server code): `pos/credit-settings.ts` `updatePosCreditSettings(ctx{tenantId, systemId}, actor, patch)` — OWNER only · strict patch `{credit?: {enabled?, requireBuyer?}, memberOnBill?}` (unknown key / wrong type ⇒ `VALIDATION` + `field`; empty or non-object ⇒ `VALIDATION`) · `$transaction` + `SELECT … FOR UPDATE` · `jsonb_set` of `settings.pos.credit` and `settings.pos.orders.memberOnBill` only · result through the pure readers · no-op ⇒ no write, no audit · audit `pos.settings.updated {section:"credit", credit:{enabled, requireBuyer}, memberOnBill}` (booleans only).
  `pos/credit-settings-actions.ts` `updatePosCreditSettingsAction({systemId, patch})` ("use server" · async only · no throw · try/catch ⇒ `UNKNOWN` · boolean `can(pos.credit.manage)`).

## 3. Behaviour
- **Company (CD-P36U-3)** — chip `pos-reg-company-chip` (name · taxId · head office/branch) + `pos-reg-company-clear`; empty `pos-reg-company-pick`. Sheet `pos-reg-company-sheet`: on open one `registerCompanySearchAction {q:""}` (recent) + `registerMemberCompaniesAction` once when a member is on the bill (section `pos-reg-company-member`); search `pos-reg-company-search` ≥ 2 chars · 300 ms · one request in flight, the latest term runs after it, older answers dropped; rows `pos-reg-company-row-<n>` (member rows first). Pick lives in RegisterScreen state only ⇒ sent as `customerPartyId` on every submit; cleared by `resetBill` (new bill · clear · hold · recall) and on lock. `CUSTOMER_INVALID` ⇒ chip removed + `credit.errors.customerInvalid` (`pos-reg-company-error`).
- **Deal (CD-P36U-4)** — `pos-reg-deal-select` (port of legacy `pos-deal-select`; legacy untouched): one `registerDealOptionsAction` per member/company change, hidden when empty; options `title · stageName` (no value); value outside the new list ⇒ cleared; `crmDealId` on submit; `DEAL_INVALID` ⇒ reset + `deal.errors.invalid` (`pos-reg-deal-error`).
- **Tile (CD-P36U-5)** — `pos-reg-paydlg-method-onaccount` when `credit.enabled` ∧ hasCrm ∧ online ∧ not table ∧ not a PLATFORM bill ∧ not the locked-method mode. No company ⇒ `aria-disabled` + reason `credit.pickCompany` (`pos-reg-paydlg-onaccount-reason`) and tap opens the picker. Status `registerCreditStatusAction({…, amountSatang: due})` as soon as the dialog has a company and on every due change (250 ms · one in flight · latest wins): `enabled:false` ⇒ tile hidden · `allowed:false` ⇒ tile disabled + `credit.errors.notAllowed` · else `pos-reg-paydlg-onaccount-status` (`data-state` · `data-sufficient` · `data-remaining`): sufficient/insufficient · `credit.termDays` · `credit.dueDate` · `credit.remaining` only when the server sent `remainingSatang`. Selecting = one row `{ON_ACCOUNT, due}` (rows removed, tip off/disabled, no split, no cash) — confirm is allowed when insufficient (the server decides → over-limit sheet). `requireBuyer` ∧ no buyer ⇒ 15A opens with `initial = {JURISTIC, name, taxId, branchCode, address "", source MANUAL}` and the confirm stays disabled with `credit.buyerRequired`; buyer taxId ≠ company taxId ⇒ `pos-reg-paydlg-onaccount-buyer-mismatch` (warning only).
- **Over-limit (CD-P36U-6)** — submit refusal `CREDIT_LIMIT_EXCEEDED` ⇒ layer `creditOver` → `pos-reg-credit-over` (`credit.overLimitTitle/Body`; `pos-reg-credit-over-figures` only when the refusal carries `limitSatang`). PIN ⇒ `send()` again with the **same key and bytes** + `creditOverride {managerUserId, managerPin}`. `PIN_INVALID`/`PIN_LOCKED`/`PIN_THROTTLED` ⇒ the pad's message · `PERMISSION_DENIED` ⇒ `credit.overLimitSelf` · OK ⇒ PayDone · other codes / unsure ⇒ sheet closes and the pay dialog shows the card / unknown state. `creditOverride` never reaches sessionStorage nor the in-memory retry copy (retry ⇒ `CREDIT_LIMIT_EXCEEDED` ⇒ sheet again). No approval-request path.
- **PayDone (CD-P36U-7)** — `credit.tile` label for ON_ACCOUNT rows · chip `pos-reg-done-due` = company name · `credit.dueDate` from the last status read (owner-ack · S follow-up: `creditTerms.dueDate` on submit result / bill detail / receipt payload).
- **Bills (CD-P36U-8 · W23)** — method label `shift.method.ON_ACCOUNT` (bills-ui METHOD_KEYS) · accounting row label `pos-bills-credit-invoice` "ใบแจ้งหนี้/ใบกำกับภาษี" (+ the existing `/account/print/<docId>` link = the credit INVOICE) · P1.13 rows hidden · refund: `pos-bills-refund-m-onaccount` only, rows `[{ON_ACCOUNT, draft.total}]` (no allocateRefund), note `bills.refund.m.onAccountSub` · `CREDIT_REFUND_EXCEEDS_REMAINING` ⇒ `refund.errors.creditRefundExceedsRemaining` · void `CREDIT_INVOICE_PAID` ⇒ `register.errors.creditInvoicePaid`.
- **Report (CD-P36U-9)** — tab `pos-reports-tab-credit` when `creditOn`; `?kind=credit` always; table `pos-reports-credit` (company · bills · credit · refunded · outstanding · overdue · oldest due, dates client-side), empty `report.credit.empty`; no `pos.report.view` anywhere ⇒ page card `pos-reports-credit-denied` (no server call) · PERMISSION_DENIED from the server ⇒ same card. CSV/PDF = generic paths.
- **Settings (CD-P36U-10)** — `pos-settings-credit-card`: switches `pos-settings-credit-enabled` / `-require-buyer` (role=switch · OWNER live · busy-disabled · state from the writer result · others `aria-disabled` + `pos-settings-credit-owner-only`) · `enabled` off ⇒ `pos-settings-credit-all-off` · accounts only for `pos.credit.manage` (else `pos-settings-credit-no-permission`) and only with a CRM system (else `pos-settings-credit-no-crm`): rows `pos-settings-credit-row-<partyId>` (name or `settings.credit.unknownCompany` · limit · term / `termDefault` · active) · edit `pos-settings-credit-edit-<partyId>` · add `pos-settings-credit-add` → `pos-settings-credit-search` (registerCompanySearchAction with the page unit · refused ⇒ `settings.credit.searchDenied`) → `pos-settings-credit-found-<n>` · form limit (whole baht ×100 · ≤ POS_CREDIT_LIMIT_MAX) / term (blank = null · 0 shows `termZeroHint` · range decided by the server) / active / note ≤ POS_CREDIT_NOTE_MAX → `saveCreditAccountAction` · refusal ⇒ `pos-settings-credit-error` (`settings.credit.errors.<code>`) · result replaces the row (+ `pos-settings-credit-saved`). Channels tab: `pos-settings-order-member` + `pos-settings-order-member-switch` (OWNER via the same writer) + help `settings.orders.memberOnBillHelp` (W17).
- **Privacy (CD-P36U-11)** — no contact person/phone/e-mail/deal value anywhere; company = name/taxId/branch from the server; limit/exposure/remaining only from server fields; nothing secret logged.
