# POS P2.9U — spec: tender UI (screen 02 row-2 tiles · gift-card panel · store credit · tips · 02b lines · 12 refund to card · tips ledger setting)

Builder U · 14 Oct 2026 · base `session/pos` 4967ce2d (code d871877c = P2.9 S merged) · prompt `pos-prompt-accountB-P2.9U.md` rulings 1–12 · S contract `wo-notes/pos-P2.9.md` §"P2.9U contract" + fix-1 lines H6/F4/H1.
Money is never computed in the UI: due = `quote.grandTotalSatang`; gift-card amount default = min(remaining, lookup `balanceSatang`); "คงเหลือ" on a row = lookup balance − row amount (display only, recomputed by the next lookup); refund caps = `refundTenderOptionsAction` (display only — `refundSale` decides).

## 1. Pay dialog 02 (`src/components/pos/register/InterimPayDialog.tsx`)

Only `RegisterScreen` passes them (not in table mode).
- Row-2 tiles (ruling 1): `registerPayTendersAction` once per dialog open.
  - `pos-reg-paydlg-method-giftcard` "ว่อชเชอร์/บัตรของขวัญ": enabled iff `tenders.giftCard.enabled` (owner enables gift cards in the member system's gift-card settings = `GiftCardSettings.enabled`, `giftcard/service.ts tenderEnabled`); off ⇒ sub "ยังไม่เปิดใช้"; on ⇒ "สแกน/พิมพ์เลขบัตร" / "✓ N ใบ".
  - `pos-reg-paydlg-method-storecredit` "เครดิตร้าน": enabled iff a member is attached, `benefits.giftCards` has a STORE_CREDIT item with balance > 0 (and `tenders.storeCredit.enabled`) and no STORE_CREDIT row yet; sub "คงเหลือ ฿x" · "ไม่มีสมาชิก" · "ไม่มีเครดิต" · "✓ ฿x".
  - `pos-reg-paydlg-method-deposit` disabled "เร็ว ๆ นี้" (P2.9b). `pos-reg-paydlg-method-roomcharge` rendered only when `tenders.roomCharge.visible` (HOTEL unit), disabled "โรงแรม · เร็ว ๆ นี้". Grid = 3 or 4 columns.
  - `pos-member-giftcards` (read-only line) now lists GIFT cards only.
- Gift-card panel (right column `pos-reg-paydlg-giftcard-panel`, replaces amount/quick rows; numpad reused) (ruling 2):
  number `pos-reg-paydlg-giftcard-number` (Enter = look up) · camera `pos-reg-paydlg-giftcard-scan` (RegisterScreen camera layer `forGiftCard` → number only) · `pos-reg-paydlg-giftcard-lookup` → `registerGiftCardLookupAction` ·
  result `pos-reg-paydlg-giftcard-result` "GC-••••1234 · คงเหลือ ฿500 · หมดอายุ dd/mm/yy" · unusable ⇒ `pos-reg-paydlg-giftcard-unusable` (SUSPENDED/EXPIRED/DEPLETED/PIN_LOCKED keys, no PIN step) · NOT_FOUND ⇒ `pos-reg-paydlg-giftcard-notfound` "ไม่พบบัตร" (19 error style) ·
  amount `pos-reg-paydlg-giftcard-amount` (tap = numpad edits the amount; typed > balance ⇒ capped at the balance; balance < remaining ⇒ `pos-reg-paydlg-giftcard-insufficient` "บัตรมี ฿x — รับส่วนต่างด้วยวิธีอื่น") ·
  PIN `pos-reg-paydlg-giftcard-pin` (`type=password`, `inputMode=numeric`, `autoComplete=off`, **uncontrolled** — value never synced to a DOM attribute; numpad = masked mode) ·
  `pos-reg-paydlg-giftcard-use` "ใช้บัตรนี้ · ฿x" (disabled until PIN ≥ 4) ⇒ row `pos-reg-paydlg-giftcard-row-<n>` "บัตรของขวัญ GC-••••1234 ฿325 ✓ · คงเหลือ ฿175";
  same card again ⇒ `pos-reg-paydlg-giftcard-error` "ใช้บัตรนี้ในบิลแล้ว" · 4th card ⇒ "ใช้ได้สูงสุด 3 ใบ" (row not added). Remaining after the row > 0 ⇒ next round = cash (or transfer when cash is used).
- PIN hygiene (ruling 3): PINs live in `pinsRef` (rowId → PIN) + the panel's uncontrolled input; cleared on close (`tryClose`), unmount (sale done), row removal, `GIFT_CARD_CHANGED`, `GIFT_CARD_PIN`/`LOCKED`. `RegisterScreen.savePending`, the in-memory retry request and the 02b layer get `stripPayPins` (number only). A PIN-less replay refused `VALIDATION` (key not committed) ⇒ `pinAgain`: rows (rebuilt from the stored request after a reload, the cart rebuilt with `submitInputToCart` and the rows recreated when the new quote equals the stored total) show "กรุณาใส่ PIN อีกครั้ง" + `pos-reg-paydlg-giftcard-row-pin-<n>` "ใส่ PIN".
- Refusals (ruling 4, `refusalMessageKey`): `GIFT_CARD_PIN` ⇒ every GIFT_CARD row `pos-reg-paydlg-giftcard-row-note-<n>` "PIN ไม่ถูกต้อง", PINs cleared, rows kept, panel reopened on the first row (PIN focus) — the refusal carries no row index and no attempts-left (`register.ts:602`, `service.ts tenderStep`) ⇒ no count shown · `GIFT_CARD_LOCKED` ⇒ re-lookup; locked/unusable rows removed + `pos-reg-paydlg-giftcard-note` "บัตรถูกล็อกชั่วคราว — นำออกจากบิลแล้ว…" (one row ⇒ that row) · `GIFT_CARD_CHANGED` ⇒ banner `pos-reg-paydlg-giftcard-changed` "ยอดบัตรเปลี่ยน — ตรวจสอบใหม่" (+ `-close`), re-lookup of every card row, amount re-capped, PIN re-entry · `STORE_CREDIT_NOT_OWNER` ⇒ row removed + toast `errors.storeCreditNotOwner` · these four codes do not show the generic error card.
- Store credit (ruling 5): tile ⇒ round amount = min(remaining, balance), numpad-editable, capped at the balance (`pay.gc.scOver`); info line `pos-reg-paydlg-storecredit-info` "SC-••••1234 · คงเหลือ ฿x"; row `pos-reg-paydlg-storecredit-row` "เครดิตร้าน SC-••••1234 ฿x ✓ · คงเหลือ ฿y"; one per bill; member removed ⇒ row removed.
- Tips (ruling 6): footer shown only when `tipEnabled` (= `parsePosPaymentSettings(sys.settings).tip.enabled`, `register/page.tsx:103`); toggle `pos-reg-paydlg-tip-toggle` enabled while a cash-like row or a cash-like round exists (else `pos-reg-paydlg-tip-cashonly`); amount `pos-reg-paydlg-tip` (tap = numpad); tip > Σ cash-like ⇒ `pos-reg-paydlg-tip-over` + confirm disabled; Σ row `pos-reg-paydlg-tip-total` "รวมทิป ฿x"; submit field = `tipSatang` (`register-shared.ts RegisterSubmitInput.tipSatang`).

## 3. 12 refund (`BillsClient.tsx`) (ruling 8 · H1)
`refundTenderOptionsAction` (new read-only wrapper, `refund-tender-actions.ts` → `refund-tenders.ts`: `saleForRefund` scope first, then the bill's payments + prior refund rows + `member.tenderCardInfo` / `member.giftCardRefundable`) ⇒ chips:
`pos-bills-refund-method-card-<giftCardId>` "คืนเข้าบัตร GC-••••1234 (สูงสุด ฿x)" (disabled "บัตรใช้ไม่ได้ — คืนเข้าบัตรไม่ได้" / "คืนเข้าบัตรครบแล้ว") · `pos-bills-refund-method-storecredit` "เครดิตร้าน · เข้ากระเป๋าสมาชิก" (member bills; replaces the P1.16 disabled `-credit` chip) · cash/original/EDC chips "สูงสุด ฿y" (`pos-bills-refund-cash-cap`) when the bill has card/credit rows.
Rows = `allocateRefund` (pure, `refund-tenders-shared.ts`): chosen chip up to its cap → bill's usable cards → store credit (member) → cash-like cap → unusable-card share as cash (walk-in only, reason text required `pos-bills-refund-card-cash`) · `pos-bills-refund-split` lists the rows · `pos-bills-refund-uncovered` when nothing covers the rest · GIFT_CARD rows always carry `giftCardId`. Refusals: `REFUND_METHOD_INVALID` ⇒ `refund.tender.methodInvalid` · `REASON_REQUIRED` ⇒ existing key · manager/approval = the existing NO_PERMISSION → PIN / APPROVAL_REQUIRED → 21B paths.
