# POS P2.9bU — spec: deposit UI (02 "มัดจำที่ชำระไว้" tile + pick panel · receive dialog + deposit receipt · 02b applying-bill lines · 12 deposit chip/refund · settings toggle)

Builder U · 15 Oct 2026 · base `session/pos` a1d8af43 (code c3c52ef1 = P2.9b S merged) · prompt `pos-prompt-accountB-P2.9bU.md` rulings 1–11 · S contract `wo-notes/pos-P2.9b.md` §"P2.9bU contract" (+ fix-2 / fix-3 / R1 F5 lines) · `pos-P2.9b-review.md` owner lines (phone required at take).
**No server behaviour change.** Thin wrappers only: `src/lib/modules/pos/deposit-actions.ts` (`registerTakeDepositAction` · `registerDepositLookupAction` · `registerRefundDepositAction` — session → ctx/actor exactly like `register-actions.ts sessionScope`; the S functions do every check).
Money is never computed in the UI: due = quote; deposit amount default = min(remaining due, lookup `remainingSatang`); "คงเหลือ" on a row = lookup `remainingSatang` − row amount (display only); refund amount = lookup remaining (S refuses anything else).

## 2. Receive dialog `deposit-receive` (`DepositReceiveDialog.tsx`) (ruling 5)
Entry: register "⋯" menu item `pos-reg-menu-deposit-receive` (md+) / mobile header button `pos-reg-mobile-deposit-receive` (< 768 has no mode tabs) — visible iff `registerPayTendersAction().tenders.deposit.enabled` (RegisterScreen reads it on mount; not in table mode) **and** the actor may sell (the page itself is `pos.sale.create`-gated; `deposit-actions.ts sessionScope` + S `registerScopeCheck` → `REG_SELL_PERMS` re-check).
Fields: amount `pos-reg-deprcv-amount` (> 0, numpad md+) · customer = member chip `pos-reg-deprcv-member` (bill's member) **or** `pos-reg-deprcv-name` (optional) + `pos-reg-deprcv-phone` (**required** for walk-in, 9–10 digits starting 0 — `depositPhoneOk` mirrors the S check) · `pos-reg-deprcv-note` (optional) · method `pos-reg-deprcv-method-cash|promptpay|card`:
CASH — `pos-reg-deprcv-cash` received (empty = exact) + `pos-reg-deprcv-change`; **`cashReceivedSatang` always sent** (R1 F5) · PROMPTPAY — `usePayIntent` + `PayIntentPanel` exactly as the register (`pi_` intent, key base = `rcvKey`, manual confirm = HF-PP manager rule); no intent setup ⇒ static QR + manual (manager rule) · CARD — EDC reference `pos-reg-deprcv-reference`; manager rule ⇒ `pos-reg-deprcv-manager-only`.
`pos-reg-deprcv-submit` → `registerTakeDepositAction` (idempotency key = `rcvKey`, issued by `RegisterScreen.openDepositReceive` per open — no key created in the dialog file, S5.21) → done `pos-reg-deprcv-done`: "ใบรับเงินมัดจำ #<receiptNo> ฿x" (`-done-title`) + change + receipt preview iframe `pos-reg-deprcv-preview` (= `renderReceiptHtml(receiptPayloadAction(receiptSaleId))` — S renderer, title "ใบรับเงินมัดจำ" (+ " / ใบกำกับภาษีอย่างย่อ") from `payload.depositReceipt`) + `pos-reg-deprcv-print` (first = original payload, then `reprintReceiptAction` copy — as 02b) + `pos-reg-deprcv-finish`.
Refusals → `pos-reg-deprcv-error`: `VALIDATION` ⇒ re-read tenders: setting off ⇒ "ร้านยังไม่เปิดรับมัดจำ", else "ข้อมูลมัดจำไม่ครบหรือไม่ถูกต้อง…" · `PERMISSION_DENIED` with the manual-confirm message ⇒ `refusal.manualConfirmManager` (`submitRefusalMessageKey`, as the register) · others ⇒ `errors.*` (`PAYMENT_MISMATCH` · `PHONE_INVALID` · `MEMBER_NOT_FOUND` · `SHIFT_REQUIRED` · `DEVICE_REVOKED` · `IDEMPOTENCY_CONFLICT` · `INTENT_*`) · `UNKNOWN`/`INTERNAL`/`BUSY`/network ⇒ `pos-reg-deprcv-unknown` + `pos-reg-deprcv-retry` (same key + same request).
Fix1 ruling 3: PromptPay intent already PAID + a definite refusal (`VALIDATION` with the setting off · `PERMISSION_DENIED`) ⇒ the sheet can be closed and `pos-reg-deprcv-paid-ref` "ชำระแล้ว อ้างอิง pi_… — ยังไม่ได้บันทึกมัดจำ…" shows the intent reference; the intent stays PAID (not cancelled), as the register's paid-intent-without-sale handling (`InterimPayDialog` `TERMINAL_SUBMIT` → close allowed + `pay.intent.refundYourself`). Fix1 ruling 4: preview iframe `sandbox="allow-same-origin"` (as ReceiptSettings/TablePreBill).
