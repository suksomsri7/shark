# POS P2.8U — spec: ออเดอร์ทุกช่องทาง (screen 09 · register tab badge · manual order sheet)

Builder U · 10 Oct 2026 · base `session/pos` c81f5bbf · prompt `pos-prompt-accountB-P2.8U.filled.md` rulings 1–9 · S contract `wo-notes/pos-P2.8.md` §"P2.8U contract" + both "P2.8U contract additions" blocks (fix rounds 2 and 3).
Money is never computed in the UI: card/column/summary numbers come from `listOrdersAction`, panel totals + commission/net from `getOrderAction` (`OrderDetail.commission`), manual-sheet line prices/total from `quoteRegisterCartAction({cart:{lines, channelId}})`, the pay dialog due amount = `OrderDetail.totalSatang`. Timers tick client-side from server timestamps only (`acceptBy`, `prepDueAt`, `at`).

## 1. Routes and frame
| route | who | content |
|---|---|---|
| `/app/sys/[id]/pos/orders?unit=` | POS of the tenant + register v2 on; no accessible linked unit = 404; `posOrdersView` refused (no `pos.sale.read` / `pos.sale.create` at the unit, or another unit asked) = refusal card `pos-orders-refusal` (HTTP 200, before any read) | `OrdersScreen` |
| `/app/sys/[id]/pos/sales?unit=&date=&bill=<saleId>` | as before (P1.16) | `?bill=` opens that bill's drawer on load ("ดูบิล" of an order) |
Frame = register frame: `RegisterTopContext` (unit switch links to `/pos/orders`, no camera) + `RegisterModeTabs active="online-orders"` (tables = link when `registerTableMode().visible`) · icon rail (`NavRail.isRailPath` matches `/pos/orders` for v2 systems). No new `POS_NAV_KEYS` (ruling 7).
Register / tables pages: the "ออเดอร์ออนไลน์" tab is a live link to `/pos/orders?unit=` with badge `pos-reg-tab-orders-badge` = `counts.byColumn.new` (hidden when 0 or unreadable). The badge polls `listOrdersAction` every 10 s only while the tab bar is mounted and the window is visible (`useOrdersBadge`); the orders page passes its own count (`ordersBadge`) instead of a second poll.

## 2. OrdersScreen (`src/components/pos/orders/OrdersScreen.tsx`)
- Layout: ≥1280 rail 220 + board + detail column 320 (`pos-ord-side`; no selection = `pos-ord-pick-hint`) · 1024–1279 rail + board, panel = right sheet 380 (`pos-ord-panel-frame`) · 768–1023 board with channel select (`pos-ord-ch-select`) + settings at the bottom, panel = right sheet · <768 channel select + segmented column tabs `pos-ord-coltab-<new|preparing|ready|done>` (one column at a time) + full-screen panel.
- Data: `listOrdersAction` + `ordersChannelsAction` every 10 s while visible (cleared on unmount) and on tab return; selected order: `getOrderAction` on every poll and after every action.
- Header `pos-ord-head` "ออเดอร์วันนี้ {count} · ยอดรวม ฿{total}" (summary) · `pos-ord-sound` toggle (localStorage `shark.pos.orders.sound`, default off; on = 2-tone WebAudio beep + "(N) " title prefix when new NEW ids arrive between polls) · `pos-ord-updated` "อัปเดต hh:mm:ss" from `at` (after mount, HF-418) · `pos-ord-manual` "+ คีย์ออเดอร์" (`pos.sale.create` only).
- New NEW ids between polls (not on first load) ⇒ toast "ออเดอร์ใหม่จาก {channel}".
- Paused channels ⇒ banner per channel `pos-ord-paused-<code>` "{channel} ปิดรับออเดอร์ถึง hh:mm" + `pos-ord-reopen-<code>` (`pos.order.accept` only) → `pausedUntil: null`.
- No `pos.order.accept` ⇒ line `pos-ord-readonly`; every accept/progress button disabled with tooltip `orders.perm.accept` (reject/cancel: `orders.perm.reject`; pay: `orders.perm.create`).
- Empty day `pos-ord-empty`; load error `pos-ord-retry`; toast `pos-ord-toast` (danger tone for refusals).
- Refusals: `messageKey` (under `pos`) when present, else `refusalMessageKey(code)` (`pos.register.errors.*`). `ORDER_STATE_CHANGED` ⇒ the card is replaced in place with the returned `order` + toast + reload. `PENDING_APPROVAL` on cancel ⇒ toast `orders.cancel.pendingApproval`. `orders.errors.saleVoided` on hand-over ⇒ panel opens with the message and "ยกเลิกออเดอร์" emphasised (hand-over hidden).

## 3. Rail (`OrdersRail` · `pos-ord-rail`)
"ทุกช่องทาง N" `pos-ord-ch-all` + one row per channel from `ordersChannelsAction` (STORE / QR_TABLE hidden) `pos-ord-ch-<code>` with `counts.byChannel` and a "ปิดรับถึง hh:mm" sub-line; static row "หน้าร้าน QR" + PLANNED chip (ruling 6 · P2.7). Rows filter the cards (counts stay server-side).
Settings `pos-ord-rail-settings` (`pos.order.accept` only — hidden for others): "รับอัตโนมัติ" switch per channel with adapter ≠ MANUAL/NONE `pos-ord-auto-<code>` → `setChannelOrderSettingsAction({channelId, autoAccept})` · PLANNED chip "พักรับอัตโนมัติเมื่อครัวค้าง" (P2.6) · "เวลาเตรียมมาตรฐาน" `pos-ord-prep-default` (10/15/20/30/45/60, "หลายค่า" when the targets differ) + hint "ส่งให้แพลตฟอร์มเป็นเวลาพร้อมรับของ" · `pos-ord-pause` "ปิดรับชั่วคราว" → sheet `pos-ord-pause-sheet` with `pos-ord-pause-15|30|60|open` ("จนกว่าจะเปิดเอง" = now + 24 h − 1 min, the server cap). Prep default and pause apply to the channel selected in the rail, or to every rail channel when "ทุกช่องทาง" is selected (`orders.rail.appliesTo`).

## 4. Columns and cards (`OrderCardView`)
Columns `pos-ord-col-<column>` from `orderColumnOf(status)`: "ใหม่ N · ต้องรับใน m:ss" (`pos-ord-new-left` = min client countdown of the column; red < 60 s) · "กำลังเตรียม N" · "พร้อม / รอไรเดอร์ N" · "เสร็จวันนี้ N". Order inside a column: oldest first (done: newest first).
Card `pos-ord-card-<ref>` (`data-status`, `data-late`): channel chip (outline; PLATFORM = bold ink border) · ref · `receivedAt` hh:mm · "N รายการ · **฿x**" · customer + `phoneMasked` (+ "รับที่ร้าน hh:mm" from `prepDueAt` for PICKUP after accept) · NEW: `pos-ord-card-timer-<ref>` "รับภายใน m:ss" (red < 60 s, "เลยเวลารับ" at 0) · ACCEPTED/PREPARING: "เตรียม · พร้อมใน N นาที" or red "เลยเวลาเตรียม N นาที" + PLANNED chip "ครัวกำลังทำ" (P2.6) · note chip · CHAT DIRECT unpaid accent strip "สั่งผ่านแชท · รอยืนยันชำระ ฿x" (other DIRECT unpaid after NEW: payment label). NEW buttons `pos-ord-card-accept-<ref>` (channel prep) / `pos-ord-card-reject-<ref>` (hidden for WEB + PAID); READY `pos-ord-card-handover-<ref>` + PLANNED chips rider (DELIVERY) / "พิมพ์ใบปะหน้า" (PLATFORM) (P3). Selected = 2 px accent ring.
Done column = compact rows `pos-ord-done-<ref>` (ref · channel · hh:mm · ฿) + footer `pos-ord-summary` (ยกเลิก/ปฏิเสธวันนี้ N · รับออเดอร์เฉลี่ย N วินาที · เสร็จตรงเวลา n จาก m — from `summary`).

## 5. Detail panel (`OrderPanel` · `pos-ord-panel`, `data-status`)
Header "รายละเอียด {ref}" + channel chip + close `pos-ord-panel-close` (non-column) · "เข้า hh:mm · รับภายใน m:ss" (NEW) / status · customer + phone · fulfilment + "ส่งถึง {address}" (text only; distance/rider = P3) · payment state (not PLATFORM_PAID) · lines `pos-ord-line-<id>` (qty · name · options + note · ฿lineTotal) · customer note · total `pos-ord-total`; PLATFORM ⇒ the P2.1U block (`pos-bill-commission`, keys `pos.channel.commissionBlock.*`): commission (rate text from the channel when known) −฿, VAT on commission when > 0, net `pos-bill-commission-net` = `commission.netSatang`, dashed note.
NEW: "เมื่อกดรับออเดอร์ ระบบจะ" `pos-ord-on-accept` — PLATFORM: open a bill on channel X + cut stock by recipe; DIRECT: bill opens when paid · PLANNED chips kitchen (P2.6) and, PLATFORM only, platform notify (P3).
Customer: "สั่งกับร้านนี้ ครั้งที่ N · เฉลี่ย ฿x" (`history`) · member line (`memberId` ⇒ "เป็นสมาชิก", else "ยังไม่เป็นสมาชิก") · timeline `pos-ord-events` (labels `orders.event.*` incl. `sale_bound`, `paid_reverted`, `prep_changed`, `refunded`).
Footer: NEW `pos-ord-accept` "รับออเดอร์ · เตรียม N นาที" (N = edited value → card `prepMinutes` → channel `prepMinutes` → 15) + `pos-ord-prep-edit` "แก้เวลา" (sheet `pos-ord-prep-sheet` ±5, 1..180; value used on accept) + `pos-ord-reject` "ปฏิเสธ (ของหมด)" · ACCEPTED `pos-ord-start` · PREPARING `pos-ord-ready` · READY `pos-ord-handover` · ACCEPTED/PREPARING `pos-ord-prep-change` → `setPrepMinutesAction` · DIRECT (not WEB) UNPAID/PAY_ON_PICKUP while ACCEPTED..READY `pos-ord-pay` "รับเงิน ฿x" · ACCEPTED..READY `pos-ord-cancel` · WEB + PAID: no reject/cancel, note `pos-ord-web-paid-note` "คืนเงิน/ยกเลิกที่หน้าเว็บร้าน" · sale ⇒ `pos-ord-bill` "ดูบิล {receiptNo}" → `/pos/sales?unit=&date=<Bangkok date>&bill=<saleId>`. Error line `pos-ord-panel-error`.

## 6. Dialogs (`OrderDialogs`)
Reject `pos-ord-reject-sheet`: reasons `pos-ord-reject-reason-<OUT_OF_STOCK|CLOSING|TOO_BUSY|OTHER>` (default OUT_OF_STOCK) + note `pos-ord-reject-note` → `pos-ord-reject-confirm` → `rejectOrderAction`. Cancel `pos-ord-cancel-sheet`: "บิล {receipt} จะถูกยกเลิกด้วย" when a sale exists, reason `pos-ord-cancel-reason` (required) → `pos-ord-cancel-confirm` → `cancelOrderAction` with one idempotency key per sheet opening. Errors stay in the sheet (`pos-ord-sheet-error`).

## 7. Pay (`OrderPay` · `pos-ord-pay-dialog`)
The register `PayDialog` with `dueSatang = order.totalSatang`, no breakdown/quote, no tip, no member/tax-invoice/platform rows, `intent = null` (PromptPay = static QR + manual confirm as P1.6). Confirm → `payOrderAction({id, idempotencyKey, payMethods, cashReceivedSatang?, deviceId})`; key = one per dialog opening; INTERNAL/UNKNOWN/BUSY/network ⇒ "unknown" + retry with the same payload/key; `SHIFT_REQUIRED` etc. ⇒ dialog error (`refusalMessageKey`); `ORDER_STATE_*` / `ORDER_NOT_FOUND` ⇒ close + toast + reload. Success ⇒ toast "รับเงิน ฿x แล้ว" (duplicate ⇒ "รับเงินไว้แล้ว").

## 8. Manual sheet (`ManualOrderEntry` · `pos-ord-manual-sheet`) — DERIVED (mockup 09 has no such sheet; owner design call pending)
Right sheet 420 (full screen < 768) with the note `orders.manual.derivedNote`. Channel `pos-ord-man-channel` = active, non-archived channels with adapter MANUAL or CHAT, excluding STORE / QR_TABLE / WEB (default = rail selection when eligible) · ref `pos-ord-man-ref` (required when channel kind CUSTOM) · name `pos-ord-man-name` (required) · phone `pos-ord-man-phone` · fulfilment `pos-ord-man-ful-PICKUP|DELIVERY` + address `pos-ord-man-address` (required for DELIVERY) · CHAT extras: conversation `pos-ord-man-conv`, party `pos-ord-man-party`, member search `pos-ord-man-member-q` / `-search` / result `pos-ord-man-member-<id>` / clear.
Items: search `pos-ord-man-search` → `registerCatalogAction` list `pos-ord-man-product-<id>` (unavailable / sold-by-weight disabled); options or variants ⇒ the register `OptionsDialog`; lines `pos-ord-man-line-<i>` with −/+ and remove; custom line (`pos-ord-man-custom`, name + price) only with `pos.sale.priceOverride`. Line totals and "ยอดรายการ" `pos-ord-man-total` from `quoteRegisterCartAction({lines, channelId})`; quote refusals with `lineIndex` highlight the line. "ยอดตามแพลตฟอร์ม" `pos-ord-man-platform-total` ≠ quote total ⇒ warning `pos-ord-man-mismatch` (`orders.manual.totalMismatch`, never a refusal).
Start state (MANUAL adapter) `pos-ord-man-start-ACCEPTED|NEW` (default ACCEPTED) · payment (DIRECT payout) `pos-ord-man-pay-UNPAID|PAY_ON_PICKUP` · note `pos-ord-man-note` · submit `pos-ord-man-submit` → `ingestOrderAction({input})` with `idempotencyKey` generated once per sheet opening. `PRODUCT_UNAVAILABLE` / `CHANNEL_NOT_SOLD` / `OPTIONS_INVALID` + `lineIndex` ⇒ highlighted line + message; `IDEMPOTENCY_CONFLICT` ⇒ message + toast, submit locked until the sheet is reopened (new key). Success ⇒ toast, sheet closes, the new order is selected.
