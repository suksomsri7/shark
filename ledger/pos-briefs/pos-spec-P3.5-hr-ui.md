## 1. 13B lock screen (rulings 1–4)
- Card chip `pos-lock-schedule-chip-<userId>` (`data-chip` today|leave|off|none) **only when the item has the `hr` key**: leave ⇒ `lock.schedule.chipLeave` (boolean only — never type/reason) · schedule ⇒ `chipToday {start,end}` (`HH:MM` by integer arithmetic, HF-418) + ` · chipOff` when `inSchedule === false` · no schedule ⇒ `chipOff` when `inSchedule === false` (day off / inactive) else `chipNoSchedule`. Leave cards are dimmed but stay selectable; `inSchedule === false` cards stay selectable. No `hr` key ⇒ render unchanged (p1.15U states).
- PIN of the selected person ⇒ `OFF_SCHEDULE {reason, window}` ⇒ `pos-lock-message` = `lock.schedule.<outsideHours|dayOff|leave|inactive>` (outsideHours with the window) + button `pos-lock-override-open` "ให้ผู้จัดการอนุญาต" (always shown on OFF_SCHEDULE — CD-P35U-2). Anonymous `PIN_INVALID` stays generic (this screen always sends `userId`).
- Override sheet `pos-lock-override-sheet` (title `overrideTitle`, `overrideFor {name}`, `overrideHint`, close `pos-lock-override-close`) reuses `ManagerPinPad` → same `verifyStaffPinAction` with `userId + pin + managerUserId + managerPin`. Wrong manager PIN ⇒ `pos-mgr-pin-error` (PIN_INVALID / PIN_LOCKED copy) · non-manager ⇒ PERMISSION_DENIED copy · `overrideTtlMin = 0` ⇒ server answers OFF_SCHEDULE ⇒ `lock.schedule.overrideDisabled` (new `ManagerPinPad.messageKeyOf` prop, additive).
- CD-P35U-1: the staff PIN lives in a component `ref` from the OFF_SCHEDULE answer until the sheet closes, succeeds, another card is chosen or a new digit is typed — never persisted, never logged, no re-ask. Keyboard input on the lock screen is ignored while the sheet is open.
