## 2. Rules (server, oracle-tested)
- **R1 Model.** `SalesChannel {id, tenantId, systemId (POS), unitId, code, kind BUILTIN|EXTERNAL|CUSTOM, name, adapter NONE|MANUAL|WEB|CHAT|API, active, sortOrder, payout PLATFORM|DIRECT, commissionBp Int 0..10000, commissionFixedSatang Int 0..1_000_000, commissionVatBp Int 0..10000, archivedAt?, createdAt, updatedAt}` + (CD7) `autoAccept Boolean false`, `prepMinutes Int?`, `pausedUntil DateTime?`, `adapterConfig Json?` unused by P2.1. `@@unique([unitId, code])`, `@@index([tenantId, systemId, unitId])`. Per **unit** (mockup 10 "ตั้งค่าเป็นรายสาขา"; C-6 `channel.list({tenantId, unitId})`) — CD1. `code` = `^[A-Z][A-Z0-9_]{1,23}$`; presets: builtins `STORE` "หน้าร้าน", `QR_TABLE` "QR โต๊ะ", `WEB` "เว็บร้าน SHARK Shop", `CHAT` "แชท" · external presets `LINEMAN GRAB FOODPANDA SHOPEE LAZADA TIKTOK` (default payout PLATFORM, adapter MANUAL) · `CUSTOM_*` (e.g. agent, DIRECT).
- **R2 Builtins are lazy and race-free.** `ensureUnitChannels(db, {tenantId, systemId, unitId})` = read; if any builtin missing, `createMany({skipDuplicates:true})` the 4 builtins (ON CONFLICT DO NOTHING — never P2002, safe inside a caller's tx) then re-read. Called by `listChannels` and by `createSale` channel resolution. `STORE`: always active, payout DIRECT, commission fields locked at 0, cannot archive (`CHANNEL_BUILTIN_LOCKED`). Other builtins: name/active/commission editable, code/kind locked.
- **R3 Service** `pos/channel.ts` (single writer; `channel-shared.ts` pure, client-safe; `channel-actions.ts` `"use server"`, async exports only): `listChannels(ctx, actor, {includeArchived?})` → `{ok, items:[{id, code, kind, name, adapter, active, payout, commissionBp, commissionFixedSatang, commissionVatBp, sortOrder, archived}]}` (needs `pos.sale.read` or `pos.sale.create` at the unit); `saveChannel(ctx, actor, input)` exact keys `{id?, code?, name, active?, payout?, commissionBp?, commissionFixedSatang?, commissionVatBp?, sortOrder?, adapter?}` (unknown key ⇒ VALIDATION; create needs `code`; ≤ 30 channels per unit ⇒ `CHANNEL_LIMIT`; dup code ⇒ `CHANNEL_CODE_TAKEN`); `archiveChannel(ctx, actor, {id})` (soft; archived ⇒ not selectable, history keeps the id). Writes need `pos.channel.manage` (new key, OWNER/MANAGER default, label "ตั้งค่าช่องทางขายและค่าคอมมิชชันแพลตฟอร์ม"). Other tenant/unit id ⇒ `CHANNEL_NOT_FOUND` (404-not-403). Audit `pos.channel.created|updated|archived {channelId, code, before?, after}` with the real userId.
- **R4 createSale input (additive only, F15.2):** `channelId?: string`, `channelRef?: string` (platform order no., trim, ≤ 40). Resolution inside the sale tx, after the dup check, before the receipt counter: `channelId` given ⇒ must be this tenant + `unitId` + not archived + active, else `PosSaleError("CHANNEL_INVALID")` (new code) with nothing written; not given ⇒ default by `sourceModule` via pure `defaultChannelCode(sourceModule)`: `ECOM → WEB`, everything else (POS, RESTAURANT, HOTEL, BOOKING, TICKET, CLINIC, SCHOOL, RENTAL, MEMBER, AI) → `STORE` (CD2; no foreign module edited). Snapshot written on the sale: `channelId`, `channelCode`, `channelRef`, `channelPayout`, `channelCommissionSatang`, `channelCommissionVatSatang` (R6). `samePayload` gains `channelId` **only when the caller passed `channelId`** (legacy callers: byte-identical idempotency) — CD3.
- **R5 PLATFORM tender rules** (createSale, so API/P2.8 inherit them): any `PLATFORM` row ⇒ resolved channel `payout = PLATFORM`; a `payout = PLATFORM` channel ⇒ `payMethods` is exactly one PLATFORM row = grandTotal, `tipSatang = 0`, no `cashTenderedSatang`; violations ⇒ `CHANNEL_PAY_MISMATCH` (new code), nothing written. DIRECT channels accept the normal tenders (never PLATFORM). Gift-card-sale bills (`giftCardId`) are always STORE/no commission.
- **R6 Commission math** (pure, `channel-shared.ts`, integer satang, half-up like VAT): base = sale `grandTotalSatang` (after all discounts, incl. service charge, excl. tip — mockup 09: ฿420 × 30 % = ฿126); `commission = min(gross, halfUp(gross × bp / 10000) + fixed)`; `commissionVat = halfUp(commission × commissionVatBp / 10000)` (VAT charged by the platform on top, Thai GP practice — CD5). Snapshot at sale time; later setting changes never touch old bills. STORE ⇒ 0/0. Refund share (R9): `share = full ? sale.commission − Σ prior refund shares : halfUp(sale.commission × refundGross / sale.grandTotal)` (same for VAT) ⇒ Σ shares = sale amount exactly after the last refund.
- **R7 GL — sale.** `applyExternalSale` channel union + `"PLATFORM"` → Dr receivable key (CD4: `AR` 1100 in option A); POS `channelOf` maps PLATFORM explicitly (never the TRANSFER default). PAID JV stays the existing single entry (Dr AR gross / Cr revenue / Cr VAT) — **byte-identical shape for every non-PLATFORM sale**. Then a **separate** idempotent JV via a new facade function `applyExternalChannelCommission({tenantId, sourceSystemId, refId: saleId, occurredAt, commissionSatang, commissionVatSatang, payout, channelName})` → gl `postExternalChannelCommission` key `PosSale#<saleId>#COMMISSION` (book GENERAL, memo "ค่าคอมฯ ช่องทาง <name> · บิล <receiptNo>"): **PLATFORM** Dr commission-expense key (`PAYMENT_FEE` 6500 in option A) `commission` + Dr `VAT_INPUT_UNDUE` 1155 `commissionVat` (VAT book) / Cr AR `commission + commissionVat` ⇒ AR left = net payout (฿420 − ฿126 = ฿294 in mockup 09); **DIRECT** same Dr / Cr `AP` 2100. Non-VAT book ⇒ VAT is folded into the expense line (no 1155). Commission 0 ⇒ no JV. Unlinked POS ⇒ `{posted:false, reason:"unlinked"}`, snapshot kept (X8). Facade calls `ensureAccounting(ctx)` first whenever it posts a PLATFORM/commission key, and the oracle proves **no SUSPENSE / needsReview** on any P2.1 entry. Called from `bridgePosSalePaid` right after `applyExternalSale` (same consumer step, after the PAID JV exists; failure throws ⇒ queue retry; PAID replay is skipped by its own key). Optional (CD6): AR/AP lines carry `contactId` of an account contact named after the channel (subledger per platform).
- **R8 GL — void.** No new code: `reverseFor` already reverses PAID + COMMISSION (oracle proves both reversed, AR and 6500 net 0 for the sale, replay ⇒ no third entry).
- **R9 GL — refund.** `refundSale` copies the channel snapshot onto the REFUND doc and stores its share (R6) in `channelCommissionSatang/VatSatang`. Refund tender: sale paid PLATFORM ⇒ refund method must be PLATFORM (platform refunds the customer); PLATFORM on a non-PLATFORM sale ⇒ `REFUND_METHOD_INVALID` (extend `REFUND_PAY_TYPES` + `refund.ts:155–156`). `applyExternalRefund` channel union + PLATFORM → Cr AR (`postExternalRefund` crLines union widened). Refund consumer then calls `applyExternalChannelCommission` in reverse mode (`refId: refundId`, key `PosSale#<refundId>#COMMISSION_REFUNDED`): PLATFORM Dr AR / Cr 6500 (+ Cr 1155); DIRECT Dr AP / Cr 6500. Replay-safe.
- **R10 Register server.** `REG_QUOTE_KEYS` + `channelId` (and held carts keep it); quote result gains `channel {id, code, name, payout}` (default = unit STORE); unknown/other-unit/archived ⇒ `CHANNEL_INVALID`. `REGISTER_PAY_TYPES` + `PLATFORM` accepted only per R5 (`CHANNEL_PAY_MISMATCH`). Submit forwards `channelId` + `channelRef` (new submit key, ≤ 40). Service charge: applied only on `STORE`/`QR_TABLE` (platform orders arrive at platform price) — CD8. Price seam for P2.2: quote passes the resolved channel into `regPrice` as an argument that P2.1 does not use (one comment `// P2.2 ▸ channel price here ◂`), no price change.
- **R11 Readers.** `BillRow` gains `salesChannel {code, name} | null` + query key `salesChannelId` (additive; the existing `channel` = sourceModule filter keeps its meaning, P1.16 oracle untouched — Q4); `BillDetail.channel {code, name, ref, payout, commissionSatang, commissionVatSatang} | null` (commission visible to `pos.report.view`/manager only); `receiptPayload` + public receipt show "ช่องทาง <name> · <ref>" when code ≠ STORE and **never** any commission figure; shift X/Z: PLATFORM is a non-cash row ("รอแพลตฟอร์มโอน", mockup 07), expected cash unchanged; payments report + close-day + `PAY_TYPE_LABEL_TH`/`POS_PAY_TYPE_LABEL`: PLATFORM = "แพลตฟอร์ม". Legacy bills (`channelId` null) read as `defaultChannelCode(sourceModule)` everywhere (pure fallback; no backfill in this card — CD9).
- **R12 Events.** No new event type. `pos.sale.paid`/`voided`/`refunded` payloads unchanged (consumers read the sale row; C-6's "payload carries channelId/commission" is satisfied by the row — note for the contracts update).
- **R13 Messages & refusals.** New codes `CHANNEL_INVALID CHANNEL_PAY_MISMATCH CHANNEL_NOT_FOUND CHANNEL_CODE_TAKEN CHANNEL_BUILTIN_LOCKED CHANNEL_LIMIT` (+ existing VALIDATION/PERMISSION_DENIED/REFUND_METHOD_INVALID); `refusalMessageKey` (`register-shared.ts`) → `pos.register.errors.*`; settings strings `pos.channel.*`; th + en in `src/messages/{th,en}/pos.json`.
