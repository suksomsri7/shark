## 4. Print module `src/components/pos/print/` (client only)
- `printReceipt(payload, cfg: PrinterConfig, opts: { copy?: boolean; locale: "th"|"en" }) → Promise<{ ok: true, via: "usb"|"bluetooth"|"browser" } | { ok: false, code: "NO_DEVICE"|"PERMISSION"|"UNSUPPORTED"|"WRITE_FAILED", message }>` — never throws; refusals as data with Thai messages.
- `usb`: WebUSB (`navigator.usb.requestDevice` with a printer-class filter + the stored ids for silent reconnect; claim the bulk OUT endpoint; `transferOut` in ≤ 16 KB chunks). `bluetooth`: Web Bluetooth (common ESC/POS GATT services `000018f0-…` / `49535343-…`; write ≤ 20-byte or negotiated MTU chunks with `writeValueWithoutResponse` when available). Both encode with `encodeEscPos(payload, { paper, drawerKick, thaiText, cut: true })`; for `thaiText: "raster"` rasterize each `rasterSlots[].text` with a canvas (Sarabun/system Thai font, width = cols × 12 px at 203 dpi → bitmap `GS v 0 m xL xH yL yH`) and splice **from the last slot backwards** (offsets are pre-splice). Default `thaiText` = `"raster"` unless `printerConfig.thaiText` says `tis620`.
- `browser`: `renderReceiptHtml` into a hidden iframe → `contentWindow.print()`; also the fallback when a transport refuses (`UNSUPPORTED` on iOS Safari for WebUSB/BT → show "เบราว์เซอร์นี้พิมพ์ตรงไม่ได้ ใช้พิมพ์ผ่านระบบแทน" and offer the browser path).
- Pairing UI (dialog): "เลือกเครื่องพิมพ์" → request device → store ids → "จับคู่แล้ว · <productName>". Unpair button.
- Unit-testable pure parts (`raster.ts`: text → bitmap bytes for a given width; `chunk.ts`) get a tiny vitest-free self-check script `scripts/qc-pos-p1.10u-print.mts` (deterministic bytes for a fixed payload, slot splice correctness: output length = Σ, every `GS v 0` placeholder replaced, order preserved) — ~6 checks, no DB.
