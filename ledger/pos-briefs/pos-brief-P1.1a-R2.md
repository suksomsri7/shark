## A. Contract changes (oracle + code)
C1 **System caller is an unforgeable marker, not `null`** (hunter M6 / reviewer N6). `catalog.ts` exports `CATALOG_SYSTEM_ACTOR` (a module-level `unique symbol`); `ctx.actorUserId: string | typeof CATALOG_SYSTEM_ACTOR`. `null`/`undefined`/empty string ⇒ `PERMISSION_DENIED` (fail closed). Backfill and (later) legacy-writer sync pass the marker. Nothing that originates from a request body/session fallback can produce it.
C2 **`trackStock` is tri-state** (hunter H2 — the earlier "explicit column, frozen at backfill" ruling was wrong: an item created today and received tomorrow would never deduct stock). Column `trackStock Boolean?`: `null` = AUTO (effective value = product has `invItemId` AND kind PRODUCT AND (the InvItem has ≥1 stock movement OR `onHand ≠ 0`), computed at read time), `true`/`false` = set explicitly by the shop through `updateProduct({trackStock: true|false|null})`. Backfill and `ensureForInvItem`/`createProduct` leave it `null` unless the caller passes a value. Read model exposes `trackStock: boolean` (effective) and `trackStockMode: "auto" | "on" | "off"`. Setting it explicitly on a product that has an `invItemId` requires `pos.product.manage` AND that the actor can access every branch the product is sold at (see C4); `true` on a product with no `invItemId` ⇒ `VALIDATION`.
C3 **Multi-warehouse POS** (hunter H1). A product with an `invItemId` is visible/sellable at unit U only if that InvItem belongs to the inventory system serving U (the same resolution today's register uses: the unit's own warehouse). Applies to `listForUnit`, `byBarcode`, search, and the `stock[unitId]` value. A POS that spans branches A (warehouse X) and B (warehouse Y) must show only X's items at A.
C4 **Branch authority** (hunter H3 / reviewer S3, S4). Writes on an all-branch product (`unitId = null`), creating one, `ensureForInvItem`, moving a product to `unitId: null`, or moving an all-branch product to one branch require an actor with access to ALL branches (`unitAccess` `*` / OWNER — use the house helper; do not hand-roll). Moving a product between branches requires the permission at BOTH the old and the new branch. A branch-limited manager keeps full control of products scoped to their own branch(es). Categories: same rule (`unitId null` category ⇒ all-branch actor). `assertCategory` must refuse a category of another branch than the product's (all-branch category is fine for any product).
C5 **`byBarcode(ctx, unitId, barcode)` returns `{items: ProductView[]}`** (0..n, deterministic order) — never silently the oldest (hunter M5). Duplicate barcodes are legal in legacy data (InvItem.barcode is not unique); the till will ask the cashier.
C6 **`listForUnit` paging**: `limit` default 100, max 500 (larger ⇒ clamped), always returns `nextCursor` when more rows exist; search is ONE query (name / nameEn / SKU / barcode incl. the linked InvItem's SKU+barcode through an `EXISTS`/join — no unordered `take: 2000` pre-query); `toViews` uses Maps (no O(n·m) filters).
C7 **Price precedence = "what the till charges today"** (hunter M1 / reviewer N8) — replaces R4 and addendum zero-price rule:
   1. `AccountProduct.salePrice > 0`, where the AccountProduct is found EXACTLY the way today's register finds it (`InvItem.accountProductId` → AccountProduct; trace `register.ts` `posCatalog`), not archived, and belonging to the accounting system linked to this POS (`findAccountLinkForPos`). No fallback through `AccountProduct.invItemId`.
   2. else `AccountProduct.posPrice > 0` only when `posEnabled = true` (same row constraints).
   3. else SERVICE: `InvItem.priceSatang > 0`.
   4. MenuItem rows: `MenuItem.basePrice` (0 kept — the restaurant really sells at that price today). ShopProduct-only rows: `ShopProduct.priceSatang` (0 kept — the web shop sells at 0 today) — but each zero is COUNTED (`zeroPriceMenu`, `zeroPriceWeb`).
   5. else `null` ("price not set"). **Cost is never used.** A product whose `salePrice` is 0/null while `costSatang > 0` (today's till charges cost) ⇒ `null` and counted as `soldAtCostToday` in the dry-run with the first 20 ids/names per tenant, so the owner sets a real price before go-live. `salePrice` 0 with cost 0 ⇒ `0` (free today, free tomorrow) counted as `zeroPriceProduct`.
   Any legacy price that is negative / not an integer / > Int32 ⇒ `null` + counted `invalidLegacyPrice` (reviewer N8). Dry-run also counts `posPriceDiffersFromSalePrice`.
C8 **VAT** (hunter M2): copy `vatRateBp` from the AccountProduct only when the linked accounting book is VAT-registered (`vatConfigOf` or the house equivalent); otherwise `null` (= "follow the system VAT configuration at sale time"; P1.6 owns VAT).
C9 **ShopProduct** (reviewer N1, hunter M3/M4): (a) has `invItemId` and that InvItem's product exists in the first POS ⇒ link to it (as today); count `shopPriceDiffersFromCatalog` when `ShopProduct.priceSatang` ≠ the product's price, and `shopInactiveLinked` when the shop row is inactive (nothing is changed on the shared product). (b) has `invItemId` but that InvItem is not in the first POS's warehouses ⇒ create the ShopProduct's OWN row in the first POS (`invItemId` set — the `(systemId, invItemId)` unique allows it — `unitId = ShopProduct.unitId`), counted `shopOwnRowInvItemOutsideFirstPos`. (c) `invItemId` points at a deleted InvItem ⇒ own row with `invItemId null`, counted `shopDanglingInvItem`. (d) no `invItemId` ⇒ own row (as today). In every case `ShopProduct.posProductId` ends set — "every ShopProduct is linked" must hold on messy data. A shop row whose branch is not a branch of the first POS keeps `unitId = ShopProduct.unitId` (web-only, invisible on tills — correct) and is counted `shopBranchNotInFirstPos`; making such rows editable is P2.8 (record as debt).
C10 **`createProduct` validity** (reviewer N7, hunter LOW): `kind MENU|BUNDLE` with an `invItemId` ⇒ `VALIDATION`; the InvItem must be non-archived and its kind must match (`SERVICE` ↔ SERVICE, `PRODUCT` ↔ PRODUCT); a barcode equal to the product's own linked InvItem barcode is NOT a conflict. Unique-violation (`P2002`) from any catalog write surfaces as `CatalogError("CONFLICT")`, never raw.
C11 **Audit truth** (reviewer S5): writers lock the row (`SELECT … FOR UPDATE` via a `forUpdate` flag in `loadProduct`, or `UPDATE … RETURNING` old value) so two concurrent `setPrice` produce a consistent chain (100→200, 200→300); `archive` returns the stored timestamp, not its own, when it lost the race.
C12 **Resolver** (hunter LOW, reviewer N9): archived branches and inactive/archived systems are excluded everywhere (`unitPos`, first-POS choice); "first POS" ordering = `createdAt, id` (same tie-break as `listSystems` — if `listSystems` has none, add the SAME deterministic rule in the resolver and note the difference).
C13 **Backfill safety**: on a production host `--tenant` or an explicit `--all` is mandatory (no flag ⇒ refuse); movement lookup via `groupBy`/raw `SELECT DISTINCT` (never loads all movements — reviewer S8); per-menu option-group grouping through a Map; a named count for every skip/zero/diff above; exit code 0 with counts, never silent.
