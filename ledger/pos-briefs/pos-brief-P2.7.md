## 2. States + money (proposal)
- **S1 Order payment states (additive enum values):** `PENDING_PAYMENT` = order exists, intent PENDING, no sale, no KDS round, no stock; not counted in 09 "ใหม่" nor the accept countdown; `accept` ⇒ `ORDER_UNPAID`. `PREPAID` = intent PAID (money in), no sale yet; accept window counts from `paidAt`. `PAID` keeps its P2.8 meaning (sale exists). `ORDER_INPUT_PAYMENT_STATES` unchanged (staff/REST cannot create these — P2.13 `orders.create` unaffected).
- **S2 TTL:** `payBy = receivedAt + qrExpiryMinutes` (shop setting, default 15, 5–60); intent `expiresAt = payBy`. Expiry ⇒ order `CANCELLED` (event `expired`, reason `PAYMENT_EXPIRED`) + intent EXPIRED, idempotent, triggered lazily by the status read / 09 list read (one conditional UPDATE, pattern `lazyExpire` `payment-intent.ts:179–181`) and by a sweep `expirePreorders()` next to `expirePaymentIntents` in the hourly cron.
- **S3 Paid:** `pos.payment.intent_paid` consumer (replaces the no-op at `outbox-consumers.ts:804`, marked) → `orders.onIntentPaid(intentId)`: order PENDING_PAYMENT ⇒ PREPAID (+`paidAt`, event `paid`, version) — replay = no change; channel `autoAccept` (and kitchen not paused/backlogged, P2.6 R13) ⇒ accept as `actor null`. Static QR: the customer's "โอนแล้ว" tap only adds event `customer_paid_claim` (rate-limited, no money effect) and a 09 chip "ลูกค้าแจ้งโอนแล้ว · ตรวจยอด"; staff confirms with the existing `confirmPaymentIntentManual` (manager rule applies) → same consumer path.
- **S4 Sale on accept (CD3):** accept of a PREPAID order = in the accept tx: `lockSaleIntents` → `orderCreateSale` with `payMethods [{PROMPTPAY|CARD, total, reference: pi_…}]`, `shiftId` = accepting device's open shift else null (non-cash, P2.8 ruling 10), `channelId QR_ORDER`, `channelRef = order code` → `consumeSaleIntents` (intent CONSUMED + saleId) → paymentState PAID → KDS round (existing `:517`). BLOCK stock / sale refusal ⇒ order stays NEW/PREPAID, nothing written (P2.8 ruling 11). Same consume path closes HF-PP2 note `:46` for this flow.
- **S5 Late / orphan money:** Beam PAID after expiry (`lateWebhook`) on a CANCELLED order ⇒ no revive (CANCELLED terminal); ops ERROR `pos.order.late_payment` + 09 cancelled card banner "เงินเข้าหลังหมดเวลา ฿x · ref pi_…"; the PAID intent stays consumable at the register for 24 h (P1.7 CD4) or is refunded outside the system (owner line). Reject/cancel of a PREPAID order ⇒ intent stays PAID unconsumed + ops ERROR refund_needed (same wording as `payment-intent.ts:390`), status page "ร้านคืนเงินให้ภายหลัง — ติดต่อร้าน". Static after expiry: manual confirm refused (`INTENT_EXPIRED`), manager handles.
- **S6 Idempotency:** ingest key from the page (one per cart, `ORDER_KEY_RE`), replay ⇒ same order + same intent (`idempotencyKey = posorder-pay-<orderId>`); 10 parallel submits ⇒ 1 order/1 intent; double webhook / webhook + manual ⇒ one `intent_paid`, one PREPAID transition, one sale (key `posorder-<id>`). Void of the sale later ⇒ P2.8 consumer (CANCELLED/REFUNDED, ruling 13).
- **S7 Stock & 86:** no reservation (P2.8 CD5); 86 + availability refused at submit (`PRODUCT_UNAVAILABLE` + lineIndex, ruling 16) and checked again by createSale at accept. Dine-in rounds keep MenuItem counter semantics; the new round path emits `pos.product.availability {source: STOCK}` on auto-86 flips.
- **S8 KDS timing:** dine-in = at round submit (as today, source QR); pre-order = at accept only (never while PENDING_PAYMENT/PREPAID).
