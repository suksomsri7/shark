Depends on P1.8 (refund server, accepted into `session/pos` with P1.10 — the acceptance SHA goes here: `<fill>`). Reports in English in `ledger/wo-notes/pos-P1.16-oracle.md` / `pos-P1.16.md`.

## 0. Why one card, two halves
P1.8 built `refundSale`/`saleForRefund` + actions; P1.10 built `receiptPayload`/`reprintReceiptAction` + pure `renderReceiptHtml`. What is missing for mockup 12 is (S) one composed page read, one bill-detail read, and a proper `voidSaleAction` (actor · reason · audit · refusals as data), and (U) the page itself. The oracle covers the S half (~22 checks); the U half is checked by the controller's visual run (`--page bills --states`) and the reviewer.

## 2. Rules — server half (S)
R1 **`billsPageData(ctx, actor, q)`** in a new `src/lib/modules/pos/bills.ts` (+ `bills-actions.ts` `billsPageDataAction`, `billDetailAction`, `voidSaleAction`; types in `bills-shared.ts`). Input `{ unitId, date: "YYYY-MM-DD" (BKK), status?: "ALL"|"PAID"|"VOIDED"|"REFUNDED"|"OFF_SHIFT_CASH", q?: string (receiptNo or customer name/phone, ≤60), channel?: string (sourceModule), staffUserId?: string, page?: number (1-based), pageSize?: 10|20|50 (default 10) }`. Permission `pos.sale.read` at the unit (scope via `posSaleWhere`). Returns `{ ok:true, date, counts: { all, paid, voided, refunded, offShiftCash }, summary: { netSatang, billCount, storeCount, onlineCount, avgSatang, yesterdayAvgSatang }, items: BillRow[], total, page, pageSize, channels: string[], staff: [{userId, name}] }`.
   - A **BillRow** is a SALE document: `{ id, receiptNo, time (ISO), sourceModule, customer: { name, sub } | null (sub = member code / tier name / platform ref — whatever the row has; never ids), payMethods: "CASH"|"CASH+PROMPTPAY"… (ordered distinct types), staffName (soldByUserId → name; `"ระบบ"` when null), grandTotalSatang, refundedSatang, status, offShiftCash: boolean (CASH payment + shiftId null), voidApprovedBy?: name (from the void audit, when present), refunds: [{ id, receiptNo, grandTotalSatang }] }`. REFUND documents are **never rows**; they hang off their sale (`refunds[]`), and the status chip shows "คืนบางส่วน" (`refundedSatang > 0 && status PAID`) or "คืนเงินแล้ว" (`REFUNDED`).
   - `counts` are for the date regardless of the active filter; `netSatang` = Σ grandTotal of PAID+REFUNDED sales − Σ refundedSatang (voided excluded) = "หลังหักคืนเงินและยกเลิก"; `avgSatang` = net / (paid+refunded count) or 0; `yesterdayAvgSatang` same formula for date−1. `storeCount` = `sourceModule === "POS"`, `onlineCount` = the rest.
   - `q` matches `receiptNo` (prefix, case-insensitive) or the customer's name/phone (via `memberId` → Customer) — one query path, parameterised, no raw LIKE on user input without escaping.
R2 **`billDetail(ctx, actor, {unitId, saleId})`** → `{ ok:true, bill: { id, receiptNo, status, docType, time, staffName, deviceName, shiftNo, sourceModule, lines: [{ name, qty, unitPriceSatang, discountSatang, lineTotalSatang, options: string[] }], totals: { subtotal, lineDiscount, billDiscount, coupon, tier, serviceCharge, vatSatang, vatRateBp, grandTotal, tip, refunded }, payments: [{ type, amountSatang, tenderedSatang?, changeSatang?, reference? }], member: { name, memberCode, tierName?, pointsEarned, customerId } | null, accounting: { docNo, docId } | null, receiptKind: "TAX_INVOICE_ABB"|"RECEIPT", refunds: [{ id, receiptNo, grandTotalSatang, time, reasonCode, reason, byName, accounting: { docNo } | null }], timeline: [{ time, text }], can: { void: boolean, refund: boolean, reprint: boolean }, voidBlockedReason?: "SHIFT_CLOSED"|"HAS_REFUNDS"|"NOT_POS"|"NO_PERMISSION" } }`.
   - `receiptKind` uses the SAME rule as `receipt.ts` — extract a pure `receiptKindOf({ vatRegistered, posAbbreviatedInvoice, taxId, vatSatang })` into `receipt-shared.ts` and use it in both places (no behaviour change for P1.10's payload). Never call `receiptPayload` for display (it audits / upgrades to copy).
   - `timeline` is built from: sale `paidAt`/`createdAt` ("เปิดบิลและชำระครบ · <staff>"), the accounting doc when linked ("ลงบัญชีอัตโนมัติ <docNo>" + " · ให้แต้มสมาชิก" when `pointEarned > 0`), each refund ("คืนเงิน ฿x · <byName> · <reason label>" + CN no), the void audit ("ยกเลิกบิล · <byName> · <reason>"), and `pos.receipt.reprint` audits ("พิมพ์สำเนา · <byName>"). Ordered by time. "ส่งใบเสร็จทาง LINE" (P1.11) and "กำลังทำรายการคืนเงิน" (presence) are NOT rendered — no invented rows.
   - `can.void` = actor has `pos.sale.void` at the unit AND status PAID AND `refundedSatang === 0` AND (`shiftId` null or that shift OPEN) AND `sourceModule === "POS"`; `can.refund` = `pos.sale.refund` AND P1.8 `saleForRefund.canRefund` logic (status PAID/REFUNDED with refundable qty > 0, POS source); `can.reprint` = `pos.sale.read`.
R3 **`voidSaleAction({ systemId, unitId, saleId, reason, idempotencyKey })`** → `{ ok:true, sale: { id, status }, duplicated?: true }` | refusal `{ ok:false, code, message }` with codes `NO_PERMISSION | SALE_NOT_FOUND | SALE_NOT_VOIDABLE (docType REFUND · status ≠ PAID · sourceModule ≠ POS) | HAS_REFUNDS | SHIFT_CLOSED | REASON_REQUIRED (trimmed reason empty or > 200) | VALIDATION | UNKNOWN`. Message keys `pos.bills.errors.*` th+en. Implementation: service `voidSaleByActor(ctx, actor, input)` in `bills.ts` that checks permission `pos.sale.void` at the unit + scope, pre-checks the refusals (read the row), then calls the existing `voidSale(tenantId, unitId, saleId, { actorUserId, reason })` — **add an optional 4th argument** to `voidSale` (additive, F15.2-safe; all existing callers unchanged) which, when present, writes `writeAudit({ action: "pos.sale.void", targetType: "PosSale", targetId, after: { reason } })` inside the same transaction. Map thrown `PosSaleError` codes to refusals; `Error("บิลนี้ void ไม่ได้")` → `SALE_NOT_VOIDABLE`. Idempotency: a second call with the same `idempotencyKey` (store it in the audit `after`, or look up the VOIDED row + its audit) returns `{ ok:true, duplicated:true }` — never a second outbox event (the outbox key `PosSale#<id>#VOIDED` already dedups; the second call must not throw).
R4 **Refund from the bills page** uses P1.8's actions unchanged. The modal's "คืนเข้า PromptPay เดิม" = `payMethods:[{type:"PROMPTPAY", amountSatang, reference: <original PromptPay reference if any>}]`; "เงินสด" = `CASH` (needs an OPEN shift when the setting requires one → `SHIFT_REQUIRED` shown inline); "เครดิตร้าน" (store credit) is **not** a P1.8 pay type → render the card disabled with "รอบถัดไป (กระเป๋าสมาชิก)" — do not invent a type. A bill that was paid by card only offers CARD (reference) / CASH.
R5 **Reprint** = `reprintReceiptAction` → `renderReceiptHtml(payload, { paper: printerConfig?.paper ?? "80", locale })` → open in a hidden iframe and `print()` (browser print; ESC/POS hardware path is P1.10U — when `src/components/pos/print/` exists in the tree, call its `printReceipt` instead; otherwise iframe). The HTML already carries the "สำเนา"/VOID stamps.
R5b **Two P1.8 leftovers (reviewer MINOR, ruled into this card's S half):** (a) `account/index.ts applyExternalRefund` must use the POS refund document's `vatSatang` (pass it from `bridgePosSaleRefunded`) when the book is VAT-registered instead of recomputing from gross, so a fully refunded bill leaves 2200 at exactly 0 — oracle check: full refund of a VAT bill in two partials ⇒ Σ CN VAT = sale VAT and the 2200 balance for that bill = 0; (b) `service.ts saleStatusByKey` returns null when the row under the key is a REFUND document (modules must never see a refund as their sale) — oracle check: 1.
R6 **No new tables, no schema, no migration.** New files only + the additive `voidSale` arg + tab label + `tabs.ts`/`layout.tsx` label lines. Do not touch `service.ts` beyond the `voidSale` argument, nor `refund.ts`/`receipt.ts` beyond extracting `receiptKindOf`.
