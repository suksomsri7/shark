# ระบบที่ 17: พนักงาน (HR) — เวลาเข้างาน ขาด ลา มาสาย

> ออกแบบโดย Fable 5 (2026-07-12) ตามคำขอเจ้าของ: "ระบบ HR พนักงาน ขาด ลา มาสาย"
> ไฟล์หมายเลข 18 — ทะเบียนระบบ = **ระบบที่ 17** · AppSystem type `HR` (feature) สร้างหลายชุด/เชื่อมระบบ business ได้ตามสถาปัตยกรรมเดิม

## 1. ขอบเขต v1 (Time & Leave — ตามที่เจ้าของขอ)
- **ทะเบียนพนักงาน**: ชื่อ/ตำแหน่ง/เบอร์/วันเริ่มงาน/ค่าแรง (รายเดือน|รายวัน|รายชั่วโมง — เก็บไว้ใช้ payroll P2) · ผูกกับ `User` (login) ได้ optional และผูก `BookingStaff`/พนักงานร้านอาหาร ได้ (คนเดียวกัน)
- **กะ/ตารางเวลา**: กำหนดกะ (เช้า/บ่าย/custom เวลาเข้า-ออก) + จัดตารางรายสัปดาห์ต่อคน + วันหยุดประจำสัปดาห์
- **ลงเวลา (Clock in/out)**: พนักงานกดผ่านมือถือ (login) หรือ**หน้าจอ kiosk ของร้าน + PIN 4 หลักต่อคน** (ร้านเล็กสะดวกสุด) · เก็บเวลา+อุปกรณ์ · GPS/รูปถ่าย = 🔜
- **สถานะอัตโนมัติจากกะ**: มาปกติ / **มาสาย** (เกิน grace period ที่ตั้ง เช่น 15 นาที) / **ขาด** (ไม่ลงเวลาในกะ) / ลา / หยุดตามตาราง — สรุปเป็นปฏิทินรายเดือนต่อคน
- **การลา**: ประเภท (ลาป่วย/ลากิจ/พักร้อน + custom) + โควตาต่อปีต่อคน → พนักงานยื่นในมือถือ → **หัวหน้าอนุมัติ/ปฏิเสธ** (แจ้งเตือน) → ตัดโควตา แสดงยอดคงเหลือ
- **OT**: บันทึกชั่วโมง OT (ยื่น+อนุมัติ) — คิดเงิน P2
- **รายงาน**: สรุปเดือนต่อคน (วันทำงาน/สาย กี่ครั้ง-กี่นาที/ขาด/ลาแยกประเภท/OT) + export CSV — พร้อมเป็น input ทำเงินเดือน

## 2. Data model (systemId-scoped ตามแบบแผนเดิม)
`HrEmployee` (userId?, name, position, pin, wageType, wageSatang, startedAt, active) · `HrShift` (name, startMin, endMin, graceMin) · `HrSchedule` (employeeId, weekday|date, shiftId | OFF) · `HrTimeEntry` (employeeId, clockInAt, clockOutAt?, source KIOSK|MOBILE, status OK|LATE(lateMin)|ABSENT-generated) · `HrLeaveType` (name, quotaDaysPerYear) · `HrLeaveRequest` (employeeId, typeId, dateFrom/To, halfDay?, reason, status PENDING|APPROVED|REJECTED, approvedBy) · `HrOtEntry` — เงินสตางค์/กติกา scope เหมือนโมดูลอื่น

## 3. การเชื่อม (จุดแข็งของ SHARK)
- **Booking**: HrEmployee ↔ BookingStaff คนเดียวกัน → ลา/ขาดแล้ว **slot จองของช่างคนนั้นปิดอัตโนมัติ** (killer feature ที่ FlowHR เดี่ยวๆ ทำไม่ได้)
- **Account (P2 payroll)**: สรุปเดือน → คิดเงินเดือน/หักสาย-ขาด/OT → สร้างรายการค่าใช้จ่ายเงินเดือน + WHT ภงด.1 ลงบัญชีอัตโนมัติ
- **Meeting**: แจ้งเตือนคำขอลา/อนุมัติเข้า channel · **AI พนักงาน**: "เดือนนี้ใครสายบ่อยสุด" / Daily Brief รวมคนลาวันนี้
- **Restaurant/Hotel**: staff ผูกกะเดียวกัน

## 4. Phasing
**P1**: ทะเบียน+กะ+ตาราง+clock in/out (mobile+kiosk PIN)+สาย/ขาดอัตโนมัติ+ลา (ยื่น-อนุมัติ-โควตา)+รายงานเดือน+เชื่อม BookingStaff · **P2**: payroll (สลิปเงินเดือน+ลงบัญชี+ภงด.1)+OT คิดเงิน+ประกันสังคม · 🔜: GPS/selfie clock-in, ประเมินผลงาน, ปฏิทินวันหยุดนักขัตฤกษ์ไทย preset

## 5. HR V2 (RUN พ.ย. 2026 · สถานะ ณ `session/hr` 292bc5b7e — ยังไม่ขึ้น production)
> แหล่งที่มา: `ledger/HANDOVER-2026-11-13-HR-H2.md` (H0–H2) · `ledger/HANDOVER-H3.md` (H3) · ผู้ตรวจ/เจ้าของ/หนี้: `ledger/HR-ACCOUNTANT-SIGNOFF.md` · `ledger/HR-OWNER-LIST.md` · `ledger/HR-DEBTS.md`

### 5.1 H0–H1 (แก้ของเดิม + โครงข้อมูล)
- **PIN**: เก็บเป็นค่าแฮช (`pinHash` + รหัสลับ `HR_PIN_PEPPER`) · ห้ามซ้ำทั้งร้าน · 4–6 หลัก · เครื่องลงเวลา (kiosk) ต้องเลือกชื่อ + PIN และจำกัดการเดา
- **รอบเงินเดือน**: กลับรายการแล้วสร้างรอบเดือนเดิมใหม่ได้ · ปุ่ม "ดึงข้อมูลใหม่" · กันอนุมัติเมื่อข้อมูลเปลี่ยน
- **สาขา**: พนักงานมีสาขาหลัก + ยืมตัวรายวัน · สิทธิ์ `unitAccess` ว่าง = ทุกสาขา · ผู้จัดการสาขาที่ถูกจำกัดเห็นเฉพาะสาขาตัวเอง และเห็นเงินเฉพาะเมื่อมี `hr.payroll.read`
- **ตารางกฎหมาย** (`HrLawTable`): ค่าประกันสังคม/ขั้นภาษี/ลดหย่อน/OT เป็นข้อมูลมีวันที่มีผล ไม่ใช่โค้ด · ทุกแถวเป็นร่างจนนักบัญชียืนยัน

### 5.2 H2 (เวลา ลา OT ของฉัน)
- ตารางกะรายวัน + กระดานจัดกะ (ลาก/วาง · เผยแพร่) · แลกกะผ่านการอนุมัติ
- ลงเวลา v2: ตามกะ · มือถือ + GPS ตามสาขา (ไม่เก็บพิกัดดิบเกินกำหนด) · kiosk ชื่อ + PIN · พัก
- ตัดสินมาสาย/ขาด/ออกก่อนอัตโนมัติ + แจ้งเตือน · ขอแก้เวลา (ของเดิมถูกยกเลิก ไม่ลบ)
- ลา: นโยบาย + โควตา + ยกยอด · วันหยุด preset 15 วันตายตัว (วันเลื่อนได้ร้านเพิ่มเอง) · ประเภทลาตามกฎหมาย + คำเตือนเมื่อต่ำกว่าขั้นต่ำ
- OT: ยื่น → อนุมัติ → จ่ายเฉพาะเวลาที่ทำจริงหลังเลิกกะ · จ่าย max(อัตราของคน, ขั้นต่ำตามกฎหมาย)
- "ของฉัน" `/app/me/hr`: วันนี้/สัปดาห์/คำขอ/เงิน/โปรไฟล์ — ข้อมูลตัวเองเท่านั้น (ระบุตัวจาก session ไม่รับจากหน้าจอ) · กล่องคำขอของผู้จัดการ (อนุมัติเป็นชุด)

### 5.3 H3 (เงินเดือนรุ่นใหม่ · เงิน)
**สิ่งที่ผู้ใช้เห็น**
- **ตารางวันทำงาน**: 1 แถวต่อคนต่อวัน (นาทีทำงาน/สาย/ขาด/ลา/วันหยุด) · วันที่ข้อมูลไม่ครบ (ไม่มีเวลาออก · ลารออนุมัติ · ข้อมูลเปลี่ยน) ต้องแก้ก่อนอนุมัติรอบรุ่นใหม่
- **กฎหักสาย/ขาด** (ปิดเป็นค่าเริ่ม): ระบบเสนอรายการหัก "รออนุมัติ" ตามสัดส่วนเวลา (÷30 ÷ ชั่วโมงปกติต่อวัน) · ไม่มีค่าปรับคงที่
- **เครื่องคิดเงินเดือนรุ่นใหม่ (v2)**: ภาษีสะสมทั้งปี · ประกันสังคมจากตารางกฎหมาย · คิดตามสัดส่วนคนเข้า/ออกกลางเดือน · เพดานหักค่าเสียหาย 10%/20% + ช่อง "มีหนังสือยินยอม" · ยอดหักที่เกินยกไปงวดหน้า · คนลาออกมีลูกหนี้ · ผู้สร้าง/คำนวณใหม่อนุมัติรอบเองไม่ได้ (เว้นเจ้าของ) · รอบที่มีเงินของผู้อนุมัติต้องให้เจ้าของอนุมัติ
- **ยอดยกมาต้นปี**: ร้านที่เริ่มใช้กลางปีกรอกเงินได้/ภาษี/ประกันสังคมก่อนใช้ระบบ (การ์ดบนหน้าเงินเดือน) · ไม่กรอก = เตือน
- **ไฟล์โอนเงินธนาคาร**: KBank · KTB (ปิดเป็นค่าเริ่ม) + CSV/XLSX ทั่วไป · ระบบไม่เก็บตัวไฟล์ สร้างใหม่ตอนดาวน์โหลดและตรวจว่าตรงกัน (หมดอายุ 7 วัน)
- **แบบยื่น**: ไฟล์ ภ.ง.ด.1 / ภ.ง.ด.1ก / สปส.1-10 ให้ร้านอัปโหลดเอง · หนังสือ 50 ทวิ PDF (พนักงานดาวน์โหลดของตัวเองได้)
- **ลงบัญชี**: เจ้าของผูก HR กับสมุดบัญชี → อนุมัติรอบ = ตั้งค้างจ่าย · บันทึกจ่าย = ตัดเงินฝาก · กลับรายการสมมาตร · ไม่ผูก = ไม่ลงบัญชี · ปุ่ม "คืนเงิน" ค่าเสียหายที่หักไปแล้ว
- **สลิป + หนังสือรับรองเงินเดือน**: สลิปในแอป + PDF + ประวัติรายปี · พนักงานขอหนังสือรับรองเงินเดือน → เข้ากล่องคำขอ → ออก/ปฏิเสธ (เอกสารภาษาไทย ไม่มีเลขบัตรประชาชน)
- **รายงาน**: เวลา · ลา · OT · เงินเดือน · ภาษี/ประกันสังคม · ค่าจ้าง · ทะเบียนลูกจ้าง (หน้า + CSV/XLSX)

**สิทธิ์**
- เปลี่ยนรุ่นเครื่องคิดเงินเดือน · เพดานหัก · ผูกสมุดบัญชี/บัญชีจ่าย · ข้อมูลผู้ยื่นแบบ · เปิดเลขบัตรเต็มในทะเบียน = **เจ้าของเท่านั้น**
- ไฟล์ธนาคาร · แบบยื่น · 50 ทวิ · ยอดยกมา · หนังสือรับรองเงินเดือน = เจ้าของ หรือคนที่มี `hr.payroll.read` + `hr.payroll.pay` และเห็นทุกสาขา (บทบาทผู้จัดการอย่างเดียวไม่พอ)
- สลิปฝั่งร้าน = เจ้าของ หรือ `hr.payroll.read` (เฉพาะคนที่สาขาหลักอยู่ในสิทธิ์)
- ปฏิเสธรายการปรับเงิน / กลับรายการรอบ ใช้คีย์ใหม่ `hr.payadjust.reject` · `hr.payroll.reverse`
- ตรวจสิทธิ์จากสมาชิกภาพในฐานข้อมูล ไม่เชื่อค่าที่ส่งมา

**ความเป็นส่วนตัว**
- ผู้จัดการไม่เห็นตัวเลขเงินในตัวอย่างรอบ/OT/กล่องคำขอ เว้นมีสิทธิ์ดูเงินเดือน · ยอดรวมในรายงานคิดจากแถวที่ผู้ดูเห็นเท่านั้น
- เลขบัตรประชาชนปิดเหลือ 4 ตัวท้ายทุกที่ (เปิดเต็มได้เฉพาะไฟล์ทะเบียนลูกจ้าง เมื่อเจ้าของเปิดค่าตั้ง) · ไม่ส่งออก เลขบัญชีเต็ม/ที่อยู่ทะเบียนบ้าน/เลขประกันสังคม/เหตุผลการลา/บันทึก
- คำปฏิเสธไม่มีข้อมูลใด ๆ และเหมือนกันทุกไบต์สำหรับทุกคนที่ไม่มีสิทธิ์ · audit ของแบบยื่นไม่เก็บเลขบัตร/เลขผู้เสียภาษี

**ป้าย "ยังไม่ได้ทดสอบกับระบบจริง"** (แสดงบนหน้าจอ ไม่บล็อก)
- ไฟล์ธนาคาร: "ยังไม่ทดสอบกับธนาคารจริง" — เปิดใช้ต้องติ๊กรับทราบ
- ภ.ง.ด.1/1ก: "ยังไม่ทดสอบกับ e-Filing จริง" · สปส.1-10: "ยังไม่ทดสอบกับ e-Service จริง" + ช่องค่าจ้าง "ยังไม่ยืนยัน"
- 50 ทวิ แบบ PDF/อีเมล และสลิป: "โปรดตรวจกับนักบัญชีของร้าน"
- ตารางกฎหมาย: "รอนักบัญชียืนยัน — ตารางกฎหมายยังไม่เปิดใช้ เงินเดือนทุกงวดยังคิดด้วยเครื่องคิดเดิมตามปกติ"

**ข้อจำกัดตอนนี้**
- เครื่องรุ่นใหม่ **ยังปิดทุกร้าน** จนนักบัญชียืนยันตารางกฎหมาย (HQ23) และเจ้าของร้านกดเปิดเอง
- ร้านที่มีพนักงานรายวัน/รายชั่วโมง/รับคอมฯ อย่างเดียว เปิดรุ่นใหม่ไม่ได้ จนกว่านักบัญชียืนยันวิธีหักภาษี (NA-11)
- รอบเงินเดือนเก่า (เครื่องเดิม) คงเดิมตลอด ไม่คำนวณย้อน
