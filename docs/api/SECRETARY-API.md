## กติการ่วม
1. **Auth**: `Authorization: Bearer <mobile token>` (`issueMobileToken` · `src/lib/mobile/auth.ts`) ทุกเส้น ยกเว้น `auth/sms/*` (ก่อนล็อกอิน) และ `secretary/invites/[code]` (สาธารณะ · เพดานต่อ IP) · เส้นระดับกิจการต้องมี `x-tenant-id` → `requireMobile` (Membership `acceptedAt ≠ null` + ร้านไม่ SUSPENDED/CLOSED) · เส้นระดับผู้ใช้ (ไม่ต้องมีร้าน) = `mobileUser`: `secretary/secretary` · `secretary/inbox` · `secretary/inbox/count` · `secretary/tenants/create` · `secretary/invites/accept` · `secretary/account/*` · คีย์สิทธิ์ปริยายของ `secretary/*` = `ai.chat.send` (คีย์เดียวกับประตูเว็บ `lib/ai/actions.ts` · `mobileDenied`) — เส้นที่ lib ตัดสินสิทธิ์จากฐานเอง (access/rules PUT · staff · support · notify · after-hours) ด่านเป็นแค่ "สมาชิก" แล้วให้ lib ตรวจ · 🔴 ตัวตน/ร้าน/เวลามาจากด่านเท่านั้น (body ห้ามมี `now`/`userId` ของผู้ทำ/`tenantId` ของผู้ทำ — schema `.strict()` ตอบ 400)
2. **มองไม่เห็น = 404** (`not_found`) ไม่ใช่ 403 · ไม่มีสิทธิ์ทำ = 403 `forbidden` พร้อมข้อความไทยไม่โทษผู้ใช้
3. **Rate limit** ด้วย `checkRateLimitDb` (`src/lib/core/rate-limit-db.ts` · fixed window 1 นาที · DB ร่วมทุก instance) กุญแจ `sec:<route>:<tenantId>:<userId>` (เส้นระดับกิจการ · ต่อ Membership แบบ inbox) / `sec:<route>:<userId>` (เส้นระดับผู้ใช้) · ทุกเส้นเขียน 30/นาที ปริยาย · `rooms/[id]/send` 10/นาที · `staff/invite*` 10/นาที · `support/upload` 10/นาที · `tenants/create` 5/นาที · `account/delete` 3/นาที · `invites/[code]` 30/นาที/IP · เกิน = **429 `{ error: "rate_limited", message, retryAfterSec }` + หัว `Retry-After`** · GET ไม่ติดเพดาน (ยกเว้นเส้นสาธารณะ)
4. **Body** zod `.strict()` · เพดาน 64 KB (`413 too_large`) · JSON เสีย = `400 bad_json` · รูปผิด/คีย์เกิน = `400 invalid` (+ `field`) · id ใน path ≤ 80 ตัว (ยาวเกิน = 404) · แนบไฟล์: แชทลูกค้า 10 MB ผ่าน `inbox/attachments` · เรื่องช่วยเหลือ ภาพ 5 MB ผ่าน `secretary/support/upload` · ส่งซ้ำได้: `rooms/[id]/send` ใช้ `clientMessageId` (จองกุญแจ 24 ชม. ใน `ChatRateBucket` · ซ้ำ = 200 `{duplicate:true}`)
5. **DTO ไม่มี** token/micro-dollar/ต้นทุน/คีย์/รหัส OTP/codeHash/credentials ช่องทาง/prompt (X10) · ตัวเลขผู้ใช้ = งาน · % · นาที
6. **รูปตอบ**: สำเร็จ `200 { ...dto }` · ล้มเหลว `{ error: code, message: "<ไทย>" }` · 401 unauthorized · 403 forbidden/missing_tenant/suspended · 404 not_found · 409 conflict (closed/quota/already/not_pending) · 410 expired · 429 `{ error: "rate_limited", message, retryAfterSec }` + `Retry-After` ทุกเส้น (และ server actions คืน `{ok:false, error:"rate_limited", retryAfterSec}`) · 503 sms_unavailable · 500 server_error (ข้อความไทยทั่วไป · รายละเอียดดิบไป `logOps` เท่านั้น) · ข้อผิดพลาดตามกติกาที่ lib โยนเป็น `Error` ไทย = 400 invalid พร้อมข้อความนั้น · `approve`/`undo`/`plans/approve` คืน 200 `{ ok:false, note }` เมื่อด่านของ lib ไม่ผ่าน (รูปเดียวกับ `/api/mobile/proposals/confirm` เดิม) · list = `{ items, nextBefore? }` (cursor `before` = ISO)
7. เวลา ISO-8601 UTC · เงินเป็นสตางค์ · แชทลูกค้า: `systemId?` ไม่ส่ง = ระบบแชทตัวแรก (`resolveChatSystemId`) · ด่านสิทธิ์ใช้ค่าคงที่ `CHAT_READ_ACTION` (guard.ts) และ `"chat.message.send"` (permissions.ts) ที่ import มา (R-K13/R-K14)

## RoomStatus (ค่าที่เซิร์ฟเวอร์ส่งจริง · `roomStatusOf` ใน `src/lib/ai/secretary/rooms.ts`)
มีแค่ 4 ค่า เลือกตามลำดับ **DONE > RUNNING > WAITING > OPEN**:
- `DONE` = ห้องถูกปิด (`closedAt` ไม่ว่าง) — **ไม่มี "DONE ขณะห้องยังเปิด"**: งานเสร็จแต่ยังไม่ปิดห้อง = `OPEN`
- `RUNNING` = มี `AiRoomJob` สถานะ QUEUED/RUNNING (เลขากำลังทำ)
- `WAITING` = มีข้อเสนอหรือแผน PENDING ที่ยังไม่หมดอายุ (รออนุมัติ) — **ไม่มีค่า `WAITING_APPROVAL`**
- `OPEN` = นอกเหนือจากนั้น (เปิดอยู่ ไม่มีงานค้าง ไม่มีอะไรรออนุมัติ)
ตัวกรอง `GET rooms?status=` รับ 4 ค่านี้เท่านั้น (อื่น = 400)

## หมายเหตุ
- ห้อง AI รุ่น 1.0 (`/api/mobile/conversations/*` · `/api/mobile/chat/send` SSE · `/api/mobile/proposals/*` · `/api/mobile/plans/*`) คงเดิมทุกตัวอักษร (COMMON §C.11) · แอปจอใหม่ใช้ `/api/mobile/secretary/*` เท่านั้น
- push: ทุกใบจาก `notifyUser` มี `data.tenantId` (R-S1.14j — แอปสลับร้านก่อนเปิดลิงก์) · deep-link: `data.link` = `/secretary/room/<id>` · `/inbox/<convId>` · `/help/<caseId>` + `data.conversationId` สำหรับ build เก่า (R-K20)
  - แชทลูกค้า (S1.24): `/inbox/<convId>?e=helper` (ถูกเรียกช่วย) · `?e=handoff` (ถูกส่งต่อ) · `?e=assigned` (กฎรับเรื่องมอบหมายให้) · `?e=sla` (เตือน/ย้ายเพราะรอนาน) — `e` แยกเรื่องให้ตัวกันสแปม 60 วิของ `notifyUser` (ผูก link) ไม่กินแจ้งเตือนเรื่องที่ต่างกัน · แอปอ่านแค่ path ก็พอ
- เส้นที่ทำให้โมเดลถูกเรียก: `secretary/rooms` POST และ `secretary/rooms/[id]/send` เท่านั้น (worker `runRoomJobs` ใน `after()` → `sendMessage` → คิดต้นทุนผ่านทางเดิมของ service · บันทึก `AiCreditTxn.conversationId`) · นับงานเฉพาะ `rooms` POST (R-K6 · `startRoom`) · `tenants/create` เปิดห้องแรกด้วย `startRoom` (นับ 1 งาน · ยังไม่เรียกโมเดลจนกว่า worker หยิบ) · `proposals/[id]/reject` ไม่เรียกโมเดล
- เว็บ (RSC): `src/lib/ai/secretary/server-actions.ts` (`"use server"` · `sec<Verb><Entity>Action` · session `requireTenant` + `assertCan(ai.chat.send)`) เรียก lib + DTO ตัวเดียวกับ route — ชื่อไฟล์ไม่ใช่ `actions.ts` เพราะ `src/lib/ai/secretary/actions.ts` = บันทึก/ย้อนของ S1.8
